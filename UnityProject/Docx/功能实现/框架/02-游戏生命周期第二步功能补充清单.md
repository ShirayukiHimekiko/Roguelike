# 游戏生命周期第二步：功能补充清单

2026-11-16 · 功能讨论稿

> 按你的要求，P0 的错误/泄漏问题先不讨论；本文只列“生命周期还需要哪些功能”。  
> **原 F1（开局参数 + RunId）已取消，不做 `GameRunConfig` / `RunSession` / `RunId`。**

## 1. 当前已经有的

```text
Start → Run
应用暂停/恢复 → Pause / Run
应用退出 → Exit
ExitGameState.OnEnter → End
OnRelease → 退订 + DestroyFsm
```

当前能做的只有：启动、切后台暂停/恢复、退出、释放。还不能“正常打完一局”，也没有结束条件、结果、返回和再开。

## 2. 功能清单

### P1：下一步就该有的

| # | 功能 | 为什么需要 | 最小形态 | 依赖 |
|---|---|---|---|---|
| F2 | Run 推进 | 现在 Run 是空类，生命周期没有“进行中”的内容 | `RunGameState.OnUpdate` 累加时间/进度；先支持手动 `Advance(dt)` 或计时 | 无 |
| F3 | 自然结束 | 没有结束条件，End 只能靠退出触发 | 胜利/失败/超时至少一种条件；先做“计时结束”样本 | F2 |
| F4 | 结果 | End 现在是空类，没有“这局怎么样” | `Completed/Abandoned/Faulted` + 一次性提交 | F3 |
| F5 | Exit 清理并回 Start | Exit 只切 End，不能返回再开 | `ExitGameState` 清理本局 → `StartGameState` | F4 |
| F6 | 主动放弃 | 只有应用退出，没有“放弃本局” | `AbandonGame()` → Exit(Abandoned) | F5 |
| F7 | 再开一局 | 生命周期必须能循环 | Start 再次进入 Run，进度归零 | F5/F6 |
| F8 | 调试入口 | 没有 UI，必须能从代码/GM 触发 | `StartRun/EndGame/AbandonGame/Restart` | F2-F7 |
| F10 | 玩家暂停 vs 切后台 | 现在只有应用暂停，玩家暂停会被后台恢复顶掉 | `GamePauseSource` + `PauseGame()` / `ResumeGame()` | F2 |

### P2：闭环之后再加

| # | 功能 | 为什么需要 | 说明 |
|---|---|---|---|
| F9 | 生命周期事件 | UI、音频、埋点、战斗都要知道开始/暂停/结束 | `RunStarted/RunPaused/RunResumed/RunEnded/RunExited`；先内部 Action，后续再接 GameEvent |
| F11 | 准备/加载阶段 | 开局前要装配样本/资源/场景 | 没有资源/UI 前先不做；需要时在 Start 与 Run 之间加 Prepare/Loading |
| F12 | 局内统计 | 结算需要伤害、击杀、用时等 | 先留统计容器，具体字段随战斗接入 |
| F13 | 失败/故障分支 | 现在只有 Completed/Abandoned | 增加 `Faulted` 的触发路径和结果 |
| F14 | 暂停时的表现冻结 | 逻辑暂停不等于动画/粒子暂停 | 先保证 Run 不推进；表现层后续接 |

### P3：依赖外部系统

| # | 功能 | 依赖 |
|---|---|---|
| F15 | 固定帧驱动 | Run 的推进改为固定 Tick；原 `02-Project_B固定帧驱动分步执行方案.md` |
| F16 | 战斗模块接入 | 局内战斗/场次管理；原 03 |
| F17 | 大厅/UI | 开始、暂停、结束、返回按钮 |
| F18 | 样本/资源加载 | YooAsset、加载失败、加载中放弃 |
| F19 | 存档/回放/奖励 | 结果、局外系统 |

## 3. 建议下一批做哪些

推荐先做 **F2–F8 + F10**，形成一个最小可验收循环：

```text
StartRun → Run（计时/手动推进）→ End(Completed)
          ├─ PauseGame()/ResumeGame()（玩家暂停）
          ├─ 切后台/回前台（应用暂停）
          ├─ AbandonGame() → Exit(Abandoned)
          └─ ExitGameState → Start
再 StartRun → 进度归零
```

理由：

- F2 没有的话，Run 永远是空壳，后面的 End/结果都没东西可挂。
- F3/F4 是“一局有结果”的最低要求；没有结果，生命周期无法验收。
- F5/F7 决定能不能循环，否则只能开一局。
- F6/F8 让没有 UI 的情况下也能手动验收。
- F10 和 F2 一起做，暂停来源和 Run 推进一起定型，避免后面返工。
- F9 事件可以等 F2–F8 + F10 稳定后再加，避免一开始就上事件总线。

## 4. 功能之间的边界

| 问题 | 建议 |
|---|---|
| End 和 Exit 谁负责什么 | End = 冻结本局结果；Exit = 清理本局并回 Start。Exit 不要再自动切 End |
| 自然结束和放弃怎么区分 | 自然结束提交 `Completed`，放弃提交 `Abandoned`，Exit 只清理不覆盖结果 |
| 应用退出算什么 | 应用退出可以先切 Exit；是否补一个 `Completed/Abandoned` 由你定，不能默认算完成 |
| 切后台算不算玩家暂停 | 不算；用 `GamePauseSource` 分开记，回前台只恢复应用暂停，不覆盖玩家暂停 |
| 结果谁发布 | End 冻结一次；Exit 只清理。只允许一个发布点 |

## 5. 暂不加入

- 固定帧驱动：等 F2–F8 + F10 稳定后再接。
- 战斗模块、UI、资源加载、存档、回放、奖励。
- `GameAppRequest`/事件总线：先直接方法调用，输入多了再抽象。
- 复杂状态机/分层状态机：5 个状态够用。
- 开局参数、RunId、RunSession：已确认不需要。

## 6. 需要你定的功能取舍

1. F3 自然结束先用什么条件：固定时长、手动 `EndGame()`，还是等战斗结果？
2. F4 结果只做三态，还是现在就把统计/奖励字段留出来？
3. F6 放弃是否允许从 Pause 进入？End 中是否允许放弃？
4. F10 应用回前台是否总是自动恢复应用暂停，还是也要玩家点继续？
5. F9 生命周期事件现在就加，还是等 UI/战斗需要时再加？
6. F15 固定帧是紧接着做，还是等 F2–F8 + F10 验收后？

## 7. 结论

当前生命周期缺的不是“更多状态”，而是**一局的内容**：Run 推进、自然结束、结果、Exit 回 Start、放弃、再开、调试入口，以及玩家暂停/切后台的来源区分。  
先把 F2–F8 + F10 做出来，生命周期才算从“能暂停的空壳”变成“能完整跑一局并重开”的系统。开局参数和 RunId 不需要。
