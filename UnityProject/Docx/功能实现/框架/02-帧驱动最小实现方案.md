# 帧驱动下一步：最小实现方案

2026-11-16 · 待确认实施稿

前置：[01 游戏生命周期](01附-游戏生命周期精简实现方案.md) 已跑通，`StartUI` 已接上。  
目标：接入唯一的固定帧推进入口，先把“整数纳秒 → 60 Hz Tick → 通道”跑通，用计数器验证；暂不接战斗、定时器、定点数和调试窗口。

全量目标见 [02-Project_B固定帧驱动分步执行方案.md](02-Project_B固定帧驱动分步执行方案.md)。本文是它的第一刀，不是替代。

## 1. 这一步做什么

- `FrameManager` 单例，唯一帧推进入口。
- 用 `ILateUpdate` 采样宿主时间，整数纳秒。
- `FrameClock` 固定 60 Hz，单次最多 4 Tick，单次最多接纳 1 秒。
- `FrameCore` + `ITimeChannel`，通道按 Order、注册序推进。
- 一个 `CounterChannel` 验证 Tick 连续、暂停、过载。
- `GameApp` 启动/释放帧驱动。

## 2. 这一步不做什么

- 定点数 `Fixed64/Point2`。
- `FrameTimer` 到期任务。
- 动态注册/注销、通道故障隔离。
- 调试暂停/单步、FrameProbeWindow。
- 战斗通道、输入、回放、插值显示。
- 与 `GameAppManager` 的暂停联动；先提供 `FrameManager.Pause/Resume` 手动接口。

## 3. 结构

```text
GameApp
  └─ FrameManager（Singleton + ILateUpdate）
       ├─ Stopwatch 采样 → 整数纳秒
       ├─ FrameClock.Advance(elapsedNs)
       └─ FrameCore.Tick(tick)
            └─ ITimeChannel.Tick(tick)
                 └─ CounterChannel（本步验证用）
```

```text
Module/Frame/
├── FrameManager.cs
├── FrameClock.cs
├── FrameCore.cs
├── ITimeChannel.cs
└── CounterChannel.cs
```

`GameApp.cs` 只改启动/释放两处。

## 4. 时间口径

| 项 | 值 |
|---|---|
| TickRate | 60 Hz |
| 单次最多 Tick | 4 |
| 倍速 | 1 倍（先不做） |
| 单次最多接纳 | 1 秒 |
| 相位分母 | `1_000_000_000 × 1_000_000 = 10^15` |
| 宿主输入 | 整数纳秒 |

规则：

- Tick 编号从 0 开始，每次成功推进后 `CommittedTick + 1`。
- 不足一步的时间留在 `Phase`，不丢。
- 超过 1 秒的部分记入 `ClippedNanoseconds`，不参与推进。
- 超过 4 Tick 的整步记入 `DroppedSteps`，相位仍保留。
- 暂停时丢弃本次输入，不积攒时间；恢复从原 Tick/Phase 继续。

## 5. API 草图

### 5.1 FrameClock

```csharp
public sealed class FrameClock
{
    private const long NanosecondsPerSecond = 1_000_000_000L;
    private const long PhaseDenominator = NanosecondsPerSecond * 1_000_000L;

    private readonly int _tickRate;
    private readonly int _maxSteps;
    private long _phase;
    private long _committedTick;

    public bool Paused { get; set; }
    public long CommittedTick => _committedTick;
    public long ClippedNanoseconds { get; private set; }
    public long DroppedSteps { get; private set; }

    public FrameClock(int tickRate, int maxSteps)
    {
        _tickRate = tickRate;
        _maxSteps = maxSteps;
    }

    public void Advance(long elapsedNs, Action<long> onTick)
    {
        ClippedNanoseconds = 0;
        DroppedSteps = 0;

        if (Paused || elapsedNs <= 0)
        {
            return;
        }

        long admitted = Math.Min(elapsedNs, NanosecondsPerSecond);
        ClippedNanoseconds = elapsedNs - admitted;

        long total = _phase + admitted * _tickRate * 1_000_000L;
        long whole = total / PhaseDenominator;
        _phase = total % PhaseDenominator;

        long budget = Math.Min(whole, _maxSteps);
        DroppedSteps = whole - budget;

        for (long i = 0; i < budget; i++)
        {
            long candidate = _committedTick + 1;
            onTick(candidate);
            _committedTick = candidate;
        }
    }
}
```

- 不做倍速；`1_000_000` 是留给后续倍速的刻度，本步固定 1 倍。
- 构造函数校验 `tickRate` 1..240、`maxSteps` 1..8。
- 不处理重入；`Advance` 只在 `FrameManager.OnLateUpdate` 调用。

### 5.2 ITimeChannel / FrameCore

```csharp
public interface ITimeChannel
{
    int Order { get; }
    void Tick(long tick);
    void Dispose();
}

public sealed class FrameCore
{
    private readonly List<ITimeChannel> _channels = new();

    public void Register(ITimeChannel channel)
    {
        if (channel == null)
        {
            throw new ArgumentNullException(nameof(channel));
        }

        int index = _channels.FindIndex(c => c.Order > channel.Order);
        if (index < 0)
        {
            _channels.Add(channel);
        }
        else
        {
            _channels.Insert(index, channel);
        }
    }

    public void Tick(long tick)
    {
        for (int i = 0; i < _channels.Count; i++)
        {
            _channels[i].Tick(tick);
        }
    }

    public void Dispose()
    {
        for (int i = 0; i < _channels.Count; i++)
        {
            _channels[i].Dispose();
        }

        _channels.Clear();
    }
}
```

本步只支持“启动前注册”，不支持 Tick 中增删；动态注册和故障隔离留到下一步。

### 5.3 FrameManager

```csharp
public sealed class FrameManager : Singleton<FrameManager>, ILateUpdate
{
    private const int TickRate = 60;
    private const int MaxStepsPerUpdate = 4;

    private readonly FrameClock _clock = new(TickRate, MaxStepsPerUpdate);
    private readonly FrameCore _core = new();
    private readonly Stopwatch _watch = new();
    private long _lastNanoseconds;
    private bool _running;

    public void Start()
    {
        if (_running)
        {
            return;
        }

        _running = true;
        _watch.Restart();
        _lastNanoseconds = 0;
        Log.Info("[Frame] started: 60Hz, max 4 steps.");
    }

    public void RegisterChannel(ITimeChannel channel)
    {
        _core.Register(channel);
    }

    public void Pause()
    {
        _clock.Paused = true;
    }

    public void Resume()
    {
        _clock.Paused = false;
    }

    public void OnLateUpdate()
    {
        if (!_running)
        {
            return;
        }

        long now = ToNanoseconds(_watch.ElapsedTicks);
        long elapsed = now - _lastNanoseconds;
        _lastNanoseconds = now;
        _clock.Advance(elapsed, _core.Tick);

        if (_clock.ClippedNanoseconds > 0 || _clock.DroppedSteps > 0)
        {
            Log.Warning($"[Frame] overload: clipped={_clock.ClippedNanoseconds}ns, dropped={_clock.DroppedSteps}");
        }
    }

    protected override void OnRelease()
    {
        _running = false;
        _core.Dispose();
        Log.Info("[Frame] released.");
    }

    private static long ToNanoseconds(long stopwatchTicks)
    {
        return (long)(stopwatchTicks * (1_000_000_000.0 / Stopwatch.Frequency));
    }
}
```

- `ILateUpdate` 由 `SingletonSystem` 统一调用，不需要再注册 `Utility.Unity`。
- `FrameManager` 启动前 `OnLateUpdate` 也会被调用，用 `_running` 拦住。
- 过载日志只在发生裁剪/丢步时打，避免每帧刷。
- `ToNanoseconds` 用 double 避免 `stopwatchTicks * 1e9` 溢出。

### 5.4 CounterChannel

```csharp
public sealed class CounterChannel : ITimeChannel
{
    private long _count;

    public int Order => 0;

    public void Tick(long tick)
    {
        _count++;

        if (tick % 60 == 0)
        {
            Log.Info($"[Frame] tick={tick}, count={_count}");
        }
    }

    public void Dispose()
    {
    }
}
```

这个通道只用于本步验收；战斗通道接入后删掉或移到 Debug。

## 6. GameApp 接线

```csharp
private static async UniTaskVoid StartGameLogic()
{
    await UniTask.Yield();

    FrameManager.Instance.RegisterChannel(new CounterChannel());
    FrameManager.Instance.Start();

    GameAppManager.Instance.Start();
    GameModule.UI.ShowUIAsync<StartUI>();
}

private static void ReleaseLogic()
{
    if (FrameManager.IsValid)
    {
        FrameManager.Instance.Release();
    }

    SingletonSystem.Release();
    GameModule.Shutdown();
    Utility.Unity.RemoveDestroyListener(ReleaseLogic);
}
```

顺序说明：

- 先注册通道再 `Start`，保证第一帧就有通道。
- `ReleaseLogic` 先释放帧驱动，再走 `SingletonSystem.Release` / `GameModule.Shutdown`。
- `GameAppManager` 的暂停/恢复暂时不调用 `FrameManager.Pause/Resume`；本步手动验证。

## 7. 验收

| 用例 | 预期 |
|---|---|
| 启动 | 日志 `Frame started: 60Hz, max 4 steps.` |
| 1 秒累计 | `CommittedTick` 到 60，`CounterChannel` 打印 `tick=60` |
| 200 ms 一帧 | 本帧推进 4 Tick，`DroppedSteps=8`，无裁剪 |
| 1250 ms 一帧 | 本帧推进 4 Tick，`DroppedSteps=56`，`ClippedNanoseconds=250,000,000` |
| 16 ms 连续帧 | Tick 连续递增，不跳号；相位保留 |
| 暂停 | `Pause()` 后无新 Tick；`Resume()` 从原 Tick 继续 |
| 释放 | 退出后不再出现 `[Frame]` 日志 |
| 通道顺序 | 启动前注册的通道按 Order、注册序推进 |
| 重复 Start | 只启动一次，不重复打印 started |

## 10. 结论

这一步只建立“唯一的固定 Tick 入口”和“通道被 Tick 驱动”的事实，不碰战斗和定时器。
