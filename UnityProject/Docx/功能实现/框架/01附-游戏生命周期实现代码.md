## 1.1 每个脚本的职责与设计理由（先看这里）

### 职责一览

| 脚本 | 一句话职责 | 边界（不做什么） | 如果没有它 |
| --- | --- | --- | --- |
| `GameContracts.cs` | 定义跨脚本共享的值类型、状态枚举和事件 ID | 不持有状态、不执行逻辑 | 每个脚本各自定义结果/快照，字段漂移，UI 和业务对不上 |
| `GameFlowState.cs` | 六个状态类 + 统一基类，只表达“当前处于哪个阶段” | 不做迁移决策、不碰资源/UI | 迁移散落在 `GameManager` 的 if/switch，新增状态要改多处 |
| `GameManager.cs` | 唯一宿主：持有 FSM、当前局、加载器；`Tick` 做唯一迁移决策；发布快照 | 不直接碰 YooAsset 句柄、不直接操作 UI 控件 | 没有单一写者，按钮回调、加载回调、协程都能改状态，出现双重迁移 |
| `RunSession.cs` | 单局值状态：样本进度、自然结果 | 不加载资源、不关窗口、不决定流程 | 进度和结果混在 `GameManager`，阶段 03 接战斗时会迅速膨胀 |
| `SampleRunLoader.cs` | 资源端口：每个 `RunId` 一条句柄，负责完成/失败/释放 | 不决定状态、不建会话、不通知 UI | YooAsset 细节渗进宿主，句柄释放容易漏，迟到结果容易串局 |
| `GameApp.cs` | 组合根：创建/释放宿主，注册退出钩子 | 不写业务规则 | 业务对象的生命周期无人负责，退出顺序不可控 |
| `ProjectBLobbyUI.cs` | 只读快照 + 提交请求 | 不改状态、不持有 `RunSession`、不做业务判断 | UI 直接改状态，迟到回调容易覆盖新局 |
| `ProjectBRunSample.json` | 联调样本数据 | 不放正式配置 | 样本硬编码，无法复现加载失败、替换阵容 |

### 依赖方向

```text
GameApp ──创建/释放──> GameManager
GameManager ──持有──> GameFlowState（经 IFsm<GameManager>）
GameManager ──持有──> SampleRunLoader ──> IResourceModule ──> YooAsset
GameManager ──持有──> RunSession
GameManager ──发布──> GameSnapshot / RunOutcome（GameContracts）
ProjectBLobbyUI ──读快照/发请求──> GameManager
ProjectBLobbyUI ──订阅──> GameEvent
```

依赖是单向的：UI 依赖宿主的只读快照和请求方法，宿主不依赖 UI 具体类型（只通过 `GameModule.UI.ShowUIAsync<T>` 打开窗口）；加载器不依赖会话和流程；会话不依赖资源。

### 数据流和调用顺序

```text
GameApp.Entrance
  └─ new GameManager
       └─ Start
            └─ CreateFsm("ProjectB.Game", 6 states)
                 └─ Start<LobbyState>
                      └─ OnFlowEnter(Lobby)
                           ├─ ShowLobby()            // 打开/复用 UIWindow
                           └─ PublishSnapshot()      // 发事件，UI 读快照

按钮点击
  └─ GameManager.RequestXxx(runId)
       └─ 校验当前状态 + RunId → 入队

每帧
  └─ FsmModule.Update → GameFlowState.OnUpdate
       └─ GameManager.Tick(realDelta)
            ├─ DrainLoadResults()   // loader.Pump，旧 RunId 丢弃
            ├─ TakeCommand()        // 按优先级取一条，失效命令丢弃
            ├─ 返回下一个状态 Type（或 null）
            └─ 基类统一 ChangeState(fsm, next)
```

一次完整开局：

```text
Lobby --Start--> Loading --LoadResult.Success--> Running
Running --Pause--> Paused --Resume--> Running
Running --进度满/模拟结束--> Finished --Return--> Exiting --清理完成--> Lobby
任意可放弃状态 --Abandon--> Exiting(Abandoned) --> Lobby
Loading --加载失败--> Exiting(LoadFailed) --> Lobby
Running --Tick 抛异常--> Exiting(Faulted) --> Lobby
```

### 为什么这样设计

1. **组合根持有，而不是 `Singleton<GameManager>`**
   `Singleton<T>.Instance` 是懒创建（`Singleton.cs:13-26`），任何迟到回调只要写 `GameManager.Instance`，就会把管理器重新创建出来，和 01 稿“旧回报不能重新创建管理器”的验收直接冲突。`GameApp` 显式 `new` 并持有，创建和释放都有唯一入口，也与执行手册的写法一致。

2. **Loading 必须是独立状态**
   加载中有自己的合法输入（放弃）、自己的失败出口、自己的结束条件。把它藏在 `Lobby` 里用 `IsLoading` 标志区分，会让每个 handler 都先判标志；而且“大厅空闲”和“开局装配”本来就是两件事，状态名应该直接表达它们。GameFramework/StarForce 的 Procedure、Shattered PD 的 `InterlevelScene` 都是把加载做成独立阶段。

3. **迁移集中在 `GameManager.Tick`，状态类只做副作用**
   TEngine 的 `Fsm.ChangeState` 是 internal，只能由状态类调用。如果让五个状态各自在 `OnUpdate` 里判“加载完成没有 / 有没有请求 / 该不该结束”，同一套判断会重复五遍，而且很难保证“同帧只迁移一次”。现在的写法是：状态基类统一调用 `Tick`，`Tick` 返回下一个状态类型，基类再执行 `ChangeState`。决策集中、可单测，状态类只剩身份和进入/离开副作用。

4. **`RunSession` 和 `SampleRunLoader` 分开**
   `RunSession` 只关心“这一局进行到哪、结果是什么”，是纯值状态；`SampleRunLoader` 只关心“资源加载到哪、句柄有没有释放”，是资源端口。两者分开后，阶段 03 接战斗只需要在 `RunSession` 里加战斗句柄，不需要动加载器；换 Addressables/Resources 也只需要换加载器，不需要动会话和流程。

5. **结果用 `RunOutcome` 值，而不是会话引用**
   UI、日志、后续存档都只应该读“已经发生的事实”。如果 UI 持有 `RunSession` 引用，`Dispose` 之后再读就是已释放对象；值拷贝可以活过会话销毁。`Exiting` 是唯一发布点，`Finished` 只冻结，避免同一局出现两个结果来源。

6. **UI 只读快照，事件只做失效通知**
   `GameEvent` 只发“快照变了”，UI 收到后主动读 `GameManager.Snapshot`。这样窗口创建时可以先读一次当前快照，不会因为“事件发得比窗口创建早”而丢状态；UI 也不会持有可变业务对象。按钮只提交带 `RunId` 的请求，管理器再按当前状态和身份校验一次。

7. **关闭用 `Application.quitting` + `AddDestroyListener` 双入口**
   Unity 不保证跨对象的 `OnDestroy` 顺序；player 下 `RootModule.OnDestroy` 还会触发 `ModuleSystem.Shutdown()`。如果业务释放只挂在 `[UpdateDriver]` 的 `OnDestroy` 上，可能晚于模块清空，出现“释放时又新建模块/GameObject”的路径。双入口 + `_released` 幂等，先保证业务收尾，再交给框架。

8. **暂停是逻辑暂停，不改 `Time.timeScale`**
   `RootModule.PauseGame()` 会把 `Time.timeScale` 置 0；`ShowUIAsyncAwait` 用 `Time.deltaTime` 计 60 秒超时，UI 异步和 `HideUI` 定时器都会被冻结。现在的暂停只是 `Tick` 不推进 `RunSession`，画面表现暂停留给 02 的帧驱动/动画参数。

9. **事件用 int 常量，不用接口事件**
   项目里 `GameEventHelper.Init()` 被注释、没有 Source Generator，`[EventInterface]` / `GameEvent.Get<T>()` 这条路径不可用。int 事件 + 常量是当前项目能直接用的能力；UI 侧用 `AddUIEvent`，窗口销毁时自动清理。

10. **`GameManager` 是普通 C# 对象，不是 MonoBehaviour**
    生命周期由 `GameApp` 控制，不依赖场景对象、`Invoke` 或协程；FSM 的 `OnUpdate` 由 TEngine 的 `FsmModule` 驱动，宿主不需要挂在场景里，也不需要 `DontDestroyOnLoad`。这样“创建/释放”是普通方法调用，顺序可读、可测，不会被场景切换或对象销毁顺序影响。

11. **用 TEngine FSM，而不是自研状态机**
    项目已有 `IFsmModule` 和 `FsmState<T>`，启动流程也在用同一套；复用它就复用了 `ChangeState`、`OnLeave(isShutdown)`、`DestroyFsm` 和 MemoryPool 回收路径，减少一套平行框架。只有将来需要并行状态机/分层状态机时，才值得在 `GameManager` 内部再拆 `RunFlow`，而不是现在就自研。

### 状态与合法输入

| 状态 | 合法输入 | 出口 | 快照可用的按钮 |
| --- | --- | --- | --- |
| `Lobby` | `Start` | `Loading` / `Exiting(LoadFailed)` | Start |
| `Loading` | `Abandon` | `Running` / `Exiting(LoadFailed/Abandoned)` | Abandon |
| `Running` | `Pause`、`Abandon`、`SampleComplete` | `Paused` / `Finished` / `Exiting` | Pause、Abandon、模拟结束 |
| `Paused` | `Resume`、`Abandon` | `Running` / `Exiting` | Resume、Abandon |
| `Finished` | `Return` | `Exiting` | Return |
| `Exiting` | 无（等待清理完成） | `Lobby` | 全部禁用 |

同帧请求按 `Abandon > Return > Resume > SampleComplete > Pause > Start` 取一条；已经提交自然结果时，`Finished` 优先于放弃。

### 后续改动应该改哪里

| 需求 | 改哪里 | 不要改哪里 |
| --- | --- | --- |
| 新增一个流程阶段 | `GameFlowStateId` + 新状态类 + `Tick` 的 switch + 快照 CanX | 不要在 UI 里判断阶段 |
| 改开局规则/校验 | `BeginStart` 或 `SampleRunLoader.Complete` | 不要改状态基类 |
| 接子战斗 | `RunSession`（持有/停止战斗）+ `Exiting` 清理顺序 | 不要把战斗对象塞进 `GameManager` |
| 换资源系统 | `SampleRunLoader` | 不要改 `GameManager` 的请求/快照 |
| 改界面布局 | `ProjectBLobbyUI` + prefab | 不要在 UI 里写业务规则 |

## 2. GameContracts.cs

**作用**：定义所有脚本共享的契约：阶段枚举、退出原因、单局结果、加载结果、UI 快照、样本数据、事件 ID。

**为什么单独一个文件**：这些类型同时被 `GameManager`、`SampleRunLoader`、`RunSession`、`ProjectBLobbyUI` 使用。如果每个脚本各自定义，字段名和语义会漂移（例如“离场原因”和“自然结果”混用）；集中定义后，编译期就能发现契约不一致。

**为什么用 `readonly struct`**：结果和快照是跨生命周期的只读事实。值拷贝可以活过 `RunSession.Dispose`，UI 也不会持有可变业务对象。`GameSnapshot.HasOutcome` 是为了避免 `default(RunOutcome)` 被误读成“Completed + RunId 0”。

**为什么 `RunSampleData` 是 class 且字段小写**：`Utility.Json` 默认走 `JsonUtility`，要求 `[Serializable]` + public 字段，并且按字段名映射 JSON；这里保留小写字段名是为了和 `ProjectBRunSample.json` 对齐。

**为什么事件 ID 是 const int**：项目的 `GameEventHelper.Init()` 被注释、没有 Source Generator，接口事件不可用；int 事件是当前能直接用的路径，1~9999 保留给框架。

```csharp
using System;
```

## 3. GameFlowState.cs

**作用**：六个状态类 + 统一基类。状态只表达“当前处于哪个阶段”，迁移决策全部转给 `GameManager.Tick`。

**为什么状态类几乎是空的**：TEngine 的 `ChangeState` 是 internal，只能由状态类调用。如果让每个状态自己写 `OnUpdate` 判断“加载完成没有 / 有没有请求 / 该不该结束”，同一套判断会复制六份，而且很难保证同帧只迁移一次。现在基类只有一个 `OnUpdate`：`Tick` 返回下一个 `Type`，基类统一 `ChangeState`；新增状态只要加一个 `Id` 和 `Tick` 里的一个分支。

**为什么 `OnEnter/OnLeave` 只转发**：开窗口、建会话、发布结果这些副作用集中在 `GameManager.OnFlowEnter`，状态对象不持有任何字段，因此不会被上一局的数据污染（`FsmState` 实例是复用的，这点很重要）。

**为什么 `isShutdown` 分支不迁移**：`Fsm.Clear()` 会以 `isShutdown = true` 调 `OnLeave`，此时不能再 `ChangeState` 或开窗口；基类只通知宿主清状态。

**为什么 catch 里转 `NotifyFault`**：`OnUpdate` 里的任何异常（资源、JSON、UI）都不应该让 FSM 停在半初始化状态；统一转到 `Exiting(Faulted)`，由宿主保底回大厅。

```csharp
using System;
using TEngine;

namespace GameLogic
{
    /// <summary>
    /// 所有流程状态的基类：状态只负责进入/离开副作用，迁移由 GameManager.Tick 决策。
    /// </summary>
    public abstract class GameFlowState : FsmState<GameManager>
    {
        public abstract GameFlowStateId Id { get; }

        protected override void OnEnter(IFsm<GameManager> fsm)
        {
            fsm.Owner.OnFlowEnter(Id);
        }

        protected override void OnLeave(IFsm<GameManager> fsm, bool isShutdown)
        {
            fsm.Owner.OnFlowLeave(Id, isShutdown);
        }

        protected override void OnUpdate(IFsm<GameManager> fsm, float elapseSeconds, float realElapseSeconds)
        {
            try
            {
                Type next = fsm.Owner.Tick(realElapseSeconds);
                if (next != null)
                {
                    ChangeState(fsm, next);
                }
            }
            catch (Exception exception)
            {
                Type faultState = fsm.Owner.NotifyFault(exception);
                if (faultState != null)
                {
                    ChangeState(fsm, faultState);
                }
            }
        }
    }

    public sealed class LobbyState : GameFlowState
    {
        public override GameFlowStateId Id => GameFlowStateId.Lobby;
    }

    public sealed class LoadingState : GameFlowState
    {
        public override GameFlowStateId Id => GameFlowStateId.Loading;
    }

    public sealed class RunningState : GameFlowState
    {
        public override GameFlowStateId Id => GameFlowStateId.Running;
    }

    public sealed class PausedState : GameFlowState
    {
        public override GameFlowStateId Id => GameFlowStateId.Paused;
    }

    public sealed class FinishedState : GameFlowState
    {
        public override GameFlowStateId Id => GameFlowStateId.Finished;
    }

    public sealed class ExitingState : GameFlowState
    {
        public override GameFlowStateId Id => GameFlowStateId.Exiting;
    }
}
```

## 4. RunSession.cs

**作用**：单局值状态：样本进度、自然结果、停止钩子。

**为什么从 `GameManager` 拆出来**：`GameManager` 的职责是“应用流程”，`RunSession` 的职责是“这一局”。阶段 03 接战斗后，会话要持有战斗句柄、回合数据、跨层状态；如果都塞进 `GameManager`，流程类会变成上帝对象。拆开后，流程只问会话“结束了吗 / 结果是什么”。

**为什么进度用 float 累加器**：每帧 `deltaSeconds * speed` 直接转 `int` 会丢小数，低帧率下进度会变慢；累加器保留余量，保证 10 秒的样本在 60fps/30fps 下都推进 10 格。

**为什么 `HasOutcome` 只提交一次**：同帧可能同时收到“模拟结束”和“进度满”，自然结果必须幂等；`Advance` / `CommitSampleComplete` 都走 `Commit`，第二次直接返回。

**为什么 `Dispose` 不发布结果**：结果发布是 `Exiting` 的职责（唯一发布点）。如果会话 `Dispose` 也发一次，会出现两次通知。`Dispose` 只做资源/战斗停止，阶段 03 在这里接 `BattleModule`。

```csharp
using System;

namespace GameLogic
{
    /// <summary>
    /// 单局值状态。阶段 03 在这里接子战斗；首期只有样本进度。
    /// </summary>
    public sealed class RunSession
    {
        private float _progressCarry;

        public int RunId { get; }
        public string SampleId { get; }
        public string DisplayName { get; }
        public int TargetProgress { get; }
        public int Progress { get; private set; }
        public bool HasOutcome { get; private set; }
        public RunOutcome Outcome { get; private set; }

        public RunSession(int runId, RunSampleData sample)
        {
            RunId = runId;
            SampleId = sample.sampleId;
            DisplayName = sample.displayName;
            TargetProgress = Math.Max(1, sample.targetProgress);
        }

        /// <summary>
        /// 推进样本。返回 true 表示本次推进提交了自然结果。
        /// </summary>
        public bool Advance(float deltaSeconds, float progressPerSecond, out RunOutcome outcome)
        {
            outcome = default;
            if (HasOutcome)
            {
                outcome = Outcome;
                return true;
            }

            _progressCarry += Math.Max(0f, deltaSeconds) * Math.Max(0f, progressPerSecond);
            int whole = (int)_progressCarry;
            if (whole > 0)
            {
                _progressCarry -= whole;
                Progress = Math.Min(TargetProgress, Progress + whole);
            }

            if (Progress >= TargetProgress)
            {
                Commit(ExitReason.Completed);
                outcome = Outcome;
                return true;
            }

            return false;
        }

        public void CommitSampleComplete()
        {
            if (!HasOutcome)
            {
                Commit(ExitReason.Completed);
            }
        }

        private void Commit(ExitReason reason)
        {
            HasOutcome = true;
            Outcome = new RunOutcome(RunId, reason, Progress);
        }

        public void Dispose()
        {
            // 阶段 03 在这里停止并清理子战斗；首期只清值状态。
            _progressCarry = 0f;
        }
    }
}
```

## 5. SampleRunLoader.cs

**作用**：资源端口。每个 `RunId` 一条 `LoadOp`，负责开始、轮询、复制、解析、失败、释放、调试延迟。

**为什么独立成 loader**：YooAsset `AssetHandle` 的生命周期不能交给 UI 或 `RunSession`；把句柄收在一个类里，“旧局结果只释放不入队”“应用退出释放全部在途句柄”才有唯一实现点。换 Addressables/Resources 时也只改这里。

**为什么用 Pull（`Pump`）而不是回调**：YooAsset 的 `Completed` 回调可能在任意时机触发；如果在回调里直接改 FSM/UI，就绕过了“同帧只迁移一次”和“身份校验”。`Pump` 把完成事实收敛到 `Tick` 的固定位置，顺序可控。

**为什么先复制 `text` 再 `Dispose`**：`TextAsset` 由句柄持有，`Dispose` 后再读 `.text` 是悬空访问；先复制字符串，再释放句柄。

**为什么失败不抛异常**：加载失败是正常分支（缺资源/坏 JSON/地址错），用 `LoadResult` 表达，交给 `Tick` 转 `Exiting(LoadFailed)`；抛异常会打断 FSM 更新。

**为什么有 `DebugDelayFrames`**：01 稿要求复现“加载中放弃 A → 开 B → A 迟到”。这里只延迟“完成处理”，不延迟实际加载，A 的句柄会一直持有到延迟结束，正好覆盖“旧请求收尾”的场景。

```csharp
using System;
using System.Collections.Generic;
using TEngine;
using UnityEngine;
using YooAsset;

namespace GameLogic
{
    /// <summary>
    /// 样本加载器：每个 RunId 一条独立句柄；完成时复制文本并释放句柄。
    /// </summary>
    public sealed class SampleRunLoader
    {
        private const string SampleAddress = "ProjectBRunSample";

        private sealed class LoadOp
        {
            public int RunId;
            public AssetHandle Handle;
            public bool Completed;
            public int DebugDelayFrames;
        }

        private readonly IResourceModule _resource;
        private readonly List<LoadOp> _operations = new List<LoadOp>(4);

        public SampleRunLoader(IResourceModule resource)
        {
            _resource = resource;
        }

        public void Begin(int runId, bool delayCompletion)
        {
            AssetHandle handle = _resource.LoadAssetAsyncHandle<TextAsset>(SampleAddress);
            LoadOp op = new LoadOp
            {
                RunId = runId,
                Handle = handle,
                DebugDelayFrames = delayCompletion ? 120 : 0,
            };
            _operations.Add(op);
        }

        public void Pump(List<LoadResult> results)
        {
            for (int i = _operations.Count - 1; i >= 0; i--)
            {
                LoadOp op = _operations[i];
                if (op.Handle == null)
                {
                    _operations.RemoveAt(i);
                    results.Add(new LoadResult(op.RunId, false, null, "handle is null"));
                    continue;
                }

                if (!op.Handle.IsDone)
                {
                    continue;
                }

                if (op.DebugDelayFrames > 0)
                {
                    op.DebugDelayFrames--;
                    continue;
                }

                LoadResult result = Complete(op);
                _operations.RemoveAt(i);
                results.Add(result);
            }
        }

        private LoadResult Complete(LoadOp op)
        {
            AssetHandle handle = op.Handle;
            bool succeed = handle.Status == EOperationStatus.Succeed && handle.AssetObject is TextAsset;
            string json = null;
            if (succeed)
            {
                // 先复制文本，再释放句柄
                json = ((TextAsset)handle.AssetObject).text;
            }

            string error = succeed ? null : handle.LastError;
            handle.Dispose();

            if (!succeed || string.IsNullOrEmpty(json))
            {
                return new LoadResult(op.RunId, false, null, error ?? $"load failed: {SampleAddress}");
            }

            try
            {
                RunSampleData sample = Utility.Json.ToObject<RunSampleData>(json);
                if (sample == null || string.IsNullOrEmpty(sample.sampleId) || sample.targetProgress <= 0)
                {
                    return new LoadResult(op.RunId, false, null, "sample is invalid");
                }

                return new LoadResult(op.RunId, true, sample, null);
            }
            catch (Exception exception)
            {
                return new LoadResult(op.RunId, false, null, exception.Message);
            }
        }

        public void Dispose()
        {
            for (int i = 0; i < _operations.Count; i++)
            {
                _operations[i].Handle?.Dispose();
            }

            _operations.Clear();
        }
    }
}
```

## 6. GameManager.cs

**作用**：唯一宿主、唯一写者。持有 FSM、loader、session、快照；接收请求；`Tick` 做迁移决策；发布离场结果；幂等释放。

**为什么所有请求都入队**：按钮点击、加载完成、协程恢复都可能发生在 FSM 更新之外；如果直接改 `_state`，就无法保证“同帧只迁移一次”。入队后由 `Tick` 统一消费，顺序和优先级可定义。

**为什么 `Tick` 返回 `Type` 而不是自己 `ChangeState`**：`ChangeState` 是 protected，只有状态类能调；返回 `Type` 让“决策留在宿主、执行留在状态基类”，两边职责都不破。

**为什么 `DrainLoadResults` 放在 `Tick` 最前**：加载完成是“事实”，应该先于本帧请求被看到；这样“加载完成 + 同帧放弃”能按优先级正确裁决（放弃优先于尚未提交的加载就绪）。

**为什么 `BeginExit` 是唯一发布点**：`Finished` 只冻结、不发布；`Completed / Abandoned / LoadFailed / Faulted` 都在 `Exiting` 统一生成 `RunOutcome`，保证一局只有一次离场通知。`_hasOutcome` 区分“本局已有自然结果”和“上一局遗留结果”。

**为什么 `ShowLobby` 只 catch 记日志**：现有 `UIModule` 没有失败回调（第 10 节补丁才能补上）；主代码不假装能处理窗口失败，避免写出一个永远不会触发的分支。

**关键方法**：

| 方法 | 做什么 | 不做什么 |
| --- | --- | --- |
| `Start` | 建唯一 FSM 并进入 Lobby | 不打开窗口（交给 Lobby 的 OnEnter） |
| `Dispose` | 停会话、放句柄、销毁 FSM，幂等 | 不负责 UI/模块释放（由 GameApp 继续） |
| `RequestXxx` | 校验状态 + RunId 后入队 | 不直接改状态、不直接调 UI |
| `Tick` | 消费加载结果和请求，返回下一个状态 | 不执行 `ChangeState` |
| `OnFlowEnter` | 进入副作用：开大厅 / 冻结结果 / 开始退出 | 不做迁移决策 |
| `BeginStart` | 分配 RunId、重置本局事实、发起加载 | 不创建会话（等加载成功） |
| `BeginExit` | 停会话、生成并发布唯一 `RunOutcome` | 不销毁 FSM |
| `DrainLoadResults` | 丢弃旧 RunId，只保留当前加载结果 | 不建会话 |
| `TakeCommand` | 按优先级取一条有效命令 | 不执行命令 |
| `BuildSnapshot` | 从当前状态生成只读快照 | 不触发 UI 操作 |

```csharp
using System;
using System.Collections.Generic;
using TEngine;
using UnityEngine;

namespace GameLogic
{
    /// <summary>
    /// 应用级游戏宿主：持有唯一流程 FSM、当前局和加载器。
    /// 迁移决策集中在 Tick，状态类只做进入/离开副作用。
    /// </summary>
    public sealed class GameManager
    {
        private const float ProgressPerSecond = 1f;

        private readonly SampleRunLoader _loader;
        private readonly Queue<GameCommand> _commands = new Queue<GameCommand>(8);
        private readonly List<LoadResult> _loadResults = new List<LoadResult>(4);

        private IFsm<GameManager> _flow;
        private RunSession _session;
        private GameSnapshot _snapshot;
        private GameFlowStateId _state = GameFlowStateId.None;
        private LoadResult? _loadResult;
        private RunOutcome _lastOutcome;
        private bool _hasOutcome;
        private int _runId;
        private int _nextRunId = 1;
        private ExitReason _exitReason = ExitReason.Completed;
        private bool _exitCleanupDone;
        private bool _debugDelayNextLoad;
        private bool _released;

        public GameSnapshot Snapshot => _snapshot;
        public bool IsReleased => _released;

        public GameManager()
        {
            _loader = new SampleRunLoader(GameModule.Resource);
        }

        public void Start()
        {
            if (_released || _flow != null)
            {
                return;
            }

            _flow = GameModule.Fsm.CreateFsm("ProjectB.Game", this,
                new LobbyState(), new LoadingState(), new RunningState(),
                new PausedState(), new FinishedState(), new ExitingState());
            _flow.Start<LobbyState>();
        }

        public void Dispose()
        {
            if (_released)
            {
                return;
            }

            _released = true;
            _commands.Clear();
            _session?.Dispose();
            _session = null;
            _loader.Dispose();

            IFsm<GameManager> flow = _flow;
            _flow = null;
            if (flow != null && !flow.IsDestroyed && ReferenceEquals(flow.Owner, this))
            {
                IFsmModule fsmModule = GameModule.Fsm;
                if (fsmModule != null)
                {
                    fsmModule.DestroyFsm(flow);
                }
            }

            _state = GameFlowStateId.None;
        }

        // ---------------- 请求入口 ----------------

        public bool RequestStart()
        {
            return Enqueue(GameCommandType.Start, 0, GameFlowStateId.Lobby);
        }

        public bool RequestPause(int runId)
        {
            return Enqueue(GameCommandType.Pause, runId, GameFlowStateId.Running);
        }

        public bool RequestResume(int runId)
        {
            return Enqueue(GameCommandType.Resume, runId, GameFlowStateId.Paused);
        }

        public bool RequestSampleComplete(int runId)
        {
            return Enqueue(GameCommandType.SampleComplete, runId, GameFlowStateId.Running);
        }

        public bool RequestReturn(int runId)
        {
            return Enqueue(GameCommandType.Return, runId, GameFlowStateId.Finished);
        }

        public bool RequestAbandon(int runId)
        {
            if (_released || runId != _runId)
            {
                return false;
            }

            if (_state != GameFlowStateId.Loading
                && _state != GameFlowStateId.Running
                && _state != GameFlowStateId.Paused)
            {
                return false;
            }

            _commands.Enqueue(new GameCommand(GameCommandType.Abandon, runId));
            return true;
        }

        public void SetDebugDelayNextLoad(bool value)
        {
            _debugDelayNextLoad = value;
        }

        private bool Enqueue(GameCommandType type, int runId, GameFlowStateId expectedState)
        {
            if (_released || _state != expectedState || runId != _runId)
            {
                return false;
            }

            _commands.Enqueue(new GameCommand(type, runId));
            return true;
        }

        // ---------------- 状态回调 ----------------

        internal void OnFlowEnter(GameFlowStateId id)
        {
            if (_released)
            {
                return;
            }

            _state = id;
            switch (id)
            {
                case GameFlowStateId.Lobby:
                    _runId = 0;
                    _loadResult = null;
                    _session?.Dispose();
                    _session = null;
                    ShowLobby();
                    break;

                case GameFlowStateId.Finished:
                    FreezeOutcome();
                    break;

                case GameFlowStateId.Exiting:
                    try
                    {
                        BeginExit();
                    }
                    catch (Exception exception)
                    {
                        // 清理阶段本身的异常不能把 FSM 卡在 Exiting
                        Log.Error($"[GameFlow] exit cleanup failed: {exception}");
                        _exitCleanupDone = true;
                    }
                    break;
            }

            PublishSnapshot();
        }

        internal void OnFlowLeave(GameFlowStateId id, bool isShutdown)
        {
            if (isShutdown)
            {
                _state = GameFlowStateId.None;
            }
        }

        internal Type Tick(float deltaSeconds)
        {
            if (_released)
            {
                return null;
            }

            DrainLoadResults();

            if (_state == GameFlowStateId.Exiting)
            {
                return _exitCleanupDone ? typeof(LobbyState) : null;
            }

            GameCommand command = TakeCommand();

            // 已提交的自然结果优先；同帧放弃不会覆盖它
            if (_state == GameFlowStateId.Running && _session != null && _session.HasOutcome)
            {
                return typeof(FinishedState);
            }

            switch (_state)
            {
                case GameFlowStateId.Lobby:
                    if (command.Type == GameCommandType.Start)
                    {
                        BeginStart();
                        return typeof(LoadingState);
                    }
                    break;

                case GameFlowStateId.Loading:
                    if (command.Type == GameCommandType.Abandon)
                    {
                        _exitReason = ExitReason.Abandoned;
                        return typeof(ExitingState);
                    }

                    if (_loadResult.HasValue)
                    {
                        LoadResult result = _loadResult.Value;
                        _loadResult = null;
                        if (result.Success)
                        {
                            _session = new RunSession(_runId, result.Sample);
                            return typeof(RunningState);
                        }

                        _exitReason = ExitReason.LoadFailed;
                        return typeof(ExitingState);
                    }
                    break;

                case GameFlowStateId.Running:
                    if (command.Type == GameCommandType.SampleComplete)
                    {
                        _session?.CommitSampleComplete();
                        return typeof(FinishedState);
                    }

                    if (command.Type == GameCommandType.Pause)
                    {
                        return typeof(PausedState);
                    }

                    if (command.Type == GameCommandType.Abandon)
                    {
                        _exitReason = ExitReason.Abandoned;
                        return typeof(ExitingState);
                    }

                    if (_session != null && _session.Advance(deltaSeconds, ProgressPerSecond, out _))
                    {
                        return typeof(FinishedState);
                    }
                    break;

                case GameFlowStateId.Paused:
                    if (command.Type == GameCommandType.Resume)
                    {
                        return typeof(RunningState);
                    }

                    if (command.Type == GameCommandType.Abandon)
                    {
                        _exitReason = ExitReason.Abandoned;
                        return typeof(ExitingState);
                    }
                    break;

                case GameFlowStateId.Finished:
                    if (command.Type == GameCommandType.Return)
                    {
                        return typeof(ExitingState);
                    }
                    break;
            }

            return null;
        }

        internal Type NotifyFault(Exception exception)
        {
            Log.Error($"[GameFlow] tick failed: {exception}");

            if (_released)
            {
                return null;
            }

            if (_state == GameFlowStateId.Exiting)
            {
                // 清理阶段再抛异常：保证下一次 Tick 能回到大厅，避免卡死
                _exitCleanupDone = true;
                return null;
            }

            _exitReason = ExitReason.Faulted;
            return typeof(ExitingState);
        }

        // ---------------- 内部流程 ----------------

        private void BeginStart()
        {
            _runId = _nextRunId++;
            _hasOutcome = false;
            _lastOutcome = default;
            _exitReason = ExitReason.Completed;
            _exitCleanupDone = false;
            _loadResult = null;

            bool delay = _debugDelayNextLoad;
            _debugDelayNextLoad = false;
            _loader.Begin(_runId, delay);
        }

        private void FreezeOutcome()
        {
            if (_session != null && _session.HasOutcome)
            {
                _lastOutcome = _session.Outcome;
                _hasOutcome = true;
            }
        }

        private void BeginExit()
        {
            // 撤销本局装配资格：迟到的加载结果不再进入 FSM
            _loadResult = null;

            if (_session != null)
            {
                if (_session.HasOutcome)
                {
                    _lastOutcome = _session.Outcome;
                }
                else
                {
                    _lastOutcome = new RunOutcome(_runId, _exitReason, _session.Progress);
                }

                _hasOutcome = true;
                _session.Dispose();
                _session = null;
            }
            else if (!_hasOutcome)
            {
                _lastOutcome = new RunOutcome(_runId, _exitReason, 0);
                _hasOutcome = true;
            }

            _exitCleanupDone = true;
            GameEvent.Send(GameEventDef.OnRunEnded, _lastOutcome);
        }

        private void DrainLoadResults()
        {
            _loader.Pump(_loadResults);
            for (int i = 0; i < _loadResults.Count; i++)
            {
                LoadResult result = _loadResults[i];
                if (result.RunId != _runId)
                {
                    continue;
                }

                if (_state != GameFlowStateId.Loading)
                {
                    continue;
                }

                _loadResult = result;
            }

            _loadResults.Clear();
        }

        private GameCommand TakeCommand()
        {
            if (TryTake(GameCommandType.Abandon, out GameCommand command))
            {
                return command;
            }

            if (TryTake(GameCommandType.Return, out command))
            {
                return command;
            }

            if (TryTake(GameCommandType.Resume, out command))
            {
                return command;
            }

            if (TryTake(GameCommandType.SampleComplete, out command))
            {
                return command;
            }

            if (TryTake(GameCommandType.Pause, out command))
            {
                return command;
            }

            if (TryTake(GameCommandType.Start, out command))
            {
                return command;
            }

            return default;
        }

        private bool TryTake(GameCommandType type, out GameCommand command)
        {
            command = default;
            int count = _commands.Count;
            for (int i = 0; i < count; i++)
            {
                GameCommand candidate = _commands.Dequeue();
                if (command.Type == GameCommandType.None
                    && candidate.Type == type
                    && IsCommandValid(candidate))
                {
                    command = candidate;
                    continue;
                }

                // 旧 RunId 或当前状态不受理的请求直接丢弃，避免队列越积越多
                if (!IsCommandValid(candidate))
                {
                    continue;
                }

                _commands.Enqueue(candidate);
            }

            return command.Type != GameCommandType.None;
        }

        private bool IsCommandValid(GameCommand command)
        {
            switch (command.Type)
            {
                case GameCommandType.Start:
                    return _state == GameFlowStateId.Lobby;

                case GameCommandType.Pause:
                case GameCommandType.SampleComplete:
                    return _state == GameFlowStateId.Running && command.RunId == _runId;

                case GameCommandType.Resume:
                    return _state == GameFlowStateId.Paused && command.RunId == _runId;

                case GameCommandType.Abandon:
                    return (_state == GameFlowStateId.Loading
                            || _state == GameFlowStateId.Running
                            || _state == GameFlowStateId.Paused)
                           && command.RunId == _runId;

                case GameCommandType.Return:
                    return _state == GameFlowStateId.Finished && command.RunId == _runId;
            }

            return false;
        }

        private void ShowLobby()
        {
            try
            {
                GameModule.UI.ShowUIAsync<ProjectBLobbyUI>(this);
            }
            catch (Exception exception)
            {
                // 现有 UIModule 没有失败回调，这里只能记录；失败出口见第 10 节可选补丁
                Log.Error($"[GameFlow] show lobby failed: {exception}");
            }
        }

        private void PublishSnapshot()
        {
            _snapshot = BuildSnapshot();
            GameEvent.Send(GameEventDef.OnGameSnapshotChanged);
        }

        private GameSnapshot BuildSnapshot()
        {
            int progress = _session != null ? _session.Progress : 0;
            return new GameSnapshot(
                _state,
                _state == GameFlowStateId.Loading,
                _runId,
                progress,
                _hasOutcome,
                _lastOutcome,
                _state == GameFlowStateId.Lobby,
                _state == GameFlowStateId.Running,
                _state == GameFlowStateId.Paused,
                _state == GameFlowStateId.Loading
                || _state == GameFlowStateId.Running
                || _state == GameFlowStateId.Paused,
                _state == GameFlowStateId.Finished);
        }

        private enum GameCommandType
        {
            None = 0,
            Start,
            Pause,
            Resume,
            SampleComplete,
            Abandon,
            Return,
        }

        private readonly struct GameCommand
        {
            public readonly GameCommandType Type;
            public readonly int RunId;

            public GameCommand(GameCommandType type, int runId)
            {
                Type = type;
                RunId = runId;
            }
        }
    }
}
```

## 7. GameApp.cs（替换）

**作用**：组合根。创建/启动/释放 `GameManager`，注册退出钩子。

**为什么不用 `Singleton`**：`Singleton<T>.Instance` 懒创建，迟到回调会复活管理器；显式持有让“谁创建、谁释放”一目了然。

**为什么双入口**：`Application.quitting` 在 player 下早于对象销毁；`AddDestroyListener` 覆盖 Editor 和异常退出。两个入口共享 `_released`，保证只执行一次。

**为什么需要 `_releaseRegistered`**：`Entrance` 可能因热更重入被调用多次，而 `AddDestroyListener` 内部是 `+=`；不防重会执行两次释放。

**为什么先业务后框架**：`GameManager.Dispose`（停会话/放句柄/销毁 FSM）必须在 `SingletonSystem.Release`（关 UI/销毁 UIRoot）和 `GameModule.Shutdown` 之前，否则会出现访问已释放窗口/模块的路径。

```csharp
using System.Collections.Generic;
using System.Reflection;
using GameLogic;
#if ENABLE_OBFUZ
using Obfuz;
#endif
using TEngine;
using UnityEngine;
#pragma warning disable CS0436

/// <summary>
/// 游戏App。
/// </summary>
#if ENABLE_OBFUZ
[ObfuzIgnore(ObfuzScope.TypeName | ObfuzScope.MethodName)]
#endif
public partial class GameApp
{
    private static List<Assembly> _hotfixAssembly;
    private static GameManager _gameManager;
    private static bool _releaseRegistered;
    private static bool _released;

    /// <summary>
    /// 热更域App主入口。
    /// </summary>
    public static void Entrance(object[] objects)
    {
        _hotfixAssembly = (List<Assembly>)objects[0];
        Log.Warning("======= 看到此条日志代表你成功运行了热更新代码 =======");
        Log.Warning("======= Entrance GameApp =======");

        if (!_releaseRegistered)
        {
            _releaseRegistered = true;
            Utility.Unity.AddDestroyListener(ReleaseLogic);
            Application.quitting += ReleaseLogic;
        }

        StartGameLogic();
    }

    private static void StartGameLogic()
    {
        if (_released || _gameManager != null)
        {
            return;
        }

        _gameManager = new GameManager();
        _gameManager.Start();
    }

    private static void ReleaseLogic()
    {
        if (_released)
        {
            return;
        }

        _released = true;

        if (_gameManager != null)
        {
            _gameManager.Dispose();
            _gameManager = null;
        }

        SingletonSystem.Release();
        GameModule.Shutdown();
        GameEvent.Shutdown();

        Application.quitting -= ReleaseLogic;

        if (_releaseRegistered)
        {
            _releaseRegistered = false;
            Utility.Unity.RemoveDestroyListener(ReleaseLogic);
        }
    }
}
```

## 8. ProjectBLobbyUI.cs

**作用**：唯一调试窗口。绑定节点、订阅快照事件、渲染、提交请求。

**为什么 UI 不直接改状态**：按钮只发 `RequestXxx(runId)`，由宿主按当前状态和身份校验；UI 的按钮可用性只是“展示同一套约束”，不是权威。

**为什么窗口跨局复用**：每局切换都异步加载窗口会引入额外的加载失败/迟到路径；同一窗口更新快照更简单，也符合 01 稿“保留加载、运行、暂停、结果和大厅在同一窗口”。

**为什么 `OnCreate` 要读一次快照**：`GameEvent` 只发“变了”的通知，窗口可能在事件之后才创建；创建时读当前快照可以避免丢状态。`OnRefresh` 处理窗口已存在时再次 `Show` 的 `UserData` 更新。

**为什么 `_bound` 检查**：prefab 节点是外部输入边界，缺节点时明确报错比在 `OnCreate` 里 NRE 好排查；这是 UI 绑定层少数需要 defensive check 的地方。

**为什么 `OnDestroy` 移除按钮监听**：`AddUIEvent` 会自动清理事件，但 `Button.onClick` 是 UnityEvent，不会随 `GameEventMgr` 清理；窗口复用/关闭时手动移除。

预制体节点名必须与 `BindMemberProperty` 一致：


## 9. ProjectBRunSample.json

**作用**：联调样本。`sampleId` 用于校验“加载到的确实是这一份样本”，`targetProgress` 控制演示时长，`displayName` 只用于调试显示。

**为什么放 `AssetRaw/Configs`**：现有 `Configs` 收集组已经存在，`AddressByFileName` 让地址等于文件名，样本加载器和 01 稿的地址约定都不用新增收集规则；正式内容后续走 Luban，不往这里塞正式数值。

**为什么用 JSON 而不是硬编码**：没有样本文件就无法复现 `LoadFailed`（删文件/改无效地址）、无法演示“加载中放弃”；样本可替换也方便给不同阶段换阵容。

```json
  "targetProgress": 10
}
```

## 10. 可选框架补丁：窗口加载失败信号

现有 `UIModule`/`UIWindow` 没有失败回调，`ShowUIAsyncAwait` 在 `Time.timeScale = 0` 时还会因为用 `Time.deltaTime` 计时而卡住。若 01 期需要“大厅装配失败”这条验收，建议做以下最小补丁（会改框架 UI 代码，落盘前需确认）。

**作用**：给现有 UI 模块补“加载失败”信号，让 `GameManager` 能把“大厅装配失败”变成一个真实状态出口，而不是只写日志。

**为什么必须改框架**：`ShowUIAsync` 返回 `void`、没有失败回调；`ShowUIAsyncAwait` 无条件返回窗口；`Handle_Completed(null)` 静默 `return`，`IsLoadDone` 永远为 false。不改这三处，`GameManager` 拿不到失败事实，01 稿的“窗口装配失败记录地址和错误”就无法落地。

**为什么标可选**：这是框架级改动，会影响所有窗口；`ShowUIAsyncAwait` 的返回值语义从“窗口”变成“窗口或 null”，现有/未来调用方都要处理 null。01 期如果只要求“窗口失败可见”，可以先只做 `LoadFailed` 标志 + 日志，不接状态机。

**风险**：`TryGetWindow` 在窗口已存在但尚未加载时会立即返回，补丁也判断不了“正在加载”，这个边界要后续再改 `ShowUIAwaitImp` 的分支；`ShowUIAsync` 依旧没有回调，只有 `Await` 路径能拿到失败。

`UIWindow.cs`：

```csharp
public bool LoadFailed { get; private set; }

private void Handle_Completed(GameObject panel)
{
    if (panel == null)
    {
        LoadFailed = true;
        IsLoadDone = true;
        return;
    }

    IsLoadDone = true;
    if (IsDestroyed)
    {
        Object.Destroy(panel);
        return;
    }
    // ... 原逻辑不变
}
```

`UIModule.cs` 的 `ShowUIAwaitImp`：

```csharp
float time = 0f;
while (!window.IsLoadDone)
{
    time += Time.unscaledDeltaTime;
    if (time > 60f)
    {
        break;
    }

    await UniTask.Yield();
}

if (window.LoadFailed)
{
    return null;
}

return window as T;
```

然后 `GameManager.ShowLobby` 改成异步：

```csharp
private bool _lobbyFailed;

private async UniTaskVoid ShowLobbyAsync()
{
    ProjectBLobbyUI window = await GameModule.UI.ShowUIAsyncAwait<ProjectBLobbyUI>(this);
    if (window == null)
    {
        GameModule.UI.CloseUI<ProjectBLobbyUI>();
        _lobbyFailed = true;
    }
}

private void ShowLobby()
{
    _lobbyFailed = false;
    ShowLobbyAsync().Forget();
}
```

`Tick` 的 `Lobby` 分支开头加：

```csharp
if (_lobbyFailed)
{
    _lobbyFailed = false;
    _exitReason = ExitReason.LoadFailed;
    return typeof(ExitingState);
}
```

需要 `using Cysharp.Threading.Tasks;`。不采用补丁时，主代码保持第 6 节的同步 fire-and-forget，窗口失败只能看日志。

## 12. 与 01 验收用例的对应

| 01 验收用例 | 本实现的行为 |
| --- | --- |
| 正常启动 | `Entrance → GameManager.Start → Lobby`，唯一 FSM 与唯一宿主 |
| 正常结束 | Running 推进到 `TargetProgress` 或点“模拟结束” → Finished → 返回 → Exiting 发布一次 `Completed` |
| 运行或暂停中放弃 | `RequestAbandon` → Exiting(Abandoned)，新局 `RunId` 递增、进度归零 |
| 加载中放弃后重开 | 旧 `RunId` 的 `LoadResult` 在 `DrainLoadResults` 被丢弃，句柄由 loader 释放；新局不受影响 |
| 装配失败后重试 | 样本加载失败 → Exiting(LoadFailed)，回 Lobby 可再开；窗口失败需第 10 节补丁 |
| 重复和交错请求 | 请求入队时校验状态 + RunId；`TakeCommand` 按 Abandon > Return > Resume > SampleComplete > Pause > Start 取一条 |
| 应用销毁 | `Application.quitting` + `AddDestroyListener` 双入口，`_released` 幂等；先业务后框架 |

## 13. 已知限制

- `GameManager` 不需要 `Singleton`；如果 UI 之外还要访问，请通过显式注入，不要恢复 `Singleton<GameManager>`。
- `ShowUIAsync` 是 fire-and-forget；不打第 10 节补丁时，窗口加载失败只有日志。
- 暂停不改 `Time.timeScale`；`RunSession.Advance` 用 FSM 的 `realElapseSeconds`，表现暂停由 02 的帧驱动负责。
- `Application.quitting` 在移动端被强杀时不一定触发；这种情况只保证“下次启动不恢复旧局”，不做退出前持久化。
- 阶段 03 接子战斗时，在 `RunSession.Dispose` 和 `Exiting` 的清理顺序里接 `BattleModule` 注销，不要改 `GameManager.Tick` 的迁移表。
