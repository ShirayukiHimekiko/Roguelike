# 单机战斗模块与逻辑帧驱动首版实现方案

单一开战入口和 TEngine FSM 驱动已接入骨架，编译和运行验收待执行。

首版以 ET10 的单局战斗和权威逻辑帧链路为对标目标。外部通过 `StartBattle(executeTick)` 创建并启动本局，使用返回的房间调用 `EndBattle(room)` 结束。项目同时具备可独立调用的定点标量基础。下一步把场景加载接入战斗初始化状态，再接入 Entitas 战斗数据、逐帧输入和定点移动演算。

## 1. 对照上游开战链路

源码基线为 ET10 `master` 固定提交 `743c635dd5b0f6f6bab549c0093382c85f3f8307`。首版对照房间的生命周期和服务端权威步进路径，按项目类型与命名重新编写。[固定提交][source]

| 时点 | ET10 | 本项目首版 |
| --- | --- | --- |
| 创建当局 | 房间初始化处理器建立 `Room` 和玩家准备数据。 | `BattleModule.StartBattle(executeTick)` 创建 `BattleRoom`。房间保存当局回调，启动自己的 FSM 并进入战斗初始化。 |
| 场景加载完成 | 客户端加载表现层并报告换场完成。服务端记录各玩家准备进度，所有人完成后才进入开战流程。 | 当前骨架同步完成初始化。接入实际场景后，由战斗初始化负责等待加载和准备结果，再切换状态。 |
| 正式开战 | 服务端确定 `StartTime`，调用 `Room.Init()`，挂上 `LSServerUpdater`，再把开战信息发给客户端。客户端收到后按同一个锚点初始化。 | FSM 进入战斗开始，建立本局的时钟和更新器，然后切到战斗进行。 |
| 帧推进 | 当局的 `LSServerUpdater` 根据当局时钟判定候选帧是否到期。 | TEngine 调用 `RunBattleState.OnUpdate()`，状态从 `fsm.Owner` 取得当局依赖，交由更新器判定并同步执行当帧。 |
| 结束当局 | 客户端切换到新房间时移除旧 `Room`，房间持有的更新器随其生命周期结束。 | `EndBattle(room)` 先解除当前房间，再进入战斗结束，释放房间的时钟、更新器和 FSM。调用方随后可以清理当局系统与场景。 |

服务端示例在所有玩家准备完毕后还等待 1 秒。单机将加载就绪和正式建立帧时钟作为内部时点。进入战斗开始时才采集时间锚点。[建房处理][create-room] · [服务端开战处理][room-start] · [客户端加载与开战][scene-change] · [权威更新器][server]

## 2. 第一步建立战斗模块和当局生命周期

| 拟新增或修改文件 | 职责 |
| --- | --- |
| `Assets/GameScripts/HotFix/GameLogic/Module/BattleModule/BattleModule.cs` | 采用项目的 `Singleton<BattleModule>`。管理当前房间，提供 `StartBattle(executeTick)`、`EndBattle(room)` 并在应用释放时清理当前局。 |
| `Assets/GameScripts/HotFix/GameLogic/Module/BattleModule/BattleRoom.cs` | 作为 FSM Owner，持有帧执行入口、本局 `FixedTimeCounter` 和 `BattleUpdater`。创建、启动和注销 FSM 都由房间完成。 |
| `Assets/GameScripts/HotFix/GameLogic/Module/BattleModule/State/` | 四个状态负责流程切换和推进。状态经由 `fsm.Owner` 访问当局资源，切换走 TEngine 的 `FsmState.ChangeState`。 |
| `Assets/GameScripts/HotFix/GameLogic/GameModule.cs` | 增加 `GameModule.Battle` 访问入口，直接返回 `BattleModule.Instance`。 |

TEngine 由 `RootModule.Update()` 轮询 `ModuleSystem`，`FsmModule.Update()` 依次驱动各 FSM 的当前状态。因此房间的实时入口是 `RunBattleState.OnUpdate()`。正常退局由房间通知当前状态切到战斗结束，再注销 FSM 和释放当局资源。应用释放时直接走房间资源释放流程。[框架主循环](../../Assets/TEngine/Runtime/Module/RootModule.cs) · [FSM 模块轮询](../../Assets/TEngine/Runtime/Module/FsmModule/FsmModule.cs) · [状态回调](../../Assets/TEngine/Runtime/Module/FsmModule/FsmState.cs)

| 状态 | 触发时点 | 状态职责 |
| --- | --- | --- |
| 战斗初始化 · `InitializeBattleState` | 创建房间 | 当前骨架在进入时切到战斗开始。后续场景加载和当局准备接在这里。 |
| 战斗开始 · `StartBattleState` | 初始化完成 | 建立房间的帧时钟和更新器，然后转入战斗进行。 |
| 战斗进行 · `RunBattleState` | 开战初始化完成 | 由 TEngine 调用 `OnUpdate()`，把房间拥有的时钟和执行入口交给更新器。 |
| 战斗结束 · `EndBattleState` | 调用 `EndBattle(room)` | 房间停止帧推进并从该状态注销 FSM、释放资源。 |

首版同时只持有一局。开战入口校验是否已有房间和是否提供执行回调，退局入口校验房间归属。内部状态使用房间已准备的数据，异步场景流程列在下一步。

~~~text
room = GameModule.Battle.StartBattle(executeTick)

TEngine 轮询当前状态
    战斗进行.OnUpdate 从 fsm.Owner 取时钟、更新器和执行回调
    更新器判断下一帧是否到期

退局
    GameModule.Battle.EndBattle(room)
~~~

## 3. 当局帧时钟和更新器

两个类型都放在 `Assets/GameScripts/HotFix/GameLogic/Module/BattleModule/`。代码使用项目命名空间，直接归入 `GameLogic`。实现按下表对照源码，无需使用上游 Package。

| 拟新增文件 | 上游行为 | 本项目实现 |
| --- | --- | --- |
| `FixedTimeCounter.cs` | `FixedTimeCounter` 从锚点推导每一帧的到期值。间隔来自 `LSConstValue.UpdateInterval`。 | 记录开战时的 `long startTimeMs`，以第 `0` 帧为锚点。固定间隔为 **50 ms（20 Hz）**。到期值为 `startTimeMs + frame × 50`。 |
| `BattleUpdater.cs` | `LSServerUpdaterSystem.Update()` 只检查下一帧。到期时先增加 `AuthorityFrame`，再执行当帧。 | 持有当局当前帧号，初值为 `-1`。以房间提供的时钟和回调推进当帧。一次状态更新最多推进一帧，从 `0` 开始，保持时钟公式、到期边界和执行顺序。 |

开战和每次更新使用同一种时间采样方式，按上游 Unity 时间源把 `Stopwatch.GetTimestamp()` 换算为整数毫秒。首帧的计划到期时刻等于开战锚点。它在战斗进行状态的第一次到期 `OnUpdate()` 推进。帧号是 `int`，毫秒时刻是 `long`。[固定步长][constants] · [时钟公式][counter] · [房间时钟初始化][room] · [时间采样][time]

~~~text
进入战斗开始状态
    room = fsm.Owner
    startTimeMs = 读取单调毫秒
    room.Clock = 以 startTimeMs 初始化当局时钟
    room.Updater = 创建帧号为 -1 的更新器
    切换到战斗进行

战斗进行.OnUpdate
    room = fsm.Owner
    room.Updater.Update(room.Clock, 读取单调毫秒, room.ExecuteTick)

BattleUpdater.Update(clock, nowMs, executeTick)
    nextFrame = 当前帧 + 1
    如果 nowMs < 时钟计算的 nextFrame 到期时刻，返回
    当前帧 = nextFrame
    同步调用 executeTick(nextFrame) 一次
~~~

`CurrentFrame` 表示已推进的当局帧。执行回调中读到的帧号与当次传入的帧号相同。回调发生异常时交给现有宿主链路处理。

当宿主卡顿时，恢复后沿原锚点依序追赶，每次状态更新最多前进一步。持续低于 20 次状态更新每秒时会持续积压。FSM 提供轮询时机，固定帧计算使用独立的单调毫秒时钟。战斗暂停涉及独立的玩法语义，首版沿用所选步进规则。[权威更新器][server] · [时间采样][time]

## 4. 定点标量基础

项目自有类型 `FixedPoint` 位于 `Assets/GameScripts/HotFix/GameLogic/Utility/FixedPoint.cs`，基于 TrueSync `FP` 的基础运算源码适配。以 `long` 保存原始值，低 32 位表示小数。乘法沿用高低 32 位拆分，除法沿用移位长除、舍入、除零和超限返回语义。定点向量和四元数也位于 `Utility`。时钟继续用整数毫秒。[定点标量][fixed-point]

~~~text
FixedPoint.FromInt(n) 的原始值 = n 左移 32 位
乘法 = 拆分操作数的高低位，合并乘积并保留 32 位小数
除法 = 给商保留额外一位，舍入后恢复符号
~~~

对账时传同样的原始值给上游 `FP` 和本项目 `FixedPoint`，用 `RawValue` 比较整数构造、正负数乘法、循环小数除法和除零行为。定点向量、平方根与四元数跟着下一步的移动依赖一并迁入。

### 生命周期的验收预期

| 场景 | 预期 |
| --- | --- |
| 应用启动，开战入口还未调用 | 没有战斗房间，派发 0 次。 |
| 开战 | 房间同步完成当前骨架的初始化并从 `-1` 开始，首次到期的状态 `OnUpdate()` 推进帧 `0`。 |
| 退局与重开 | 退局后旧执行入口不再收到回调，新局在自己的锚点从 `0` 开始。 |

### 帧序列的验收预期

设当局开战锚点为 `1000 ms`，当前帧初值为 `-1`。给上游参考规则和本地更新器输入同一组毫秒值，逐次比较派发帧与调用结束时的当前帧。重复采样覆盖积压时每次只推进一帧的规则。

| 1 | 999 | 1000 | 无 | -1 |
| 2 | 1000 | 1000 | 0 | 0 |
| 3 | 1049 | 1050 | 无 | 0 |
| 4 | 1050 | 1050 | 1 | 1 |
| 5 | 1220 | 1100 | 2 | 2 |
