# Project B 索敌与 RVO2 移动接入战斗模块方案

2026-11-15 · 修订稿。以 [战斗模块](../02-Project_B-战斗模块方案.md)、[索敌](11-战斗寻路与索敌实现方案.md) 和 [RVO2 调用代码](19-寻路模块实现代码.md) 为基础。RVO2 接入从项目固定 Tick 运行。

## 1. 模块边界

| 所有者 | 数据与动作 |
| --- | --- |
| 地图与占位 | 维护部署格和当前阻挡投影，固定轮廓进入 ORCA static，变更轮廓进入 dynamic。维护阻挡版本及方向保护资格。 |
| 单位 | 从敌对合法候选锁定目标，按受击盒与射程选择停止或继续追击。移动目标来自该目标的接敌点、存在的地图入口或明确配置路点。 |
| RVO2 移动适配 | 本场 ORCABundle/Agent 和障碍。接当前权威位置、期望速度和地图快照，固定步调用 ORCA，交回一批量化坐标。 |
| 索敌 | PreMove 供移动单位选敌，PostMove 供塔选敌。全扫为正确性基准，目标计算独立于 ORCA 邻居与内部空间树。 |
| 建筑、命中及帧 | 建筑管理发射状态和生命，HitResolver 统一结算。帧通道控制世界候选步和已提交结果。 |

## 2. 接线顺序

~~~text
BattleChannel → BattleWorld 候选 Tick
  撤销开步到期资格 → 依序应用命令 → 冻结当步阻挡、保护与 PreMove
  → 单位索敌 → 从目标计算 Stop / Goal 与 prefVelocity
  → ORCA.Run(1f / TickRate) 完成 → 位置量化并由 Entitas 所有者统一写回
  → 从移动后位置冻结 PostMove → 塔索敌 → 按射程和屏障复核发射
  → HitResolver → 派生下一步占位与保护 → Cleanup → 候选批次
~~~

地图投影先处理当步命令产生的阻挡，再同步 ORCA。N 步伤害造成外塔破损，清理时形成下一步阻挡和保护变更。发射使用当前步的新位置与冻结的保护规则。若攻击者跨方向，按移动后位置对同一保护规则复核。塔范围内出现本步刚走进来的单位时应能选中。`QuadTargetBatch` 若开启，两阶段在各自读结果前完成，索引绑定各自 BatchStamp。

## 3. 接敌与结果写回合同

- 索敌请求、结果都含寻敌者 ID，结果还带目标 ID。消费时校验场次、Tick、阶段、当前身份与资格，空目标清锁。塔锁定需要符合当前自动发射规则。
- `MoveInput` 包含 ActorId、Position、Goal、Speed、Stop。`Goal` 可由攻击方到目标受击盒最近点或目标外侧配置点导出；先按攻击距离和保护检查当前位置是否应停。在较窄地形使用策划/关卡配置的入口或点序列，让 ORCA 负责沿指向的目标移动，点序列只做目标控制。
- ORCA 批量输出后，以 `BattleId + ActorId` 核对身份并走已有 `ReplaceActor` 写位置。业务实体只由单位系统写。浮点求解的状态和版本按照 [19](19-寻路模块实现代码.md) 与回放合同记录。
- 近距离拥挤、停步、目标资格失效是不同事实。短时间零位移保留当前合法目标，在规则允许时按固定 Tick 重查，地图版本变化重新计算目的地。没有全局搜索失败的结果供索敌永久排除。若配置明确排除某入口或站位，按当步地图与资格投影过滤。发射处理始终按实际几何再判断。

## 4. 生命周期与验收

| 情景 | 检查项 |
| --- | --- |
| 新增、过期、死亡和重新开战 | Agent 数量等于本场注册单位；取消或换场后旧 Agent、障碍及 Job 都释放，旧 ActorId 映射不传给新场。 |
| 测试塔站定与单位绕让 | 塔的障碍形状与受击形状按各自配置；两单位可局部避让，停步单位当步位置守恒。 |
| 塔障碍和保护提交 | 同 Tick 破损产生下一步障碍变更，保留复活位按地图合同分别检查。 |
| PreMove 与 PostMove | 塔能本步选择刚进入射程的单位，推进前后的索敌索引不串用。 |
| 回放、暂停与故障 | 暂停时不推进库，同环境记录逐 Tick 输出。候选步失败关闭本场，宿主仍可消费此前已提交批次。 |
