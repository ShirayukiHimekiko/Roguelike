# Project B 建筑实现方案

状态为实现提案。建筑子系统管理玩家建筑、普通塔、元素塔、特殊塔、光环塔、抵抗塔和英雄核心。战斗统一判定命中与伤害，建筑子系统提交建筑生命和生存状态。战场占位由唯一所有者提交，建筑提供足迹与状态变更所需数据。[战斗编排](00-战斗编排与集成方案.md) · [敌方 AI](02-敌方AI实现方案.md)

## 策划口径与配置

- 敌方只布置静态建筑。存活常规塔在准备阶段回复**已损生命的 15%**，可受物品修正；抵抗塔每回合回满，曾破损的抵抗塔下回合满血复活且不掉法球。抵抗塔碰撞体比常规塔大。原案修订 5989 L232–262。[Project_B 原案](https://my.feishu.cn/wiki/AIEkwlgbqiha8dkcxXSc0oH9nae) · [需求 10](../../游戏设计/功能需求/10-敌方防御塔.md)
- 核心固定占圆心一格，无星级，每回合准备时回到满血。外围八方向至少清空一方向后开放攻击；玩家单位索敌从外向内。核心直接击破增加塔破坏分，核心本体不掉法球，同时使其他存活敌塔破损并结束本层。原案 L236、L499–511。[需求 11](../../游戏设计/功能需求/11-英雄核心.md)
- 击破常规敌塔的概率法球与击败英雄的必掉法球为两个来源。第一至第四层有稀有度表，第五层如何处理待确认。核心本体的禁掉落与英雄层奖励用独立原因表达。连带破损与抵抗塔能否记分仍待确认。原案 L139–157、L234–236、L262–270、L286。[需求 14](../../游戏设计/功能需求/14-战斗评分.md) · [需求 19](../../游戏设计/功能需求/19-法球掉落与领取.md)
- 玩家建筑由建筑牌部署，有存在期限，固定位置且不攻击。结束回合回收，回收不触发死亡，玩家建筑不算作提前终止所用的非建筑存活单位。场地章节明确敌塔不受地形影响，BUFF 小节又列了敌塔地形项。首版评审按场地章节让敌塔豁免，保留按目标标签配置的入口。原案 L205–229、L264–266、L374–405。[需求 08](../../游戏设计/功能需求/08-卡牌类型与效果.md) · [需求 27](../../游戏设计/功能需求/27-增益、减益与持续范围.md)
- 塔表及基础属性表按定义与星级映射，核心用明确的无星级配置键。Luban 在准备前加载并转成带版本的值快照。建筑另需足迹、阻挡体、受击体、攻击定义、光环规则和可搬动能力。原表含基本移速，静态塔按原案固定，该字段细节待策划确认。[项目 Luban 规范](../../../.agents/skills/tengine-dev/references/luban-config.md)

## 数据所有权和生命周期

| 数据或系统 | 职责与所有者 |
| --- | --- |
| 建筑身份与生命 | 建筑持有种类、定义 ID、星级、所属、当前生命与上限、生存状态、代际、攻击可用 Tick。每回合用稳定 `BattleEntityId` 寻址，敌塔另有当前层跨回合稳定的 `TowerInstanceId`。抵抗塔复活时同一 `TowerInstanceId` 递增代际。 |
| 布局投影 | 建筑使用已核准放置的锚点与足迹定义计算位置、受击盒、阻挡体和光环投影。真实占位、保留、释放和修订版本由战场占位所有者持有。 |
| 效果与数值 | 效果系统持有来源、叠层和持续规则，建筑按本阶段有效的属性和最终 HP 上限提交生命变化；局内持久效果所有者决定跨层继承。 |
| 战斗编排 | 接收阶段请求，协调一套 `Battle` Context 与阶段系统，统一归集攻击请求与命中事实，再将建筑结果交给建筑所有者提交。其他模块经编排领用只读值。 |

敌塔状态为 `Active → BrokenPermanent`（常规敌塔或核心）及 `Active → AwaitingRevive → Active`（抵抗塔）。永久破损保留历史和清理所需的值。抵抗塔破损时撤销受击和行动资格，提议保留原位给下回合复活并即时去掉移动阻挡，是否仍为遮挡核心的屏障待确认。玩家建筑状态为 `Active → PendingExit`，原因包括 `Destroyed`、`Expired`、`Reclaimed`，后两种按回收类结果分发，时限到期是否有专属效果待确认。

每回合新建 `BattleWorld`。建筑导出 `EnemyBuildingRoundState`，包含英雄层身份、配置版本、`TowerInstanceId`、代际、占位锚点、生命、生存状态、明确可跨回合的建筑字段或持久效果引用 ID，以及核心保护政策需要的历史。例如策划确认暴露永久、或要求记录曾有塔的方向时，可保存相应掩码。下一准备窗口按快照预检占位，应用有效上限和恢复规则、复活抵抗塔，再交由 AI。玩家建筑、未提交攻击、目标与战斗 Tick 生命周期限于单回合。换层由编排按局内规则创建下一英雄建筑快照。[帧驱动设计 §3–6](../Project_B-帧驱动框架设计方案.md)

首期评审建议先确定准备阶段有效最大生命 `maxHP`，将继承生命裁到 `0..maxHP`。普通塔按 `current + (maxHP - current) × repairRate` 限幅至 `maxHP`，使用公共生命单位和舍入规则。物品如何修正基准 15% 与变动上限如何影响生命待策划确认。核心和抵抗塔满血。永久破损不参与恢复。准备重复输入以 `RoundId + WindowId` 识别，已提交的准备回复不会重复发生。

## 阶段、范围与破损

| 阶段 | 本模块读写与输出 |
| --- | --- |
| 准备窗口 | 经编排、占位预检后创建塔、治疗、复活。AI 规划成功后接受经核准的移动与放置批，导出 Tick 0 投影。 |
| 入帧 → 指令提交 | 入帧封存本 Tick 指令和到期事件。玩家建筑到期在指令前撤销资格。编排联合预检部署、费用、卡牌变更，建筑经批准创建。 |
| 效果与属性 | 光环查询按来源和目标排序，按格层发布来源键。效果系统解析资格、叠层及持续期限，建筑消费只读属性结果。 |
| 行动与命中 | 攻击塔与暴露核心从编排投影读取合法玩家单位，按权重、距离、稳定 ID 选目标。到达可攻击 Tick 后输出 `AttackRequest`，附元素或特效定义。统一战斗处理攻击请求与后续效果。 |
| 结算 → 收尾 | 战斗生成有序 `ResolvedHit(BattleId, Tick, HitOrdinal, …)` 及每目标最终生命。建筑写生命并记录破损或核心击破。编排联合提交占位、暴露与效果结果，再对外发值事实。 |

光环的第一层采用 `max(abs(dx), abs(dy)) ≤ 1` 的九宫格距离，建议首期按锚点计算。是否含自身、影响核心、跨层叠加及多格边缘如何处理待定。以 `(AuraSourceId, SourceGeneration, TargetId, EffectId)` 表达持续链接，同一来源对同一目标登记一次。来源失效后下一 Tick 效果阶段去掉其链接，重排和复活后从新一回合快照重建。命中前固定有效属性和防御。

核心八方向用显式的 `SlotId → RingIndex + DirectionMask`。地图定义方向边界的重叠、屏障成员和通往核心的合法入口。战斗编排读取占位与建筑投影，计算各方向从外到内的剩余屏障，将核准的保护状态交建筑提交。同一规则供 AI 评分、单位索敌及 `HitResolver` 权限校验使用。首期提案将**曾有塔且被战斗清空**、并存在合法入口的方向作为暴露候选；开局空方向、抵抗塔破损时的屏障资格、回合间重新堵上和技能穿透待确认。N 步发生外塔破损，N 步仍消费旧保护，N+1 使用新保护判定开火与受击。开放格位、光环或拆塔均不改写围栏位置。

```text
CommitResolvedBuildingLife(approvedChanges, hits)
    按编排定序，通过 BattleEntityId 与代际定位每个建筑
    使用战斗工作缓冲中的最终生命替换生命组件
    记录 HP 首次由正至零的直接破损并撤销资格
    若核心直接破损
        稳定遍历本步直接破损以外的存活敌塔
        将其转为连带破损，记录 CoreCascade 原因
    由编排汇总占位更新和暴露态，建筑提交核准的核心状态
    返回带原因及 HitOrdinal 或派生序号的值事实
```

同 Tick 多次命中可保留多笔事实，只有一笔令建筑首次归零；同 Tick 已直接击破的塔保留直接原因。连带破损无新增伤害命中或重复过量伤害，积分与法球消费者按原因处理。英雄击败奖励消费层完成事实。玩家建筑到期与回收使用单独退出原因。若同一攻击重叠目标多形状，统一战斗依照攻击实例、攻击段和目标去重。

## Entitas 1.14.1 与失败处理

- 正式拟定的 `Battle` Context 挂建筑身份、标签、生命、效果输入、攻击行动、足迹投影和待清理组件，运用生成的 `BattleMatcher`、`AddX`、`ReplaceX`。建筑系统只使用模块拥有的数据和编排传入的值缓冲。逐笔请求和生存事实显式保存，Collector 适合提交后状态刷新。影响规则的遍历一律按业务 ID 排序。[Entitas 1.14.1](https://github.com/sschmid/Entitas/releases/tag/1.14.1) · [项目 Entitas 规范](../../../.agents/skills/entitas-dev/SKILL.md)
- 按帧方案 §3 把旧 Demo 的 Jenny 配置迁移至正式输入与独占生成目录，先确认 1.14.1 CLI、目标程序集引用和扫描范围。表现桥接拥有 Unity 对象与异步加载，请求返回需匹配世界、实体代际。资源加载失败不会改变权威布局或生命。
- 初始占位重叠、遗失核心或复活保留格冲突在准备预检报错。部署合法性失败不扣费或库存；实际写入在全部所有者预检之后。工作批次回写目标版本不符、HP 超域、预留容量不足或部分提交失败时，帧宿主按整步故障退出，保留此前已提交结果。

## 执行步骤与验收

- [ ] **建筑组件和初态。** 确认足迹、碰撞体、塔种类与寻址；实现 `塔定义 + 准备批 → 建筑组件 + 布局投影`。
- [ ] **生命和跨回合。** 处理常规恢复、核心满血与抵抗塔代际；实现 `上轮值快照 → 预检恢复/复活/保留 → 本轮快照`，补齐玩家建筑时限和退出原因。
- [ ] **攻击和光环。** 写阶段投影、稳定目标排序和到期字段；实现 `效果源 → 规则折叠`、`可行动攻击者 → 攻击请求`，接战斗统一命中流程。
- [ ] **结算和核心联动。** 实现 `ResolvedHit → HP 提交 → 一次破损 + 占位变更 + 暴露写回`，核心终止及连带原因交回编排。
- [ ] **同频与跨轮验收。** 对照 ID、占位、伤害写回、每步事实的先后及回合快照重建，覆盖配置冲突与合法回合转换。

| 场景 | 预期 |
| --- | --- |
| 常规塔满值 100、当前 60、恢复率 15% | 进入本轮后为 66。同窗口重复完成仍是 66。抵抗塔和核心按规则回满。 |
| 多候选重叠同一塔、两笔合法命中跨归零边界 | 同段只扣一次，工作生命只扣实际值。单个直接破损，命中、掉落资格和评分来源可追溯。 |
| 抵抗塔被破坏并在下回合复活 | 结算时撤销后续行动与受击资格，保留本步已采集的合法发射。破损不掉球；占位保留，复活后满血且代际递增，旧引用失效。 |
| 外层最后一塔在 N 步破损 | N 步各命中仍用旧保护，结算写入暴露，N+1 核心可攻击和受击。核心直接归零记录一次自身破损和各塔一次连带破损。 |
| 玩家建筑到期或回合回收 | 退出目标集合，无阵亡逻辑，不延后「没有存活非建筑单位」的检测。 |
| 光环源破坏、重排和边界邻格 | 第一层含已配置对角邻格，来源只登记一次，来源失效后按下一步阶段解除。 |
