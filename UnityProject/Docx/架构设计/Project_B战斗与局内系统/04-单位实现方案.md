# Project B 单位实现方案

状态为实现提案。单位系统拥有玩家可移动召唤物的生命、移动、目标和攻击行为。玩家建筑及敌塔由建筑模块负责。两者由战斗编排协调，以统一的攻击候选、命中结算、格位和只读投影交换数据。[战斗编排](00-战斗编排与集成方案.md) · [建筑](03-建筑实现方案.md)

## 策划口径

- 玩家出牌在合法地点召唤配置数量的单位；单位自动接近并攻击守方建筑，玩家不能指定目标、卖兵或撤兵。单位实例与召唤它的牌是不同对象，同一张卡洗回后可再次召唤。原案修订 5989 L161–209、L213–229。[Project_B 原案](https://my.feishu.cn/wiki/AIEkwlgbqiha8dkcxXSc0oH9nae) · [需求 07](../../游戏设计/功能需求/07-出牌与费用.md) · [需求 09](../../游戏设计/功能需求/09-玩家单位.md)
- 单位表以单位定义与星级为双键，含最大生命、攻击、两类防御、速度、攻击与索敌范围、存在时间、被索敌权重。存在时间 0 表示无时间限制；HP 归零阵亡，回合结束统一回收且不触发死亡逻辑。提前结束由编排结合不能再出牌与存活非建筑单位判断。原案 L205–221、L505–507。[需求 03](../../游戏设计/功能需求/03-回合准备与终止.md)
- 索敌要求兼顾距离和权重、外到内逐层推进。原案将《部落冲突》《皇室战争》列为参考，权重用表配置。围栏固定，普通单位在外部署，个别单位可在内，地形决定能否站立和部署。抵抗塔扩大碰撞体阻挡单位。原案 L195、L217、L236、L254–266、L545–549。[需求 04](../../游戏设计/功能需求/04-战场地形与部署范围.md) · [需求 11](../../游戏设计/功能需求/11-英雄核心.md)
- 距离和权重的比较顺序、目标切换、围栏内例外的穿层权限、阻挡与友军碰撞、寿命到期与死亡的关系以及攻击时序仍待定。「召唤出来的单位不会影响其他单位」需与技能、地形和状态表对齐。首期评审用不阻挡友军的配置，外部单位增减益由效果系统应用，单位间的协同能力逐条按效果定义确认。原案 L215、L374–405、L523–525。[需求 27](../../游戏设计/功能需求/27-增益、减益与持续范围.md) · [需求 39](../../游戏设计/功能需求/39-伤害与攻击结算.md)

## 状态与值接口

| 内容 | 拟定职责 |
| --- | --- |
| `UnitSpawnSpec` 和 `UnitSpawned` | 由编排从合法 `BattleCommand(BattleId, TargetTick, InputSequence, Payload)` 解出。载荷是命令身份、召唤序号、单位定义、星级、阵营、部署位置和实例初始效果来源。单位返回已创建 `BattleEntityId`、代际与出生 Tick。出牌卡牌、费用及地图合法性由各所有者预检，编排负责联合提交。 |
| 单位实体 | 单位拥有身份与代际、基础属性键、当前生命、当前/上一逻辑位置、目标 ID 与代际、行进状态、阻挡版本与可选配置路点游标、动作序号、攻击冷却与寿命到期 Tick。多个召唤使用稳定的命令序号、单位召唤序号分配 ID。 |
| `UnitTargetSnapshot` 和地形投影 | 战斗编排提供带世界 ID、Tick、占位/屏障版本的值，包括可索敌建筑的优先层级、保护与资格、固定点位置和盒、静态阻挡及格可通行性。单位按自身属性产生目标选择、移动与攻击请求，只在核准的数据内查询。 |
| `AttackRequest`、`ResolvedHit` | 单位发攻击定义、来源、目标或范围、攻击段、动作身份、Tick。编排按稳定行动顺序分配全场唯一攻击实例 ID、固定几何和防御快照，使用 `HitResolver`；单位只消费本模块目标的有序 `ResolvedHit(BattleId, Tick, HitOrdinal, …)` 和最终生命。 |
| 单位退出事实 | `UnitExit` 携 `BattleId, BattleEntityId, Generation, Tick, Reason, CauseId`；按原因区分 `Killed`、`Expired` 与 `Reclaimed`。只在生命从正数到零时产生一次阵亡。效果所有者消费单位退出回收效果，编排消费存活非建筑单位数与阵亡事实。 |

选择出生点建议以指令位置为锚点，按配置声明的固定候选偏移为多单位分配子序号，整批验证能否部署、绑定合法这一帧的阶段与数量。允许的拥挤策略和找位半径待策划确认。若配置要求全部召唤，候选不足则整张牌命令失败且资源不扣。读卡牌时只取本次召唤需要的值，牌进弃牌区以后本单位保持该次召唤生成的独立实例。围栏内部署例外只改变出生限制，首期评审仍服从同一索敌保护。

Entitas 采用正式拟定的 `Battle` Context。缓存单位、单位行动、待退出等 Group，使用生成的 `BattleMatcher` 及 `ReplaceX` 提交变化，逐笔指令、攻击与退出用有序缓冲。组件保存可重建的值或内部索引；跨模块由编排传递稳定 ID 和值，表现持有动画组件与资源。每回合新建系统树、Context 和结果缓冲；所有场上单位在收尾离开。持久局内属性和牌组交接值数据。工具接入按帧方案替换 Demo 的 Jenny 输入/输出，确认独占生成目录、程序集和所需类型。 [项目 Entitas 规范](../../../.agents/skills/entitas-dev/SKILL.md) · [Entitas 1.14.1](https://github.com/sschmid/Entitas/releases/tag/1.14.1) · [帧驱动设计 §3–6](../Project_B-帧驱动框架设计方案.md)

## 帧阶段、索敌与移动

| 阶段 | 单位处理 |
| --- | --- |
| 入帧 → 指令提交 | 封存指令与到期清单，先撤销到期单位的行动、索敌及受击资格，再接收核准的召唤批。初版提案中有限寿命靠 `[SpawnTick, ExpiryTick)` 表达，寿命 0 使用无到期值，合法出生可在同 Tick 参与后续步骤。 |
| 效果与属性 | 按编排给定的位置与地形取样，读取已确定的有效移速、攻击距离、抵抗、减益和行动资格。效果的应用时机若由命中或跨格产生，派生变化建议在下一 Tick 的效果阶段生效。 |
| 行动与命中 | 单位先从允许的屏障前沿确定目标，再推进移动；战斗取移动后位置和阶段的最终防御投影，收集攻击请求并统一处理。 |
| 结算 | 对一次最终生命写入判断阵亡，生成值事件。所有者不重复应用每个命中，阵亡后从行动计数排除。编排依据最终批次的核心、时间、出牌与非建筑单位数判断终止。 |
| 收尾 | 回合结束时对仍在场单位产生回收事实。解除效果边、释放缓存与表现绑定，等同一步消费者读完再统一 Cleanup。 |

战斗提供每个可达方向上允许索敌的最外存活层；索敌与伤害权限共享屏障规则，进入围栏的例外仍按该规则处理。过滤条件包括敌对、可作为攻击目标、位于索敌范围且满足层级限制；距离在发射阶段另按实际攻击范围复验。首期比较 `权重降序 → 与目标受击盒距离平方升序 → BattleEntityId 升序`。一旦锁定，保持至目标无效、出允许范围、屏障版本变化或行为规则要求重评，避免在等权邻塔之间抖动。距离使用战斗共用定点几何。附近没有合法目标时，建议向地图定义的进攻入口前沿趋近，按固定扫描节奏重查。按地图配置排除明确禁用的站位。被阻挡或拥挤时等待或按固定扫描节奏重新评估合法候选，不跨层追敌。

移动直接通过用户提供的 RVO2 工程运行。战斗选择目标外侧的接敌点或配置入口，根据当步位置计算 `prefVelocity`。抵抗塔的大阻挡体进入动态障碍投影，一场一个 `ORCABundle<Agent>` 统一求解，完成后把坐标量化写回 Entitas。单位半径和速度由配置提供，进入射程或受控制时按玩法决定站定或让步。代码见 [RVO2 移动接入](19-寻路模块实现代码.md)。

```text
CollectUnitAction(tick, targets, terrain)
    按 BattleEntityId 枚举活着且可行动的单位
    复核当前锁定身份、作用层级、范围和通路版本
    如需重选，从允许的层级按权重、距离和 ID 枚举
    将接敌点或入口转成移动意图 → RVO2 固定步 → 写回量化位置
    在移动后的位置复核发射条件与冷却
    生成攻击意图，由编排封存攻击请求并返回发射确认
    已获发射确认时推进攻击序号和下次可用 Tick

CommitUnitLife(tick, approvedBatch)
    按稳定目标查找 BattleEntityId 与代际
    使用结算工作缓冲给出的最终生命替换组件
    首次从正生命变零时标记 Killed 并输出一笔退出事实
```

单位发射成功消耗冷却，命中失败不会反推已发射的冷却。攻击在某步收集后可与同 Tick 的敌塔攻击互杀，后续跨 Tick 的飞行物、特殊效果和源失效规则属于统一战斗攻击实例生命周期。首期建议有明确的发射 Tick 与最小间隔，后续根据配置加前摇、攻击段和追踪策略。帧宿主只推进一份 `BattleTick`，移动、寿命、冷却和效果使用帧方案固定时间。角色技能减慢的是回合倒计时语义，是否同时影响单位行动需策划确认，慢计时不引入单位子循环。

## 失败处理

- 当前命令的世界、阶段、卡牌实例、配置、部署不满足时给出具体拒绝原因，联合提交前不扣费、不创建空壳。重复或陈旧召唤使用命令身份去重。编排预留单位/候选/输出容量，超产品上限优先在入口拒绝；执行中出现配置数值越界、批次身份不匹配或部分写入故障时退出故障会话，不发布部分 Tick。
- 目标移除、抵抗塔复活、世界换回合会使旧引用失效。正常失效时清空目标、站位和相关配置路点游标，在下一合法扫描重选。跨模块持有的旧值在世界、ID、代际不匹配时拒绝。动画、贴图加载失败或回调迟到不改变出生、攻击、死亡和计分。
- 一次命中归零后，后续同目标伤害由工作生命缓冲裁决。回合回收、到期退出单列原因。单位寿命到期步先移除受击资格，同步命中不会把到期改记为击杀；回合时间截止仍按统一战斗终止口径执行完整 Tick。

## 执行步骤与验收

- [ ] **召唤、寿命与回收。** 连接单位和星级表、已核准的批量召唤、生命与资格，到期和回合结束路径。实现 `合法牌命令 → 预检全部出生点 → 创建实例` 与 `到期/回合终止 → 标记原因 → 收尾`。
- [ ] **屏障及稳定索敌。** 消费当前地图、建筑投影及方向/层级；实现 `合法屏障前沿 → 扫描/稳定优先级 → 锁定`，覆盖目标失效、围栏内例外和核心转为暴露。
- [ ] **RVO2 移动。** 支持接敌站位、抵抗塔动态障碍与回收；实现 `Goal/Stop → prefVelocity → RVO2 固定步 → 写回并复核`。
- [ ] **攻击与生命写回。** 用统一攻击请求、动作序号、冷却和阶段结果，接通受伤、阵亡、计数。实现 `攻击动作 → HitResolver → 目标所有者一次提交`。回放摘要包含量化位置、冷却与活动攻击。
- [ ] **表现与回放验收。** 接编排的一次值事实并按身份显示。对同状态和输入序列比较不同渲染帧率下的逐步状态摘要及结果，独立覆盖异常路径。

| 场景 | 预期 |
| --- | --- |
| 同一张牌洗回重打，多只单位同一步生成 | 合法提交相同输入得到稳定身份和出生结果，每个单位是独立实例；部署失败时费用、卡牌与单位不发生部分写入。 |
| 更近内层高权塔、外层两塔同权同距 | 先受层级限制，外层同分以稳定 ID 选择，固定输入顺序得到同一结果。 |
| 抵抗塔大阻挡体封路、外塔清除后开新通路 | 有配置入口时沿入口局部避让；封路时停滞或等待合法重选。障碍改变后下一步同步；攻击不得穿越保护层。 |
| 寿命为 0、单位到期步及回合回收 | 0 表示无到期，非零到达截止步前撤资格。回收仅产生对应退出事实，不触发阵亡逻辑。 |
| 伤害同时互杀、死亡后仍收到旧结果 | 同 Tick 合法发射可以互杀。零生命只产生一次阵亡，目标或世界身份不匹配的旧输入拒绝。 |
| 有存活玩家建筑但非建筑单位已清空 | 编排按「不能再出牌」及非建筑存活数计算提前结束，建筑存活不阻塞。 |
