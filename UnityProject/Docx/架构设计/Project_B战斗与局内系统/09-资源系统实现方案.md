# Project B 资源系统实现方案

2026-11-15 · 架构评审稿

## 策划依据与边界

当前 [Project_B 原件修订 5989](<D:/缓存/WorkBuddy/2026-11-13-23-19-02/Project_B.md>) 的 L103–121、L193–211、L268–280、L338–356、L407–429、L531–539 规定如下。

- 初始金币、费用和荣誉来自角色表。金币用于自购、付费刷新、拆除和购买经验，来源含评分、利息和喂养对手。原文「每一局评分给金币」与每回合逛商店的循环需要确认到账点。费用消耗、恢复、上限增长使用独立规则，准备时回满，剩余额度不结转。
- 荣誉是整局生存资源，按回合评级 F/E/D/C/B/A/S 对应 -10/-8/-6/-3/0/+2/+5，归零结局由战斗编排裁定，荣誉上限待定。
- 经验与等级是成长模块状态，角色特殊能量属于技能系统。资源模块承接两者使用金币/费用的输入与结果。资源 A–F 的局外奖励保留配置引用及局末奖励事实交接，待局外功能确定后对接持久化。法球是一次领取或发放机会，法球的生成、掉落生命周期和兑现归局内养成及战斗编排，若抽中某种货币，余额通过账本变更。

## 数据、入口与帧接入

| 状态 | 存续 | 写入 |
| --- | --- | --- |
| `Wallet(Gold, Honor, Revision)` | 局级，随选定角色初始化，跨回合和换层延续 | 资源系统 |
| `RoundBudget(RoundId, CurrentCost, MaxCost, Revision)` | 局级容器下的回合状态，从准备开始存活至该回合关闭 | 资源系统 |
| `ResourcePatch` | 从预检到同批提交 | 账本输入 `ResourceKind, Operation, Amount, Reason, ScopeId, OriginId, LineOrdinal`，金额及版本由权威配置和当前状态求得 |
| `ResourceChanged` | 提交后按序发布 | `FactId, Before, After, Requested, Applied, Reason`，区分请求恢复和实际恢复 |
| 来源额度与去重 | 本回合或整局 | 命中批次、评级表和购物请求由战斗赋稳定身份，Buff/技能负责效果触发限额，资源只登记结算行是否已消费 |

金额按策划计量用整数。利息率若为分数，公式使用整数比例和明确舍入，预检溢出。不用 `-amount` 混淆消费、惩罚、覆盖和上限变更。消费不足直接拒绝，荣誉惩罚下限为 0，费用恢复至多到 MaxCost。金币上限与各余额上限的处理写进规则配置，超出设计域视为异常规则，不能靠静默环绕。MaxCost 下降时先裁剪当前值，增加上限后是否同时增加剩余值由效果显式指定。准备阶段先编译本回合生效修正，再以 MaxCost 填满。

福利、状态效果和操作允许各模块单独编排。比如技能产出「恢复费用」值请求，资源提交其合法额度；角色能量用已提交实际花费累积，免费施放、失败或净退款不应被当成新的费用消费。双向交易需先决定「有前置售价」还是「只发奖励」，配置一笔扣款和一笔增款来表达前者。前置售价必须可从交易前的金币支付，奖励款不能隐式为同一交易融资。利息首期建议取进商店前的既有余额，按配置阶梯计算，本回合评分收入随后入账，首版不滚入本次利息基数。该顺序作为评审提案。

使用普通 C# 局级 Wallet 和受资源所有者独占的 RoundBudget，由 RunSession 持有其生命周期。BattleWorld 通过编排的资源端口读取费用快照和准备变更，若需要 Entitas 查询只投影值。命令只在 [战斗编排](00-战斗编排与集成方案.md) 的当前阶段提交。商店用 WindowId、Revision 和 RunCommandSequence，战斗用 BattleId、TargetTick、InputSequence；预算和限次记录使用 RoundId。Buff 来源的回合触发次数按来源与效果身份追踪，重复出牌和弃牌洗回不能重置同一实例的次数。

```text
PrepareResourceRows(work, orderedRows)
    for row in orderedRows
        validate kind, operation, amount, origin, bounds
        before = work.read(row.kind)
        after = policy.evaluate(before, row)
        if rejected: reject full command or settlement
        work.write(row.kind, after)
        add fact with before, after and actual delta
    return versioned patch + ordered facts

PrepareRoundResources(committedRoundResult)
    earn = knownGoldIncome(committedRoundResult.rating, configuredPayoutPoint)
    interest = interestPolicy(goldBeforeCurrentIncome)
    prepare honor adjustment + eligible income rows with RoundResultId
    commit with combat session and growth settlement
    return HonorAfter to combat session for outcome policy
```

出牌扣费只有在卡牌、合法位置/目标与当下会产生的载荷都可准备后提交。金币购买经验在成长准备完成后同批扣费。对同一命令产生多笔同品种变化必须按笔共用工作余额。重复奖励身份在提交时固定，普通业务拒绝不写账、不给角色技能能量、不会产生表现成功。异常中途写入隔离故障会话，规则同 [战斗编排](00-战斗编排与集成方案.md)。

## 分步实施与验收

- [ ] **余额及账本。** 实现角色初值、余额边界、消费/收入/惩罚和有序结果。流程为 `请求 → 工作余额 → 提交 → 值通知`。
- [ ] **费用与战斗。** 按准备生效配置回满，接出牌、主动技能与恢复请求。流程为 `请求 → 同批预检 → 实际费用事件 → 技能能量输入`。
- [ ] **回合与商店。** 用战斗提供的评级和配置推导荣誉及入账，接进店、刷新、交易、拆除、购买经验。流程为 `RoundResultId → 收入/利息/荣誉补丁 → 商店报价`。
- [ ] **局末交接。** 输出稳定结算身份和来源明细，将局内账户回收。局外账户和保存由后续需求确认。

| 输入 | 预期 |
| --- | --- |
| 余额 5，按序两笔 4 的交易 | 第一笔成功，第二笔拒绝。各次余额、顺序和 UI 与事实一致。 |
| 敌方购买售价 8、奖励 10，余额 7 | 配置为先付后奖时拒绝，敌方物品和玩家金币均未变。 |
| 上限 12，费用 11，收到恢复 4 | 实际入账 1，下一回合按该回合上限回满。 |
| 荣誉 6 评 E，同 Tick 核心破损 | 账本输出荣誉为 0；战斗同时收到核心与荣誉事实，根据已确认优先级交付唯一局结果。 |
| 两次消费同一回合评分、同一命中派生或同一店面交易 | 账本不重复增减。合法的新标识可再次使用。 |
