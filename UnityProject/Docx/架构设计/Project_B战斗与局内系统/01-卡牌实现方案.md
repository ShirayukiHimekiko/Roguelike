# Project B 卡牌实现方案

设计提案 · 2026-11-15。需求依据为 2026-11-15 导出的 [《Project_B》修订 5989](https://my.feishu.cn/wiki/AIEkwlgbqiha8dkcxXSc0oH9nae) L55–121、L161–230、L487–497、L531–539。编号为本次导出稿行号。仓库 [牌组与卡牌区域](../../游戏设计/功能需求/05-牌组与卡牌区域.md)、[局内卡组合成、升级与删牌](../../游戏设计/功能需求/22-局内卡组合成、升级与删牌.md)、[卡牌羁绊](../../游戏设计/功能需求/23-卡牌羁绊.md) 供追溯。局内升级方式、羁绊口径及装备问答以本次导出稿为准。接口、字段及表名均为提案。

## 1. 规则与数据入口

| 原案规则 | 实现入口与待确认项 |
| --- | --- |
| 开局使用角色初始牌组。开战洗牌，默认起手 5 张，手牌上限 10。科技可提升起手数。牌库顺序隐藏。 | `DeckEntry(DefinitionId, BaseStar, Count)` 支持同名同星多副本。`OpeningHandSize`、`HandLimit`、`DrawInterval` 由本局配置和所属效果给出。起手牌不足时抽尽现有牌，起手目标受手牌上限约束为提案。 |

| 单位牌按数量召唤且单位继续行动。建筑牌部署有存续时间且不移动/攻击的建筑。技能牌可施加增减益或直接攻击，强化卡强化玩家。 | `(DefinitionId, Star)` 映射费用、目标规则、显式行为数据或效果 ID、召唤数量和建筑寿命。持续范围按效果表编码，强化卡的“一整轮”需确认具体边界。 |
| 同名同星两张合成一张更高星卡。升级物品、海克斯及任务可直接升级。卡牌、羁绊可临时升级指定牌，回合结束恢复。 | `MergeRule` 和 `UpgradeRule` 给出星级路径、资格及目标。永久基准星与本回合覆盖分字段。正式星级上限、局外解锁、删牌最低数量、批量升级失败政策待确认。 |
| 羁绊按当前牌组的不同卡牌 ID 计种数，重复卡或星级变化不额外计数。取最高满足档位。 | 用稳定 `DefinitionId` 作原案卡牌 ID 的归组键。影响何时重算、同羁绊重复授予规则、效果叠加及牌组变动触发点可配。首期提案在战斗开始前锁定羁绊档位，下一回合新增或永久移除生效时同步重算，当前手中或场上的区域变化不触发重算。 |
| 一张卡最多一件装备。仅该卡受益，由它召唤的所有单位应带同样的装备来源。合卡一件继承，两件都返还。 | 背包拥有 `EquipmentAssignment(CardInstanceId, ItemInstanceId)`。开战时编排传装备快照，回合内卡牌、单位、效果系统共享同一来源 ID 的值描述。删牌、消耗牌移除后的装备去向待确认，提案事务性返还。 |

L103–121 的费用上限来源可包含等级、物品、海克斯、羁绊及任务。费用回复可能按触发概率或次数受限。资源模块只写余额。编排把卡牌、装备等产生的回复意图交给效果域判定触发，携带来源实例、效果 ID、回合身份以及所需次数上限。提案中同一张卡被洗回再打出时沿用实例 ID，不能重置每回合单次计数。战斗末判定“可继续出牌”同时考虑同 Tick 已确定的资源与效果结果。

L537 的补时读取开始本回合时纳入抽取的牌组份数，数量由卡牌回传。补时的数值和应用由战斗编排处理。初始牌组应确认重复牌表示，L493 的字典可作设计键说明，实例表必须表达每种牌的份数。

## 3. 数据所有权与值合同

- `RunSession` 内的卡牌域唯一改本局普通牌实例、基准星和永久移除记录。例 `RunCard(CardInstanceId, DefinitionId, BaseStar, EligibleFromRound)`。实例 ID 本局唯一，局外模板和下一局独立。羁绊档位是在指定重算点按本局牌组衍生的快照。
- 每回合的 `BattleWorld` 卡牌所有者唯一改 `Draw/Hand/Discard/Removed`、处理中状态 `Playing`、`TemporaryStar`、下次抽牌时间和可出牌起始 Tick。世界启动时用不可变牌组清单、防重身份和装备值投影开局。每个参与实例只有一个归属；临时牌单独分配本局唯一 ID，禁止落入普通牌组。攻击期间普通奖励登记进本局牌组并标记 `EligibleFromRound = RoundNo + 1`，当前战斗牌区保持原抽取清单。消耗牌结算入移除区时同次事务写普通实例的永久移除记录，编排据移除事实处理装备。普通牌留在牌组时无须复制或合并两份实例。收尾输出归并清单，临时覆盖作废，释放世界。
- 背包法定装备归属由装备实例和卡牌实例关联确定。出牌请求读取编排下发的值快照，可生成 `SpawnUnitSpec`、`AttackSpec`、`EffectSpec`，附 `CardInstanceId`、`PlayId`、`ItemInstanceId` 等来源。格位合法性、生成单位、效果和命中各由自己的所有者写入。技能直伤进入同一 HitResolver 请求链，建筑和单位牌按配置指定目标/出生点，卡牌域只检查手牌、星级、有效配置和局内牌操作资格。
- `PlayCard(CardInstanceId, PlacementOrTargetValue)` 装入 `BattleCommand(BattleId, TargetTick, InputSequence, Payload)`。目标是稳定格位或 `BattleEntityId`。携带的局部瞄准量使用已量化固定点，费用从当前有效星级、规则及效果值重新算。编排消费 `CardPlayIntent(CardId, QuotedCost, ToZone, EffectSpecs, SpawnSpecs, AttackSpecs)` 并路由。`CardPlayed(PlayId, CardId, Cost, ToZone, SpawnedIds)`、`CardDrawn`、`CardsRetired`、`CardRejected(Reason)` 由批次交到表现或业务消费方。手牌快照可展示费用和倒计时，仅提供牌库/弃牌可见计数以及已授权的牌面信息。
- `AddCard`、`RemoveCard`、`MergeCards`、`UpgradeCard` 使用值入参，授权窗提交用 `(WindowId, Revision, RunCommandSequence)`；效果授予携带其来源唯一 ID。`PrepareDeckEdit` 输出版本与变动描述 `DeckEditPlan(Added, Removed, StarChanges, AssignmentChangesRequested)`，编排用 `Removed`、新卡 ID 向背包准备继承/返还结果。永久批量升星和 BackPack 购买消费走同一协调入口，合成默认生成新 ID，升星可保原 ID。临时覆盖走 `PrepareTemporaryUpgrade`，目标资格由效果产生的明确名单过滤，重复应用按效果叠加策略计算。

## 4. 关键流程

```text
初始化 BattleWorld(本轮牌组准入快照, 规则, 装备投影)
    以 CardInstanceId 升序收集可参与实例，用战斗牌组随机流 Fisher–Yates
    抽取 min(起手目标, 手牌上限, 可用数)，初始化抽牌到期 Tick

指令提交阶段：按 InputSequence 逐条处理已封存的出牌和技能命令
    把起始快照或先前成功提交后的状态用于 PreparePlay
    校验卡在手、其最早出牌 Tick、目标值和有效星级，返回费用和效果意图
    编排准备用费、出生或攻击请求、效果，以及结算时永久消耗的必要计划
    所有者均能提交则原子扣费、移卡 Hand → Playing、写入后续载荷
    请求失败则丢弃计划。处于 Playing 的实例无法再次出牌、不占手牌槽

指令提交阶段末尾：处理到期及挂起的抽牌
    未到期、满手：结束本步抽牌；满手到期时保留待抽
    牌库空且弃牌区非空：转移弃牌并在同一提交中重新洗牌
    两区皆空：保留待抽，不消耗随机状态
    抽到一张：移入手牌，PlayFromTick = 当前 Tick + 1
    仅抽到后设置 DrawDueTick = 当前 Tick + 正数间隔刻度

结算阶段：按 PlayId 提交本 Tick 已结算牌的去向
    已获准的牌按规则 Playing → Discard / Removed，携带同次承诺的永久移除计划
    技能命中查询零合法命中按技能结算口径处理，不回滚已承诺的付费
    编排传入已结算的余额和后续行动可用性
    计算手中可消费牌的最低有效费用
    手牌未满且本回合还能抽取时，再纳入牌库以及可洗回的弃牌
    输出候选存在、可支付、等待可达回复及各自原因，供编排判断回合结束

回合收尾：全部消费者读完后归并
    编排提交结算后取尚存普通牌、已永久移除的普通牌、待下一回合的新增牌
    校核唯一 ID；收尾输出本局牌组摘要和新手牌投影视图
    回收临时牌和覆盖星级，到下一回合开战由新 World 洗牌
```

原案 L178 要求先结算效果再进弃牌。`Playing` 区预留会立即空出手牌槽，指令阶段尾抽牌只能洗此前已落入弃牌区的牌。若当前只有刚打出的唯一普通牌，结算后它进入弃牌区，下一 Tick 的待抽才可洗回。首期接同 Tick 结算的卡。未来定时或延迟卡由 `PlayDestinationTiming` 明确授权即结算或者等实际效果完成才转区。后者在等待期间仍保留 `Playing`，并需要定义回合终止时的去向和效果取消规则。

原案 L189 在回合末还写了归并后洗匀，开战又明确洗牌。提案只在新 World 洗入抽取顺序，商店以 CardInstanceId 或指定 UI 排序展示。若策划要保留收尾随机化，用独立来源和稳定快照实现。`CanStillAfford` 报告原案的费用必要条件，空候选与全部超价明确区分。费用可由技能或待触发效果恢复、满手但有途径释放卡、付得起却没有合法部署点等需要策划确认。首期提案在已知延迟回复或条件未定时维持回合，超时兜底。

| 失败或竞态 | 行为 |
| --- | --- |
| 过期世界/窗口、重放指令、两次点同一张牌、同 Tick 第二笔不够费用 | 校验身份及受理顺序。成功的第一笔完成后，第二笔读取新权威状态；重复的指令返回既有结果。 |
| 卡费用够但目标无效、召唤无合法位置、无升星表行、装配或返还失败 | 编排丢弃全部准备计划，余额、手牌、装备和随机状态保持。多单位部署失败的口径由召唤规则明确，未配置时整笔拒绝。 |
| 牌堆都空、满手时等待、同 Tick 打出一张腾出位置 | 挂起抽牌到同阶段尾；应抽一张时最多补一张，不补积压周期。只在实际成功抽牌时重启计时。 |
| 退局、重开、打出时临时消耗牌、商店删卡 | 临时牌移除仅属当回合。普通消耗卡的永久移除、商店删牌及合成都由卡牌所有者确认。世界和本局结束时各清理所属状态。 |

## 5. Entitas 与 TEngine 接入

[项目现行帧方案](../Project_B-帧驱动框架设计方案.md) 的指令消费先于到期抽牌。公共阶段为入帧 → 指令提交 → 效果与属性 → 行动与命中 → 结算 → 收尾。准备、商店与回合收尾的局状态按 Run 指令顺序推进，攻击期才推进 `BattleTick`；世界终帧或离局冻结输入。帧外组装器先以 Luban 固化且核对所有表引用，TEngine UI 只提交命令、订阅提交后快照，图标异步加载归界面生命周期。

卡牌热路径可用领域私有的有序 ID 容器和实例数组，挂在新 `BattleContext` 的系统装配上，由单一提交系统写入。单位由其系统以 Entitas 1.14.1 的 `IExecuteSystem`、Matcher Group 和生成 API 管理。卡牌若有 ECS 组件消费需求，由 Jenny 生成 `[Battle]` 或 `[Context("Battle")]` 相关 API 并用 `ReplaceX` 等提交。索引和通知型字段禁止直接改挂载集合。卡牌区顺序、同 Tick 指令和逐笔效果保留显式顺序，`ReactiveSystem` 仅用于提交后反映状态变化。`creationIndex`、字典枚举、Unity Transform/时间与渲染帧均不作业务顺序依据。现有项目有 1.14.1 插件，Demo 业务和生成物在当前工作树已移除；落地前按本仓 `entitas-dev` 核目标程序集、Jenny provider/生成目录和正式 Context。[Entitas 1.14.1](https://github.com/sschmid/Entitas/releases/tag/1.14.1)

每笔 `Prepare` 仅读权威状态，在事务私有工作视图合并同所有者的值变动。提交前配置完整、容量可用、所需 ID 和落点均已确定。编排在同一同步边界提交全组所有者，再加入 `BattleTickBatch` 或窗结果。提交区间隔绝回调、同步 UI 事件和可恢复异常；拒绝发生在准备阶段。

## 6. 分步实施与验收

- [ ] 落地实例、牌表编译、牌组与区域，防止同一牌同时存在两个区域。伪代码 `for row sorted: AllocateCopies(row.Count); Move(id, from, to)`。验收两张同名同星有不同实例 ID，初始模板不随牌组改变。
- [ ] 接开战起手、满手待抽、弃牌回流和隐藏视图，保持实时循环独立于表现。伪代码见 §4 `初始化` 和 `指令提交阶段末尾`。验收满手停 0，成功出牌同 Tick 可抽此前已在牌库或可洗的弃牌，新抽牌下一 Tick 才可消费；刚打出的唯一普通牌在结算入弃牌后下一 Tick 可洗回，双空保持，种子重放顺序一致。
- [ ] 接出牌费用、部署/效果/命中事务和可用性结果。伪代码见 §4 `指令提交阶段` 和 `结算阶段`。验收费用合法但目标拒绝仍保留手牌；单次支付出三单位，装备应用到三者；低费牌仅在可回流弃牌时能改变终止判定。
- [ ] 接四类牌、永久移除、临时卡和持续范围。伪代码 `ToZone = ResolveDestination(Origin, Keyword); StagePermanentRemovalIfNeeded()`。验收普通牌可重抽，消耗牌不进后续回合，临时牌及覆盖星不跨回合，普通新牌不插入当前牌库。
- [ ] 接商店改牌、指定升级、最高档羁绊和装备联动。伪代码 `PlanMerge/PlanUpgrade -> PrepareEquipmentChanges -> CommitAll -> BuildTraitProjection()`。验收合成净减一、单装备继承、双装备全返还、删牌/返还失败保持原牌组，重复同名不提高羁绊计数。
- [ ] 接回合收尾、停用重开、稳定摘要与界面。伪代码 `FinalizeRetiredCards(BattleId); DisposeWorld(); SnapshotDeck(Revision)`。验收回合末所有本局正牌仍与 ID 一一对应，重开拒绝旧命令，UI 关闭与资源延迟完成不写玩法状态。

本稿记录实现和验收条件，待策划确认表值与边界后逐项授权实施。
