## 3. 所有权、数据与接口草图

Buff 独占作用域、实例、来源和叠加状态，按目标导出有序 `ModifierDelta`。单位、建筑拥有基础/有效属性与生命，资源拥有费用，牌组拥有星级和区域，背包拥有装备及绑定，局内养成拥有羁绊，双向选择拥有海克斯的授予记录。战斗编排是上述各域产出的唯一跨域消费者，由它组装值快照、传递请求和安排生效顺序。Buff 与技能、卡牌、单位、建筑内部系统各自只读写自身数据。 [帧驱动方案](../Project_B-帧驱动框架设计方案.md) · [技能实现方案](07-技能实现方案.md)

| 拟议类型 | 字段、身份及生命周期 |
| --- | --- |
| `BuffDefinition` | `BuffDefId`、合法目标类别、作用域、可选持续 Tick、叠加组和策略、上限、效果序列、可选 `Strength` 比较口径。由 Luban 内容编译时检查引用与数值。 |
| `BuffRequest` | 场次或准备窗口身份、因果序号、操作、`SourceKey`、`TargetKey`、`BuffDefId`、定点值载荷。`SourceKey` 含来源类型与来源实例稳定 ID，区分同种物品实例、光环塔实例及卡牌实例。 |
| `BuffContribution` | `BuffInstanceId`、请求身份、施加 Tick、可选 `ExpireTick`、来源、目标、叠加组、效果载荷和脉冲游标。按目标建立索引，按来源撤销贡献，编排从值批次取得变更。 |
| `BuffTriggerState` | 回合窗身份、来源实例键、效果条目、有效触发次数、最近已消费因果键。持续 Buff 负责其触发状态，卡牌/装备提交直接触发的恢复由编排交给该效果所有者使用相同身份约定。 |
| `ModifierDelta` | 目标键、修正项身份、字段、操作、数值及撤销标记。所有者基于基础属性和现有修正集合计算结果。 |
| `RunBuffSeed` | `RunId`、稳定来源键、匹配条件、Buff 定义和可复用载荷。附着某座敌方建筑时以稳定建筑实例 ID 和关卡实例关联，整类规则可在合法新目标出现时重新匹配。由 RunSession 按所有者保存可延续数据，下一场映射成当场身份。需要延续独立层数或有时限的常驻效果时另定层数与时限结转规则，首期配置拒绝「常驻且有限战斗时长」组合。 |

建议 Buff 先作为 `GameLogic` 的独立局部状态与系统组接入每回合 `BattleWorld`。需要 Entitas 查询时，在正式 `BattleContext` 中以 Buff 自有组件表达，禁止借实体引用穿透所有权。逐条输入用数组或请求实体，缓存 Group 只供本域维护活动集合。生成的写入方法维护索引和通知，对外输出值副本。正式组件与 Jenny 入口随帧框架确认。运行时插件已在仓库，Demo 业务源已清理，早期 Editor Demo 脚本仍存在。当前文档中的类型和签名均是提案。 [Entitas 1.14.1 项目规范](../../../.agents/skills/entitas-dev/SKILL.md) · [帧驱动方案 §3](../Project_B-帧驱动框架设计方案.md#3-模块所有权与工程接入)

## 4. 叠加、撤销与帧时序

默认按 `(TargetKey, StackGroupId)` 聚合。仅当策划选择按来源分组时，组键后加入来源身份。相同 `RequestId` 只消费一次。同种规则按数据明确适用规则，重复来自不同来源的实例保持可追溯。

| 策划规则 | 首期建议语义 |
| --- | --- |
| 叠层 | 接受至显式 `MaxStacks`。每层保留独立来源、数值和到期。到上限时当前申请失败且不刷新已有层。需要公用计时或满层刷新时增加明确配置。 |
| 刷新持续时间 | 同组有效一份固定载荷。每个申请保留来源和截止，组的截止取活跃贡献的最大值，同一来源同组只保留较晚截止。撤销最长来源后可回落。变化幅度的效果应使用另一叠加规则。 |
| 取最高 | 保留各来源的候选。按策划配置的可比 `Strength` 取优胜，平手用较早施加序和实例 ID。负向倍率和复合效果须显式定义强度。赢家消失后在所属阶段选次强，次强保有原截止。 |

修正值首期建议只支持定点平加及同字段百分比加成。由所有者计算 `clamp((Base + SumFlat) × (1 + SumRate))`，后续可按真实词条增加覆盖、独立乘区或字段约束。上限变化后，当前费用或生命由所有者按自身规则截断、回满或保持比例。首期建议平常属性刷新只截断超限值，初始/准备回满走独立命令。字段组合、限值和舍入在配置快照中冻结。 [帧驱动方案 §5](../Project_B-帧驱动框架设计方案.md#5-定点数与几何)

| 阶段 | Buff 的读写与编排责任 |
| --- | --- |
| 入帧 | 检查 `[StartTick, ExpireTick)`，`ExpireTick` 步先撤掉已失效的贡献。同步会影响本步指令合法性的属性和费用上限，再处理当步指令。 |
| 指令提交 → 效果与属性 | 验证和提交有序指令。编排器交付新来源和当步可用的覆盖快照。Buff 输出修正，编排按域发给所有者。此阶段产生的合法即时修正供当步行动和命中快照读取。首期出牌费用按指令提交时可见的已提交修正计算。命中以下阶段产生的持久效果在下一 Tick 首次参加属性生效。 |
| 行动与命中 → 结算 | 持续伤害是有编号的脉冲意图，进入共同的 `AttackRequest → HitCandidate → ResolvedHit`。按期脉冲可参与本步，命中派生的攻击在下一 Tick 进入。伤害、计分和技能能量采用结算事实。周期等于持续截止时默认无脉冲，显式需要终止前一次派发的效果可使用所属模块声明的结算时点。 |
| 收尾 | 已死亡、破损或回收对象按场次事实撤消当场作用对象。光环源失效后，从下一 Tick 的属性快照中消失。回合结束关闭输入，清理临时效果、记录和工作缓冲，通过值交接常驻来源后释放 World。 |

准备、商店以及换层通过局流程的有序事件处理。准备窗口按「提交授予/撤销 → 重新评估对应修正 → 由所有者计算回复或上限」排序。各场内 `BattleTick` 只在该回合战斗期间推进，全局回合号随 RunSession 跨场保留。切层或换房间强制释放当场目标、光环覆盖和周期记录，明示跨场的常驻来源通过局内种子重新匹配。已离开的建筑或单位不会用旧 `BattleEntityId` 恢复。回合结束回收原因独立于死亡原因。 [回合准备与终止](../../游戏设计/功能需求/03-回合准备与终止.md)

```text
在入帧或效果与属性阶段处理 Buff 批次
    收集到期、来源撤销、覆盖退出和新施加请求
    按阶段、因果序号、请求内效果序号排序
    按 TargetKey 和内容表确认资格，应用叠加规则，记受影响组
    对每个脏组按稳定键重算有效贡献，产出修正差量和到期事实
    编排器送修正差量给属性所有者，所有者同步该阶段有效值
    对到期且仍有效的脉冲按 (DueTick, BuffInstanceId, PulseIndex) 编号发意图

更新光环覆盖
    编排器从建筑和地图取得阵营、格位、活跃身份的值快照
    根据光环 Definition 算邻格，按目标 ID 排序，和上次成员做差集
    仅对进出或源失效送增删请求；回合部署完成后重新构建
```

首期为光环成员采用部署、占位或源活跃变化后的局部重建。移动对象的地形按已提交位置确定，移动进入新格后的效果在下一 Tick 生效。准备阶段塔回血的物品修正走同一值接口，避免由 Buff 代写塔生命。逐笔状态变更保留请求身份，表现通知用已提交快照。 [TEngine 事件规范](../../../.agents/skills/tengine-dev/references/event-system.md) · [Entitas 调度与生命周期](../../../.agents/skills/entitas-dev/references/systems-and-lifecycle.md)

费用恢复按 `(RoundId, SourceInstanceKey, EffectOrdinal)` 统计回合额度。卡牌效果键包含 `CardInstanceId`，装备效果用 `CardInstanceId` 与 `EquipmentInstanceId`，避免洗回或重复召唤重置同一条额度。物品单次以持有实例还是定义为准需策划确认。羁绊和海克斯从已配置上限判定剩余机会。先过滤重复事实、失效来源、目标与回合次数，再按稳定顺序调用独立随机流。成功规则产生带身份的恢复意图，资源系统产出实际到账额；满费是否计一次及概率失败是否计额度按明确配置处理。战斗结束预判所需的恢复时点、剩余次数和条件由编排从对应所有者取得。 [出牌与费用](../../游戏设计/功能需求/07-出牌与费用.md) · [资源系统](09-资源系统实现方案.md)

## 5. 失败与接入计划

- 阶段过期或目标不在当场，拒绝对应请求并保留原因，已提交的上游交易或技能按其失败规则处理。相同请求身份带不同载荷视为生产方错误。
- 开战前校验 Buff 引用、目标类别、叠加参数、修正字段和有限时长。应用与脉冲缓冲在提交前确认容量。超出数值域或批次空间时按帧框架关闭故障会话，暂不发布这一步的局内结果。
- [ ] **定义与持久边界**：编译定义及 `RunBuffSeed`。输入 `计划表 → 完整值快照 → 出战种子`。覆盖三类目标、离局清理、另存来源身份。
- [ ] **叠加、刷新、过期**：接稳定请求队列及目标/来源索引。输入 `施加/撤销批次 → 叠加组 → 修正差量`。覆盖重复请求、持续结束和最高候选回落。
- [ ] **跨域消费**：编排器接属性、费用、光环、装备初始化以及技能和伤害契约。输入 `装备卡提交 → 三个单位种子 → 三个本地贡献`，输入 `光环死亡事实 → N+1 撤销`。覆盖玩家、单位和建筑各一个内容样本。
- [ ] **窗口及边界**：接准备效果、回合结束和换层。输入 `EndBattle → 导出允许的常驻来源 → Dispose → 新 BattleWorld`。覆盖临时效果、本场身份、场次结果和常驻效果重建。

验收按同一初态与有序命令重跑，对比组赢家、有效属性、脉冲和结算事实。三层相同 Buff 达上限后第四层被拒，最高先撤时次高仍生效且按原截止结束，刷新只剩短来源时截止回落。一次装备派生三个单位，各 `+10`，同卡重新洗到时原单位没有重复增益。玩家与建筑常驻来源可在下一回合重新绑定，回收单位和换层光环无旧场次残留。按策划确认的满费口径，检查满费时回复到账为 0、触发次数是否增加。相同的有效概率机会序列应得到相同判定和随机游标，重复或在预检阶段拒绝的请求不得多消费取样。确定性重跑、Unity 集成与性能验收留待实现授权后进行。
