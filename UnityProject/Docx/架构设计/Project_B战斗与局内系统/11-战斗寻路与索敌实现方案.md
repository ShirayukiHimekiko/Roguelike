# Project B RVO2 移动与索敌实现方案

2026-11-15 · 修订稿。移动采用用户提供的 Nebukam Unity RVO2 源码，复用该实现已有的单位、障碍和速度求解。业务负责确定向哪里移动、何时站定以及能否攻击。

## 1. 模块选择

| 职责 | 实施方式 |
| --- | --- |
| 移动与局部避障 | 单场用一个 `ORCABundle<Agent>`，把该场的单位与障碍投到 `AxisPair.XY`，每固定战斗 Tick 执行一次库的步进。 |
| 目的地与站位 | 战斗按攻击目标的受击几何、射程和保护决定接敌目标点。尚未锁定时用已有的进攻入口。灰盒若需要越过墙体，使用地图中明确配置的入口点序列。 |
| 索敌 | 使用自己的一份目标快照。先全扫，实测需要时切紧凑塔列表、移动格桶或四叉树。候选过滤和权重与 ORCA 邻居独立。 |
| 地图和障碍 | 地图负责部署资格、可站范围、阻挡形状与保护投影。永久地图轮廓进静态障碍；可拆、可部署或可复活建筑进动态障碍。占位表仍由战斗写入。 |

源目录提供 Common、JobAssist、ORCA。样例从目的地计算 `prefVelocity`，运行库后读 Agent 实际位置。取舍是直接调用这套库，关卡初版使用明确可接敌的地图。Nebukam 和 RVO2 的文档均将全局规划留给调用方，库内 KD-tree 服务邻居、障碍和射线查询。需要自动寻找任意地图的全局路线时，另确认可复用的现成全局路线来源。 [Nebukam 作者说明](https://github.com/Nebukam/com.nebukam.orca#high-level-concept) · [RVO2 官方全局规划说明](https://gamma-web.iacs.umd.edu/RVO2/documentation/2.0/whatsnew.html)

## 2. RVO2 接入

- 开场从出生/占位投影建立本场 Agent 与障碍。每步稳定采集位置、有效速度和目标点，先更新目标和停步条件，再调用 `orca.Run(1f / tickRate)`。原库完成 Job 并回填 Agent 结果。
- 命中范围内可按战斗行为站定，必要时可配置为允许让步。跨入保护方向后按实际位置重查攻击许可。停步和短时拥挤只用于行为展示和有界重选，不产生全局不可达结论。
- ECS 坐标采用原固定刻度，输入转换到 XY，库输出完成后量化一遍，由单位所有者用生成 API 写回。固定 Tick 和量化都保留。浮点/Burst 的逐 Tick 一致性先在同一约定 Player、平台和数据验证。
- 塔的部署足迹、受击形状和移动阻挡是独立投影。固定围栏默认是部署边界，只有配置成实体地形时生成 ORCA 障碍。抵抗塔的复活占位和存续阻挡单独遵循本局规则。 [地图与占位](../Project_B整游实现/17-地图地形与部署占位.md)

具体 API、导入与释放见 [RVO2 接入代码](19-寻路模块实现代码.md)。

## 3. 高性能索敌

| 候选组织 | 使用范围 |
| --- | --- |
| 独立全扫或紧凑塔列表 | 首期对全部合法敌塔、核心及单位作正确性基准。 |
| 移动单位格桶/四叉树 | 先按实机候选量、区域密度和构建成本测收益。索敌快照按对应阶段构建，记录 Job 等待及分配。 [索敌 Job 方案](12-四叉树JobSystem索敌实现方案.md) |
| ORCA 内部索引 | 由库做局部移动求解。邻居上限、碰撞层与索敌阵营、类型、射程和保护属于不同规则。 |

- 单位在 PreMove 选择固定塔/核心。塔使用移动结果写回后的 PostMove 快照选择单位；例如单位本步从距离 6 进入射程 5，必须进入塔的有效查询结果。
- 受击盒边界采用定点最短距离平方。若按目标锚点入桶，候选半径要包含最大受击盒外伸及锚点偏移，再对候选做精确判定。负坐标使用向下取整。
- 筛选阵营、存活、类型、索敌半径、当前部署/方向层和保护。建议以权重降序、距离平方升序、ActorId 升序排序。锁定用 BattleId、ActorId 和约定代际识别，失效后重选。沿用保护规则对实际接敌方向复核。
- 查询必须独立于 ORCA 的 `maxNeighbors`。当邻居表被友军占满时，处于索敌范围的合法目标仍应被找出。

## 4. 接线与验收

~~~text
命令/到期/有效属性 → 固定当步保护、占位及 PreMove 快照
→ 选敌和目的地 → RVO2 固定步 → 量化并提交位置
→ PostMove 塔选敌 → 按实际射程发射 → 命中、清理、提交
~~~

- [ ] **接入本地源码和移动。** 空场直达、相向避让、指定入口绕过墙体、动态塔换位和复活。
- [ ] **接入两阶段索敌。** 同权同距按稳定 ID，移动后新入射程对象参与选敌，旧战场身份拒绝。
- [ ] **验证宽度、阻挡和销毁。** 以实际 Agent 半径验可用通道，无入口的封闭墙验证局部停滞和超时，退场释放并可重开。
- [ ] **验证固定样本回放。** 同目标环境重放种子和命令，比较量化位置及战果，记录版本和性能数据。

可执行步骤见 [阶段 05–08](../Project_B整游实现/执行手册/03-寻路索敌与对打.md#s05) · [接线方案](13-索敌与寻路接入战斗模块方案.md)。
