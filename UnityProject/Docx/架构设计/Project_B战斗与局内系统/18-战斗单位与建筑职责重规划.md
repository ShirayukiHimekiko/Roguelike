# Project B 战斗单位与建筑职责重规划

2026-11-15 · 设计提案，待确认

## 设计决定

**战斗中统一为一种单位实体。** 策划上保留「移动单位」和「建筑」两个类别。移动、主动攻击、可被选中、场内阻挡分别按配置和当前状态生效。玩家建筑和敌塔都属于建筑。固定攻击塔具备开火能力，玩家建筑由建筑牌部署，按现有策划静止且无主动攻击。建筑成功落地时，在当前逻辑步同步登记配置给它的阻挡。本步的索敌和移动读取更新后的布局。建筑的分类来自定义，移动单位受定身时仍按移动单位的规则统计。

建筑专属规则仍由战斗内的建筑系统和局级敌塔部署流程维护。场内战斗单位共享 `BattleEntityId`、代际、生命与可交互状态。地图负责部署占位和寻路阻挡。这样可以统一战斗规则的入口，同时保留建筑各自的准备、回合承接和破损行为。[玩家建筑牌](../../游戏设计/功能需求/08-卡牌类型与效果.md) · [玩家单位](../../游戏设计/功能需求/09-玩家单位.md) · [敌方防御塔](../../游戏设计/功能需求/10-敌方防御塔.md) · [伤害结算需求](../../游戏设计/功能需求/39-伤害与攻击结算.md)

## 现状和取舍

现有 03、04 方案分别维护建筑与移动单位的生命、攻击状态和退出，用同一 `Battle` Context、命中接口和占位合同连接。保留两套战斗实体可以分别演进，但生命归零、攻击冷却、受击资格、Buff 和退出处理容易出现两个标准。把所有规则塞进一个单位系统，则会让寻路、破塔奖励、核心屏障、跨回合复活挤在同一个入口。推荐共享战斗实体与共用系统，把建筑专属规则留在明确的阶段系统里。现有设计文件内的暂定参数和评审默认值以设计依据处理，玩法歧义在本提案收口。[建筑 03](03-建筑实现方案.md) · [单位 04](04-单位实现方案.md) · [战斗编排 00](00-战斗编排与集成方案.md) · [模块组装 15](15-模块分类与战斗组装方案.md)

- OpenRA 的规则把 `Building`、`Health`、`Targetable` 组合在同一个 Actor 上。建筑足迹允许区分占位、通行和可选中格，加入或离开世界时更新地图登记。Project B 复用职责划分与登记时机，保留自己的固定 Tick、回合快照和伤害归因。[OpenRA 规则](https://github.com/OpenRA/OpenRA/blob/bleed/mods/ra/rules/defaults.yaml) · [Building.cs](https://github.com/OpenRA/OpenRA/blob/bleed/OpenRA.Mods.Common/Traits/Buildings/Building.cs#L20-L105) · [Health.cs](https://github.com/OpenRA/OpenRA/blob/bleed/OpenRA.Mods.Common/Traits/Health.cs#L117-L209)

## 职责和状态所有权

| 职责 | 权威状态与输入输出 |
| --- | --- |
| 战斗单位 | 同一 `Battle` Context 下按实体身份保存阵营、定义、位置和行动资格。具有生命的对象由公共生命提交系统唯一写场内 HP。生成、有效上限变化、受击和治疗通过统一写入通道。普通单位阵亡、建筑破损、寿命到期与回合回收使用各自的退出原因。 |
| 移动、索敌与攻击 | 移动系统只处理具备移动能力且当前可行动的实体。移动单位和固定攻击塔共用攻击意图、冷却推进和命中提交。沿现有普攻口径，玩家移动单位选合法敌塔与核心，敌塔及暴露后的核心选玩家移动单位。玩家建筑仅在攻击或技能显式授权时进入相应目标候选。各入口同时判断阵营、当前资格、范围和屏障。`HitResolver` 用命中快照和批内工作生命计算逐笔结果，生命提交系统负责实际写回。 |
| 建筑规则 | 根据建筑定义及生命归零事实，计算永久破损、抵抗塔待复活、核心击破和连带破损。提供足迹和占位变更请求。局级准备系统管理 `TowerInstanceId` 和跨回合快照，决定敌塔回复、复活与重新布防，并将结果作为下场战斗单位的初始化值。破塔积分、掉落及层结束由各消费者按原因处理。 |
| 战场地图与占位 | 准备阶段由部署域管理布局，开战后由 `BattleWorld` 的地图系统提交场内占位和阻挡。地图分别记录部署足迹、移动阻挡投影和复活预留，派生屏障前沿所需的数据。受击形状由战斗单位定义提供，核心专属规则读取已提交布局及其屏障投影。地图地形和纯地图障碍可直接贡献阻挡。 |
| 战斗与局级编排 | 统一预检费用、出牌、实体和占位，稳定顺序提交。同一逻辑阶段提交战斗资格与布局，再让查询和事件消费者读取。提前结束沿用「无可用牌且无存活玩家非建筑单位」的现有回合合同，额外读取已确认可救援的回费等条件。 |

同一建筑在场上只保留一份生命。抵抗塔的 `TowerInstanceId` 跨回合保持稳定，复活时递增代际。场内引用按 `BattleId + BattleEntityId + Generation` 校验，局级数据以值快照承接。配置可继续按单位表和塔表分别编辑，加载时由 Luban 映射成共用属性和专属配置。组件命名和 Jenny 接入沿用正式 `Battle` Context 与 Entitas 1.14.1 的既有设计。业务规则位于 `GameLogic` 热更侧，由一场战斗的系统树组装。[模块组装 15](15-模块分类与战斗组装方案.md) · [Entitas 项目规范](../../../.agents/skills/entitas-dev/SKILL.md) · [Luban 项目规范](../../../.agents/skills/tengine-dev/references/luban-config.md)

## 固定 Tick 的提交顺序

```text
入帧：处理到期退出，撤销对应资格和场内阻挡
部署：按命令序号预检费用、卡牌、完整足迹和阻挡几何
      在预检成功后提交实体与占位，推进布局版本，再对后续命令、移动发布
行动：冻结 PreMove 快照，移动单位索敌并调用 RVO2，完成后提交位置
      以 PostMove 快照为固定塔索敌，统一复验攻击资格、实际距离和冷却
命中：归集合法攻击和伤害意图，冻结命中快照并逐笔计算
收尾：预检生命、退出原因、占位及暴露差量，再在同一阶段联合提交
      计算回合终止，收集值事实后清理；本 Tick 提交后对外发布
```

放置失败保留原卡牌、费用和布局。首版提议将有效阻挡体与受其影响的现有单位站位冲突纳入部署预检，避免在单位脚下制造无法退出的位置。场内建筑的锚点取已提交放置值。敌塔准备阶段如果允许换位，由部署域先对完整终态校验，再提交新锚点与布局。通行或屏障投影变化时更新相应版本。旧版 Job 结果不得写回，下一步 RVO2 先同步障碍并用现行条件选择目标点。外塔在 N 步破损后，N 步已采集的合法攻击按原快照结算，N+1 使用更新后的屏障和移动阻挡。归零的那一笔只产生一次直接击破，核心连带破损单独归因，不追加伤害。抵抗塔复活预留在准备窗口先进入布局，AI 再为其他塔选位。表现读取外层时钟确认的值批，`RunSession` 读取最终 `BattleResult`。候选步已登记障碍但最终提交失败时，按现有故障步规则处理，外部不消费该步的出牌、布局或奖励事实。[战斗编排 00](00-战斗编排与集成方案.md) · [索敌与寻路接入 13](13-索敌与寻路接入战斗模块方案.md) · [伤害与破损 19](../Project_B整游实现/19-伤害公式与破损归因.md)

## 需确认的玩法口径

1. **阻挡对象。** 按本次需求，建筑落地即发布阻挡。首版建议所有建筑对适用的地面移动类别提供基础阻挡，抵抗塔有更大的阻挡范围。策划原文明确了抵抗塔阻挡，其他塔的阻挡范围、玩家建筑是否挡住己方地面单位，以及不同移动类别的适用性待确认。投射物遮挡由单独的命中规则控制。
2. 抵抗塔破损后，建议沿用整游评审稿的默认值，本回合退出屏障和移动阻挡，保留原位给下回合。在同方向仍有其他合格外塔、或路线依旧受地形阻挡时，核心仍受保护。若策划希望废墟继续挡路或继续封住该方向，分别调整阻挡和屏障配置。[抵抗塔需求](../../游戏设计/功能需求/10-敌方防御塔.md) · [原建筑方案](03-建筑实现方案.md) · [核心专项评审稿](../Project_B整游实现/18-英雄核心屏障与暴露.md)
3. **玩家建筑的交互。** 玩家建筑是否有可扣减的生命、是否可被普通攻击、直接伤害、技能或 Buff 影响，按各入口授权。建议首版对占到受阻单位站位的建筑部署直接拒绝，避免挤出和卡位。回合回收沿用现有口径，记为回收。寿命到期的专属效果待确认。[建筑牌](../../游戏设计/功能需求/08-卡牌类型与效果.md) · [场地需求](../../游戏设计/功能需求/04-战场地形与部署范围.md) · [回合准备与终止](../../游戏设计/功能需求/03-回合准备与终止.md)

## 确认后的设计同步顺序

- [ ] **先同步词汇和所有权。** 在程序策划案明确战斗单位总称、移动单位和建筑类别。将建筑 03 的场内生命与公共攻击职责并入单位 04，03 保留建筑专属规则。同步编排 00 和模块分类 15 的唯一写入方。
- [ ] **同步地图、命中和配置合同。** 明确部署成功同 Tick 发布、破损和预留分别投影、同一生命提交入口以及准备与开战交界。更新寻路索敌 11 和 13、整游实现 17–19 和受影响的实现代码草案。现有占位代码草案以 `Active` 开关移动阻挡，若允许废墟挡路，需要把阻挡生效从行动状态中独立出来。[战场地图与占位代码草案](../Project_B模块实现代码/17-战场地图与占位.md)
- [ ] **按场景复核设计。** 移动单位正常索敌、追击、受击和阵亡。玩家建筑落地改变当步动态障碍，非法放置保留费用和卡牌，故障步的障碍无外部可见结果。固定攻击塔能选中本步刚进入射程的移动单位。抵抗塔破损只生成一条直接破损事实，地图按确认口径撤销阻挡或保留废墟，下回合满血复活且旧引用失效。核心暴露与击破满足屏障和归因规则。活着但被定身的移动单位仍参与提前结束统计，仅玩家建筑存活时按现有条件可以提前结束，回收按回收事实处理。纯地图障碍持续参与寻路。
