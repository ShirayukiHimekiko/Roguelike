```csharp
// TargetSelector.cs。ActorSpan 来自阶段内冻结快照；本方法返回 0 表示无目标。
internal long Select(in ActorQuery query, ReadOnlySpan<TargetCandidate> actors)
{
    long bestId = 0;
    int bestWeight = int.MinValue;
    long bestDistance = long.MaxValue;
    foreach (ref readonly TargetCandidate candidate in actors)
    {
        if (!query.Allows(candidate)) continue;
        int weight = candidate.Weight;
        long distance = candidate.HitBox.DistanceSquared(query.Position);
        if (bestId == 0 || weight > bestWeight || (weight == bestWeight &&
            (distance < bestDistance || (distance == bestDistance && candidate.Id < bestId))))
        {
            bestWeight = weight;
            bestDistance = distance;
            bestId = candidate.Id;
        }
    }
    return bestId;
}
```

上面的写法假设已校验距离有限，排序字段不随迭代器变化。实现时距离用索敌 C# 的 `RawBox.DistanceSquared(RawPoint)` 实际签名，输入的坐标按 HitGeometry/地图的最严格原始范围校验。选中后只保存身份和版本，移动系统据目标位置变化刷新目的地，射击时用移动后的范围和防护再次检查。

**验收。** 两敌同权同距，输入数组调换顺序仍选较小 ActorId。近敌失效后改选其他合法目标；短时拥挤不会把近敌永久排除。友军、死亡、受保护核心与上一场 ID 不能入选。全无目标保持等待或使用已配置入口。

```csharp
// CombatDecisionSystem.TryQueueAttack。队列容量在本步写入前预检。
private void TryQueueAttack(long tick, BattleEntity source, in ActorState target)
{
    ActorState actor = source.actor.Value;
    if (tick < actor.NextAttackTick || !_range.CanAttack(in actor, in target)) return;

    long attackId = checked(++_lastAttackId);
    actor.NextAttackTick = checked(tick + actor.AttackIntervalTicks);
    _attacks.Add(new AttackRequest(attackId, 0, actor.Id, actor.Team,
        actor.AttackDefinitionId, actor.Power, target.Id, 0, default));
    source.ReplaceActor(actor);
}
```

给阶段 04 的 ActorState 增加 `AttackDefinitionId`，配置保证间隔至少 1。构造 snapshot 后调用 `Resolve(attacks, targets, ledger, rule)`，首个伤害规则口径用 `max(0, Power - Defense)`，如 [伤害专题](../19-伤害公式与破损归因.md) 所定。DamageCommit 按返回顺序更新工作血量表，核对同目标衔接的 HpBefore，再写回最终血量；Attack 与 Defeat/TimeOut 判定同 Tick 时先完成双方已发行请求。复制所需的统计和表现事件，按正式实现调用 HitLedger.Apply 关闭生命周期结束的段，避免无限保存已结束攻击。正式伤害归因用单独 cause/ordinal 字段驱动评分与掉落。

敌方部署的核心选格写法如下。`TryApplyPlacement` 以预检过的脚印和库存写草稿，`TryScore` 用草稿中的假放置评价最薄方向、覆盖、移动成本；至少比较一个合法配置。灰盒配置用唯一锚位，正式阶段传全候选集。

```csharp
// EnemyDeploymentPlanner：遍历稳定排序的库存和格位。
foreach (TowerSeed tower in inventory.OrderByStableTowerId())
{
    int chosen = -1;
    DefenseScore best = default;
    foreach (int slot in map.OpenSlotsById)
    {
        if (!draft.TryScore(tower, slot, out DefenseScore score)) continue;
        if (chosen >= 0 && score.CompareTo(best) <= 0) continue;
        chosen = slot;
        best = score;
    }
    if (chosen >= 0)
        draft.ApplyPlacement(tower, chosen);
}
// 由准备提交方在同一 RoundId 内应用布局、领取库存及清理规则。
```

Tick 顺序为 `取命令及已计划的到期效果 → 生成和更新范围快照 → 索敌 → RVO2 固定步与位置写回 → PostMove 塔索敌 → 冻结攻击及防护快照 → 按序发攻击 → 解析/写回伤害 → 死亡回收、更新占位与屏障 → 决定结果 → 整批提交`。本 Tick 中打掉挡塔后核心在下一 Tick 开放。核心击破和到时并存时保留两个事实，以击破作为结束原因。外层统计通过提交批次消费。

**验收。** 同段重复投递只造成一次伤害，另一段可以再命中。超量扣血按剩余 HP 计。双方同 Tick 致死，两条有效请求都结算；死亡只清理一次。核心暴露前后各打一枪，前一枪无伤害、后一枪正常。重复准备确认时同一个 RoundId 不重复布阵和扣库存。
