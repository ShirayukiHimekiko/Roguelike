### 状态行为与代码

- **StartBattle** 进入时创建世界和 Feed，装配完注册帧通道，之后保持该态执行已开始的战斗。空战返回 `candidateTick >= deadlineTick`。装配失败进入 ExitBattle；部分成功资源从已取得的作用域逆序释放。
- **EndBattle** 仅消费最终已提交 BattleTickResult。复制战斗结果，向 RunSession 交接评分数据，封口并释放剩余外部订阅。FrameCore 注销通道会释放世界，宿主仍能消费 Feed。
- **ExitBattle** 接取消和故障。取消关闭输入并注销通道，故障提供最后成功水位和错误给诊断。两者都向 RunSession 报离场原因，不走正常评分和发奖。已进入 End 后退出只是结束展示和移除模块。
- 无活动战斗时 `RunSession.Battle = null`。暂停依赖外层 FSM，PauseGame 的控制泵仍可退出子战斗。根宿主的开战装配在当前帧采样边界完成，`Activate` 提交 Tick 0，下一次宿主采样才注册/推进通道，把已登记状态与未注册资源所有者一起跟踪。退出请求在开始下一次帧驱动前受理。场内阶段内部只提出结束候选，宿主在 `FrameCore.Update` 返回后作状态转换。

```csharp
// Battle/World/IBattleSimulation.cs
internal interface IBattleSimulation : IDisposable
{
    BattleTickResult InitialResult();
    BattleTickResult RunTick(long tick, int tickRate);
}

// Battle/Flow/BattleModule.cs。_feed/_channel 用既有实现的签名。
private void DrainFeed()
{
    while (_feed.TryRead(out BattleTickResult batch))
    {
        // 字段只含值；快照和数组转移所有权或复制，不能引用可回收池/Entity。
        LastCommittedTick = batch.Tick;
        if (batch.Ended)
        {
            _phase = BattlePhase.EndBattle;
            _commands.Seal();
            _sink.AcceptCompleted(BattleId, batch);
            return;
        }
        _sink.PublishTick(BattleId, batch);
    }

    if (_feed.Status == BattleStatus.Faulted)
        ExitActive(BattleExitReason.Faulted);
}

private void ExitActive(BattleExitReason reason)
{
    if (_phase != BattlePhase.StartBattle) return;
    _phase = BattlePhase.ExitBattle;
    _commands.Seal();
    _scope.Invalidate();
    if (_registered) _core.Unregister(_channel); // 帧核心拥有已注册对象。
    else _channel?.Dispose();
    _sink.AcceptExit(BattleId, reason, LastCommittedTick);
}
```

实现时在 RunSession 以 BattleId 核实 `AcceptCompleted` 与 `AcceptExit`，事件发布给 UI 前先写所有者状态。最终批次由 AcceptCompleted 同时路由本步伤害、离场、表现和结果；先写入 Round 和战斗状态，再投送事件。命令和 UI 回调只排请求，避免在 DrainFeed 内嵌套更新、立即开新场。装配失败且尚未注册时由建造者释放，避免多所有者 Dispose。Fault 路径先消费已提交的前一批次再离场。

### 核心 C# 方法

```csharp
// ActorStore.cs。_entities 是当前 BattleId 的 id -> BattleEntity 索引。
public long Spawn(in ActorState template)
{
    var value = template;
    value.Id = checked(++_nextActorId);
    BattleEntity entity = _context.CreateEntity();
    entity.AddActor(value);
    _entities.Add(value.Id, entity);
    _tickEvents.AddSpawn(value);
    return value.Id;
}

public void Collect(long tick)
{
    // _departures 在前序系统按死亡优先、再寿命到期判定，
    // 同一 id 只排一次，按 id 升序处理。
    foreach (long id in _departures)
    {
        BattleEntity entity = _entities[id];
        ActorState value = entity.actor.Value;
        _tickEvents.AddDeparture(tick, in value);
        _entities.Remove(id);
        entity.Destroy();
    }
    _departures.Clear();
}
```

生成和回收均在 Tick 内或装配边界执行，退出只释放场景，不追加伪战斗死亡。视图通过提交事件绑定，禁用视图后用同样的逻辑样本应仍得同样的死亡与 Tick。释放顺序为封口、令 ViewScope 失效、完成已安排的 Job、停系统、清 Context、回收表现。
