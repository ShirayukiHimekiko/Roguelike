### 五个状态

| 状态 | 进入与推进 | 出口 |
| --- | --- | --- |
| StartGame | 进入大厅先等待 Start。受理后分配新 RunId、冻结配置、打开局域资源，启动完成后移交运行 | Ready → RunGame；放弃/失败 → ExitGame |
| RunGame | 使用本局资源与输入门；下一阶段由此处推进 FrameCore | 暂停 → PauseGame；放弃/故障 → ExitGame；自然结果 → EndGame |
| PauseGame | 禁止业务输入，停止本局 Tick。可继续处理 UI、退出战斗和回大厅 | 继续 → RunGame；放弃 → ExitGame |
| ExitGame | 拒绝新输入 → 令旧令牌失效 → 关闭子战斗 → 释放局作用域。已完成 End 的情况下仅做返回清理 | 完成 → StartGame |
| EndGame | 只受理自然结果一次，冻结本局并显示结算。奖励口留给阶段 12 | 确认返回 → ExitGame |

同一帧已提交自然结果优先保留，其次处理退出，再处理暂停/继续；退出若先在本次更新被受理，则本次更新直接进入取消路径。挂起装配仅能在匹配 `RunId + generation` 时报告 Ready 或 Failed；离开时取消，迟到实物由生产者释放。关应用经 `ReleaseLogic()` 同步撤销输入和业务资源，异步持久进度使用已落盘的记录恢复。

### 核心 C# 接线

从 `GameApp` 接线，保留现有日志和销毁监听。状态类使用 `TEngine.FsmState<T>`。当前 `IFsm<T>` 没有公开的 `ChangeState`，在状态类内部调用对应保护方法。实作时销毁缓存首次创建时的 `IFsmModule` 与句柄，框架关停已回收句柄时直接释放业务所有者。所有请求和状态推进都在 Unity 主线程。`IFsm.IsDestroyed` 可查询；宿主和业务作用域清理应独立于句柄是否仍在。

```csharp
// GameApp 的字段与入口对应替换行。
private static GameLogic.ProjectB.GameManager _gameManager;

private static void StartGameLogic()
{
    _gameManager ??= new GameLogic.ProjectB.GameManager();
    _gameManager.Start();
}

// 加在 ReleaseLogic() 的开头，在 SingletonSystem.Release() 前。
_gameManager?.Dispose();
_gameManager = null;
```

```csharp
// GameManager.Start() 的核心方法。_module 与 _flow 是实例字段。
public void Start()
{
    if (_flow != null) return;
    _module = GameModule.Fsm;
    _flow = _module.CreateFsm("ProjectB.Game", this,
        new StartGameState(), new RunGameState(), new PauseGameState(),
        new ExitGameState(), new EndGameState());
    _flow.Start<StartGameState>();
}

// RunGameState.cs。RunGameState : FsmState<GameManager>。
protected override void OnUpdate(IFsm<GameManager> fsm, float elapsed, float real)
{
    var owner = fsm.Owner;
    if (owner.HasCommittedRunOutcome)
    {
        ChangeState<EndGameState>(fsm);
        return;
    }
    if (owner.TakeExitRequest())
    {
        ChangeState<ExitGameState>(fsm);
        return;
    }
    if (owner.TakePauseRequest())
    {
        ChangeState<PauseGameState>(fsm);
        return;
    }

    owner.PumpRunning(real); // 阶段 01 只消费样本命令。阶段 02 接帧。
    if (owner.HasCommittedRunOutcome)
        ChangeState<EndGameState>(fsm);
}
```

Start 的 OnEnter 恢复大厅，清除旧请求。Pause 进入时封闭普通游戏输入。Run 每次进入只恢复本局输入，局初始化由 Start 第一次受理请求完成。End 进入时记录一次已提交展示值。相应方法核心如下。

```csharp
// GameStates.cs。前四个片段分别位于命名对应的状态类中。
// StartGameState.OnUpdate：BeginStart 同步占用当前局位后再发异步装配。
var start = fsm.Owner;
if (start.TryTakeStartRequest(out RunStartSpec spec))
    start.BeginStart(spec);
if (start.TakeExitRequest() || start.StartFailed)
    ChangeState<ExitGameState>(fsm);
else if (start.IsRunReady)
    ChangeState<RunGameState>(fsm);

// PauseGameState.OnUpdate：只跑控制面。退出整局优先于退出子战斗。
var paused = fsm.Owner;
if (paused.TakeExitRequest())
{
    ChangeState<ExitGameState>(fsm);
    return;
}
paused.PumpPausedControls(); // 消费退战、取消/装配收尾；不调用 FrameCore.Update。
if (paused.TakeResumeRequest()) ChangeState<RunGameState>(fsm);

// EndGameState.OnEnter / OnUpdate
fsm.Owner.FreezeAndShowOutcome(); // OnEnter，按 RunId 去重。
// OnUpdate：
if (fsm.Owner.TakeReturnToLobby()) ChangeState<ExitGameState>(fsm);

// ExitGameState.OnEnter / OnUpdate
fsm.Owner.BeginCloseRun(); // OnEnter，关闭输入，取消令牌和子场。
 // OnUpdate：
if (fsm.Owner.IsRunClosed) ChangeState<StartGameState>(fsm);
```

Pause 逻辑保持帧时钟冻结并支持退出。正式战斗是否开放玩家暂停按钮，原需求 03 写了战斗无暂停。本次保留五态与调试暂停能力，热战按钮按确认后的玩法规则配置。销毁只做资源清理，状态 OnLeave 的 `isShutdown` 分支不跳转和开窗口；根释放只能在 FSM 刷新栈之外销毁 FSM。缓存句柄存在、未销毁且 `ReferenceEquals(_flow.Owner, this)` 时才调用 `_module.DestroyFsm(_flow)`，避免已回收句柄参与销毁。

### 验收

| 输入或操作 | 通过条件 |
| --- | --- |
| 冷启动后连续点两次“开始” | 只产生一个 RunId，从 Start 进入 Run；启动场景无旧 Demo 丢脚本或编译引用错误。 |
| Start → Run → Pause → Resume | 同 RunId、同会话，暂停时普通命令拒绝，恢复后可用。 |
| 暂停时点退出，返回再开 | 不产生自然结局，旧 UI 回调拒绝，第二次生成新身份。 |
| Run 注入样本胜利再同时退出 | 已提交结局只展示一次；返回大厅且下次可开。 |
| 装配未完成时退出，等资源晚到 | 不进入旧 Run；无残留实例和订阅。 |

### 核心 C# 接线

`RootModule.Update()` 向 FSM 传 `GameTime.unscaledDeltaTime`。转换只发生在外层，时间整数到时钟后不用 Unity float；余量用于即时宿主量化。同相位的回放直接给固定 Tick，不从实时输入重算 Tick。

```csharp
// GameManager.PumpRunning() 的主体。_fractionNs 在建局/离局时归零。
public void PumpRunning(float realSeconds)
{
    double exact = realSeconds * 1_000_000_000d + _fractionNs;
    long elapsedNs = (long)exact;
    _fractionNs = exact - elapsedNs;
    _frameCore.Update(elapsedNs);
    DrainCommittedBattleBatches(); // 阶段 03 接入。阶段 02 此处读取探针。
    while (_frameCore.TryReadFault(out var exception))
        ReportChannelFault(exception); // 记录原因并请求退出故障会话。
}
```

业务暂停在 RunGameState 推进之前发生，恢复时仅用当次宿主间隔。调试单步通过时钟自己的 `SetDebugPaused` 与 `RequestDebugStep` 操作单通道，开发入口与普通暂停分开。过载仅允许每更新四步、丢弃超额整步并保留余量，战斗倒计时因此只随已执行 Tick。宿主即时汇总 FrameClock 每次 Advance 重置的计数。候选步异常由 FrameCore 摘除通道，已写候选世界不再继续；业务对外仅看到提交过的结果。
