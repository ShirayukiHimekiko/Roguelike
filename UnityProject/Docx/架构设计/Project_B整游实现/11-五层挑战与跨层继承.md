原案 L15–25、L127–133、L234–236、L284–294、L535–539 确立五层、前四层有额外选择、全局轮次与能量延续。敌方跨层继承由本篇给出供评审的默认。[需求 02](../../游戏设计/功能需求/02-五层挑战与英雄.md)

## 跨层交接

| 值 | 评审默认 |
| --- | --- |
| 角色、难度、种子、版本、全局回合号 | 留在 Run。进入下一层当天不增加回合号，打开下一次准备才加一 |
| 玩家金币、等级经验、荣誉、牌组/装备、物品、常驻 Buff、已持有海克斯、任务、技能能量 | 玩家 Run 所有者继续持有。临时效果、牌区、费用余量与场内对象随回合清理 |
| 敌方等级、经验、格位、塔、背包、海克斯和来源 | 旧英雄实例归档并注销。新英雄用 `LayerDef` 的基础值和阵型；不给旧英雄发任何为下一战准备的成长奖 |
| 局级待领与待选票据 | 玩家法球归 Run。尚未出候选的海克斯机会明确绑定下一位英雄。本局重置仍可选玩家持有项，其敌方配对依专项处理 |
| 清层回合敌方经验与指定发放 | 先作为该回合结算规则的输入。评审默认正常固定/额外经验归旧层并记账，直接退出的敌方不发塔、物品及 Buff，记录跳过原因 |

```text
onCommittedClear(roundResult):
    sealOldLayerFacts()
    takeFrozenClearRewardsFromRoundResult()
    if finalOrDefeat: return routeTerminalWithPermanentRewardLines()
    activateNextLogicalLayerOnce()
    routeQueuedTickets(nextLayerId)
    drainIntermission(); loadNextLayerView(); prepareNextRound()
```

新英雄逻辑实例允许先于场景创建。场景加载失败重试同一层逻辑，并保留已经领到的奖励与提交过的敌方交易。已开候选窗口的目标固定，转层不能把已显示内容静默改投另一英雄。[海克斯机会](24-海克斯机会与配对.md)

**验收**　第 1 层第 6 回合清层，第 2 层使用第 7 回合表；旧塔和敌方增益消失，同批清层票据与等级票据各消费一次，均写入新英雄；重复加载新场不会重发。
