# Project B · 双向交易与来源撤销

2026-11-15 · 设计评审稿

原案 L246–252、L407–429：自购、喂养与拆除是双向商店的三种交易。正文同时规定敌方物品/Buff 即时生效且不入背包，及喂养当回合能拆。评审默认区分背包持有物和可撤销的即时效果来源，均有明确实例身份。[需求 21](../../游戏设计/功能需求/21-双向购买与拆除.md)

| 交易 | 冻结报价与同批结果 |
| --- | --- |
| 自购 | 余额够且接收域允许时扣金币，按奖励类型给卡、物品、装备或效果，关闭该报价 |
| 喂养 | 用配置的正价或零价扣费，塔进待部署背包，物品/Buff 当店生效。赠金币按独立流水。评审样本允许零价报价在零金币成交，其余报价仍要求先支付 |
| 拆除待部署资产 | 将实例 ID、持有修订、英雄实例、报价绑定，只移除符合条件的目标并扣价；已部署塔无此入口 |
| 拆除即时增益或海克斯 | 即时增益保存 `SourceId`、作用对象、可撤销标记及当前贡献。只对白名单源生成可拆报价。扣价与移除当前来源同批，已发资源和已生效的一次性产物保留 |

```text
validate(window, offerId, targetId, versions)
planAcross(wallet, sourceOrInventory, offerState)
commitThenPublish()
```

购买和拆除各有报价身份、独立价格和一次消费。拆除不产生回购或再次喂养收益。主动喂养可增加同店可拆池，购买次数、付费重刷数量上限与经济组合交给内容检验，零费无限刷新配置不得让同一可重复报价无限增金。目标消失后在新版本中重报或关闭拆除报价，拒绝保留原余额。

**验收**　零余额能买成本为 0 的敌塔，晋级部署前同店可拆。两种相同 Buff 来源叠加，只移除被选中那一笔。不可逆瞬时发货无拆除按钮。旧拆除报价不会误拆新英雄。
