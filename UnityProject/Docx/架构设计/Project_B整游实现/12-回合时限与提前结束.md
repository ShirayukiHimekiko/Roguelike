## 计时与判断

开战前计算 `RoundDuration = Base + max(0, EligibleDeckCount - Expected) × SecondsPerCard`。采用 RoundSetup 冻结的可参战永久卡份数，不用卡种数。不计本轮后续赠卡。战斗以固定 Tick 执行，倒计时用定点扣减。角色技能只改变倒计时速率。[角色技能时钟](33-角色主动技能与时钟.md)

终帧先按正常次序提交本步命令、战果、费用/能量和回收资格，再读结束原因。超时这一步完整执行，下一步关闭输入。提前结束检查手牌；手牌未满且有可执行抽牌时判断牌库和可洗回的弃区。评审建议把下次有资格抽牌且早于输入截止的牌纳入，手满时库内牌不能提供出牌资格。零费可支付牌仍阻止提前结束。修订 5989 的费用判定先按费用和牌区可达性，目标暂不可投放的提示由 UI 单独解释。

```text
earlyEnd = aliveNonBuildingUnits == 0
           and noAffordableReachableCard(committedState)
           and noScheduledPathToAffordBeforeInputCutoff(committedState)
```

后半条件只认可已排定的、次数未用且前提可达的回费与可释放的角色回费技能，现有玩家建筑以及确定投递的临时牌通过同一合同登记。冻结以当前已知事件为准，无法预测的随机回费不单独拖延战斗。可能出现于最后执行步的回费须等后续仍存在可输入步才算救援。

对有条件兑现的牌，取 `EarliestPlayableTick = max(DrawTick + 1, EarliestAffordableInputTick, CardAvailableTick)`，已经在手且可用的牌去掉抽取项。费用在 Late 才提交时，最早可用于下一 Tick 的输入。把这个最早值和该条可达路径下预计的最后合法输入 Tick 比较。若技能本身是救援动作，必须先验证它能及时施放，再按其减速后的剩余时间计算后续回费与可用步。

**验收**　无单位、无费用、下一步明确回 2 且能在截止前出一张 2 费牌时继续。若预计在最后允许输入的 D 步才抽到或回费，D+1 已关闭，不能延缓本回合。满手全不可支付且牌库有 0 费牌但无法抽到时允许结束。最后一步核心与超时同时成立时只产一个战果入口。[评分和裁决](14-战斗评分与荣誉裁决.md)
