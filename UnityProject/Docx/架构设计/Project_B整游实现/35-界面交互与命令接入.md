# Project B · 界面交互与命令接入

2026-11-15 · 设计评审稿

目标是把键鼠与拖放映射到局/场输入。规则入口由 [整游总流程](02-整游总流程.md) 确定，使用项目的 TEngine UIWindow、UIWidget 和 GameEvent 生命周期。[UI 生命周期](../../../.agents/skills/tengine-dev/references/ui-lifecycle.md)

| 界面 | 必要信息、可操作项与回显 |
| --- | --- |
| 大厅、选角、难度、局外成长 | 持有/未解锁、树节点成本与前置、禁用额度、开局选择。提交后显示新档案修订或明确拒绝原因 |
| 准备 | 当前层/全局轮次、塔、敌方库存预览与回合改动。确认后锁按钮，预检或加载失败回到可操作状态 |
| 战斗 | 手牌、实际费用/上限、剩余时间、能量、队伍与核心方向。鼠标选择/拖放用相机转换逻辑地图坐标，预览和权威阶段走同一部署规则。空格绑定角色技能，输入命令后以真实提交状态回显 |
| 商店、背包、任务 | 两侧分栏、交付对象、成本与收益、可拆原因、锁定和刷新。选择窗遮挡交易操作，回到同 WindowId。法球与任务可单领或合规批量结算 |
| 海克斯 | 每项并列两边效果，明确当前受益英雄。锁定已选候选直到提交完成或收到失败原因 |
| 局末 | 胜负或中断原因、清层、拆塔、回合、累计评分、已登记奖励和已入账收据。中断/重试有明确入口 |

`OnRefresh` 从当前读模型重建，`RegisterEvent` 中用 `AddUIEvent` 接变化。`OnDestroy` 回收自身订阅外的操作/资源。手势形成 `BattleId + TargetTick + InputSequence` 或 `WindowId + Revision + CommandSequence` 命令，界面只做预览、等待与结果显示。失败回显以最新投影重建；焦点、连续按下、旧拖拽与 UI 事件到达顺序不改变底层结果。战斗没有原案外的暂停入口。

**验收**　拖拽期间旧 BattleId 被替换，命令失效且新局状态不变。重开店面不刷新，支付与开窗失败的真实原因可见。一次 UI 丢通知后重新打开可还原状态。
