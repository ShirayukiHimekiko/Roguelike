# Project B 整游方案编写范围

2026-11-15 · 设计评审稿

玩家扮演进攻方，实时出牌闯过五名守方英雄。每轮伤害和破塔表现决定下一轮还有多少生存与经营空间。双向商店和海克斯让玩家在增强自己、提高下一战难度和获取更强长期收益之间作选择。

- **交付**　整游设计思路、总流程、工程实现、分步执行方案，以及按独立规则或交付边界拆开的补齐专题。[整游方案索引](00-整游方案索引.md)
- **输入**　磁盘上的 Project_B 修订 5989 正文、随附流程白板、仓库 42 项功能需求和现有模块架构。仓库内链接见索引，正文行号均指修订 5989。
- **边界**　独立模块保留数据所有权，BattleModule 装配场内模块，RunSession 串联准备、结算、商店、选择和换层，GameManager 接开局和返回。方案中出现的字段、状态与函数名均为设计合同。
- **验收**　42 项均有可追溯的实现落点。新增专题给出写入方、触发阶段、依赖、失败恢复及可验收样例。用同一条跨层主链说明资源、奖励、选择、实体和窗口的交接。
- **首批工作**　按所调用技能的普通应用处理，以一次资料对照和完整首稿为主。最需要核对的是同回合胜负、敌方跨层接收方、即时效果与异步退场。另由独立代理比对原件和首稿，回件影响本版的决策直接修入专题。主动投入以完成文档为限，无新增付费作业。消费方为程序、策划和美术的方案评审。
- **口径**　明确规则按原案；原案冲突或缺数据时注明评审建议、例子和改动影响。选角扩展、属性叠层与资源 F 可作为独立交付阶段，仍属于整游设计范围。

独立核验覆盖原案、白板、既有模块及首稿的 42 项映射。首稿返修集中在通关法球与永久子行的分支先后、末步回费/抽牌与可出牌步、报价保底格、任务与选择交接和场内费用单写入。文档中的示例是实施验收条件。
