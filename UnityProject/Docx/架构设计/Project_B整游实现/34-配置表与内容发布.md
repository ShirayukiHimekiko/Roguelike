## 表族、生产者和消费者

| 表族 | 策划或美术生产输入 | 业务读取 |
| --- | --- | --- |
| 局外树 | 科技树；卡牌技能和技能树；角色技能和技能树；玩家角色、解锁条件、初始卡组 | Profile 与开局装配，生成有效树节点、技能和禁用/解锁快照 |
| 对局成长 | 物品、装备、卡牌、卡组、羁绊、商店、海克斯、配对、任务与敌升级表 | 局级供给、成长、票据、奖励与准备 |
| 战斗 | 塔、单位/塔基础属性双键、地形、效果、Buff、通用技能、回合 | 建图与 BattleWorld，预编译数值和效果参数，运行期读值 |
| 补表 | 难度、五英雄路线、Map/Spawn/Layout、正的评分基数、评分与荣誉/金币/经验规则、掉落/奖励权重、备选池和资产清单 | RunRules、BattleRules、MapRuleData、RewardRules 与表现适配 |

卡组表从“卡牌 ID + 星级字典”规范化为 `(CardDefId, Star, Count)` 行，保留同卡多实例和不同星级。核心在塔双键使用专用无星键，去除普通星级池资格。原效果字典编译成明确动作顺序、阶段、目标域和数值单位；异步包装集齐所有二进制后再由生成 Tables 读入。生成物只由现有工具落到 GameProto。已有规范示例使用同步 LoadAsset 作构造加载器，实施时在 GameLogic 适配器先异步取 bytes，再提供 CPU 侧同步取值函数，保持热更程序集单向依赖。具体配置工具版本以仓库为准。

## 发布条件

```text
compileSources → validateRows → prefetchBlobs → buildRuleProjection
    → validateCrossDomain → publishImmutableVersion
```

- 校验 ID/双键、引用、资源与范围。树前置/冲突、目标作用域、阶段、效果环和显式上限。
- 校验五层组合、定点范围、塔足迹/地图/八方向可达性、星级阈值、回合时限和正评分分母。全局轮次可超出已填行时，由策划选择明确的末行延展或继续补表。样本使用最小内容包的末行延展，固定发放条目须单列是否重复。
- 校验角色初始牌组与禁用交集、三选一的可达正权重、商店保底槽、掉落和奖励接收域。动态状态仍须运行期合法性核对。
- 关键缺项拒绝新局，保持已加载旧版本的活动局。艺术资源失败可回退占位图，必需地图规则缺失则暂留在安全阶段。新版本用稳定 ID 与迁移规则处理档案，永久待奖励存冻结入账行。

**验收**　两个 (同卡, 不同星) 的卡组行都生成独立份数；无星核心有数值且不会入有星掉落。漏一条地形或奖励引用时提示表/行/字段和消费者，本局已冻结的版本仍可结束。
