# Project B · 整局结算与局外奖励

2026-11-15 · 设计评审稿

原案 L21–25、L274–280、L298–336，玩家胜利或荣誉耗尽后按表现领取局外资源。架构衔接 [局外养成](../Project_B战斗与局内系统/16-局外养成实现方案.md) 的 Profile 单写和持久回执。

## 结算明细与发放

| 输入 | 产出 |
| --- | --- |
| 结果类型、已击败英雄数、合格拆塔数、完整回合数 | 资源 A 的各贡献项，由奖励版本配置胜负附加 |
| 本局永久升星的已提交事实、结果类型 | 资源 B。局外新卡解锁的 B 由 Profile 在解锁事务中单独发，不并入本局 |
| 累计战斗评分及荣誉余额 | 结果展示和配置的额外奖励计算。资源 F 走独立启用项 |
| 正常胜负以外的退出 | 保存退出原因和已提交诊断信息，评审默认不产生完成局奖励 |

RunSession 冻结 `RunOutcome(ProfileId, RunId, Digest, OutcomeKind, RewardRuleVersion, FactSummary)`。GameManager 用同版本计算奖励行，Profile 持久登记后消费。余额、账本、收据及待办移除在一次事务提交。回执返回前显示“结算中”及重试状态。局末窗口只读已经领取的局内信息；待领普通局内奖励按 [法球政策](16-法球掉落与领取.md) 关闭，支线资源 F 如启用则独立结转。[荣誉勋章](32-荣誉勋章.md)

```text
pending = stageOutcomeOnce(runOutcome, frozenAwardLines)
receipt = applyPendingOnce(pending.ProfileId, pending.RunId)
display(receipt, pending.outcomeSummary)
```

**验收**　奖励登记后重启可恢复；已入账未显示时重试拿原回执。相同 RunId 不同摘要要保有原奖励并报告冲突。A、B 倍数缺真实策划数值时使用标识为样本的规则。
