# Project B 分步实施方案

2026-11-15 · 待实施

从固定阵型的单回合走到可真实经营、连续五层与永久结算，然后补足完整正式内容。阶段目标都是业务可消费结果。每项目标在实际完成后勾选并附完成内容及验证证据。这里的伪代码均表示拟增加或接通的调用。[整游实现方案](03-整游实现方案.md)

## S1 · 固定场次到唯一战果

- [ ] **帧宿主、正式 Entitas 与规则投影。** 接 GameApp / FrameCore，确定 Jenny 正式 Battle Context 与 GameLogic 引用，读取一份标识为样本的内容。让同种子、同命令重建同一 Tick。伪代码 `host.Sample → FrameCore.Advance → BattleWorld.Step → Commit`。验收按不同宿主帧组合、同已执行 Tick 得同状态，异常步无结果。
- [ ] **空间、单位、建筑、命中。** 接场地图、格位、围栏、普通敌塔、简化玩家单位和暴露核心；用 [阶段 05](执行手册/03-寻路索敌与对打.md#s05) 直接接用户提供的 RVO2，索敌先全扫并沿 12/13 评估四叉树和 Job。伪代码 `Select → RVO2.Run → CommitPositions → CaptureShapes → ResolveHits → CommitHealthAndTopology`。验收外塔和核心从同一前沿合同消费，回收无击杀。
- [ ] **回合入口和退出。** 固定局级替身给 RoundSetup，抽牌、费用、出牌和自动攻击走实体，封存成功战果并拆卸。伪代码 `RoundSetup → CardCommand → LastCommittedTick → BattleResult → teardown`。验收满手抽牌、同段去重、同 Tick 核心/超时、旧输入拒绝。
- [ ] **灰盒视图。** 先圆、方、三角，至少两张不同费用、两个方向与一个角色技能操控。伪代码 `PointerToMap → Command → CommittedTickBatch → Feedback`。验收投放反馈与真正入帧同口径。

## S2 · 打通完整局的一条可玩闭环

- [ ] **大厅、开局与层状态。** GameManager 连接 Profile 的替身/真实端口和内容服务，RunSession 创建五层路线，准备回复、AI 部署、未部署库存清理在局级提交。伪代码 `StartRun → Freeze → Prepare → DeployOnce → startBattle`。验收重复确认和加载重试不会重复恢复、部署和扣库存。
- [ ] **结算与归因。** 接评分、荣誉、金币、经验和掉落，回合闭环只从最后成功水位消费。伪代码 `BattleResult → RoundResult + Rewards + Branch`。验收阈值、终局同触发、来源去重、故障隔离。
- [ ] **商店、牌组与效果。** 接双方报价、支付、喂养、同店拆除、背包、合成、装备、等级曲线和属性修正。伪代码 `Offer + Price + Give/Remove → PlanAllOwners → CommitOnce`。验收同资产和同 OfferId 仅消费一次，局内永久新卡下轮进入牌库。
- [ ] **海克斯、任务、法球和清层。** 接双边票据、领取、重置、英雄切换和任务奖励。伪代码 `ResolveRound → BindNextHero → Claim → Choose → Shop → NextRound`。验收第 6→7 回合及前四层奖励，第五层和荣誉耗尽两个终局均走通。
- [ ] **正式场内能力。** 补抵抗、元素、特殊、光环塔和全部卡类型。接主动技能、效果时钟、地形和独立来源撤销。伪代码 `EffectFacts → TypedActions → OwnedStatePatches`。验收跨回合临时效果回收及来源撤销，同时比较回放摘要。
- [ ] **永久结算和基本养成。** 接 A/B、科技树、卡技能树、C/D/E、禁用快照、正常胜/负回执和返回。伪代码 `RunOutcome → PendingReward → WalletTxn + Receipt → Lobby`。验收登记后重启、回执后重发。新局从 Profile 重建。

## S3 · 完整内容与交付验收

- [ ] **正式配置和数值。** 用 [配置方案](34-配置表与内容发布.md) 补齐玩法、权重、时限、分数基数、初始阵型和奖励表。按 [规则决策表](05-规则决策表.md) 审定冲突项带来的数值改动。伪代码 `Generate → CrossValidate → PublishVersion → FreezeOnRun`。
- [ ] **角色与成长扩展。** 启用有正式定义的多角色选择、角色技能树、F 和属性叠层槽位。伪代码 `UnlockRole / Node → BuildLoadout` 与 `GainTrack → ReplaceModifier`。验收解锁和节点同账本、F 去重、短期 Buff 与长期层数独立。
- [ ] **UI 与美术生产。** 完成大厅、回合、商店、双向选择、任务、奖励、结算状态和正式像素简笔画资产，迁移排序。伪代码 `CommittedReadModel → PresentationScope → BindIfCurrent`。验收正式样本在目标分辨率辨识清楚，旧加载迟到无残留。
- [ ] **目标 Player 和性能验收。** 用固定大、小阵型复现 Tick 链，按目标硬件比较索敌全扫/格桶/四叉树的结果与构建、查询、等待和分配。测场景、视图资源释放及五层重复运行。伪代码 `ReplayFixture → Hash + ProfilerCounters`。60 Hz 固定 Tick 与 0 B/Tick 若被确认，用作性能目标，实际结果依项目真机记录。
- [ ] **发布与恢复验收。** 验证内容坏包、档案迁移、结算落盘故障、旧窗口、同地址资源加载、干净重开。伪代码 `OpenProfile → MigrateOrRecover → RetryPending → RetrieveReceipt`。用同版样本交付玩法、工程、内容三方记录。

首个完整演示至少覆盖“失败前可经营赢回来”“清层后敌方收益确实交到下一英雄”“第五层结束奖励只发一次”。最低内容包需要初始角色、难度、五英雄规则、四类基础卡样本、塔阵与下一回合升级配置、至少三组合法双向选择、商店双方商品、掉落/任务与奖励曲线。未获确认的正式字段单列在各专题，联调定值供试做。
