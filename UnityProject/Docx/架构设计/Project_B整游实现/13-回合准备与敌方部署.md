# Project B · 回合准备与敌方部署

2026-11-15 · 设计评审稿

原案 L209–211、L232–252 要求备战回满费用，塔按类型恢复，玩家确认后由 AI 部署并清理未部署塔。依 [AI 方案](../Project_B战斗与局内系统/02-敌方AI实现方案.md) 和 [建筑方案](../Project_B战斗与局内系统/03-建筑实现方案.md) 补全准备期的提交边界。

## 从开窗到开战

1. RunSession 用当前英雄值和已确认的成长状态打开 `Preparation(WindowId, RoundId, Revision)`。资源域为本回合建立满费用；常规活塔按当前有效上限回已损生命的 15%，核心回满，抵抗塔复活并回满。恢复只在准备开窗提交一次。准备前光环、物品变更先形成有效修复规则。
2. 玩家确认后，AI 在纯值工作视图读存量和待部署塔，输出稳定排序的互换和部署提案。布局域移除提案涉及的旧足迹再批量检查新足迹。背包域按已部署库存 ID 扣用，并丢弃剩余待部署塔，只影响当前英雄和本次准备。
3. RunSession 同原 WindowId 一次提交布局、消耗、丢弃及 RoundSetup。能移动的旧塔随实例保留 HP 和持久状态，不能移的塔与核心占位固定。
4. BattleModule 初始化失败且 Tick 0 未发布时，用原 RoundSetup 和新 BattleId 重试。回合准备预检失败保留原窗口可重新生成提案，禁止跨阶段补扣同批资产。

```text
confirm(window):
    plan = ai.plan(preparedLayout, enemyInventory, stableSeed)
    patches = validateTogether(plan, emptyFootprintDelta, deployAndDisposeInventory)
    commitPreparedRoundOnce(patches); createBattleFromFrozenSetup()
```

**验收**　100 上限、当前 60 的存活塔恢复为 66，重复确认仍为 66。两座同尺寸塔交换格位可成功，多格踏越不可用格整体拒绝。重复初始化不部署第二份塔。[占位规则](17-地图地形与部署占位.md)
