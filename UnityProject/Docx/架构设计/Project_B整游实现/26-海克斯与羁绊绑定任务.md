# Project B · 海克斯与羁绊绑定任务

2026-11-15 · 设计评审稿

原案 L61–77、L123–133、L479–499、L541–543 给海克斯/羁绊绑定任务与卡、装备、升星、费用、海克斯等奖励。任务档案按局生存，规则缺省采用下方提案。[需求 37](../../游戏设计/功能需求/37-绑定任务.md)

## 生命周期与事实输入

- `TaskDef` 包含条件谓词/计数目标、有效范围、接取策略、奖励行、显示说明。绑定时按 `TaskInstanceId(TaskDefId, SourceInstanceId, Ordinal)` 建实例。任务不追认绑定之前的事实，条件若定义按当前状态评估则读取绑定时的提交后快照。
- 任务只消费同作用域内已提交的稳定事实，例如 `RoundSettled`、`DirectTowerBreak`、`CardPlayed`、`DeckChanged`。战斗统计可以在场内按 Tick 更新投影，用明确的事实游标随 BattleResult 交回；首版奖励在安全窗结算。若策划要求战斗内立即回费，独立增加确定性 Tick 的即时奖励入口，沿场内资源合同。
- 玩家任务跨回合、跨层保留。失去羁绊阈值时暂停同一实例，重达后恢复进度，防止重领。海克斯被重置时，未完成的旧绑定关闭，已完成待领的保留。相同绑定按本局任务键只给一次完成奖励，配置声明可重复的任务以显式独立额度处理。
- 已达成进入可领，评审默认在回合间可主动领取，闭窗前需处理。进度、发货与消费标记有身份。对尚有合法接收目标但暂无法选择的奖励，保留并给可恢复 UI；已无目标的奖励必须在表定义可审的替代或放弃规则。奖励连锁后续任务若依赖重新形成自身条件，发布闸门拒绝即时环及无上界增发。

```text
foldFactOnce(task, factId, factValues)
if completed: makeClaim(taskId, frozenRewards)
claim: preflightRewardTargets(); commitRewardAndConsume()
```

**验收**　重复命中事件不涨两次进度，羁绊失档又恢复不能重复获奖。完成任务送选择、该选择绑定新任务，顺序可追溯且终止。
