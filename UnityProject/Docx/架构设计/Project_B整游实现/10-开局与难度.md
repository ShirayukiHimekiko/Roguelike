# Project B · 开局与难度

2026-11-15 · 设计评审稿

原案 L15–27、L49–51、L531–533 规定开局选难度，由角色给初始牌组、基础费用、金币、荣誉和主动技能。难度档数、加成与解锁门槛仍缺正式数据。[需求 01](../../游戏设计/功能需求/01-开局与难度.md)

## 开局提交

- 大厅读取当前档案和已发布内容，显示可选角色、难度与简短差异。原型配置一个明确的测试难度和初始角色。
- `DifficultyDef` 持稳定 ID、展示文案、准入条件、英雄路线/可选数值修正。评审样本只切换有配置的塔与回合规则，不默认改变评分、掉落或奖励倍率。难度差异来自内容表。
- GameManager 收到 `StartRun(RoleId, DifficultyId, ProfileRevision, ContentVersion)` 先占用启动转移，再停大厅的新写入，等待已接受写入，若快照变化则重读确认所选仍合法。
- 用角色、局外树与难度合成只读开局值。校验五层路线、初始牌组非空、可达地图、费用与正的初始荣誉，再分配开局值和 RunId。必带首发卡设为不可禁用。若旧档中禁用了选中角色的首发卡，提示玩家解除冲突后开局。[多角色选择](29-多角色选择与解锁.md)
- `validate → freeze → load → createRun`。重复点击归到同一转移。加载失败回大厅，旧加载完成后只释放自己取得的场景。

**验收**　改动档案后旧 UI 的开始命令不能闯过准入。载入途中换表时，本局仍使用冻结版本。两个难度如果给相同数据，只显示为联调数据，正式差异须由策划表确认。

禁用的三个额度按上限处理，解禁即归还有效额度。评审采用统一内容准入，随机与固定授予、双方池及临时卡均用同一过滤；强制奖励需要配置合法替代或保护项。任一半被禁用时整对从海克斯池剔除。装备是否按物品类别受禁用由表明确。稳定规则见 [局外养成 §4](../Project_B战斗与局内系统/16-局外养成实现方案.md#4-禁用卡牌星级及开局装配)。
