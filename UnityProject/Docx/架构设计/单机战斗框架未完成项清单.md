# 单机战斗框架未完成项清单

范围：单机战斗框架、正式单机入口与验收。以当前工作区及 ET10 固定提交 `743c635dd5b0f6f6bab549c0093382c85f3f8307` 为准。本清单不安排联机工作，也不设计具体玩法。

执行更新：**01–03 已实现并通过独立宿主回归，Unity Play Mode 尚未复验。** 下表保留改动前的缺口描述；最新契约、前后数据和验收结果见[单机回放定位与分歧停止执行方案](./单机回放定位与分歧停止执行方案.md)。

后续工作按[单机战斗框架剩余工作分步执行方案](./单机战斗框架剩余工作分步执行方案.md)推进。该文档将待验收、可立即实现及依赖正式玩法的事项分开排程。

当前已具备：每局 Room 和四状态 FSM、50 ms 帧时钟、本地权威输入及环形历史、Entitas 世界和系统树、稳定实体 ID、可恢复随机数和登记过的组件、逐帧输入和帧前指纹、周期检查点、V3 录像存读、前后定位和四档倍速。已有 [1,206 帧重建](./单机战斗世界快照与重建分步执行方案.md)、[793 项定点对账和 40 帧倍速验收](./定点运算对账与单机回放倍速验收.md)。下面只列差距、待确认项和待验收项。

## 一、框架代码还没做或只做了一半

| 编号 | 未完成项 | 当前实现与完成标准 |
| --- | --- | --- |
| 01 | 回放定位分批重演 | 当前 `SeekReplay` 在调用中从最近检查点同步重演，单次最多推进 1,200 个逻辑帧。ET 的 [JumpReplay][jump] 配合[回放更新器][updater]跨轮询追帧。先用 Demo 测同步定位的主线程开销；若采用该机制，由更新器按预算推进至目标，位置、帧指纹和定位后继续播放的表现与同步版一致。预算检查发生在单帧结束后，不能保证一个重型逻辑帧也在预算内。 |
| 02 | 回放同区间正向定位复用世界 | 目前每次定位都释放和重建世界及系统树。ET 在同一检查点区间向前时可沿用当前世界。与 01 一起处理；倒退、跨区间和分歧后的恢复仍以正确的检查点为准。 |
| 03 | 回放遇到分歧时的停止边界 | 现有离线帧前 Hash 校验会记下差异并停止后续帧，但已经推进房间帧号，且当帧仍会执行一次系统。若契约是“分歧帧不执行”，应定义最后确认帧、分歧帧、已投递输入及对外可见状态；用故意不匹配的录像检查连续播放和定位都满足该契约。这是项目已有能力的缺口。 |
| 04 | 从逻辑帧内请求自然结束 | 有手工 `EndBattle`、Esc 退局、释放、回菜单并保存；未有玩法在模拟中请求、由一帧执行和清理结束后统一完成的入口，也未有可交给外层的完成通知。胜负规则由玩法决定。 |
| 05 | 末帧执行后的状态校验 | 当前每帧存的是帧前指纹，最后一帧执行后的状态没有下一帧可校验。若要求验证终局一致，需保存并对照末帧执行后的状态指纹，并决定录像版本兼容策略。不能把已有帧前指纹当成终局校验。 |

## 二、框架有接口，正式游戏还没接

| 编号 | 未完成项 | 当前实现与完成标准 |
| --- | --- | --- |
| 06 | 独立战斗场景、资源就绪及退场 | 有 `isReady` 和房间释放，正式入口只检查已打开的 `main`。选定独立战斗场景后，由 `Runtime/Battle` 串起加载、准备完成才开第 0 帧、退局后卸载；入口如何响应真实的加载失败或取消，跟所选加载流程一起定义。ET [准备事件][scene]可参考，样例本身也留了场景/UI 资源占位。若正式方案始终复用主场景，此项相应缩减。 |
| 07 | 正式 Entitas 玩法装配 | 正式 Battle Context 为空；`BattleWorldSetup` 的建局、系统、输入及组件编解码接口都已有。接第一批玩法时，由 `Runtime/Battle` 装配同一套实时与回放规则，并把影响复演的状态放入可恢复组件或开局数据。组件、系统次序及需要按实体 ID 遍历的地方随实际玩法验收。 |
| 08 | 正式输入桥接 | 框架已有 `SubmitLocalInput`，正式开局不配置玩家槽，也没有向战斗帧提交正式操作。输入设备、按键、持续值或一次性操作的语义随玩法定义；回放读录像输入。Esc、R 等流程快捷键已经存在。 |
| 09 | 正式表现及定位后重绑 | 未接逻辑状态到 Unity 的实体视图、插值和销毁同步。回放定位可能替换 Context，视图需以稳定 ID 重新查询或重绑，不能持有旧实体引用继续更新。ET 有[表现初始化][view]和[世界替换后通知][jump]可参考；镜头、动画、特效规则留给玩法。 |
| 10 | 正式战斗结果与结算展示 | 框架完成通知见 04。结果字段、胜负规则、结算 UI 和奖励等留给玩法，当前没有这些内容，也不作为框架迁移任务。 |

## 四、按产品需求决定的项目

- 暂停、继续、单步、回放进度和播完提示：当前已有四档倍速、前后定位及末帧停止；尚未提供这些独立控制或完整回放界面。若需要先明确实时单机暂停和回放暂停是否为两个行为。
- 录像列表、手动导入导出、跨版本兼容及无法读取时的用户提示：当前入口只管理最新一份 V3 录像，有文件格式校验；模式、保留策略和历史版本迁移需按产品需求定义。
- 本地分歧诊断：已有首个分歧帧提示；没有自动生成逐组件差异报告。录像保存的是每帧指纹和周期快照，不能直接从普通录像拿到任意帧的原始预期世界，若要诊断须单独确定取证方式。
- 补充定点数学：现有基础标量、向量、朝向和独立随机数已接；三角查表、更多矩阵/几何 API 等按实际算法需求增加。已覆盖样本的对账不能视为所有边界值、平台或算法已验收。

建议顺序：先量测并决定 01–02，明确 03 的停止契约；04–05 在确定正式对局结束契约时处理。06–10 随正式场景和玩法设计推进；11–15 属于验收和交付，不等同于缺少 ET 框架机制。以上为盘点，本轮没有实现或运行验证。
