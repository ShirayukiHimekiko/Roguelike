# 单机战斗快照、回放与进退场执行方案

本阶段完成世界快照、状态 hash、恢复重演、整局录制和单机进退场。沿用项目现有 `BattleRoom`、四状态 FSM 和 Entitas 世界。实际战斗系统仍由 `Runtime/Battle` 按业务需要注册。单机入口复用现有 `main` 场景与 `StartUI`。

## 步骤 1 · 帧前快照与状态 hash

- [x] **世界状态。** `BattleWorld` 以固定单位槽顺序导出世界下一帧、单位 ID、位置、旋转和输入的定点原始值，并支持从相同格式恢复。快照字节用于计算稳定的 64 位 hash。
- [x] **帧容器接线。** `BattleRoom.Tick` 在写完当帧输入后、执行系统前记录快照。快照与输入使用同一环形槽，房间支持按帧查询 hash。

~~~text
封存输入 → 确定权威帧 → 写入实体输入
    → 保存该帧演算前的世界与 hash → 驱动 Entitas 并推进世界帧
~~~

## 步骤 2 · 整局录像、文件与回放

- [x] **整局记录。** `BattleModule` 保存初始单位、每帧完整输入和 hash，每 1,200 帧保留周期快照。正式本地流程指定持久化目录中的 `battle-last.replay`，框架负责版本化二进制异步读写和完成后替换。
- [x] **回放调度。** 录像输入经同一个 `BattleRoom.Tick` 执行，逐帧核对 hash。回放追帧在每一次推进后检查 5 ms 预算。
- [x] **定位和调速。** 从最近检查点恢复世界并清空短期历史，再重演到目标帧。支持 1、2、4、8 倍速，跳帧后重设时钟锚点，换速保留当前帧的时间锚点。

~~~text
Seek(frame)
    恢复该帧前最近的检查点
    从检查点帧重演到目标帧，逐帧比较保存时的 hash
    以目标帧为锚点恢复回放调度
~~~

## 步骤 3 · 单机菜单和退局

- [x] **真实调用入口。** `StartUI` 的开始按钮调用单机流程，场景就绪后启动空战斗世界。测试单位与输入序列放在验收 Demo 中。
- [x] **退局。** Esc 关闭房间、返回菜单，并保存已推进的实时录像。
- [x] **回放控制。** 菜单按 R 读取最后一局。回放中 Tab 换速，左右方向键前后跳 100 帧，Esc 返回菜单。

## 验收

- [x] 独立 C# 宿主完成 2,445 项断言，覆盖位姿恢复、逐帧输入和 hash、6 次跳转、4 个倍率及回放分歧停止。
- [x] 录制 1,205 帧跨过 1,200 帧环形历史，生成 2 个检查点。首次保存、覆盖、读取和拒绝损坏文件均通过。
- [x] 归位前的原型在 Unity `6000.0.69f1` 验证菜单开局、临时键盘输入、退局存档、读档、调速和跳帧。当前版本的空世界及独立 Demo 验收记录见[战斗框架文件归位方案](战斗框架文件归位方案.md)。

`Module/BattleModule` 管理时钟、帧容器、房间生命周期、世界及录像格式。`Runtime/Battle` 的 `LocalBattleFlow` 连接菜单与框架，并提供本地保存路径。状态及输入在外部入口校验，内部直接消费已确定数据。

当前回放格式覆盖战斗世界已有的单位 ID、位姿和输入。新增确定性组件或系统内部状态时，将它们的状态一起纳入快照的编码、恢复和版本管理。
