# 单机权威帧与战斗世界分步实现方案

框架已落地。按目录职责重整并删除默认示例移动后，通过两局 Unity Play Mode 和独立 .NET 对账。源码基线为 ET10 `master` 的固定提交 `743c635dd5b0f6f6bab549c0093382c85f3f8307`。已有时钟、`BattleModule`、`BattleRoom` 与四状态 FSM。本阶段将原先的帧号回调接到真实输入、房间和 Entitas 战斗世界。[当前战斗房间](../../Assets/GameScripts/HotFix/GameLogic/Module/BattleModule/BattleRoom.cs) · [当前更新器](../../Assets/GameScripts/HotFix/GameLogic/Module/BattleModule/BattleUpdater.cs) · [前置差距分析](逻辑帧房间与战斗世界接线差距分析.md)

## 交付目标

以固定输入序列验收本地战斗框架。每次 FSM 的战斗进行状态轮询，由本地权威更新器判定时钟。到期时封存该帧输入、更新权威帧号，经 `BattleRoom.Tick(frame, inputs)` 写入当局 Entitas，再由 `BattleWorld.Tick()` 驱动 Entitas 系统树并推进世界帧号。正式菜单启动空世界，测试单位和输入序列由独立 Demo 提供。菜单进退场、快照、hash 和回放已接入。玩法输入、单位视图和具体演算按业务推进，预测、联网回滚、网络与校时列在联机阶段。[单机总方案](单机战斗完整迁移执行方案.md) · [快照、回放与进退场](单机战斗快照回放与进退场执行方案.md)

| 职责 | 所属对象 |
| --- | --- |
| 开局、校验外部请求、登记当前房间、提交本地输入、退局 | `BattleModule` |
| FSM 生命周期、当局时钟、权威帧号、帧输入槽、当局世界、把帧输入交给世界 | `BattleRoom` |
| 按单调整数毫秒判断到期、每次轮询最多推进一帧 | 现有 `BattleUpdater` |
| 收集待消费输入、补齐并封存当帧、按帧保留实际使用的输入 | `BattleFrameBuffer` |
| Entitas Context、单位索引、固定顺序的系统树、下一待执行帧 | 新增 `BattleWorld` |
| 系统装配 | `Module/BattleModule/BattleWorld.cs` 通过 `createSystems` 获取由玩法层按顺序装配的系统树 |

开局时 `AuthorityFrame = -1`，`BattleWorld.Frame = 0`。执行第 `n` 帧时，房间先确认 `AuthorityFrame = n`，世界执行系统树并清理当帧后把 `Frame` 加为 `n + 1`。现有只读 `CurrentFrame` 返回房间的 `AuthorityFrame`。固定时钟仍以第 0 帧为锚点、50 ms 为步长。TEngine FSM 提供轮询入口，定点数学用于战斗演算。[帧时钟][clock] · [房间单帧处理][room] · [上游世界与帧号][world]

## 步骤 1 · 落定类型与生成接线

- [x] **数据契约与组件。** 在 `Assets/GameScripts/HotFix/GameLogic/Runtime/Battle/` 下放置 `BattleStartData.cs`、`BattleUnitStartData.cs`、`BattleInput.cs` 及 `Components/` 中的单位 ID、移动输入、定点位置和定点旋转组件。开战数据提供本地玩家 ID 及按顺序排列的初始单位。帧输入保留对应玩家的定点二维方向，按钮值沿用上游 `LSInput.Button` 的数据语义，本阶段为零。单位创建、玩家 ID 查询和组件更新使用 Entitas 1.14.1 生成 API。
- [x] **定点数学。** 工具源码归在 `Utility/`。扩展 `FixedPoint.cs` 的平方根和源常量转换，补 `FixedVector2`、`FixedVector3`、`FixedQuaternion` 及 `LookRotation` 实际依赖的定点矩阵计算。按固定提交移植实际调用路径。保留归一化、乘除顺序、舍入与矩阵转四元数分支。定点二维向量除标量时，上游先求倒数，再乘两个分量。后续位置、旋转以及常量均以原始值比较。[标量][fp] · [二维向量][vector2] · [定点矩阵][matrix] · [四元数][quaternion]
- [x] **Jenny 接线。** 将战斗组件标入 `Battle` Context，在 `UnityProject/Jenny.properties` 配置 `Game, Battle`。目标目录为 `Assets/GameScripts/HotFix/GameLogic/Runtime/Entitas/`，Jenny 在其下写入 `Generated/`。调整 `Tools/Entitas/EntitasGen/EntitasGen.csproj` 的 `Compile Include`，让它解析 battle 组件以及字段所用的定点类型。输出目录只存生成物，避免 Jenny 清理过程影响手写代码。[Jenny 配置](../../Jenny.properties) · [当前生成工程](../../../Tools/Entitas/EntitasGen/EntitasGen.csproj) · [Entitas 生成流程](../../.agents/skills/entitas-dev/references/jenny-and-integration.md)

关键伪代码

~~~text
BattleStartData = 本地玩家 ID + 有序的初始单位
BattleUnitStartData = 玩家 ID + 定点位置 + 定点旋转
BattleInput = 定点方向 + Button
生成工程扫描战斗组件及字段类型 → Jenny 生成 BattleContext、BattleEntity、BattleMatcher 和组件 API
~~~

实际使用 Entitas 1.14.1 官方 `Jenny.zip`，从临时目录运行 CLI，使用当前解析项目、`Game, Battle` Context 配置和独立输出目标。生成 16 个 C# 文件，生成产物现归在 `Assets/GameScripts/HotFix/GameLogic/Runtime/Entitas/Generated/`。CLI 和生成插件未加入仓库。重新生成时可将该版本 `Jenny.zip` 解压到本地 `UnityProject/Jenny/`，再使用项目 Jenny 配置。[仓库生成说明](../../../Tools/Entitas/EntitasGen/README.md)

## 步骤 2 · 建立当局世界与系统装配位置

- [x] **新增 `BattleWorld.cs`。** 每局创建一个独立的 Battle Context 和系统树。按开战数据顺序创建单位并建立玩家 ID 到实体的映射。实体注册顺序与上游单位工厂创建逻辑更新组件的顺序对照。单位按开战顺序创建并接收当帧输入，查询按玩家 ID。世界从 `Frame = 0` 开始，完成 `Systems.Execute()` 和 `Systems.Cleanup()` 后加一。房间关闭前停止推进，随后 `TearDown()` 并释放当局的实体和索引。[单位工厂][unit-factory] · [实体调度顺序][world-updater] · [Entitas 系统顺序](../../.agents/skills/entitas-dev/references/systems-and-lifecycle.md)
- [x] **保留系统装配位置。** `BattleWorld` 继续初始化和推进 Entitas 系统树。已删除用于对账的示例移动系统及其默认注册。实际移动、伤害和技能系统在规则确定后加入 `Runtime/Battle`。

关键伪代码

~~~text
开局按初始单位顺序创建 Entitas 实体，Initialize() 初始化当局系统树

一次战斗世界 Tick
    Systems.Execute()
    Systems.Cleanup()
    World.Frame += 1
~~~

## 步骤 3 · 接本地输入与权威帧房间

- [x] **新增 `BattleFrameInputs.cs` 与 `BattleFrameBuffer.cs`。** 输入按开局时的单位槽排序。同一帧到期前多次提交时，取最后一次。到期时，缺失本帧输入的单位沿用上一帧，首帧缺失使用默认零值。显式零输入是有效提交，用来表示松键。封存结果保存到历史槽，由同一房间同步消费。[上游输入补齐][authority] · [上游帧容器][buffer]
- [x] **修改 `BattleModule.cs` 与 `BattleRoom.cs`。** 开战入口替换为接收 `BattleStartData`。在入口检查当前局和输入配置，保证单位 ID 唯一、开战单位包含本地玩家，并保留当局使用的初始化数据。提供针对当前房间的本地输入提交入口。房间持有世界、时钟、权威帧和帧容器。实现 `Tick(frame, inputs)`，由开局时的玩家 ID 决定本地槽和单位映射，按稳定槽把已确定输入写入世界，再执行一次世界 Tick；结束时先停止 FSM 的战斗进行轮询，再拆除房间资源。
- [x] **修改 `BattleUpdater.cs`、`InitializeBattleState.cs`、`StartBattleState.cs`、`RunBattleState.cs`。** 初始化状态建世界和输入槽，开战状态建立本局时间锚点。进行状态调用权威更新器，更新器按下列顺序直接推进房间。移除公开开战 API 上的帧号回调参数。现阶段 `BattleRoom` 提供读取已执行帧号及按 ID 查看逻辑位姿的入口，供阶段验收与后续表现层接入。[现有 FSM 推进入口](../../Assets/GameScripts/HotFix/GameLogic/Module/BattleModule/State/RunBattleState.cs) · [权威更新源码][authority]

关键伪代码

~~~text
StartBattle(startData)
    在模块入口校验并建立当局开战数据
    创建房间并启动四状态 FSM
    初始化状态：创建 BattleWorld、初始化系统树、创建输入槽
    开始状态：建立固定帧时钟与权威步进状态

战斗进行.OnUpdate
    nowMs = 单调整数毫秒
    nextFrame = room.AuthorityFrame + 1
    若 nowMs 小于 room.Clock.FrameTime(nextFrame)，返回
    inputs = room.FrameBuffer 封存 nextFrame 的完整输入
    room.Tick(nextFrame, inputs)

BattleRoom.Tick(frame, inputs)
    room.AuthorityFrame = frame
    将已确定输入按开局 ID 对应的稳定槽写到世界实体
    BattleWorld.Tick()
~~~

输入关联、FSM 状态切换等校验集中在外部入口。内部只消费已经确定的房间与帧数据。搬运涉及的数值分支按上游实现。脚本输入先通过同一提交入口注入，用于核对输入、帧号和房间生命周期。真实键盘采样、场景加载和显示接在后续单机进场步骤。

## 步骤 4 · 框架验收

- [x] **本次重整后的输入与帧验收。** 独立 .NET 宿主通过 81 项断言。两局覆盖第 0 帧、到期边界、卡顿一次只补一帧、同帧最后一次输入生效、缺失继承和显式零输入。确认本地输入只写入指定单位，位姿保持开局值，房间权威帧和世界下一帧相差一帧。
- [x] **本次重整后的房间验收。** Unity 6000.0.69f1 在验收副本完成首次导入并编译，控制台编译失败标志为 false。在 `Assets/Scenes/main.unity` 的 Play Mode 通过 94 项检查，两局均由场景中的 TEngine 主循环推进到帧 0、1、2。输入按钮值按 2、2、0 写入，另一单位保持默认输入。退局释放世界，旧房间拒绝输入和退出请求，新局从第 0 帧开始。

验收副本将 Pipeline 的本地依赖路径从原清单的 D 盘位置指向副本里的同版本包，原工程清单和场景文件保持原样。运行期间控制台错误数为 0。启动时已有 UniTask 和 YooAsset 目录命名警告各一条，进入主场景后出现一条 Missing Script 警告，早于战斗验收脚本运行。当前工程的 `main.unity` 中还保留了旧 `EntitasDemoBehaviour` 的脚本引用。

示例移动移除前曾用独立 .NET 宿主通过 293 项断言，包含两局各 13 帧的上游 TrueSync 位姿对账。该记录对应当时的示例系统。[之前的初始位姿][room-start] · [示例移动源码][movement] · [上游方向与旋转][unit]

## 步骤 5 · 按帧保存权威输入

- [x] **写入历史。** 到期后由 `BattleUpdater` 调用 `BattleFrameBuffer.Seal(nextFrame)`。封存时先补齐缺失输入，再复制到环形历史的当帧区间。槽记录实际帧号，默认容量为 1,200 帧，即 50 ms 步长下的 60 秒逻辑帧。房间消费的就是该区间的输入。[上游帧容器][buffer]
- [x] **读取历史。** `BattleRoom.TryGetFrameInput(frame, playerId, out input)` 复用世界的玩家 ID 到单位槽映射。查询只返回输入值，已覆盖、尚未推进的帧以及已退出房间返回 `false`。
- [x] **验收。** 用独立 .NET 宿主编译实际战斗代码和 Entitas 生成物，加载项目的 TEngine FSM，共通过 50 项检查。分别验证容量 1、3 和默认 1,200 的覆盖边界。两局都从空历史开始，读回非零输入、缺失继承和显式零输入，并核对历史和单位组件一致。此步未另跑 Unity Play Mode。
