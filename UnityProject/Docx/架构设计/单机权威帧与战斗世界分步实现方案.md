方案待确认。所有执行项均未开始。源码基线为 ET10 `master` 的固定提交 `743c635dd5b0f6f6bab549c0093382c85f3f8307`。已有时钟、`BattleModule`、`BattleRoom` 与四状态 FSM。当前调用链在更新器内只发出帧号回调。本阶段把它接到真实的输入和 Entitas 世界。[当前战斗房间](../../Assets/GameScripts/HotFix/GameLogic/Module/BattleModule/BattleRoom.cs) · [当前更新器](../../Assets/GameScripts/HotFix/GameLogic/Module/BattleModule/BattleUpdater.cs) · [前置差距分析](逻辑帧房间与战斗世界接线差距分析.md)

## 交付目标

以固定输入序列开一局本地战斗。每次 FSM 的战斗进行状态轮询，由本地权威更新器判定时钟。到期时封存该帧输入、更新权威帧号，经 `BattleRoom.Tick(frame, inputs)` 写入当局 Entitas，再由 `BattleWorld.Tick()` 执行实际的定点移动与旋转。能够读取逐帧位姿原始值，退局后以相同配置重开得到相同结果。首版输入通过脚本或调试入口提交。本阶段的输入槽只保留当帧和上一帧。后续按单机总方案接菜单、场景、实时设备输入、视图，以及完整的帧历史、快照、hash 和回放。预测、回滚、网络与校时列在联机阶段。[单机总方案](单机战斗完整迁移执行方案.md)

| 职责 | 所属对象 |
| --- | --- |
| 开局、校验外部请求、登记当前房间、提交本地输入、退局 | `BattleModule` |
| FSM 生命周期、当局时钟、权威帧号、帧输入槽、当局世界、把帧输入交给世界 | `BattleRoom` |
| 按单调整数毫秒判断到期、每次轮询最多推进一帧 | 现有 `BattleUpdater` |
| 保存未消费输入与上一帧的已确定输入，封存当前帧 | 新增 `BattleFrameBuffer`，当前只实现输入部分 |
| Entitas Context、单位索引、固定顺序的系统树、下一待执行帧 | 新增 `BattleWorld` |
| 写入位姿和朝向的规则 | Entitas 的 `BattleMovementSystem` |

开局时 `AuthorityFrame = -1`，`BattleWorld.Frame = 0`。执行第 `n` 帧时，房间先确认 `AuthorityFrame = n`，世界写完位姿并清理当帧后把 `Frame` 加为 `n + 1`。现有只读 `CurrentFrame` 返回房间的 `AuthorityFrame`。固定时钟仍以第 0 帧为锚点、50 ms 为步长。TEngine FSM 提供轮询入口，定点数学用于战斗演算。[帧时钟][clock] · [房间单帧处理][room] · [上游世界与帧号][world]

## 步骤 1 · 落定类型与生成接线

- [ ] **数据契约与组件。** 在 `Assets/GameScripts/HotFix/GameLogic/Module/BattleModule/` 下新增 `BattleStartData.cs`、`BattleUnitStartData.cs`、`BattleInput.cs` 及 `Components/` 中的单位 ID、移动输入、定点位置和定点旋转组件。开战数据提供本地玩家 ID 及按顺序排列的初始单位。帧输入保留对应玩家的定点二维方向，按钮值沿用上游 `LSInput.Button` 的数据语义，本阶段为零。单位创建、玩家 ID 查询和组件更新使用 Entitas 1.14.1 生成 API。
- [ ] **定点数学。** 扩展现有 `FixedPoint.cs` 的平方根和源常量转换，补 `FixedVector2`、`FixedVector3`、`FixedQuaternion` 及 `LookRotation` 实际依赖的定点矩阵计算。按固定提交移植实际调用路径。保留归一化、乘除顺序、舍入与矩阵转四元数分支。定点二维向量除标量时，上游先求倒数，再乘两个分量。后续位置、旋转以及常量均以原始值比较。[标量][fp] · [二维向量][vector2] · [定点矩阵][matrix] · [四元数][quaternion]
- [ ] **Jenny 接线。** 将战斗组件标入 `Battle` Context，在 `UnityProject/Jenny.properties` 添加 `Battle` 并保留当前 `Game` 配置。生成目标设到项目自己的独立生成目录，例如 `Assets/GameScripts/HotFix/GameLogic/Generated/Entitas/`。调整 `Tools/Entitas/EntitasGen/EntitasGen.csproj` 的 `Compile Include`，让它解析 battle 组件以及字段所用的定点类型。输出目录只存生成物，避免 Jenny 清理过程影响手写代码。[Jenny 配置](../../Jenny.properties) · [当前生成工程](../../../Tools/Entitas/EntitasGen/EntitasGen.csproj) · [Entitas 生成流程](../../.agents/skills/entitas-dev/references/jenny-and-integration.md)

## 步骤 2 · 建立当局世界并迁入示例移动

- [ ] **新增 `BattleWorld.cs`。** 每局创建一个独立的 Battle Context 和系统树。按开战数据顺序创建单位并建立玩家 ID 到实体的映射。实体注册顺序与上游单位工厂创建逻辑更新组件的顺序对照。第一版单位在开局时注册，用同一份稳定顺序执行移动，查询仍按玩家 ID。世界从 `Frame = 0` 开始，完成 `Systems.Execute()` 和 `Systems.Cleanup()` 后加一。房间关闭前停止推进，随后 `TearDown()` 并释放当局的实体和索引。[单位工厂][unit-factory] · [实体调度顺序][world-updater] · [Entitas 系统顺序](../../.agents/skills/entitas-dev/references/systems-and-lifecycle.md)
- [ ] **新增 `Systems/BattleMovementSystem.cs`。** 使用 Entitas 连续执行系统，读取已写入的定点方向。沿用上游的定点位移表达式和长度平方阈值，按 XZ 平面写位移，通过实际位置差求 `LookRotation`，保留定点四元数输出。源示例的 `Forward` setter 会计算四元数，位置差只作为旋转的输入。[移动源码][movement] · [方向与旋转源码][unit]

关键伪代码

~~~text
开局按初始单位顺序建 Entitas 实体，注册固定的移动系统，Initialize()

一次战斗世界 Tick
    Systems.Execute()
        按稳定逻辑更新顺序访问实体
        displacement2 = 输入方向 × 6 × 50 ÷ 1000
        若 displacement2.LengthSquared 小于上游阈值，结束这个单位的移动
        oldPosition = 单位位置
        更新定点位置，将二维位移映射到 XZ
        用新旧位置差和定点上方向计算旋转
    Systems.Cleanup()
    World.Frame += 1
~~~

## 步骤 3 · 接本地输入与权威帧房间

- [ ] **新增 `BattleFrameInputs.cs` 与 `BattleFrameBuffer.cs`。** 通过稳定的单位槽排序保存当帧和上一帧输入。同一帧到期前多次提交时，取最后一次。到期时，缺失本帧输入的单位沿用上一帧；首帧缺失使用默认零值。显式零输入是有效提交，用来表示松键。封存后把该帧输入同步交给房间，直到当帧处理结束才允许复用槽。将来扩展按帧索引的环形历史时沿用这一份输入载荷。[上游输入补齐][authority] · [上游帧容器][buffer]
- [ ] **修改 `BattleModule.cs` 与 `BattleRoom.cs`。** 开战入口替换为接收 `BattleStartData`。在入口检查当前局和输入配置，保证单位 ID 唯一、开战单位包含本地玩家，并保留当局使用的初始化数据。提供针对当前房间的本地输入提交入口。房间持有世界、时钟、权威帧和帧容器。实现 `Tick(frame, inputs)`，按玩家 ID 把已确定输入写入世界，再执行一次世界 Tick；结束时先停止 FSM 的战斗进行轮询，再拆除房间资源。
- [ ] **修改 `BattleUpdater.cs`、`InitializeBattleState.cs`、`StartBattleState.cs`、`RunBattleState.cs`。** 初始化状态建世界和输入槽，开战状态建立本局时间锚点。进行状态调用权威更新器，更新器按下列顺序直接推进房间。移除公开开战 API 上的帧号回调参数。现阶段 `BattleRoom` 提供读取已执行帧号及按 ID 查看逻辑位姿的入口，供阶段验收与后续表现层接入。[现有 FSM 推进入口](../../Assets/GameScripts/HotFix/GameLogic/Module/BattleModule/State/RunBattleState.cs) · [权威更新源码][authority]

关键伪代码

~~~text
StartBattle(startData)
    在模块入口校验并建立当局开战数据
    创建房间并启动四状态 FSM
    初始化状态：创建 BattleWorld、注册系统、创建输入槽
    开始状态：建立固定帧时钟与权威步进状态

战斗进行.OnUpdate
    nowMs = 单调整数毫秒
    nextFrame = room.AuthorityFrame + 1
    若 nowMs 小于 room.Clock.FrameTime(nextFrame)，返回
    inputs = room.FrameBuffer 封存 nextFrame 的完整输入
    room.AuthorityFrame = nextFrame
    room.Tick(nextFrame, inputs)

BattleRoom.Tick(frame, inputs)
    将已确定输入按玩家 ID 写到世界实体
    BattleWorld.Tick()
~~~

输入关联、FSM 状态切换等校验集中在外部入口。内部只消费已经确定的房间与帧数据。搬运涉及的数值分支按上游实现。脚本输入先通过同一提交入口注入，用于逐帧对账。真实键盘采样、场景加载和显示接在后续单机进场步骤。

## 步骤 4 · 逐帧对账与退局验收

- [ ] **数学对账。** 上游与本工程以相同定点原始值输入，比较归一化、位移、位置三轴和旋转四分量。首组用上游示例的初始位置 `(20, 0, -10)` 与单位旋转。第 0 帧输入 `(+1, 0)` 时，按上游先算倒数的路径推导，X 位移原始值为 `1,288,490,100`，X 位置原始值为 `87,187,836,020`。实施时再和上游输出逐值核对。覆盖零方向、四轴、斜向、连续变向和阈值附近。[初始位姿][room-start] · [向量除法][vector2] · [移动源码][movement]
- [ ] **时间与输入对账。** 假设开战锚点为 `1000 ms`。输入时刻 `999, 1000, 1049, 1050, 1200, 1200` 应依次推进 `无, 0, 无, 1, 2, 3`。按 `第 0 帧有输入 → 第 1 帧缺失 → 第 2 帧显式零`，验证移动、继承、停止。每次成功推进第 `n` 帧后应观察到 `AuthorityFrame = n` 和 `World.Frame = n + 1`。
- [ ] **宿主与房间验收。** 在实际 TEngine FSM 轮询中确认开战后才推进、每次轮询至多一次、退局后旧世界停止且索引释放。相同初始数据和输入重开，逐帧原始值一致。执行检查后在对应条目填写实际结果。

完成条件为单机真实输入能够修改当局 Entitas 的定点位置与旋转，并能明确从帧号追溯该帧使用的输入。当前文档只有实施步骤和预计结果。
