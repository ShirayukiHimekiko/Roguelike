# 战斗框架文件归位方案

`Runtime/Battle` 用于本项目的玩法和应用流程。`BattleModule` 管理当局生命周期、输入、逻辑世界和重演。原先放在 `Runtime/Battle` 的 13 个框架脚本已归入现有的 `Module/BattleModule`。

| 文件 | 目标目录 | 职责 |
| --- | --- | --- |
| `BattleWorld.cs`、`BattleUnitState.cs`、`BattleWorldSnapshot.cs` | `Module/BattleModule` | 持有当局 Entitas 世界和系统树、查询单位状态、导出与恢复快照 |
| `BattleInput.cs`、`BattleFrameInputs.cs`、`BattleStartData.cs`、`BattleUnitStartData.cs` | `Module/BattleModule` | 单帧输入、帧集合、开局数据和单位槽契约 |
| `BattleRecording.cs`、`BattleRecordingFile.cs` | `Module/BattleModule` | 逐帧录像、周期检查点、录像编解码和指定路径读写 |
| 四个基础组件 | `Module/BattleModule/Components` | 框架世界直接使用的单位 ID、定点位置、定点旋转和封存输入 |
| `LocalBattleFlow.cs` | `Runtime/Battle` | 本项目的菜单、场景准备、本地录像路径、退局和回放控制 |

正式的移动、技能、伤害、波次、表现和结算规则后续写在 `Runtime/Battle`。框架提供 `createSystems` 装配入口，由具体玩法选择系统。定点数学和通用 hash 位于 `Utility`，Jenny 生成产物在统一生成目录 `Runtime/Entitas`，验收 Demo 位于 `Tools/BattleFrameworkDemo`。

- [x] `EntitasGen.csproj` 的两处显式源路径已指向 `Module/BattleModule`，生成工程构建通过，0 警告、0 错误。
- [x] 单机执行文档和 Entitas 生成说明已更新。正式开局入口、Demo 和生成工程均使用当前目录与类型。
- [x] 正式开始按钮用空初始单位列表启动房间。临时 WASD 与空格采集已从正式入口移除。测试单位、固定输入序列、位移系统和视图标记集中在 `Tools/BattleFrameworkDemo`。
- [x] 在 Unity `6000.0.69f1` Play Mode 运行独立 Demo，25 帧定点位移与回放对账通过。正式开始按钮独立开出零单位房间，推进 5 帧后通过模块结束，将录像写到临时路径，再读回并核对回放帧 hash。

## Demo 的移除

删除 `UnityProject/Tools/BattleFrameworkDemo/` 即可统一移除测试单位、固定输入、移动系统和 Scene 视图标记。Demo 只由 Pipeline 显式运行，场景和正式程序集不持有 Demo 引用。正式玩法由 `Runtime/Battle` 自行提供初始数据、设备绑定、系统装配和表现。

```text
Runtime/Battle/LocalBattleFlow → BattleModule.StartBattle(..., createSystems)
BattleModule → BattleRoom → BattleWorld → 由玩法传入的 Entitas 系统树
```
