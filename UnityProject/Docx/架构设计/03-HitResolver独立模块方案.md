# 03 HitResolver 独立模块方案

Project B · 待确认

## 1. 目标与依赖

HitResolver 接收一批合法攻击请求、受击快照和旧命中记录，计算该批有序命中、生命变更和去重增量。调用者决定何时执行及何时提交，测试程序可以直接构造一批输入并调用。可以在战斗模块和帧驱动均未接入时端到端验收。

建议源码放在 `GameLogic/Module/HitResolution/`。其中几何查询、目标/攻击数据、结算算法和会话命中记录使用纯 C#，只依赖标准库和共享定点数值层。API 传业务 ID、形状和属性等值数据。收到的每一批由调用者有序提交，API 无帧时钟或 Entitas 类型，结果由调用者映射到战斗 Tick 和实体组件。

模块内部由 `HitGeometry` 生成几何候选，`HitResolver` 对候选归并、验证、计算并产生结果。选取圆盒扫描作为首期实现，后续空间索引或扫掠通过同一候选契约接入。 [Box2D 事件 API](https://box2d.org/documentation/group__events.html) · [OpenRA 范围伤害](https://github.com/OpenRA/OpenRA/blob/bleed/OpenRA.Mods.Common/Warheads/SpreadDamageWarhead.cs) · [OpenRA 指定目标伤害](https://github.com/OpenRA/OpenRA/blob/bleed/OpenRA.Mods.Common/Warheads/DamageWarhead.cs)

## 2. 定点相交与数值边界

建议使用独立的 `GameLogic/Math/FixedPoint/` 作为共享纯 C# 数值层，供战斗和本模块引用。采用 `Fixed64.Raw / 1_000_000`，可精确表示至多六位小数。配置从原始整数或固定文化十进制文本一次量化。超精度输入拒绝。定点乘除向零舍入，乘除在最终舍入前保证中间值准确，除零和溢出报告错误。热路径根据已校验的操作范围走 checked `long`。离线以 `BigInteger` 对照宽运算。选择该刻度是 Project B 的评审建议，应先用地图与配置的实际单位验证范围。 [FixedMath.Net 的 Fix64 源码](https://github.com/asik/FixedMath.Net/blob/master/src/Fix64.cs) · [Photon Quantum 的精度与溢出约束](https://doc.photonengine.com/quantum/v3/manual/quantum-ecs/fixed-point)

| 范围 | 做法 |
| --- | --- |
| 主体形状 | 二维轴对齐受击盒。先验证最小边界不超过最大边界。攻击圆半径非负。 |
| 圆与盒 | 各轴将圆心夹到盒的边界区间，求圆心到最近点的两轴差值。按原始整数比较 `dx² + dy² ≤ radius²`，边界相切计作几何重叠。 |
| 运算上界 | 原型建议圆心和盒边界在 ±1000 世界单位内，半径 ≤1000。每轴差值至多 `2×10^9 Raw`，平方和至多 `8×10^18`。创建盒和运行时移动后均校验边界。 |
| 输出容量 | 可受击目标数、形状数、攻击请求数及活跃攻击段上界决定各缓冲。达到容量上限而无法完整收集、排序或输出时，该批返回错误，不交付部分命中。 |

## 3. 输入、输出与所有权

| 数据 | 约定 |
| --- | --- |
| `AttackRequest` | 攻击实例 ID、命中段 ID、来源 ID、攻击定义 ID、形状或指定目标，并附该批计算所需的源攻击值和修正快照。调用者确保同一会话内实例 ID 唯一且不复用，段号在实例内不复用，每个实例的来源和定义固定。 |
| `TargetSnapshot` | 目标 ID、开始生命、受击形状、阵营和供规则读取的资格与防御数据。攻击开始资格经调用者固定，受击资格通过所提供的快照和规则判断。 |
| `HitCandidate` | 实例、段、目标、候选种类、攻击形状 ID 和受击形状 ID。直接伤害进入同一流程，规则仍检查它与该目标的合法关系。 |
| `HitLedger` | 调用者持有每场账本。Resolver 读取旧记录，返回本批增量。调用者在确认结果可提交时应用。攻击段关闭且本批所有候选处理完后回收其记录。 |
| `HitBatchResult` | 稳定序列的每击结果、每目标最终生命、首次从正值降到零的事实、段命中增量。每击包含批内序号、来源与目标、计算伤害、实际扣血、前后生命。 |
| `IHitRule` | 用显式进攻与受击快照校验资格并计算伤害。首期用固定伤害规则验收，正式公式由战斗侧装配。规则执行期间禁止改战场或读取会变化的外部对象。 |

生命与伤害使用同一单位，原型采用整数。浓缩后的击破事实只描述目标首次归零。塔种类、核心连带破损、计分、掉落和表现由战斗解释。结算调用可以复用工作缓冲，持久结果须在缓冲复用前由调用端转移或复制。

## 4. 归并与结算契约

去重键为 `(AttackInstanceId, SegmentId, TargetId)`，因此同一段可以伤害多个目标，而持续重叠对同一目标只结算一次。排序在三元组之后按候选种类、受击形状 ID、攻击形状 ID 决胜。原型优先合法的直接候选。等键的相同候选归并，同批身份相同却有冲突负载时报输入错误。跨批实例身份与段的关闭由调用者保证，关闭后回收段账本。脉冲重复命中用新段号。 [白井功名的持续帧防重复案例](https://www.gameres.com/657016.html)

```text
Resolve(requests, targetSnapshot, priorLedger, rule, buffers)
    预检输入身份、数值范围和缓冲容量
    将圆盒查询与直接路径的结果写成统一候选
    按稳定键排序并以命中去重键分组
    for each group
        取第一个满足 rule.Eligible 的候选
        跳过无资格候选、旧账本已有记录和工作生命已为零的目标
        damage = rule.Calculate(候选, 固定快照)
        若 damage 为负或超出生命计量范围：失败
        applied = min(damage, 工作生命)
        更新局部工作生命，生成每击结果和账本增量
        若旧工作生命为正且新值为零：生成一次归零事实
    返回完整批次
```

资格和防御以该批固定快照为准。工作生命逐击递推，便于稳定确定实际扣血和最后一击。例如 HP 5 先收 3 后收 4，结果为 3 与 2，第二击产生唯一归零事实。双方已产生的有效攻击即使同批归零也照常处理。免疫和非法候选不占去重键，评审默认合法零伤占去重键。异步、反击重入和后续攻击创建由调用方在批次外处理。

## 5. 实施清单和独立验收

- [ ] **形状与候选。** 明确共享定点输入域，完成圆盒相交、直接目标的统一候选表示以及容量判断。
- [ ] **结算。** 实现排序去重、固定规则注入和局部生命递推，产出批次及账本增量。
- [ ] **批次生命周期。** 写清结果缓冲借用期和账本提交/关闭行为。按提交顺序跑两批或多批合成输入，验证段复用和会话隔离。

| 独立用例 | 预期 |
| --- | --- |
| 相切、相离一 Raw、负坐标和最大合法域 | 按闭边界判定。超域拒绝，平方和无溢出。 |
| 同批多盒和跨批重复目标 | 同段同目标只确认一次，同段其他目标可命中。新段可再次处理该目标。 |
| 打乱同一组输入，重复或冲突身份 | 正常候选的每击顺序一致。完全重复归并，同身份冲突将整批拒绝。 |
| HP 5，命中 3、4、7 | 实际扣血 3 和 2，第三击跳过，仅一条归零事实。 |
| 免疫、合法零伤、负伤害和容量不足 | 按资格契约处理。负伤害和超容量失败时，旧账本与输入快照不变。 |

战斗侧如何生成攻击请求、提交 Entitas 和发布结果见 [战斗模块方案](02-Project_B-战斗模块方案.md)。
