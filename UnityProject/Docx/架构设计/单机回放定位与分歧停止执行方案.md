# 单机回放定位与分歧停止执行方案

- [x] **记录改动前基线。** Demo 构造 1,206 帧录像，量测 100→105 和 1,200→1,199，并注入错帧指纹。实际分别同步推进 106 和 1,200 帧；分歧第 3 帧仍执行。伪代码：`seek(1199); measure(ticks, elapsed); play(tamperedFrame); observe(lastExecuted)`。
- [x] **把重演交给房间更新器。** 已实现接收目标、复用健康的同区间正向世界、必要时恢复检查点，回放更新器按原有预算推进，完成后以当前倍速重新锚定时钟。伪代码：`request(target); while (next <= target && budget) tick(next); reanchor(target)`。
- [x] **在执行前停住分歧帧。** 输入先写入用于帧前对账；Hash 不一致时记录分歧帧、取消当前定位，不提交该帧历史与房间帧号，也不执行系统。世界停止在已投递失败帧输入、尚未执行该帧系统的状态；再次定位时从检查点重建以清除失败帧的输入。伪代码：`applyInput; capture; if (mismatch) stop; else commitAndExecute`。
- [x] **更新正式调用方和 Demo。** `SeekReplay` 返回值表示是否受理。调用方以 `ReplaySeekTargetFrame == -1`、`CurrentFrame == target`、`ReplayDivergedFrame == -1` 判断定位完成；连续按键按未完成目标累加。现有 Editor Demo 改成等待更新器完成。
- [x] **当前源码独立回归。** 同区间复用、跨区间和倒退重建、定位中替换目标、分批预算、恢复倍速、逐帧输入和指纹，以及普通播放/定位的分歧停止和恢复全部通过。录像格式、联机和玩法不变。
- [ ] **Unity Play Mode 现场验收。** CLI 未找到项目 Pipeline 实例；未运行正式菜单或 Editor Demo。

| 路径 | 修改前 | 修改后 |
| --- | --- | --- |
| 100→105 | 106 次 Tick，重建世界；同步调用约 5.36 ms | 5 次 Tick，复用世界；单次轮询约 0.10 ms |
| 1,200→1,199 | 1,200 次 Tick，单次同步调用约 47.78 ms | 1,200 次 Tick，分 6 次轮询，最长约 6.00 ms |
| 第 3 帧 Hash 不一致 | 当前帧和最后执行帧都为 3 | 当前帧和最后执行帧均为 2；失败帧没有已确认输入与指纹，重新定位恢复 |

耗时来自本机 .NET 宿主的轻量 Entitas Demo，倒跳案例的首次轮询显式注入过期预算以固定验证让步；它不是 Unity 主线程或正式玩法的性能指标。预算在每个 Tick 后检查，也包含首批恢复的耗时，因此不能承诺单次轮询硬性不超过 5 ms。复跑命令见 [Demo README](../../Tools/BattleFrameworkDemo/README.md)。
