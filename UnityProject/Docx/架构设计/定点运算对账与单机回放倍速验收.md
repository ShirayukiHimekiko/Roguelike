# 定点运算对账与单机回放倍速验收

日期：2026-11-18。

本轮只补框架验收，不增加生产玩法、网络或录像协议，也不修改战斗及定点运算实现。验收代码放在 [`Tools/BattleFrameworkDemo`](../../Tools/BattleFrameworkDemo/README.md)，可以单独移除。

## 执行目标与结果

- [x] **用上游源码逐项检查定点数。** 以 ET10 提交 `743c635dd5b0f6f6bab549c0093382c85f3f8307` 的 [TrueSync 定点标量][fp]、[向量][vectors]、[四元数][rotation] 作为参照。下载到 `Temp`，核对源码文件的 SHA-256，用同一宿主编译上游与项目当前 `Utility` 源文件。伪代码：`project = Utility(raw); upstream = TrueSync(raw); assert(project.RawValue == upstream.RawValue)`。实际执行 **793 项，0 差异**。范围包括标量转换、正负数和分数加减乘除、开方、3 个除零样本、二维和三维归一化、叉积、`LookRotation`。结论只适用于覆盖的样本，不代表全部溢出边界、完整 TrueSync API 或跨平台结果已通过。
- [x] **验证回放倍速与帧边界。** 上游 [回放更新器][replay] 用 `50 / speed` 的整数毫秒步长并保留当前权威帧的时间锚点。Demo 使用实际 `BattleModule`、`BattleRoom`、`BattleUpdater`、`BattleWorld`、TEngine FSM 与 Entitas，先录制 40 帧，再依次切换 `1× → 2× → 4× → 8× → 1×`。伪代码：`record(0..39); changeSpeed(speed); advance(due-1); assert(noTick); advance(due); assert(oneTick); catchUp(); assert(lastFrame == 39)`。实际步长为 `50/25/12/6/50 ms`；没有提前执行、漏帧、重复执行或越过末帧，40 帧的指纹和系统随机样本都一致。
- [x] **编译两个宿主入口。** `.NET 8` 独立宿主执行通过，使用 Unity 已编译的 `GameLogic` 和 `TEngine.Runtime`，由宿主轮询真实 FSM；绕过 Unity 场景启动和 Singleton 注册。Editor 分支另用 Unity 编辑器程序集做了编译检查，0 警告、0 错误。
- [ ] **在 Unity `main` 场景 Play Mode 重跑同一入口。** 本机已有该工程的 Editor 会话，CLI 未发现可连接的 Pipeline，保留了该会话。连上后按 [Demo 复跑说明](../../Tools/BattleFrameworkDemo/README.md) 执行 `ReplaySpeedDemo.Run`。这一步用于验收实际场景启动与 Unity PlayerLoop 接入。

当前回放验证用可控到期时间驱动真实更新器，并用足够迟的时间检查末帧上限。它没有测量真实墙钟吞吐或单次追帧的 5 ms 开销，也没有验证 Player、联网或跨平台回放。
