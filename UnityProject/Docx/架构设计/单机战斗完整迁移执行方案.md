# 单机战斗完整迁移执行方案

方案待确认，实施项尚未开始。现有 `BattleRoom` 和四状态 FSM 作为宿主。阶段目标是从开始菜单进入一局本地战斗，完成加载、操控、逐帧演算、显示、退局与重开，并能保存并重放这一局。

以 ET10 `master` 固定提交 `743c635dd5b0f6f6bab549c0093382c85f3f8307` 为准。Lockstep 示例的 `MatchCount` 是 `1`，进场仍经过匹配、服务器房间和开战消息。这套示例中可以直接对标的单机行为包括房间初始化、输入、逻辑帧、定点移动与转向、单位显示和回放。阶段内移植这些行为，本地流程负责原先由服务器提供的开战数据和已确定输入。伤害、技能、AI 和关卡规则由项目自己的战斗需求定义。[示例常量][constants] · [进场路径][scene-change] · [房间开战][room-start] · [移动演算][movement]

## 2. 当局职责与确定性

- `BattleModule` 提供一次开战与退局入口。实际进场接入后，建议由调用方传入场景与初始单位数据，由 `BattleRoom` 自己装配系统并执行当帧，替换骨架阶段的公开帧回调参数。
- `BattleRoom` 是 FSM 的 Owner，持有本局开战参数、时钟、更新器、输入、Entitas Context、系统树和当局资源。FSM 负责「战斗初始化 → 战斗开始 → 战斗进行 → 战斗结束」。初始化等待加载和逻辑准备。开始状态才采集锚点。进行状态由现有 TEngine FSM 轮询。结束状态断开步进，按顺序释放系统、实体和场景。
- `BattleUpdater` 保留固定帧的判定与提交。每次由 `RunBattleState.OnUpdate()` 调用，以单调整数毫秒判断到期。局内系统按固定顺序执行。上游更新排序依据注册的逻辑实体 ID，适配时用建局时确定的更新顺序保留其语义，Unity 容器或 Entitas Group 的遍历顺序不作为对账依据。
- Entitas 持有逻辑位置和旋转。Unity 表现读取逻辑输出再转浮点并做插值，输入桥接和视图通过稳定玩家 ID 与本局关联。

~~~text
StartUI 开始按钮 → BattleModule 请求开战并创建 BattleRoom
    战斗初始化：加载场景，创建当局 Entitas 实体和系统，绑定本地输入及视图
    战斗开始：采集单调毫秒，初始化时钟、更新器和输入来源
    战斗进行：
        TEngine FSM 回调 → 下一帧到期？
        到期 → 封存当帧输入 → 提交帧号 → 写入单位 → 记录输入与可选快照
             → Systems.Execute() → Systems.Cleanup() → 向表现层提供新的逻辑状态
    战斗结束：停止帧推进 → TearDown 与实体清理 → 释放视图和场景 → 回到菜单
~~~

对账使用相同起始数据、相同帧号和相同逐帧输入。验收数据以定点分量的 `RawValue` 为准，Unity 插值后的浮点坐标只用于显示。回放快照标明帧边界，复算时需要明确快照是演算该帧之前的状态。[当前战斗房间](../../Assets/GameScripts/HotFix/GameLogic/Module/BattleModule/BattleRoom.cs) · [当前战斗进行状态](../../Assets/GameScripts/HotFix/GameLogic/Module/BattleModule/State/RunBattleState.cs) · [Room 输入与录制顺序][room]

## 3. 实施顺序

### 第一个交付点 · 能从菜单完整打一局

- [ ] **接实际进退场。** 接通已有 `StartUI` 开始按钮。把场景加载与当局准备放进战斗初始化状态，通过 `GameModule.Scene` 管理场景，模型实例通过 `GameModule.Resource` 加载。创建时进入初始化，成功后切到战斗开始。首个可玩场景用项目内的简单场景与单位模型，以开始、移动、退局、重开为验收路径。[StartUI](../../Assets/GameScripts/HotFix/GameLogic/UI/StartUI.cs) · [项目场景模块](../../Assets/TEngine/Runtime/Module/SceneModule/ISceneModule.cs) · [上游进场][scene-change] · [上游视图建立][scene-finish]
- [ ] **接落地的 Entitas 组件和生成。** 拟增加独立 `Battle` Context，由房间创建与释放。第一批数据包含单位 ID、移动输入、定点位置和定点旋转。项目当前 `Jenny.properties` 只声明 `Game`，输出指向 `EntitasDemo/Generated`，生成项目也只纳入 Demo 组件目录。实施时补齐战斗 Context 配置和 `Compile Include`，让生成项目能解析真实手写组件及其定点字段类型，将 Jenny 产物归入项目业务源码的生成目录。先生成并接通创建、查询与替换，再开始演算。[Jenny 配置](../../Jenny.properties) · [生成工程](../../../Tools/Entitas/EntitasGen/EntitasGen.csproj) · [Entitas 系统生命周期](../../.agents/skills/entitas-dev/references/systems-and-lifecycle.md)
- [ ] **补输入与定点数学依赖。** 输入桥保留 WASD 方向语义，先形成整数轴，再走源码同等的定点归一化。每帧按玩家 ID 封存输入，首帧无输入为零。扩展现有 `FixedPoint`，补精度一致的常量转换及平方根，沿调用链适配二维、三维向量和矩阵、四元数所需运算。数学类型随实际输入和移动调用迁入。[输入采样][input-view] · [定点标量][fp] · [二维归一化][vector2] · [定点矩阵][matrix] · [定点转向][quaternion]
- [ ] **迁移示例战斗演算。** 单位初始化沿用源初始数据与顺序。每帧先写输入，再执行 Entitas 移动系统。按源码保留 `V × 6 × 50 ÷ 1000` 的运算顺序、位移长度平方阈值、XZ 位移与按实际位移计算四元数朝向。静止、四轴、斜向、松键、阈值附近、连续变向都逐帧对照位置与旋转原始值。[单位工厂][unit-factory] · [移动演算][movement] · [朝向属性][unit]
- [ ] **接单位显示、退出和重开。** 实现逻辑单位到 Unity 视图的映射、位姿同步、移动动画和跟随镜头所需行为。用同样的输入序列，在不同渲染帧率下比较相同逻辑帧的输出。退局后旧单位、场景、输入和系统按当局生命周期释放，重开从新锚点和第 0 帧开始。[单位视图][unit-view] · [动画][animator] · [相机][camera]

### 第二个交付点 · 能录制、播放和回看这一局

- [ ] **录本地数据。** 保存单位开战数据和已确定的每帧输入，按上游记录点生成阶段快照。数据使用项目自己的本地记录格式，保存定点原始值和稳定 ID。文件 IO 放在业务边界，采用项目异步流程。[录像数据][replay-model] · [记录点][room] · [上游保存入口][replay-helper]
- [ ] **回放同一套 Entitas 演算。** 以录像初始状态建房，由回放路径按帧获得记录输入。先验收 1 倍完整播放的每帧结果，再接上游的 1、2、4、8 倍速和快照跳转。回放的追帧和时间预算单独适配到回放路径，权威实时战斗的单次轮询推进规则继续保留。[上游回放进场][scene-change] · [回放更新与速度][replay-updater]
- [ ] **核对回放跳转边界。** 上游录制在帧内演算前取快照，间隔为 60 秒对应的逻辑帧数。对照跳转后的恢复边界，覆盖首帧、相邻快照边界、跨边界和向后跳转。用连续播放结果逐帧比较恢复结果，出现帧序差异时记录对应快照和输入帧后再决定处理方式。[快照记录][room] · [快照间隔][constants] · [跳转逻辑][replay-helper]

两阶段按相同原则迁移。外部输入与生命周期校验在入口完成一次。状态和演算系统消费已经确定的数据。源码的算术条件和异常语义保留。项目层新增分支须对应实际流程，新增防御先说明已确认风险与代价。没有明确恢复需求时直接让错误沿现有调用链传播。
