# 01 帧驱动独立模块方案

Project B · 待确认

## 1. 目标与依赖

帧驱动模块把宿主传入的整数纳秒转换为连续的逻辑 Tick，为每条时间通道提供固定步进、限步、调试暂停与单步、到期任务和相位信息。通用模块独立用纯 C# 实现，可以用「每步把计数加一」的通道完成开发和验收。

模块只接收时间值、通道接口和步进回调。帧序内的战斗规则、Entitas Context、几何查询和命中结果都归调用端。时钟用整数相位运算，倍率的百万分之一刻度是时钟自身的整数单位。它和战斗定点数即使使用相同的刻度，也各有独立类型和约束。

建议源码位置为 `GameLogic/Module/Frame/`。纯 C# 源可以独立编译。首期在 Unity 中沿用现有 GameLogic 热更程序集，依赖边界由模块 API、命名空间和独立编译验收约束。独立 asmdef 涉及 HybridCLR 打包和 AOT 保留，待实施时单独决定。

## 2. 对象和所有权

| 对象 | 接口草图 | 职责 |
| --- | --- | --- |
| `FrameCore` | `Register(channel)`、`Unregister(channel)`、`Update(elapsedNs)`、`Dispose()` | 按 Order、同级注册序迭代通道。注册成功即接管通道生命周期，每个实例只注册一次。 |
| `ITimeChannel` | `Order`、`Advance(elapsedNs)`、`Dispose()` | 声明一条由调用方定义的独立时间流。通道可以组合时钟和定时器。 |
| `FrameClock` | `Advance(elapsedNs, executeStep)`、`CommittedTick`、`TickRate`、`Phase`、`SetDebugPaused()`、`RequestDebugStep()` | 计算各步候选编号和预算，执行成功才提交编号。以整数 Phase 和固定分母暴露分数进度。 |
| `FrameTimer` | `BeginTick(tick)`、`Once(delay, callback)`、`Repeat(interval, callback)`、`Cancel(handle)` | 按截止 Tick 稳定派发同步任务。调用方把它安排在业务步的指定位置。 |

Core 在同一线程按序执行。分发中新注册的通道下一轮生效，注销请求可跳过同轮尚未运行的通道，通道在分发收尾释放。禁止重入。故障通道退出本轮和后续循环，Core 保留可供宿主读取的故障记录，其余通道仍可推进。调用端负责处理自己已写入的状态。

## 3. 时间语义

- 每个 Clock 从 Tick 0 开始，步长为精确的 `1 / TickRate` 秒，候选编号为上次提交编号加一。普通返回或者请求在本步后停止都提交本步。若步进抛错，保留上一提交编号，故障通道由 Core 退场。
- 建议上下限为 `1..240 Hz` 和 `0..4` 倍速。Project B 以 **60 Hz、每次最多 4 步、1 倍速**作为待确认的调用配置。长于 1 秒的宿主采样先截时长，记录截去的纳秒。再丢弃超预算的整步时间，记录丢掉的整步数，保留小于一步的相位。已提交编号始终连续。
- 调试暂停保留相位，暂停期间无普通步进且不积攒时间。暂停时最多挂起一个单步请求，下次 Advance 执行一 Tick，成功后清零相位。恢复时取消尚未消费的单步。推进中请求暂停或终止时，当前步完成后立即停止剩余步数。常量倍率在本轮开始时读取。
- Phase 是精确的分子。宿主在显示边界用浮点除法得到 Alpha。暂停、插值快照和传送的显示策略由消费方处理。

```text
PhaseDenominator = 1_000_000_000 × 1_000_000
Advance(elapsedNs, executeStep)
    若暂停：
        若消费到单步请求：RunStep(executeStep); phase = 0
        返回
    若 scaleRaw == 0：返回
    elapsed = min(elapsedNs, 1_000_000_000)
    total = phase + elapsed × scaleRaw × tickRate
    whole, phase = DivRem(total, PhaseDenominator)
    budget = min(whole, maxSteps)
    记录截去的纳秒和 whole - budget
    在 budget 内逐步调用 RunStep
    收到 StopAfterCommit 或暂停时停止余下预算

RunStep(executeStep)
    candidate = committedTick + 1
    directive = executeStep(candidate, tickRate)
    committedTick = candidate
    返回 directive
```

最大正常输入的乘积为 `9.6 × 10^17`，加相位仍在有符号 `long` 范围内。输入校验拒绝负时间、非法步频或预算、超范围倍率。截止加法和 Tick 自增使用显式溢出检查。与渲染时间、固定步余量和降速有关的参考来自 [Glenn Fiedler 的固定步长设计](https://gafferongames.com/post/fix_your_timestep/) 和 [Bevy 的 Fixed 调度源码](https://github.com/bevyengine/bevy/blob/main/crates/bevy_time/src/fixed.rs)。

## 4. 到期任务

计时器按「截止 Tick、登记序」派发。开始派发前先推进计时器的当前 Tick，延迟与周期至少 1 Tick，因此本步新加的任务最早下一步执行。同一截止批次中，先执行的任务可以取消未执行项，重复任务可以自取消，未取消时从上次截止 Tick 推导下一次。句柄包含计时器身份，注销通道清理剩余任务。任务只在所在线程执行。需要重放的业务应存截止字段或具名任务数据，任意委托和异步 continuation 留给宿主侧用例。

## 5. 实施清单和独立验收

- [ ] **时钟。** 实现整数相位、倍率、限步、提交号与暂停单步。用可控的纳秒序列和记录候选编号的回调驱动。
- [ ] **通道。** 实现稳定注册序、注销延迟、故障隔离和释放。使用多个计数通道和一个失败通道验收。
- [ ] **帧定时器。** 实现同截止顺序、取消和周期重排。用回调记录执行编号和取消行为。

| 独立用例 | 预期 |
| --- | --- |
| 60 Hz 下依次收到 8ms、9ms、200ms | 执行 0、1、4 步。最后一次丢 8 整步，保留 0.02 步相位。 |
| 60 Hz 下先输入 16,666,666ns，再输入 1ns | 先 0 步再 1 步。把 1 秒均匀拆成约 1/60 秒的 60 段后累计应提交 60 步。 |
| 暂停、半速、单步和停止 | 暂停无时间债务，单步提交一次，停止在已完成的当前步。 |
| 通道新增、退出和故障 | 同序按注册顺序，新注册下一轮推进。故障候选编号未提交，其余通道继续，退场只释放一次。 |
| 定时器同截止取消和重复 | 登记顺序稳定。执行中取消后项、自取消、跨通道句柄、新任务延后一 Tick 均有明确结果。 |
