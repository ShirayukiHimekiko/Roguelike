## 1. 分层与调用约定

### 1.1 分层

```
表现层（UIWindow / 演出）        ← 只读状态，通过 GameEvent 接收通知
─────────────────────────────────
规则层（Game/*）：谁持有状态谁负责结算
─────────────────────────────────
基础设施（GameModule.Resource / ConfigSystem / Utility.Json / Audio / Log）
```

**铁律**

| # | 规则 | 原因 |
|---|---|---|
| R1 | 表现层**不得**直接改规则层字段，只能调 `Module` 的公开方法 | 状态只有一个写入口 |
| R2 | 规则层**不得**引用 `UnityEngine.UI` / Prefab | 逻辑要能脱离场景跑（Debug 场景 + 未来单测） |
| R3 | 模块间通信：同步查询用接口，跨状态通知用 `GameEvent` | 沿用框架既有模式，不引入新总线 |
| R4 | 所有 IO（存档、读表、加载资源）用 `UniTask`，禁止协程 | 项目编码红线 |
| R5 | 随机统一走 `PcRng`，禁止 `UnityEngine.Random` / `System.Random` | 必须可复现（C-14） |
| R6 | 时间统一走 `Day` / `TripTime` 计数器，禁止 `DateTime.Now` 参与规则 | 存档可精确恢复 |

### 1.2 模块注册

在 `GameModule` 上扩展业务模块访问器（沿用现有 `UIModule` 的写法）：

```csharp
public static GameFlowModule Flow { get; }
public static MapModule Map { get; }
public static TravelModule Travel { get; }
public static DockModule Dock { get; }
public static StationModule Station { get; }
public static GridCardModule GridCard { get; }
public static DrawModule Draw { get; }
public static MapEventModule MapEvent { get; }
public static StaminaModule Stamina { get; }
public static TrainModule Train { get; }
public static CharacterModule Character { get; }
public static StoryDirector Story { get; }
public static EconomyModule Economy { get; }
public static QuestModule Quest { get; }
public static SaveModule Save { get; }
```

- 业务模块是**普通 C# 类**（不进 `ModuleSystem`），由 `GameApp` 的启动逻辑按依赖顺序创建。
- 生命周期：`Init(ConfigSystem, SaveModule)` → `NewGame(seed)` / `LoadSave(data)` → `Tick(deltaTime)` → `Dispose()`。
- **只有 `GameFlowModule.Tick` 由外部驱动**，其他模块不自己 Tick（避免时序竞争）。
- 为什么不进 `ModuleSystem`：`ModuleSystem` 的模块是**框架级、全局单例、随应用生命周期存活**的；业务模块需要"开局创建 / 结束销毁 / 读档重建"，用普通类 + 显式依赖注入更直接，也方便在 Debug 场景里脱离 Unity 跑一遍生成与结算。

### 1.3 事件命名

`GameEvent` 用于"发生了什么"，格式 `<系统>.<事件>`：

| 事件 | 载荷 | 订阅方 |
|---|---|---|
| `flow.state.changed` | `(FlowState old, FlowState now)` | 表现层切场景/UI |
| `map.region.unlocked` | `regionId` | 地图渲染、小地图 |
| `cell.placed` | `HexCoord` | 地图渲染 |
| `draw.session.started` | `sessionId, offeredCardIds[]` | 抽卡面板 |
| `draw.guarantee.injected` | `count` | 抽卡面板（提示"保底"） |
| `time.day.changed` | `day` | HUD、剧情 |
| `story.queue.updated` | `count` | HUD |
| `station.repaired` | `stationId` | 地图、HUD |
| `event.fired` | `cellCoord, eventId` | 事件面板 |
| `battle.finished` | `result` | 流程/结局 |

> 命名必须与本文档一致，UI 侧订阅错误的事件名不会有编译错误，只会在运行时"没反应"。

## 2. 时间模型（双时钟）

> **依据**：策划案"行驶推进时间"+"回休息站才推进时间"两句话，只有拆成两个计数器才能同时成立。若不拆，`Day` 会被路上每格消耗推进，与"回站才推日期"直接冲突。见 G-01。

### 2.1 两个量

| 量 | 类型 | 推进时机 | 用途 | 存档 |
|---|---|---|---|---|
| `TripTime` | float | 行驶时每格 `+= BaseCost / TrainSpeed` | 本趟行程表现、事件条件 | ✅（也可按 Trip 重置，仍建议存） |
| `Day` | int | 入站结算"强制休息" `+1`；剧情可 `+N` | 剧情触发、神降日、Rank 门槛 | ✅ |

### 2.2 契约

```csharp
public sealed class TimeScheduleModule
{
    public int Day { get; private set; }
    public int DescentDay { get; private set; }
    public float TripTime { get; private set; }

    /// 行驶推进：只在 Driving 状态调用，一格调一次。
    public void AdvanceTrip(float cellBaseCost, float trainSpeed);

    /// 天数推进：只在 Settling 状态的"强制休息"和"剧情加天"里调用。
    public void AdvanceDay(int delta, DayAdvanceReason reason);

    /// 时间修正（事件/剧情/道具挂上来的）。
    public void AddModifier(TimeModifier modifier);
    public bool IsDescentDay => Day >= DescentDay;
}
```

| 边界 | 行为 |
|---|---|
| `cellBaseCost <= 0` 或 `trainSpeed <= 0` | **报错**并发日志（配置问题，不静默兜底），读取时跳过该格路耗为 0 |
| `AdvanceDay` 一次推进跨过多个剧情触发点 | 合法。剧情队列按 `triggerDay <= Day` 收集（见 §12） |
| `Day` 超过 `DescentDay` | 合法（剧情加天可能超），但只在结算第 7 步判定终局，中途不打断 |
| 时间修正为负数（延迟神降） | 合法，但 `DescentDay` 不得小于当前 `Day`（会立刻触发终局），需夹紧并报日志 |

## 3. 核心状态机

### 3.1 状态定义

```csharp
public enum FlowState
{
    None,
    Driving,    // 行驶：推进 TripTime，禁开决策面板
    Docked,     // 停靠：格内处理 / 站内功能
    Settling,   // 结算：入站结算 7 步
    Finale,     // 终局：神降战 + 结局
    Ended,      // 局结束
}
```

### 3.2 迁移表（唯一合法路径）

| From | To | 守卫条件 | 副作用 |
|---|---|---|---|
| `None` | `Docked` | 新局/读档且停在站 | 打开站内 UI |
| `Docked` | `Driving` | 玩家点了「出发」且路线合法 | 创建 `TripContext`，清空本趟临时状态 |
| `Driving` | `Docked` | 抵达**可停靠**格 | 冻结 TripTime，构造 `DockContext` |
| `Docked` | `Settling` | 当前位置是固定站或临时站，且玩家结束站内操作 | 构造 `SettlementContext(step = Arrive)` |
| `Settling` | `Docked` | 7 步走完且未到神降日 | 恢复站内，允许出发 |
| `Settling` | `Finale` | 第 7 步 `IsDescentDay == true` | 进入战斗 |
| `Docked` | `Finale` | 读档时已是神降日且玩家确认开战 | 同上 |
| `Finale` | `Ended` | 战斗结束 + 结局结算 | 写结局存档 |

**非法迁移**：其余全部 `Log.Error` + 忽略请求（不抛异常，避免把玩家卡在坏状态里）。

```csharp
public sealed class GameFlowModule
{
    public FlowState State { get; private set; }

    /// 唯一迁移入口。内部做守卫校验。
    public bool Transition(FlowState to, object context = null);

    public void Tick(float deltaTime);   // 唯一被外部驱动的 Tick
}
```

### 3.3 入站结算 7 步

```csharp
public enum SettlementStep
{
    Arrive = 1,       // 回到休息站
    DrawCards = 2,    // 抽完囤积的格子选择
    Dialogue = 3,     // 和成员对话
    ForceRest = 4,    // 对话次数归零 → 强制休息
    AdvanceDay = 5,   // Day + 1
    StoryQueue = 6,   // 按天数判剧情（内部循环）
    DescentCheck = 7, // 神降日到了吗
    Done = 8,
}
```

| 要求 | 说明 |
|---|---|
| 顺序写死 | 不允许重排（策划案原文"顺序写死"） |
| 可中断可恢复 | `SettlementContext.Step` 进存档；进程被杀后重进从该步继续 |
| 每步幂等 | 进入某步后若中途退出再进来，不得重复发放奖励（用 `StepDoneMask` 标记） |
| 可调试跳步 | `Debug.SkipSettlementStep` 只在编辑器/调试包生效 |

## 4. 地图数据契约

### 4.1 坐标

Axial 坐标 `(Q, R)`，六邻接：

```csharp
public readonly struct HexCoord : IEquatable<HexCoord>
{
    public readonly int Q;
    public readonly int R;
    public int S => -Q - R;

    public static readonly HexCoord[] Directions =
    {
        new( 1,  0), new( 1, -1), new( 0, -1),
        new(-1,  0), new(-1,  1), new( 0,  1),
    };

    public static int Distance(HexCoord a, HexCoord b)
    {
        int dq = a.Q - b.Q, dr = a.R - b.R;
        return (Math.Abs(dq) + Math.Abs(dr) + Math.Abs(dq + dr)) / 2;
    }

    /// 打包成 int 作字典键：Q/R 各 16 位，够 -32768..32767 的图。
    public int Pack() => (Q << 16) ^ (R & 0xFFFF);
}
```

| 约束 | 值/说明 |
|---|---|
| 地图尺寸上限 | 建议 `|Q|,|R| <= 64`，超过视为配置错误【推断】 |
| 字典键 | 用 `int` 打包键做 `Dictionary<int, CellRuntime>`，不用引用相等 |
| 邻接遍历 | 6 方向，不做"环面"（World Wrap） |

### 4.2 运行时格子

```csharp
public enum TerrainType : byte { Void = 0, Sea = 1, Land = 2 }

public enum CellKind : byte
{
    Empty = 0,          // 陆地空位（可铺卡）
    Village = 1,        // 城镇类 tier 1
    Town = 2,           // 城镇类 tier 2
    City = 3,           // 城镇类 tier 3
    Dungeon = 10,
    Sanctuary = 11,
    Miracle = 12,
    EnemyNormal = 20,
    EnemyElite = 21,
    EnemySpecial = 22,
    Unknown = 30,
    Resource = 31,
    FixedStation = 40,
    TempStation = 41,
    Relay = 42,
    SeaTrack = 50,
}

public sealed class CellRuntime
{
    public HexCoord Coord;
    public TerrainType Terrain;
    public CellKind Kind;
    public int RegionId;            // 0 = 不属于任何区域（海/虚空）
    public int StationId;           // >0 表示站点格
    public int CardInstanceId;      // 由哪张格子卡铺成；0 = 生成
    public int Rarity;              // 1..5；0 = 不适用
    public int MaxUses;             // 0 = 无限（策划案"写 0 就是无限次"）
    public int RemainUses;
    public int Level;               // 城镇类：1..；其他类型可恒为 1
    public int Tier;                // 城镇类 1/2/3，= Ceil(Level / 3)

```

| 规则 | 说明 |
|---|---|
| `MaxUses == 0` | 表示无限次，`RemainUses` 恒为 0，消耗时直接跳过 |
| `Tier` | 派生字段，不单独存。`Tier = (Level + 2) / 3` 钳到 1..3 |
| `Kind` 与 `Terrain` | `SeaTrack` 的 `Terrain` 仍是 `Sea`；可通行判定看 `Kind`，不看 `Terrain` |

### 4.5 生成流水线（伪代码）

```text
Generate(config) -> MapBuildResult { HexGrid grid, CrossingList list, int demand }

1. 地形层
   a. rand = PcRng(channel = MapGen, seed)
   b. 起点大陆：选中心格，随机 2~4 个附属点，用"随机方向游走 + 半径抖动"生长
   c. 远方大陆：随机选一个距起点 >= R_far 的位置，重复 1~2 次
   d. 岛：随机 1~3 个，半径 2~4
   e. 未覆盖 = Sea；地图外 = Void
2. 区域与站
   a. 起点站放在起点大陆中心
   b. 其余固定站/坏站/临时站按配置模板放（数量随区域）
   c. 每座站归属一个 Region；Region = 从站出发的可达陆地格集合
3. 格子层（每区域独立）
   a. 从站的邻格开始；每次从"最外圈"随机挑一格，向随机方向长一格
   b. 7 成向外扩、3 成回填内部空洞；距站越远，生长概率乘衰减系数
   c. 长到 CellsPerRegion 或达到 MaxDepthPerStation 停止
   d. 只落在 Land 上
4. 削边
   a. 给每个"最外圈格"一个随机值，< 阈值则删（置回 Empty/Land 或直接删格）
   b. 削完检查：站/固定副本是否仍可达；被切断就把它补回来
5. 打洞
   a. 区域内部随机挖 1~2 团，每团 3~6 格，挖成 Void（不可通行）
6. 硬约束
   a. 每座站至少 2 条边不重叠的路（见 4.6 校验算法），不满足则在站周补实心格
   b. 每个固定副本 6 邻接补满实心格
   c. 总格数 > TotalCellCap：按"距最近的站的距离"降序删边缘格
7. 连通性总校验：所有站 + 所有固定副本互相可达（用 BFS）
8. 算跨海账：见 §7.4，写入关卡配置
9. 若 demand > MaxCrossingDemand：重掷（seed + 1），最多 MaxReroll 次；仍失败则 Log.Error 并放行（不阻塞玩家）
```

**确定性要求**：同 `Seed` 必须得到完全相同的格子集合与跨海清单。实现上：单一 `PcRng` 实例按固定顺序消费随机数，**不允许**在生成过程中"按字典遍历顺序"取值（`Dictionary` 顺序不稳定）——生长候选集必须先排序或按坐标打包排序。

### 4.6 "每站两条路"校验算法

要求：从站出发的两条路，**除站本身外不共用任何格**。

```text
CheckTwoDisjointPaths(station):
  neighbors = 站的 6 邻格中 Walkable 的
  for each 有序对 (n1, n2) from neighbors:
      p1 = BFS(n1 -> 任意"区域边界格"), 禁止经过 station
      if p1 == null: continue
      blocked = p1 的中间格
      p2 = BFS(n2 -> 任意"区域边界格"), 禁止经过 station 和 blocked
      if p2 != null: return true
  return false
```

| 失败处理 | 动作 |
|---|---|
| 第 1 轮失败 | 在站的邻格补 1~2 个实心格后重试（最多 3 轮） |
| 3 轮仍失败 | 整张图重掷（同 §4.5 第 9 步） |
| 重掷用尽 | `Log.Error`，保留地图但记录 `MapQualityIssue`，不阻塞开局 |

**复杂度**：站数 × 邻格对数 × BFS(O(N))，N ≤ 400，可忽略。

### 5.2 路线枚举

**问题**：策划要"能走通的路全部列出来"，但简单路径数量在地图上是指数级的。

**方案**：DFS + 深度剪枝 + 结果截断。

```text
EnumerateRoutes(start, end, maxResults = 32, maxExpansion = 20000):
  shortest = BFS 最短格数
  budget = shortest + MaxDetourDelta   // 建议 6，配置化
  results = []
  DFS(cur, visited, path):
      if expansionCount > maxExpansion: throw/return partial
      if cur == end: results.add(path); return
      if path.Count >= budget: return
      for nb in 6 方向:
          if !Walkable(nb) or visited(nb): continue
          DFS(nb, visited + nb, path + nb)
  return results 按 CellCount 升序，去重（路径格集哈希）
```

| 参数 | 建议值 | 说明 |
|---|---|---|
| `maxResults` | 32（UI 展示前 8） | 超出的进"更多路线"折叠 |
| `maxExpansion` | 20000 | 触达则停止，返回已找到的（不是失败） |
| `MaxDetourDelta` | 6 | 只接受"比最短路多 6 格以内"的路线，超出视为绕路无意义 |
| 去重键 | 排序后的坐标序列哈希 | 防止同一路由不同方向重复 |

> 若地图出现"两站直连一条、绕行 3 条"的极端连通，`DFS` 仍可能触达上限。**触达上限不是错误**：UI 显示"仅展示前 N 条"，玩家最关心最短路。

### 5.3 Trip 推进

```text
StartTrip(route):
  Flow.Transition(Driving, new TripContext(route))
  Trip.Cursor = 0

OnTick(Driving):
  if 尚未到下一格: 走动画/补间（表现层）
  next = Path[Cursor + 1]
  cell = Map.Get(next)
  Time.AdvanceTrip(CellCost.Of(cell), Train.BaseSpeed)   // 路耗 = 基础耗时 ÷ 速度
  Cursor++
  if CellRules.IsDockable(cell):
      Flow.Transition(Docked, new DockContext(next, alongTrip: true))
  else if next == Path[^1]:
      // 站一定是 Dockable，走到这里说明配置/生成坏了，不要静默吞掉
      Log.Error($"[Trip] 终点不可停靠 coord={next} kind={cell.Kind}")
```

> `CellCost.Of(cell)` 是配置查询（按 `CellKind` / 卡的 `BuildCost` 取"格子基础耗时"），**不是** `CellRuntime` 的字段——耗时属于配置域，不进存档。

| 边界 | 行为 |
|---|---|
| 路线中途被玩家铺的卡"截断" | 不可能：行驶中不能建造（C-02/C-03） |
| 路线中途格被事件删除 | 不允许事件改地形（事件效果白名单里没有"删格"） |
| 终点站被"用尽"（临时站次数归零） | 到达时仍可停靠一次？见 G-16；默认允许本次停靠，停完降为中继格【推断】 |
| `Cursor` 越界 | `Log.Error` + 强制结算，不静默循环 |

**一次会话的规则**

6. 保留上限 `RetainCap`（1→3，靠能力提升），超出拒绝并提示。
7. 保留卡不能被抽中第二次（同一实例不会重复出现在两个候选里）。
8. 候选不足 5 张：池抽空时用"空位"填充（`CandidateInstanceIds` 可为 `0`），UI 显示空槽，不允许玩家拿空槽【推断】。

### 7.4 跨海清单与保底

**清单生成**

```text
BuildCrossingList(grid):
  // 1. 组件划分：按"不用新建轨道就能走通"的关系连通
  comps = 并查集：Land 格之间 6 邻接连通 + 已铺 SeaTrack 把两侧陆块连起来
  若 comps.Count == 1: return empty(无跨海需求)

  // 2. 组件间距离 hops = 两陆块之间必须新铺的海格数
  for each pair (a, b):
      从 a 的所有陆地格做多源 BFS，只允许走 Sea 格（不含 SeaTrack，因为那条已经算连通了）
      第一次踩到 b 的陆地格时，记 steps = BFS 层数
      hops[a, b] = steps - 1        // 中间的海格数；adjacent 陆地不可能分属两组
      若整张图 BFS 完都踩不到 b：hops = +∞（理论上不应发生，发生即地图坏）

  // 3. 最小生成树：把全部组件串起来，边权和最小
  mst = Kruskal(comps, weight = hops)
  list = mst 的边集合
  demand = Σ hops(e) for e in list
  return list, demand, quota = ceil(demand * 1.25)
```

| 关键点 | 说明 |
|---|---|
| 为什么用 MST | "把所有陆块串起来的最少跨海段" = 组件图上的最小生成树，权重是海格数。用 MST 才能说"最少"是唯一最优（这也是 G-10 需要策划确认的点） |
| `hops` 定义 | 两陆块之间**必须新铺的海格数**。1 格海隔开 → `hops = 1`（1 张轨道卡） |
| `steps - 1` | BFS 路径形如 `landA → sea → landB` 是 2 步、1 格海，所以减 1 |
| 已连通的段 | 组件划分时已把 SeaTrack 算进去，所以重算后两端同组的段自然消失，无需单独"划掉"逻辑 |
| 清单重算时机 | 每铺完一段轨道；每次进 `Fixed` 站查账；读档时校验一次 |
| 存档 | `list`、`demand`、`quota`、已铺轨道格都要存 |

**保底权重（【推断】，具体公式待策划确认，G-09/G-11）**

```text
Remaining = Σ hops(e) for e in list           // 清单剩余
Hand      = 手里轨道卡数量 + 保留位里的轨道卡
Shortage  = max(0, Remaining - Hand)
Ratio     = Remaining > 0 ? Clamp01(Shortage / Remaining) : 0

Phase     = GetPhase(Day)                     // 0..3，按天数进度切（节点 TBD）
Boost     = BoostByPhase[Phase]               // 建议 {0, 1, 2, 3}

WeightMultiplier(card) =
    card.IsSeaTrack ? 1 + Boost * Ratio : 1
```

**三层强制（按优先级）**

1. **权重抬升**：每次抽卡按上式计算，`Ratio` 越高轨道卡越容易出。
2. **节点补发**（硬补）：到达最后一个补发节点且 `Hand < Quota` 时，**绕过概率**，直接把 `min(Quota - Hand, 2)` 张轨道卡塞进候选的空位（每抽最多 2 张）。
3. **进站查账**：每次进入 `Fixed` 站，若 `Hand == 0 && list 非空` → 立刻往保底池补，忽略 `Quota` 上限。

**关闭条件**：`list` 为空 且 全陆块连通 → 池里轨道卡权重归零、从候选剔除；已抽到的不回收。

### 7.5 稀有度与会话池

| 概念 | 说明 |
|---|---|
| `Rarity 1..5` | 只影响"刷新概率"，不影响等级 |

## 11. 事件系统

### 11.1 触发

```text
OnEventRoll(cell):
  if cell.EventFiredCount > 0 && eventConfig.OncePerCell: return   // 每格一次
  p = EventChanceByLevel(cell.Level) * cellKindChanceModifier      // 配置驱动
  if !Rng.Event.Roll(p): return                                    // 没中：不消耗、不记录

**公式（策划案原文，程序照抄）**

```
FailChance = Clamp01( Pow(Deficit / Need, 1.5) * MulModifier + AddModifier )

```

| 边界 | 行为 |
|---|---|
| `Need <= 0` | `FailChance = 0`，直接成功（配置错误要报日志） |

| `Current == 0` 且 `Need > 0` | `FailChance = 1`（必然失败）；仍需允许执行（策划案"体力不够也允许执行"） |
| 失败后扣多少体力 | **未定义（G-26）**。默认失败不扣（【推断】），策划确认后改 |
| 回复地点 | `Fixed` / `Temp` 可以，`Broken` 不行（C-04，写死在 `Restore` 里校验） |
| 回复量 | 配置；固定站回满？临时站回固定量？TBD（G-22） |

    public UniTask RunQueueAsync(int currentDay, int descentDay);
    /// 跳过播放，直接结算结果（C-12）
    public void SkipCurrent();
}
```

**队列算法（必须带终止保护）**

```text
RunQueue:
  for guard in 0..MaxIterations:      // MaxIterations = 32【推断】
      if Day >= DescentDay: break
      queue = CollectPlayable(Day)    // triggerDay <= Day && !played && 条件满足
      if queue empty: break
      sort by (priority asc: 主线<角色<支线<突发<其余, triggerDay asc, id asc)
      story = queue[0]
      await Play(story)               // 可跳过
      ApplyRewards(story)             // 跳过也发
      MarkPlayed(story.Id)
      if story.AddDays > 0: Time.AdvanceDay(story.AddDays, Story)
      else:                 Time.AdvanceDay(1, Rest)      // 剧情后休息
  if guard == MaxIterations: Log.Error("剧情队列可能死循环")
```

| 规则 | 说明 |
|---|---|
| 优先级 | 主线 > 角色 > 支线 > 突发 > 其余；同级按 `triggerDay` 升序，再按 Id 稳定排序 |
| 站内限制 | 主线只在站内播（本方法只在 `Settling` 调用，天然满足） |
| 加天数 | 剧情直接改 `Day`，不是"跳过几天不结算" |
| 跳过 | 只跳播放；奖励、天数变化、标记全部照常 |
| 已播标记 | 存档持久化；`CollectPlayable` 必须过滤 |

## 15. 性能与预算

| 项 | 预算 | 说明 |
|---|---|---|
| 单张地图生成 | < 200ms（400 格） | 主线程可接受；超了移后台线程（地形层纯数据，无 Unity API 依赖） |
| 路线枚举 | < 5ms/次，展开 ≤ 20000 | 触达上限就截断 |
| 抽卡一次 | < 1ms | 纯权重计算，不打表遍历 |
| 存档序列化 | < 50ms，< 1MB | 全量格子；不存美术资源引用 |
| 每帧规则层 Tick | < 1ms | 只做计时/补间状态机，不做遍历全图 |
| 内存 | 单局 < 30MB（规则层） | 格子用数组 + 打包键字典 |

**GC 注意**

- 生成与寻路里避免 `LINQ`（可读性换性能的临界点：循环内 > 1000 次调用）。
- 抽卡/事件的候选列表复用 `List<T>` 缓存，别每次 `new`。
- 日志只在异常/状态迁移打，不要在 `Tick` 里打。

## 16. 错误处理与日志

**原则**（对齐项目规则）：**入口校验，链路不重复判空**。

| 位置 | 处理 |
|---|---|
| 配置加载 | 强校验：Id 唯一、外键存在、权重 > 0、枚举合法。表错就 `Log.Error` 并跳过该行（不崩游戏） |
| 模块公开 API 入口 | 校验参数（坐标在网格内、Id 存在、状态允许），非法直接返回失败 + 一条带上下文的日志 |
| 内部私有方法 | 不重复判空（上游已保证） |
| 异步回调 / 事件回调 | 重新校验生命周期（模块是否已 Dispose、玩家是否已离开该格） |
| 存档读档 | 失败必须让玩家可见（提示 + 保留旧档），不静默 |
| 状态机非法迁移 | `Log.Error` + 忽略，不抛异常（避免卡死） |

**日志格式**（必须带可排查上下文）

```
[MapGen] seed=12345 区域=3 格数=412 超上限 12 已删最远边缘格
[Dock] coord=(3,-2) kind=Dungeon 事件未触发 p=0.35 roll=0.61
[Draw] session=7 pool=High shortage=12/25 保底注入 2 张
[Settle] day 12->13 step=StoryQueue 剧情 30 入队
```
