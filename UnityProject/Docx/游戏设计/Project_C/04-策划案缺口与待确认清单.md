## 1. 怎么用这份文档

- 每条都有**原文引用**，方便策划对照。
- **问题**是"为什么现在不能实现"，不是"我觉得不好"。

## 2. P0 · 阻塞项

### G-01 时间到底是几个时钟？

- **原文**
  - §四：「全游戏三个状态：行驶、停靠、结算。**只有行驶推进时间**，停靠和结算都冻结。」
  - §五（一）：「时间结算：大部分情况下**回到休息站才推进时间**（回到休息站 → 开格子选择 → 和成员对话 → 强制休息 → **推进时间** → 按时间判断剧情。类似 P5R 的日期，通常只有休息才推日期）。」
- **问题**：两句话不能同时为真。若"只有行驶推进时间"，回站那步推进的是什么？若"只有休息才推日期"，路上每格消耗的是什么？现在文档里"时间"同时指两样东西。
- **影响**：M-02 时间模块、HUD、剧情触发、神降日、存档字段、所有事件的时间效果。
- **建议**：拆成两个计数器。
  - `TripTime`（行程时间/路耗）：行驶时每格 `+= 格子基础耗时 ÷ 列车速度`，**只影响本趟**。
  - `Day`（天数）：只在**强制休息**和**剧情加天**时推进，驱动剧情与神降日。
  - HUD **只显示 Day**（否则玩家看到两个倒计时会困惑）；`TripTime` 只用于表现和条件判断。
- **状态**：待确认 · P0

### G-05 战斗系统完全缺失

- **原文**：§五（六）只写了「每人最多 8 张牌、最多 3 件装备」「上阵 5 人」；§五（八）「神降日：打最终 BOSS，用车上的队伍和牌」。全篇**没有**：回合结构、行动顺序、牌的费用/冷却、敌人行为、站位、伤害公式、胜负条件、战斗时长、失败惩罚。
- **问题**：战斗是终局和副本的唯一出口，现在只有"要打"没有"怎么打"。程序无法定 `BattleRequest/BattleResult` 的字段。
- **影响**：M-15 无法开工 → M-11 体力（动手）、M-18 结局、副本奖励、装备/技能牌系统全部悬空。
- **建议**：单独立《战斗设计文档》，最小必须包含：
  1. 战斗结构：回合制还是即时？谁先手？
  2. 行动经济：每回合能动几次、资源是什么（费用/能量/牌数）。
  3. 牌的规则：出牌上限、是否消耗、重复使用。
  4. 敌人：难度分档、数量、AI 粗规则。
  5. 胜负与撤退，失败惩罚。
  6. 目标时长：普通战 X 分钟、BOSS 战 Y 分钟。
- **过渡方案**：设计未出前，程序先做"占位战斗"（按队伍战力自动结算，出结果界面），保证流程能跑。
- **状态**：待确认 · P0

### G-06 副本（异世界碎片）里到底做什么？

- **原文**：§二 副本定义；§2.4 表格「副本 | — | 1」；§2.3「升级靠经验，**经验下副本才给**」；§2.5「岛上放稀有副本和特殊产出」。
- **问题**：全篇没有"进入副本之后"的任何描述。而**列车长升级 → 抽卡次数**这条成长链完全依赖副本。
- **影响**：升级系统、抽卡节奏、岛的价值、格子卡保底（升级给抽卡次数）。
- **建议**：先定最小闭环：
  1. 进入条件与消耗（体力？次数？）
  2. 内部结构（几层？战斗/事件/宝箱的比例）
  3. 退出：通关 / 主动撤退 / 团灭，各自结果
  4. 奖励：经验 + 格子卡（进袋）+ 钱
  5. 难度分档与推荐等级
- **状态**：待确认 · P0

### G-08 抽法一（保留）还是抽法二（不留）？

- **原文**：§2.3「格子选择有两套抽法，两套都留在文档里，**实测完再定用哪一套**」。抽法一：5 选 1 + 保留 1~3 张到下次；抽法二：攒几次抽几次，抽完即散。
- **问题**：两套的**存档结构、UI、抽卡会话状态机都不同**。抽法一要给"保留位 + 候选快照"存档，抽法二只需要一个计数。
- **影响**：M-09 抽卡模块、`DrawSave` 结构、M1 垂直切片（会返工）。
- **建议**：
  - **优先抽法一**：文档自己给了理由——"保留是为了地图，把随机压下来，让地图在玩家手里可控一些"。抽法二会让"抽不到轨道格"的概率变高，与保底机制叠加后体感会很怪。
  - 若必须实测再定：M1 先按抽法二实现计数，接口预留 `Retain()`，实测后替换。
- **状态**：待确认 · P0

### G-10 "最少跨海段"的算法定义与上限

- **原文**：§2.5「把所有互不相连的陆块串起来，最少要跨几段、每段跨几格，加起来记进关卡配置。这个数就是 2.3 里抽卡保底的门槛。」「算出来的数太大就重掷地图……上限 TBD。」「一次最多跨几格看列车。跨几格 TBD。」
- **问题**："最少"没有算法定义。可能是"任意两陆块直接连"（完全图最小生成树），也可能是"沿最近陆块逐段连"。两者结果不同，保底数就不同。
- **影响**：M-09 保底、地图重掷率、玩家能否过海。
- **建议**：
  - 明确为：**陆块为点的完全图上，边权 = 两陆块间最少海格数，取最小生成树，边权和 = 最低需求**。这是"把所有陆块串起来"的唯一严格解。
  - 需求上限建议 `≤ 64` 或 `≤ 陆地格数 × 15%`（取小者），超了重掷，最多 8 次；8 次仍失败则放行并记日志。
  - 列车单次跨海跨度：建议 `2 + 车厢数/2`，或直接给配置。
- **状态**：待确认 · P0

### G-14 剧情日期例子自相矛盾

- **原文**（§七，两段例子几乎逐字相同但结论不同）
  - 例 1：「剧情A在第30天触发，剧情B在第29天，进站休息后日期为第28天**先发出剧情A**」
  - 例 2：「剧情A在第30天触发，触发后跳过2天。剧情B在第28天触发，进站休息后日期为第30天**先发出剧情A**」
- **问题**：例 1 里当前是第 28 天，A 要第 30 天、B 要第 29 天，两个都还没到，**凭什么先发 A**？例 2 里"剧情B在第28天触发"与"第30天先发A"之间，B 何时发、发了没有，没交代。
- **影响**：M-14 剧情队列算法（这是最容易写出死循环的地方）。
- **建议**：把规则改成可执行的判定，并给一个完整算例：
  - 触发条件：`Day >= TriggerDay` 且该剧情未播放 且其他条件满足。
  - 算例：当前 Day 28 → 触发 A（`TriggerDay=28`，播完 `AddDays=2`）→ Day 30 → 重新收集 → 触发 B（`TriggerDay=29`）→ 播完后休息 → Day 31 → 队列空 → 结束。
  - 明确"剧情后必休息一次（+1 天）"还是"只有配置了加天才推"。
- **状态**：待确认 · P0

  - **不停**：中继格、海上轨道、虚空。
  - 路线排序键：格数（默认）/ 可停靠次数 / 途经城市数。

## 3. P1 · 关键但可占位

### G-02 稀有度数值写错

- **原文**：§2.4 定义「1 普通、2 优良、3 稀有、4 史诗、5 传说」；表格却写「村庄 | 1 普通 到 **2 稀有**」「城镇 | 1 普通 到 **3 优良**」「神迹 | **3 优良** 到 5 传说」。
- **问题**：2 是优良不是稀有；3 是稀有不是优良；"1 到 3 优良"顺序颠倒。
- **影响**：`TbPcGridCard.Rarity` 填错、抽卡权重错、颜色显示错。
- **建议**：统一写「1~2」「1~3」「3~5」，并按定义校对；配置表加校验（Rarity ∈ [1,5]）。
- **状态**：待确认 · P1

### G-03 城镇档位命名不一致

- **原文**：§2.4「城镇类每 3 级换一个档位：**村庄 → 小镇 → 城市**」；但表格只有「村庄」「城镇」两行，没有"小镇"。
- **问题**：枚举里到底有几档？表格里的"城镇"是"小镇"还是"城市"？
- **影响**：`CellKind` 枚举、合成等级换算、UI 文案。
- **建议**：三档统一为 `村庄(1~3) / 小镇(4~6) / 城市(7~9)`，表格补"小镇"行，删掉"城镇"这个含糊词。
- **状态**：待确认 · P1

### G-04 事件"九个字段"未定义，且九条事件是空的

- **原文**：§八「所有事件排在一张总表里，用**九个字段**描述」；后面的表只有 6 列（编号/档位/事件名/适用格子/选项与结果/消耗），且数据行全是空表格。
- **问题**：字段清单没给，程序无法建表；"已经排出来的九条"实际没内容。
- **影响**：`TbPcEvent` / `TbPcEventOption` 表结构、事件校验器、内容排期。
- **建议**：九字段定为：`编号 / 档位 / 事件名 / 适用格子 / 排除格子 / 触发权重 / 选项与结果 / 消耗 / 每格一次`。再补 9 条实际事件（每条 2~3 选项）。
- **状态**：待确认 · P1

### G-07 稀有度是"卡实例"还是"卡类型"的属性？

- **原文**：§2.4「稀有度只影响格子刷新的概率，**不和等级挂钩**」，同时给每种格子一个稀有度**区间**。
- **问题**：如果稀有度是类型属性，那区间就没意义（类型只能有一个值）；如果是个体属性，那"刷新概率"指的是什么？
- **影响**：`GridCardInstance` 是否要存 `Rarity`；抽卡时按实例出还是按类型出；同一张"村庄"能不能出白/绿两种。
- **建议**：按**实例**。卡类型给区间（决定该类型能出什么稀有度），抽到时掷出具体值；稀有度影响该卡的产出/事件概率。
- **状态**：待确认 · P1

### G-09 抽卡池分级内容未定

- **原文**：§2.3「池分几级、每级放什么、最高级池里具体放哪几张：**TBD**」。
- **影响**：内容排期、抽卡权重表、修站的吸引力（修站给最高池，得让玩家觉得值）。
- **建议**：先做 2 级（`High`/`Normal`）。`High` 池只放"改变地图连通性"的卡（轨道、桥、传送）+ 稀有产地格，保证修站立刻能感知到收益。
- **状态**：待确认 · P1

### G-11 保底权重与节点未定

- **原文**：§2.3「越往后抬得越高。随游戏推进分几个节点，每过一个节点，轨道格的权重再抬一档。**节点怎么切、每档抬多少：TBD**」「补在哪个节点：**TBD**」。
- **影响**：抽卡手感、防卡死强度。
- **建议**：按 `Day / DescentDay` 切 4 档：`0~33% / 33~66% / 66~90% / 90~100%`，轨道卡权重倍率 `{1, 2, 4, 8}`；在最后一档（90%）执行硬补，每次最多补 2 张。
- **状态**：待确认 · P1

### G-12 好感 Rank 门槛、对话轮数、心愿次数

- **原文**：§7.1「一次到站给几轮，聊完就强制休息。**几轮 TBD**」；§7.3「各人几次 **TBD**」；§7.2 只说「好感度上限是 1000，Rank 最大等级为 10」，**没给映射**。
- **影响**：M-13 无法验收（连"Rank 4 要多少好感"都算不出来）。
- **建议**：`Rank = Floor(Affinity / 100) + 1`（线性）；每站 3 轮对话；心愿次数按角色 1~3 配。
- **状态**：待确认 · P1

### G-13 结局判定边界 + 外神身份机制

- **原文**：§五（八）「每套结局都按好感 Rank 分：跟谁 Rank 最高，就走谁那条」「降临的是哪一位外神：**TBD**。外神一共几位还没定，定了之后这条按"局内哪一位的信仰最高"来判」。
- **问题**：① 两个角色 Rank 并列第一怎么办？② 所有角色 Rank 都很低（比如全 1）怎么办？③ "信仰"是什么数值？文档里**没有信仰系统**，只有"乘客身上带着信仰"的设定描述。
- **影响**：M-18 结局分支、可能要多一个"信仰/污染度"全局变量。
- **建议**：① 并列按"该角色支线完成数 → 好感数值 → charId 升序"取唯一；② 给"无人达标"的通用结局；③ 把"信仰"落成单一全局数值（建议叫"外神恩赐"或"污染度"），由格子卡/事件累加，神降时取最高派系。
- **状态**：待确认 · P1

### G-16 临时站的入站结算跑到哪一步？

- **原文**：§四「「入站结算」**只在休息站跑**」；§五（四）临时站「只提供休息，休息以外的功能一律没有」。
- **问题**：停在临时站，跑不跑"抽卡 → 对话 → 强制休息 → 推时间 → 判剧情"这一串？"休息"本身就包含"推时间"吗？
- **影响**：抽卡节奏（玩家能不能在临时站把囤的卡抽掉）、天数推进速度、临时站的价值。
- **建议**：临时站跑「强制休息 → 推时间(+1) → 剧情判定 → 神降判定」，**跳过**抽卡与对话。理由：抽卡和对话是固定站的核心价值，临时站只解决"续命"。
- **状态**：待确认 · P1

### G-17 经济只定义了"钱"，没定义市场机制

- **原文**：§六「钱是唯一货币，没有上限。可以通过：跑商，卖道具卖装备等功能获得。」（全文 7 行）
- **问题**：没有价格、供需、库存、买卖差价、跑商规则。"跑商"这个词暗示区域差价，但没写。
- **影响**：M-16、经济成长曲线、修站/造站的钱从哪来。
- **建议**：先做 `固定价 + 每站库存 + 卖出折价（如 60%）`；"跑商（区域差价）"放 P2，因为它是玩法而非基础经济。
- **状态**：待确认 · P1

### G-18 存档时机与"路上退出"的损失

- **原文**：§五（四）「所有站点都自动存档。」
- **问题**：行驶中、副本中退出会怎样？回退到上一个站会丢整趟进度（可能 5~10 分钟），玩家能接受吗？
- **影响**：玩家体验、可能被刷的漏洞。
- **建议**：维持"站内自动存档"，但行驶中退出时提示"本趟进度将丢失"；副本内存档单独设计（进副本存一次，退出即回）。
- **状态**：待确认 · P1

### G-20 "替换"格子的语义

- **原文**：§2.3「建筑选项可以对格子进行**建造、替换、升级**等」。
- **问题**：替换后旧卡返还吗？被替换格上的事件状态（已触发/次数）怎么清？已铺的轨道能拆吗？
- **影响**：M-08、经济平衡（能不能靠替换刷资源）。
- **建议**：替换后**旧卡回袋**（不亏），被替换格的事件状态清空；轨道**不可拆**（海是咽喉点，拆了会破坏清单重算逻辑）。
- **状态**：待确认 · P1

### G-21 地图规模与陆海比例

- **原文**：§2.1「格子总数量有上限」（**没给数**）；§2.5「陆地与海的比例 **TBD**，倾向值是起点大陆占陆地四成、远方大陆三成、岛三成」。
- **问题**：没有绝对量，程序无法定生成参数与性能预算。
- **影响**：M-03、性能、UI 可读性（格子太密看不清）。
- **建议**：总上限 **400 格**（陆地约 220，海约 180）；一张图约 25×25 六边形范围。
- **状态**：待确认 · P1

### G-23 车厢怎么增加？

- **原文**：§五（六）「一节住 3 人，车上人数上限 = 车厢数 × 3」；§三「开局一辆车、**一节车厢**」。
- **问题**：全文没说车厢数怎么涨。可上阵 5 人，但开局 1 节车厢只能装 3 人 —— 第 4、5 个人怎么上车？
- **影响**：M-12、队伍成长线、抽卡/招募的节奏。
- **建议**：修好固定站给 1 节车厢（与"修站开区域"绑定），后续用钱加装。
- **状态**：待确认 · P1

### G-24 好感 1000 → Rank 10 的映射

- **原文**：§7.2「好感度上限是 1000，Rank 最大等级为 10」。
- **问题**：没给每级门槛。100/级、还是递增曲线？
- **影响**：M-13、支线门槛可达性（支线要 Rank ≥ 4，玩家得知道要攒多少）。
- **建议**：线性 `100 × (Rank - 1)`；若想让后期更肝，改成 `100 × n^1.2`（需要数值支持）。
- **状态**：待确认 · P1

### G-25 "牌"这个词指两样东西

- **原文**：§2.3「格子就是牌」/「把这一趟带回来的钱、人、**牌**砸进车和路」；§五（六）「每人最多 8 张**牌**」/「牌是乘员自己的技能」。
- **问题**：同一个字指"格子卡"和"技能牌"。配置表、UI、沟通全都会撞。
- **影响**：命名、表结构、UI 文案。
- **建议**：统一为**格子卡**（GridCard）与**技能牌**（SkillCard），文档里彻底替换。
- **状态**：待确认 · P1

### G-26 体力不足执行失败后，体力怎么算？

- **原文**：§五（五）「体力不够也允许执行，按概率失败。失败率 =（缺额 ÷ 需求）的 1.5 次方，再乘修正、减修正、钳到 0 到 100%。」
- **问题**：只给了**失败率**，没给**扣减规则**。失败后是否扣体力、扣多少、扣 0 会不会被无限重试刷过？另外"再乘修正、减修正"里的修正来源（乘区/加区各自的修正项）没定义。
- **影响**：M-11、所有"做事"入口（任务/寻宝/战斗）、防刷。
- **建议**：
  - 失败仍扣**一半需求**（向下取整），最低扣 1，避免"反复撞墙无限试"。
  - 修正拆成两个显式字段：`MulModifier`（乘区，如装备加成）与 `AddModifier`（加区，如疲劳 Debuff），具体来源由配置给。
  - 体力为 0 且需求 > 0 时允许执行，但失败率钳到 100%，并给 UI 明确提示。
- **状态**：待确认 · P1

## 4. P2 · 打磨项

### G-19 "减少时间"与"延迟神降"是同一个操作吗？

- **原文**：§五（一）「一些特殊事件也会**减少时间**。一些特殊事件可以**延迟神降**。」
- **问题**：减少时间 = `Day += n`（更接近死）还是 `DescentDay -= n`？延迟神降 = `DescentDay += n` 还是 `Day -= n`？两者数学上等价，但 UI 表现完全不同。
- **建议**：统一用 `Day` 变化（`Day += n` 表示提前，`Day -= n` 表示延后），`DescentDay` 只在开局配置里定死。UI 上"推迟神降"表现为"天数回退"。
- **状态**：待确认 · P2
