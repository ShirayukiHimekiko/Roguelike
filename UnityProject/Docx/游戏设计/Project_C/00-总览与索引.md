## 1. 这套文档解决什么问题

策划案写的是**游戏应该是什么样**，用的是策划语言（"回来之后那一步"、"格子不是拿来凑套路的"）。
程序需要的是**能被实现、能被验收、能被配置驱动**的东西：状态、时序、数据契约、边界、优先级。

这套文档做三件事：

1. **把散落在章节里的流程收敛成可执行流程图**（01），让程序看到"谁在什么时候调用谁"。
2. **把功能切成能独立开发、独立验收的模块**（02），给出依赖、优先级和里程碑。
3. **把玩法规则翻译成程序契约**（03）：状态机、数据结构、配置表、关键算法、存档、边界。
4. **把策划案里互相矛盾、缺失、写死 TBD 的地方全部挖出来**（04 详细论证 + 05 全量索引），逐条给建议方案和影响面。

> 原则：**不确定的地方不猜着实现**。所有推断都标注 `【推断】`，所有未定项都进 04，编号 `G-xx`，程序遇到就查 04，不要自己拍板。

## 3. 一句话概括（用于对外对齐，不是需求）

> 你是一列火车的最后一位列车长。世界被外神污染，你只在**能休息的站**里成长，在**有限的趟数**里把格子铺出去、把路接通、把人带上车，在**神降日**那天用车上的队伍和牌跟降临的外神打一场。

三个数字概括单局：**倒计时（天）**、**地图（格）**、**车队（人 + 牌）**。

## 4. 术语表（策划 / 程序统一叫法）

> 本表是**唯一命名标准**。程序里的类名、配置表字段名、UI 文案，都以"程序名"一列为准。

| 策划叫法 | 程序名 | 定义 | 易混点 |
|---|---|---|---|
| 格 | `Cell` | 六边形地图上的一格，有地形、类型、次数、等级、事件状态 | 不是"关卡" |
| 地形 | `Terrain` | 陆 / 海 / 虚空。地形层先定，格子层只长在陆地上 | 海不是"不可走"，是"只能铺轨道" |
| 行程 / 一趟 | `Trip` | 从一座站出发到另一座站结束的完整过程 | 不是"一圈" |
| 停靠 | `Dock` | 停在某一格上，处理这一格的全部交互 | 全游戏唯一交互入口 |
| 入站结算 | `ArrivalSettlement` | 回到休息站后那套固定 7 步流程 | 只在休息站跑 |
| 结算 | `Settlement` | 把这一趟的钱、人、卡落袋并展示 | 与"入站结算"不是同一件事 |
| 站 / 休息站 | `Station` | 站点的统称，三种形态见下 | — |
| 修好的固定站 | `StationType.Fixed` | 永久有效，开一片区域，唯一能改车/改阵容/造格子的地方 | 程序内也叫"好站" |
| 坏站 | `StationType.Broken` | 能到、能停、能出发，零功能 | 不可休、不回体力 |
| 临时站 | `StationType.Temp` | 花钱造，只休息，用一次降为中继格 | 次数 = 1 |
| 中继格 | `RelayCell` | 只出现在路线上，不停靠、不触发、不消耗 | 与"空格"不同 |
| 海上轨道 | `SeaTrack` | 玩家用轨道格子卡铺的海上格 | 不停靠、不消耗 |
| 格子卡（"格子"） | `GridCard` | 玩家抽到、拿在手里、能铺到地图上的卡 | **与"技能牌"重名，见下条** |
| 技能牌（"牌"） | `SkillCard` | 乘员自己的战斗技能牌，每人 ≤ 8 张 | 策划案两处都叫"牌"，程序内必须区分 |
| 入袋 | `CardBag.Add` | 抽到即入袋，与"铺上"解耦 | 入袋立刻完成 |
| 建造 / 铺 | `Build` | 把袋里的格子卡放到地图格上，或替换/升级现有格 | 只能在修好的固定站做 |
| 格子选择 / 抽卡 | `DrawSession` | 5 选 1 的抽卡会话 | 分"站内当场抽"和"站外囤着抽" |
| 保留 | `Retain` | 抽卡时留下不拿、下次仍在候选里的卡 | 上限 1~3，靠能力提升 |
| 清单 | `CrossingList` | 把所有陆块连通所需的最少跨海段集合 | 与"保底"绑定 |
| 跨海段 | `CrossingSegment` | 清单里的一段，记录两端陆块和要跨几格海 | 长度 = 需要的轨道卡数 |
| 保底 | `Guarantee` | 保证轨道卡发够、不让人卡死在岸边的一套机制 | 三层：权重抬升 + 节点补发 + 硬补 |
| 档位 | `Tier` | 城镇类格每 3 级换的档：村庄 → 小镇 → 城市 | 与"稀有度"无关 |
| 稀有度 | `Rarity` | 1 普通 / 2 优良 / 3 稀有 / 4 史诗 / 5 传说（白绿蓝紫橙） | 只影响刷新概率 |
| 天数 | `Day` | 全局日程计数，单局第几天 | 神降日 = 固定天数上限 |
| 路耗 | `TravelCost` | 走一格消耗的时间量 = 格子基础耗时 ÷ 列车速度 | 与"天数"是两个时钟，见 03 §2 |
| 神降日 | `DescentDay` | 天数到达该值即进入终局 | 归零不是结束，是 BOSS 战 |
| 体力 | `Stamina` | 路上唯一资源，只有"做事"才花 | 移动/进格不花 |
| 乘员 / 角色 | `Character` | 车上的本地人，有好感度、技能牌、装备 | 与"列车长"区分 |
| 上阵 | `Formation` | 出战队伍，固定 5 个位置 | 与"车上人数"无关 |
| 车厢 | `Carriage` | 载客单位，1 节 = 3 人上限 | — |
| 好感度 | `Affinity` | 0~1000，界面只显示 Rank | 上限与 Rank 10 的映射见 04 |
| Rank | `AffinityRank` | 1~10，管支线开启 / 结局分支 / Rank 奖励 | — |
| 心愿任务 | `WishQuest` | 角色开口要的那件事，送礼只能在这里 | 次数按角色写死 |
| 角色支线 | `SideStory` | 四门槛开启（Rank / 主线章节 / 日期 / 前置支线） | — |
| 突发剧情 | `Incident` | 条件触发的支线类剧情 | 优先级低于主线/角色/支线 |
| 剧情 | `Story` | 主线/角色/支线/突发 的统称 | 播放有优先级与队列 |
| 副本 | `Dungeon` | 外神投放的异世界碎片（或本神分裂物） | 玩法内容缺失，见 G-06 |
| 圣地 / 神迹 | `Sanctuary` / `Miracle` | 地图上的特殊格类型 | 次数 TBD |

## 6. 程序必须守住的硬约束（来自策划案，违反即设计错误）

> 这些是"策划明确写死、不允许程序为了方便改掉"的规则。03 会给出每条的落地方式。

| # | 约束 | 出处 |
|---|---|---|
| C-01 | 停靠是唯一交互入口；行驶中不开任何决策面板 | 四、§三 |
| C-02 | 只有修好的固定站能改车、改阵容、造格子；坏站零功能 | 五（四） |
| C-03 | 格子卡入袋当场完成；铺到地图只能在修好的固定站 | 五（二）2.3 |
| C-04 | 体力只在固定站和临时站回，坏站不回（防死循环，不可改） | 五（五） |
| C-05 | 空格（虚空/海）不可通行；没有路通到的站不可选，因此不会卡死 | 五（二）2.1 |
| C-06 | 海上轨道不停靠、不触发、不消耗，与中继格同等待遇 | 五（二）2.5 |
| C-07 | 跨海段不受"两站之间不止一条路"约束：海就是一条，是咽喉点 | 五（二）2.5 |
| C-08 | 每座站至少两条边不重叠的路通到外面（生成后校验） | 五（二）2.5 |
| C-09 | 每个固定副本周围补一圈实心格 | 五（二）2.5 |
| C-10 | 总格数有上限；超限从离站最远的边缘格开始删 | 五（二）2.5 |
| C-11 | 时间只在行驶按格消耗、休息按天推进，其余冻结 | 四 / 五（一） |
| C-12 | 剧情跳过只跳播放，不跳结果（奖励照发） | 七 |
| C-13 | 所有站点自动存档 | 五（四） |
| C-14 | 同一种子必须复现同一张图；跨海需求记进关卡配置 | 五（二）2.5 |
| C-15 | 事件不是进格必出：先按格子等级掷点，没中不消耗、下次可再试 | 八 |
| C-16 | 抽卡必须保留"格子是拿来铺地图的"定位：轨道卡有保底，不允许抽到死局 | 五（二）2.3 |

## 7. 文档维护约定

1. **状态流转**：草稿 → 待确认 → 执行中 → 已完成 / 已废弃。状态以首屏表格为准，不用正文声明。
2. **改需求先改 04**：策划任何结论变化，先在 04 里把对应 `G-xx` 标记为"已确认（结论：…）"，再改 01/03。避免文档和实现各说一套。
3. **`【推断】` 标记**：凡策划案没写、由程序补的默认值，一律加 `【推断】`，并在 04 的对应条目登记。策划确认后去掉标记。
4. **不抄代码**：本文档只写契约（类型/字段/时序/算法），完整实现代码放代码里。
