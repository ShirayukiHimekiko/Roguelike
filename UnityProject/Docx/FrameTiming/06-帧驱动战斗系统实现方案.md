## 0. 结论先行

1. 单机阶段采用 **“Entitas 战斗世界 + 自研帧驱动内核”**：Entitas 负责实体/组件/系统顺序，自研层负责 tick、时间轴、定时器、动作帧和表现插值。
2. 不改 Entitas 运行时核心，只在其外围补层；`EntitasDemo` 仅作为沙盒，不承载正式战斗。
3. 先做 **60Hz 固定逻辑帧**，再做动作帧数据、输入缓冲、取消窗口、命中与顿帧；联机不在本阶段实现。
4. 为了未来联机不推翻重来，本方案强制三条纪律：逻辑层不读 `DateTime`/`Random`/Unity 物理；实体有稳定 ID；逻辑与表现严格分离。
5. 不建议现在做快照/回滚；但组件、事件、系统顺序要按“可快照”的方式设计。

## 1. 目标与非目标

### 1.1 目标

- 逻辑帧唯一权威：所有战斗判定按整数帧推进，渲染帧只做采样与插值。
- 动作可数据驱动：前摇、判定、后摇、取消窗口、无敌帧、位移曲线、帧事件都来自配置。
- 手感可控：输入缓冲、取消窗口、顿帧、受击硬直、击退可调。
- 逻辑/表现分离：逻辑层不创建 GameObject、不碰 Animator、不读输入设备。
- 可调试：帧号、当前状态、当前帧、Hitbox、缓冲、顿帧可视化。
- 可演进：未来接联机时，能替换 tick 源、加输入同步/快照，而不重写战斗数据与系统分层。

### 1.2 非目标（本阶段不做）

- 联机帧同步、回滚、预测、断线重连。
- 服务器权威模拟、反作弊。
- 多世界（Verified/Predicted）并行。
- 通用动作编辑器（先用 Luban/Excel，工具后置）。
- 全量 ECS 化 UI、资源、场景。

## 2. 名词与帧语义

| 名词 | 含义 |
| --- | --- |
| 逻辑帧 / Tick | 战斗逻辑推进的最小单位，本方案 60Hz，1 tick = 16.667ms |
| 渲染帧 / Frame | Unity `Update`/`LateUpdate`，频率不固定 |
| 动作帧 | 一个动作内部的帧号，从 0 开始 |
| 前摇 / Startup | 输入生效到判定出现之前的帧 |
| 判定 / Active | Hitbox 有效的帧 |
| 后摇 / Recovery | 判定结束到可再次行动 |
| 取消窗口 / Cancel Window | 允许切换到其他动作的帧区间 |
| 顿帧 / Hitstop | 命中瞬间冻结动作推进的帧数 |
| 硬直 / Hitstun | 受击方无法行动的帧数 |
| 时间轴 / TimeAxis | 控制逻辑推进速度的轴，分 Global 与 Unit |

**区间约定**：统一使用闭区间 `[startFrame, endFrame]`；持续 N 帧时 `end = start + N - 1`。配置、运行时、调试器都用同一语义，避免“第 3 帧到底算不算”的歧义。

- 逻辑层可脱离 Unity 运行（纯 C#），便于未来服务器复用。

```
                            │ 创建/销毁

│                                                             │
│  ┌──────────────────────┐      ┌─────────────────────────┐  │
│  │ Frame Module         │      │ Entitas Contexts        │  │
│  │  FrameClock          │      │  GameContext            │  │
│  │  FrameScheduler      │      │  Components / Groups    │  │
│  │  FrameTimer          │      │                         │  │
│  │  TimeAxis            │      │  SimulationFeature      │  │
│  └──────────┬───────────┘      │   Intent → TimeAxis →   │  │
│             │ tick             │   Timer → FSM → Action  │  │
│             └─────────────────►│   → Move → Hit → Damage │  │
│                                │   → Cleanup             │  │
│                                └───────────┬─────────────┘  │
│                                            │ 只读组件        │
│                                ┌───────────▼─────────────┐  │
│                                │ BattleView（表现层）     │  │
│                                │ 插值 / Animator / 特效   │  │
│                                └─────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

分层原则：

1. **Frame 层**不知道 Entitas，只负责“什么时候跑”。
2. **SimulationFeature** 不知道 Unity 表现，只读写组件。
3. **BattleView** 只读组件，不写逻辑状态。
4. **TEngine** 只负责生命周期、资源、UI、热更，不参与战斗规则。

## 5. 帧驱动内核

### 5.1 FrameClock

职责：把渲染时间转换成逻辑 tick。

```csharp
public sealed class FrameClock
{
    public const int TickRate = 60;
    public const float FixedDelta = 1f / TickRate;
    private const int MaxTicksPerFrame = 4;

    public long Tick { get; private set; }
    public bool Paused { get; set; }
    public float Alpha { get; }   // 0..1，用于表现插值

    public int Advance(float deltaTime); // 返回本渲染帧要执行的 tick 数
    public void RequestStep();           // 暂停时单步
}
```

规则：

- 累加 `deltaTime`，`while (acc >= FixedDelta && ticks < MaxTicksPerFrame)` 执行 tick；
- 超过 `MaxTicksPerFrame` 的欠账丢弃，避免卡顿后“快进”；
- `Paused` 时不推进，但 `Alpha` 保留，表现层仍可渲染；
- 单机可提供 `TimeScale`（回放变速），联机模式禁用。

### 5.2 FrameScheduler

职责：固定一帧内的阶段顺序。

```
InputPhase   采集输入 → 写 Intent 组件
LogicPhase   SimulationFeature.Execute() → Cleanup()
LatePhase    事件派发、表现层准备（可选）
```

注意：物理/命中不要另起 `FixedUpdate`，统一在 LogicPhase 内按系统顺序执行，避免 Unity 物理时钟与逻辑帧漂移。

### 5.3 FrameTimer

按 tick 到期，不按秒。

| 类型 | 语义 | 用途 |
| --- | --- | --- |
| `OnceTimer` | 第 N tick 执行一次 | 延迟出招、延迟伤害 |
| `RepeatTimer` | 每 N tick 执行 | 持续伤害、Buff 周期 |
| `WaitTimer` | `await` N tick，可取消 | 动作协程、演出 |

实现建议：

- `SortedDictionary<long, List<FrameTimerAction>>` 或最小堆，键为到期 tick；
- 记录 `minFrame` 跳过空帧；
- `RepeatTimer` 执行后重新排入 `tick + interval`；
- `WaitTimer` 用 `UniTask` + `CancellationToken`，战斗结束统一取消；
- 定时器归属 `BattleWorld`，不放到全局单例。

### 5.4 TimeAxis（双时间轴）

```
Global Axis  ── 影响所有单位
Unit Axis    ── 只影响单个单位（顿帧/慢动作/时停）
```

规则：

- 全局暂停：`Global.Scale = 0`，所有单位不推进；UI/表现仍按渲染帧走。
- 顿帧：命中时给攻防双方加 `FreezeTicks`，到期自动恢复；冻结期间不推进动作帧、不移动。
- 慢动作：`Unit.Scale < 1`，按累计小数帧推进（内部用整数 tick 累计器，避免浮点误差）。
- 时间静止：`Global.Scale = 0` + 白名单（UI、部分特效）。
- 单位时间轴只影响该单位的动作/移动/定时器，不影响其他单位。

数据结构建议：

```csharp
public struct TimeAxis
{
    public float Scale;        // 1 = 正常，0 = 暂停
    public int FreezeTicks;    // 顿帧剩余
    public long LastTick;      // 上次推进到的 tick
}
```

单机可以用 float scale；如果确定要做联机，改成整数分子/分母或定点数，避免跨平台误差。

## 6. Entitas 战斗世界

### 6.1 Contexts

每场战斗创建一个 `GameContext`，不要复用 `Contexts.sharedInstance` 跨战斗。

```csharp
var contexts = new Contexts();          // 需要验证 1.14.1 生成代码是否支持多实例
var game = contexts.game;
```

如果生成代码强依赖 `Contexts.sharedInstance`，则在启动层做注入封装，避免业务系统直接摸静态单例。

### 6.2 组件清单（第一版）

| 组件 | 字段 | 说明 |
| --- | --- | --- |
| `TransformComponent` | `float X, Y, Z; float RotY` | 逻辑位置/朝向 |
| `VelocityComponent` | `float X, Y, Z` | 逻辑速度 |
| `UnitStateComponent` | `int StateId; int StateFrame; int StateElapsed` | 单位状态机 |
| `ActionComponent` | `int ActionId; int Frame; int Phase` | 当前动作与帧 |
| `HitboxComponent` | `int ActionInstanceId; List<Range> Ranges` | 当前帧攻击框 |
| `HurtboxComponent` | `List<Range> Ranges` | 受击框 |
| `HealthComponent` | `int Hp; int MaxHp` | 生命 |
| `TeamComponent` | `int TeamId` | 阵营 |
| `IntentComponent` | `int MoveX, MoveY; int Buttons` | 本帧输入意图 |
| `TimeAxisComponent` | `float Scale; int FreezeTicks` | 单位时间轴 |
| `StatusComponent` | `int StunTicks; int InvincibleTicks` | 硬直/无敌 |
| `PendingDestroyComponent` | `int Tick` | 延迟销毁 |
| `ViewRefComponent` | `int ViewId` | 表现层绑定 id（不存 GameObject） |

原则：

- 组件只放小数据，不放配置对象、不放 GameObject、不放 List 以外的复杂引用；
- 帧数据通过 `ActionId + Frame` 查表，不塞进组件；
- 需要列表的组件（Hitbox）用池化数组或固定长度结构，避免每帧 new List。

### 6.3 SimulationFeature 系统顺序

```csharp
public sealed class SimulationFeature : Feature
{
    public SimulationFeature(GameContext game) : base("Battle Simulation")
    {
        Add(new IntentSystem(game));          // 1. 消费输入
        Add(new TimeAxisSystem(game));        // 2. 顿帧/慢动作
        Add(new FrameTimerSystem(game));      // 3. 帧定时器
        Add(new StateMachineSystem(game));    // 4. 单位状态机
        Add(new ActionSystem(game));          // 5. 动作帧推进
        Add(new MovementSystem(game));        // 6. 移动
        Add(new HitboxQuerySystem(game));     // 7. 命中查询
        Add(new DamageSystem(game));          // 8. 伤害/硬直/击退
        Add(new CleanupSystem(game));         // 9. 延迟销毁/事件清理
    }
}
```

顺序原则：

- 输入先于一切；
- 时间轴先于动作帧；
- 移动先于命中查询（避免“位置没更新就打中”）；
- 命中查询先于伤害；
- 清理最后。

### 6.4 实体生命周期

- 创建：`CreateEntity()` → 加组件 → `ViewId` 分配；
- 销毁：加 `PendingDestroy`，由 `CleanupSystem` 在 tick 末统一销毁；表现层看到销毁事件后再回收 GameObject；
- 禁止在 System 里直接 `DestroyEntity`，避免遍历中修改集合。

## 7. 动作帧数据与 ActionMachine

### 7.1 数据模型

```text
ActionConfig
├─ id
├─ stateName
├─ totalFrames
├─ loop
├─ nextActionId
├─ frames[totalFrames]
│   ├─ hitboxes[]
│   ├─ hurtboxes[]
│   ├─ invincible
│   ├─ cancelable
│   ├─ moveX/moveY 曲线
│   └─ events[]
├─ cancelWindows[]
│   ├─ startFrame, endFrame
│   ├─ targetActionIds[]
│   └─ conditions
└─ events[]
    ├─ frame
    ├─ type（特效/音效/镜头/召唤/伤害）
    └─ param
```

字段语义：

| 字段 | 说明 |
| --- | --- |
| `startup` | 第 0 帧到判定出现前 |
| `active` | Hitbox 有效帧，允许多段 |
| `recovery` | 判定结束到 `totalFrames - 1` |
| `cancelWindows` | 闭区间，命中/未命中可不同 |
| `invincible` | 逐帧无敌标记 |
| `moveX/moveY` | 逐帧位移，或关键帧曲线 |
| `events` | 帧事件，表现层消费 |

### 7.2 ActionMachine 运行时

```csharp
public sealed class ActionMachine
{
    public int ActionId;
    public int Frame;
    public int ActionInstanceId;
    public int FreezeTicks;
    public int NextActionId;
    public int NextPriority;

    public void Tick(ActionConfig config);
    public void ChangeAction(int actionId, int priority);
    public bool CanCancel(int targetActionId);
}
```

Tick 逻辑：

```
if (FreezeTicks > 0) { FreezeTicks--; return; }
Frame++;
if (Frame >= config.totalFrames)
{
    if (config.loop) Frame = 0;
    else ChangeAction(config.nextActionId);
}
```

切换规则：

- `ChangeAction` 只记录“下一动作”，在 tick 末统一切换，避免半帧切换；
- 带优先级，低优先级请求被忽略；
- 切换时重置 `Frame`、`ActionInstanceId`、Hitbox 命中集合；
- 命中/取消窗口的判定在 `ActionSystem` 里完成。

### 7.3 数据来源

第一版建议 **Luban 表**：

| 表 | 主键 | 内容 |
| --- | --- | --- |
| `TbAction` | `id` | 动作基础信息、总帧数、循环、下一动作 |
| `TbActionFrame` | `actionId + frame` | 逐帧 Hitbox/Hurtbox/无敌/位移/事件 |
| `TbCancelWindow` | `actionId + index` | 取消窗口、目标动作、条件 |
| `TbFrameEvent` | `actionId + frame + index` | 帧事件 |

后续再做编辑器（逐帧时间轴 + Hitbox 拖拽），但运行时只认编译后的数据。

## 8. 输入、窗口与连招

### 8.1 输入缓冲

- 渲染帧采集输入，写入 `InputBuffer`（按 tick 的环形队列）；
- 逻辑帧消费：从当前 tick 往前找最近 N 个 tick 的输入；
- 缓冲长度建议 6–10 tick（100–166ms），可配置；
- 消费后清除，避免重复触发；
- 按键组合（方向 + 攻击）在缓冲层解析成 `Intent`，不把原始按键传进战斗。

### 8.2 取消窗口

```
当前动作 A，窗口 [8, 14]
输入 B，且 B 在 A 的 cancel 目标列表
→ 在窗口内允许 A → B
```

规则：

- 窗口是闭区间；
- 命中/未命中可有不同窗口；
- 目标动作有优先级，高优先级可覆盖低优先级；
- 窗口外输入进入缓冲，等待下一个窗口或动作结束；
- 连招图用“当前动作 + 输入 → 目标动作”的查表，不写 if-else 链。

### 8.3 连招图

```text
Light1 --(8..14, Light)--> Light2 --(10..16, Light)--> Light3
Light1 --(8..14, Heavy)--> Heavy1
Light2 --(10..16, Special)--> Special1
```

配置化：`TbCancelWindow` 的 `targetActionIds` 即边；条件（能量、命中、距离）作为字段。

## 9. 命中、伤害、顿帧

### 9.1 命中查询

- `ActionSystem` 每帧把当前帧的 Hitbox 写入 `HitboxComponent`；
- `HitboxQuerySystem` 在移动之后执行，用 Hitbox vs Hurtbox 做重叠查询；
- 每个 `ActionInstanceId` 维护 `HashSet<EntityId> HitEntities`，同一动作实例对同一目标只命中一次；
- 多段判定用多个 `Hitbox`，每段独立 `ActionInstanceId` 或 `HitGroupId`；
- 查询用 `Physics.OverlapBoxNonAlloc` 或自研空间哈希，避免每帧 GC。

### 9.2 伤害结算

```
命中 → 计算伤害（攻击力、防御、暴击、抗性）
     → 加硬直（Hitstun）
     → 加击退（Knockback）
     → 加顿帧（双方 FreezeTicks）
     → 触发受击事件（特效/音效/镜头）
```

伤害公式放 `DamageCalculator`，配置驱动；不在 System 里写死。

### 9.3 顿帧

- 命中瞬间给攻防双方 `FreezeTicks = N`；
- 冻结期间 `ActionSystem` 不推进帧、`MovementSystem` 不移动；
- 表现层仍可播放命中特效/镜头震动；
- 全局顿帧可选（`Global.FreezeTicks`），但第一版建议只做单位顿帧，避免影响其他单位。

## 10. 表现层与插值

### 10.1 分离原则

- 逻辑层不 `Instantiate`、不 `Destroy`、不碰 `Animator`；
- 表现层只读组件，事件通过队列/回调消费；
- 表现层可以有插值、平滑、镜头、音效，但不能写回逻辑。

### 10.2 插值

```csharp
// 每渲染帧
var alpha = clock.Alpha;
var prev = view.PreviousPosition;
var curr = transform.Position;
view.transform.position = Vector3.Lerp(prev, curr, alpha);
```

- 每次逻辑 tick 前保存 `PreviousPosition`，tick 后保存 `CurrentPosition`；
- `alpha = accumulator / FixedDelta`；
- 传送/复活时直接 snap，不插值；
- 不要用固定 `Lerp(..., 0.25f)` 代替插值，否则帧率变化时手感不一致。

### 10.3 动画

```csharp
animator.speed = 0f;
animator.Play(animName, layer, normalizedTime);
```

- 逻辑层只给 `AnimName + NormalizedTime`；
- `NormalizedTime = actionFrame / totalFrames`；
- 动画事件不作为逻辑判定来源，判定只认动作帧数据；
- 过渡/融合用 `Animator.CrossFade` 或 Playables，表现层决定。

### 10.4 事件消费

- 逻辑层产生 `FrameEvent`（特效/音效/镜头/召唤）；
- 表现层在 `LateUpdate` 消费，按 tick 排序；
- 事件带 `Tick`，回放/调试时可重放；
- 不要用 `SendMessage`/全局字符串事件。

## 11. 完整流程

### 11.1 一帧

```
Update():
  ticks = clock.Advance(Time.deltaTime)
  for i in 0..ticks-1:
      InputPhase: 采集输入 → Intent
      LogicPhase:
          SimulationFeature.Execute()
          SimulationFeature.Cleanup()
  BattleView.Render(clock.Alpha)
```

### 11.2 一次攻击

```
1. 输入缓冲检测到 Attack
2. IntentSystem 写 Intent
3. StateMachineSystem: Idle → Attack
4. ActionSystem: 加载 ActionConfig，Frame=0
5. MovementSystem: 按逐帧位移曲线移动
6. HitboxQuerySystem: 当前帧 Hitbox 与目标 Hurtbox 重叠
7. DamageSystem: 伤害/硬直/击退/顿帧
8. 表现层: 播放动画/特效/音效/镜头
9. 动作结束或取消窗口 → 下一动作
```

### 11.3 顿帧

```
命中 → 双方 FreezeTicks = N
tick: TimeAxisSystem 递减 FreezeTicks
      ActionSystem/MovementSystem 跳过
      BattleView 继续渲染特效
FreezeTicks == 0 → 恢复推进
```

### 11.4 暂停/单步

- `FrameClock.Paused = true`：不再产生 tick，表现层保持；
- `RequestStep()`：暂停时手动产生 1 个 tick；
- 调试器显示 tick、alpha、当前动作、帧号、Hitbox。

## 12. 模块与 TEngine 集成

### 12.1 模块划分

| 模块 | 位置 | 职责 |
| --- | --- | --- |
| `FrameModule` | `HotFix/GameLogic/Module/Frame` | FrameClock/Scheduler/Timer，全局唯一 |
| `BattleModule` | `HotFix/GameLogic/Battle` | 创建/销毁 BattleWorld，战斗生命周期 |
| `BattleWorld` | `HotFix/GameLogic/Battle` | Entitas Contexts + SimulationFeature |
| `BattleView` | `HotFix/GameLogic/Battle/View` | 表现层，MonoBehaviour |
| `ActionConfig` | Luban 生成 | 动作帧数据 |

### 12.2 生命周期

```
进入战斗:
  BattleModule.Create()
    → new Contexts()
    → new SimulationFeature()
    → 加载配置/关卡
    → 创建实体
    → BattleView.Bind()

每帧:
  FrameModule.Tick()
    → BattleWorld.Tick()

退出战斗:
  BattleView.Unbind()
  BattleWorld.Dispose()
  FrameModule.Reset()
```

- 战斗结束必须取消所有 `WaitTimer`（`CancellationToken`）；
- 必须销毁所有 Entitas Contexts，避免残留实体；
- 必须回收表现层 GameObject/池。

### 12.3 热更边界

- 战斗逻辑全部放 `GameScripts/HotFix/`，遵守 HybridCLR 边界；
- Entitas 1.14.1 是 DLL，放 `Assets/Plugins`，不热更；
- 如果未来需要热更 Entitas 组件生成代码，需评估程序集划分。

### 12.4 与 `GameModule.Timer` 的关系

- `GameModule.Timer` 是秒制，服务 UI/表现；
- 战斗用 `FrameModule` 的 tick 定时器，两者不混用；
- 战斗内的延迟/冷却/硬直全部用 tick，不用 `WaitForSeconds`。

### 12.5 现有代码处置

| 现有内容 | 处置 |
| --- | --- |
| `EntitasDemoBehaviour` / `DemoMoveSystem` / `DemoViewSystem` | 保持沙盒，不接入正式战斗；不再往这里加功能 |
| `EntitasDemo` 的 `CreatePrimitive` 视图 | 不迁移；正式表现层用 Prefab + 池 |
| `GameModule` | 新增 `Frame` 属性，指向 `FrameModule` |
| `GameModule.Timer` | 保持秒制，只服务 UI/表现；战斗不混用 |

### 13.2 校验

- `startFrame <= endFrame < totalFrames`；
- 取消窗口不重叠或按优先级排序；
- Hitbox 帧必须在 `active` 区间；
- `nextActionId` 必须存在；
- 事件类型必须已注册；
- 加载期统一报错，不带病进战斗。

### 14.2 动作数据校验

- 启动时遍历所有 `ActionConfig`，检查帧数、窗口、事件、ID；
- 输出缺失动画/特效/音效的警告；
- 提供“动作帧预览”窗口（后续）。

### 14.3 回放（单机）

- 记录每 tick 的输入；
- 回放时用同一 FrameClock 重跑；
- 用于复现 Bug、调手感，不等同于联机回滚。

## 15. 性能与 GC

- System 内缓存 `IGroup`，不要每帧 `GetGroup`；
- 遍历用 `GetEntities()` 返回的数组，不 LINQ；
- Hitbox 查询用 `NonAlloc`；
- 事件用池化对象，避免每帧 new；
- 组件避免大对象/字符串；
- 表现层插值不分配；
- 目标：单帧逻辑 < 2ms（50 单位），无每帧 GC。

## 16. 联机演进预留（本阶段不实现）

虽然现在单机，但以下纪律现在就要遵守，否则未来联机要重写：

1. **逻辑层不读 `DateTime`/`Time.time`/`Random`/Unity 物理**；随机用可注入的 `IRandom`。
2. **实体有稳定网络 ID**：`creationIndex` 会复用，新增 `NetIdComponent` 或在创建时分配稳定 id。
3. **系统顺序固定**：输入 → 时间轴 → 定时器 → 状态机 → 动作 → 移动 → 命中 → 伤害 → 清理。
4. **逻辑与表现分离**：表现层不写逻辑状态；逻辑层不创建 GameObject。
5. **事件分层**：表现事件可预测；结算事件只在确认后触发（单机可先统一，但接口预留）。
6. **组件可序列化**：第一版可以不实现，但组件字段保持简单，避免引用 Unity 对象。
7. **单线程模拟**：不要为了性能把逻辑拆多线程；联机需要确定性顺序。
8. **数学封装**：位置/速度/命中盒通过 `BattleMath` 封装；如果确定 PvP，尽早换定点数，避免后期全量替换 float。

Entitas 在联机上的限制（记录在案）：

- 无快照/序列化；
- `Contexts.sharedInstance` 全局单例；
- Group 遍历顺序不保证；
- ReactiveSystem 回滚会重复触发；
- 实体销毁即时。

这些不影响单机，但决定未来联机时需要额外补层或换框架。

## 17. 里程碑与验收

### M0：帧内核（1–2 周）

- FrameClock + Scheduler + Timer；
- 一个移动单位 + BattleView 插值；
- 暂停/单步/调试面板。

验收：60Hz 稳定；暂停/单步正确；插值无抖动；无每帧 GC。

### M1：动作帧 + 一次攻击（2–3 周）

- ActionConfig 表 + ActionMachine；
- 前摇/判定/后摇/帧事件；
- Hitbox/Hurtbox 查询 + 一次伤害；
- 表现层动画手动进度。

验收：攻击帧与配置一致；命中只触发一次；表现与逻辑对得上。

### M2：输入缓冲 + 取消窗口（2–3 周）

- InputBuffer；
- 取消窗口 + 连招图；
- 轻攻击 3 段连接。

验收：窗口内可取消、窗口外不生效；缓冲不吞输入；连招稳定。

### M3：顿帧 + 手感（1–2 周）

- 单位时间轴/顿帧；
- 受击硬直/击退；
- 镜头/特效/音效事件。

验收：顿帧只影响目标单位；手感参数可调；无逻辑/表现错位。

### M4：调试与回放（1 周）

- 帧调试器；
- 输入录制/回放；
- 配置校验。

验收：能复现一次战斗；配置错误启动即报。

## 18. 风险与取舍

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| Entitas 无快照/回滚 | 未来联机要补层或换框架 | 现在保持组件简单、系统顺序固定、逻辑表现分离 |
| 全局 Contexts | 多战斗/多世界冲突 | 每场战斗独立 Contexts，业务不摸静态单例 |
| Group 顺序不确定 | 行为不稳定 | 需要顺序时按稳定 ID 排序 |
| ReactiveSystem 重复触发 | 事件重复 | 结算不用 ReactiveSystem，走显式事件队列 |
| 动作数据编辑成本 | 内容生产效率 | 先用 Luban/Excel，后续做编辑器 |
| 顿帧/多时间轴复杂 | 状态难调 | 第一版只做单位顿帧，全局时停后置 |
| Unity 6 + Entitas 1.14 | 兼容性 | 已在 6000.0.69f1 编译通过；持续验证 |
| 未来 PvP 确定性 | float 需替换 | 现在封装数学；确定 PvP 就尽早定点化 |

| 方案 | 适合 | 代价 | 结论 |
| --- | --- | --- | --- |

## 21. 验收用例

| 用例 | 操作 | 预期 |
| --- | --- | --- |
| 暂停/单步 | Space 暂停，N 单步 | 逻辑停/走一帧，表现不炸 |
| 卡顿追帧 | 人为掉帧 200ms | 最多补 4 tick，不出现快进 |
| 动作边界 | 总帧 18，第 17 帧结束 | 不越界，自动切 nextAction |
| 取消窗口 | 第 8 帧按轻攻击 | 切 1002；第 15 帧按无效 |
| 多段命中 | 同一动作 3 帧 Hitbox | 同一目标只结算一次 |
| 顿帧 | 命中目标 | 攻防双方冻结 N tick，其他单位正常 |
| 插值 | 60Hz 逻辑 + 120Hz 渲染 | 移动平滑，无阶梯 |
| 传送 | 瞬移/复活 | 直接 snap，不插值穿模 |
| 配置错误 | 窗口越界/缺动作 | 加载期报错，不进战斗 |
| 退出战斗 | 结束/切场景 | Contexts、定时器、View 全部清理 |
| 回放 | 录制 10 秒输入 | 重放结果一致（单机） |
