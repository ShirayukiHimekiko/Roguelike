# 维护已有 Skill，保留已经有效的能力

收到具体反馈、使用失败、原件/工具变化、能力扩展或整理已有 Skill 的委托时读本页。维护应改变下一次真实调用；不是不断追加告诫、重建目录或把整个旧版重写一遍。

维护在授权内自主推进，协作沿主文约定。涉及解释/推理或一套流程时，按[完整流程与解释迭代](workflow-learning.md)恢复当前模型及必要覆盖，保旧解释/预测/反证/修订与受影响回归；文件、代码和知识变化分别核其后果，不能因无人外审而省略实际结果。

同时执行[受控学习](learning-control.md)的维护模式：复用当前有效证据，给修订／试用／返修／回归有限预算；按[四时点](comparison-and-regression.md)核方法行为，不以自由交错或“仅文案”免检。规则已写却未改变首选／主投入，仍是方法消费接口的整改证据；沿实际入口、任务输入与后继修原承担位置，不归责执行实例或仅再加提醒。

## 找实际源与变化承担位置

启动或接续时按[自动定位与持续推进](task-continuity.md)查回相符工作区和目标作者源，不要求用户每次重给目录。先读原 `SKILL.md`、相关参考/脚本/素材、元数据及当前调用者。区分仓库作者源、已安装副本、发行包和正在执行的进程；改了一个副本不等于其它副本已更新。保工作树未提交修改及自定义资源，确认谁负责当前写域，不覆盖他人的在途工作。

按[反馈推动新认识](workflow-learning.md)核用户原话怎样改变目标、认识或方法，将改变落到具体选路、分支优先级、参数解释、作者操作或恢复处，保贡献出处。把反馈接到能复核的触发、应有结果、实际结果、对象和版本；没有运行证据时保假设，做能区分原因的最小验证。知识解释、方法选择、流程分支、技巧细节、执行工具和供给来源分别追责；先修决定错误的原位置，不用更多规则或永久拒绝盖住原因。

局部技术持续替代专业制作时，回[父级决定](workflow-learning.md#next-author-work)及[任务供给](workflow-learning.md#proactive-value)，定位哪项选法／作者操作／消费未承担原差异；修下一调用实际读取的原位置，并核首动作和后继，不再另写同义原则。

普通小修不强制新增合同、流水账或版本平台。涉及既有合同、I/O、素材或工具接线时，核旧消费者和兼容性；涉及原件变化时追其对解释的实际影响，而不是仅刷新指纹。

涉及工具链/模型/供应商/资源或历史调整时，按[生产供给到自主执行](source-to-automation.md)追实际生效变化及原失败证据，更新配置、方法/恢复和相应自动调用；保用户凭证引用/定制，不复制秘密值。维护版仍要在供给、工艺控制与必要品质依据成立后自主完成相应新任务，不能让自动路径退化成逐步人工操作而未说明。

## 在原结构中做有界修订

- 保留未受影响的知识、正常用法、来源及失败事实。新知识按[设计方法](skill-design.md)转成可选择的流程或技巧，放在实际会读到的位置；重复和矛盾项合并到唯一正文。
- 对回[学习基准与来源选择](scope-and-selection.md)，保调用名、触发、必要能力和品质；新发现接回待扩展处，不能用维护批次重置原目标。改名/拆分给旧调用者迁移路径；有据排除保理由，不把失败正常用途排出去，也不为单个新样例泛化到所有相关任务。
- 保前言已有的合法 `metadata`、许可和宿主字段；改 `agents/openai.yaml` 时保不相关的 `policy`、`dependencies` 和界面选择。不要用生成器全量覆盖未知设置。
- 脚本与资源变化追到入口引用、参数/单位、实际供给和消费结果。素材换版、链接坏链或正文分支改变同样可能影响行为；不因“只是文档”跳过核回。
- 保旧版或精确差异，沿项目版本约定更新：修正局部错误、兼容扩展、破坏调用分别说明，不由工具替代判断。证据复核与采用状态变动不单凭字段机械升版；`trialed/adopted` 不能由测试自动晋级。

## 比较的对象须包括 Skill 本身

`learnpack.py compare OLD_PACK NEW_PACK` 比较的是两份能力合同，不能证明正文、参考、脚本、素材和宿主元数据未变。另用以下工具或项目已有等效差异工具读取新旧实际 Skill：

```text
python scripts/skill_files.py inspect NEW_SKILL_DIR
python scripts/skill_files.py compare OLD_SKILL_DIR NEW_SKILL_DIR
```

`skill_files.py` 只读取文件：`inspect` 核必需前言、正文及普通内联本地链接（忽略代码围栏示例与外链，不验证 Markdown 全语法、锚点或运行时依赖）；`compare` 列实际文件增删改和版本信息，忽略 `.git`、`.venv`、`__pycache__` 等生成目录。不能枚举的目录或链接不能冒“无变化”。返回 0 表示对应机械检查无问题/未变化，2 表示输入或检查问题，`compare` 的 3 表示存在需审查差异，不是自动不兼容、自动升版或合并失败。工具不运行 Skill 命令、不安装、不替换文件。

普通方法型 Skill 无合同也能做文件检查/比较；深学证据包仍单独核原件指纹和合同。正文或资源变化可以没有合同变化，不能把前者隐在后者的“无差异”里。

## 核回行为，再采用

先冻结未预填修法的真实输入下的首次选择／实际派发，再对照最小相关修订；查第一作者动作是否真的改变及产生什么结果。工程整体失败用完整目标／规模／当前实现／成熟供给事实检父级选法，保“有据局修”和“有限有效研究”正常对照。比较方法内容、真实选择、实际作者消费与最终产品效果四层；hash／版本／准确声明不独自关闭后两层。

先由原失败原因确定本次修复必须证明什么，再选因果相关的检查，复用未变旧证。专业能力/迁移失败触发的整改，原专业差异、相应真实新需求及正常收益应进入核回；换成被预填修法的低阶样件只能证其执行命题，不能把维护范围自行改叫“责任链有限闭合”后解除原整改。任务可以按依赖分段，局部方法可有据使用，原失败责任仍保持到相应结果成立。

用户明确仅要求修改Skill时，当前交付按方法责任是否修到、指令可执行性、原反例因果及受影响正常场景核验，再核真实作者源/安装等采用；不据此强造原产品或以未来专业成品作本次维护前置。文本内容通过、推演可用与实际专业效果分别声明，原生产P0不由此关闭。成熟局部修正按其实际影响验证，不统一扩成全领域或全量工程测试。

按实际变化和风险选择调用、输出核查、解释预测与方法回归，检查分支、产物和失败恢复，并核适用反馈。生成者自验、检查器passed和文件存在不代必要的真实结果，也不能裁剪原品质。旧行为丢失或使用负担增加时修原责任层/回退并保失败；必要结果已有据后停止重复查证，交实际用户继续使用。

推理回归须看新解释是否保留原来有效的预测和流程选择，而不只跑相同测试取绿。关键证据推翻旧认识时，修现行知识、关联技巧与操作，旧结论保历史并标明已撤回/收窄；恢复时读当前知识与下一验证点，不靠完整聊天或一项旧“通过”续用失效解释。

还要看项目特定的输入是否真的改变控制和产物、生图/脚本是否承担对应工序，工具或供给碰壁后是否查证并保持品质。新文本、评审一致或机械正常不证明整改有效；必要目标内效果仍须相应实践核回。回退有问题的修改保数据，不把目标和质量一起回退。

本次维护的必要结果和受影响回归已有据后，在授权写域采用当前版，核入口读到的确是该候选；局部版本采用不关闭原学习面未闭。稳定安装未获替换授权时交候选、差异与证据，不冒已更新安装；确缺外部条件保具体接回责任。不新增全局权限、后台学习、发布步骤或逐项审批。

最后说明：改了什么及为何、哪些能力保留、实际新旧调用结果、当前版本/路径、仍未知的范围及接回动作。维护这个局部 Skill 的成功不关闭原学习领域的其它必要目标。
