# 意图还原、回读与漂移检测：先钉住用户要的结果

**结论：** 开工 10 分钟内写一屏 `INTENT.md`；第一张粗画面出来时（最晚 30 分钟）用白话向用户回读一次；之后每波开头花 1 分钟查有没有偏离。用户要的结果只有用户能确认，AI 之间互相核对防不住“大家一起理解错”。

**为什么：** 实际失败案例里，用户要“原神、鸣潮级的二次元水”，AI 把原话拆成一组可核对的条款（能运行、能看、写 Skill），参照取不到就换成吉卜力静湖；之后四个 AI 都以静湖为准互相审查，越认真离原需越远，2 小时里一直在修深度、NaN、相机穿地这类小 bug。

实质任务都要做；普通问答不做。视觉、风格化任务必须做全套，纯代码任务把“画面”换成“用户第一次实际使用的结果”。本页是八步骤中第 1 步“定目标”的开头部分，不新增步骤，也不改变步骤之间的证据依赖。

<a id="intent-md"></a>
## 1. 第 0 步：开工 10 分钟内写 `INTENT.md`

先于读其它规则正文，放在工作区根目录，不超过一屏。必须写这六项：

1. **核心名词和最高级形容词**，例：“二次元水体”“顶级”。它们就是成功的定义。
2. **用户举的例子按三级处理：**

   | 用户怎么说 | 怎么处理 |
   |---|---|
   | 直接点名（“做成原神那样”） | 不可替换。每个都要取到实机画面。 |
   | “如 / 比如 A、B、C” | A、B、C 界定了目标类别，同样按点名对象去取；可以加同类，不能换成类别外的东西（例：二次元游戏的水换成写实湖或吉卜力静湖）。 |
   | “参考可自行查找” | 只授权**增加**参照，不授权替换或删掉用户给的。 |

   两种说法同时出现（“可自行查找，如 A、B、C”）时两条都适用：A、B、C 仍按点名去取，此外可以加同类。取不到时仍按 [reference-acquisition](reference-acquisition.md) 第 1 节：三个来源都失败才问用户，不自己换。
3. **用户第一眼的判断句**：用用户的口吻写一句，例：“这水像原神、塞尔达里的水吗？”每次出图先用这句话自测。
4. **什么会让用户失望**：从原话和这位用户以往的反馈里列。本用户已知会失望的：只交报告、最小实现、换题、只修 bug 不推主线、初版物理或效果就不正确。
5. **“不是 X 而是 Y”**：原话里的 Y 是底线。例：“不是调研报告，而是真正做出顶级效果”。
6. **决定成败的未知项**，按对结果的影响排序，最多 3 条。只有影响结果的才算；配置、格式这类合规小问题不占名额。这 3 条要在回读消息里问用户。

<a id="core-noun-scope"></a>
### 核心名词锁定范围

- **核心名词是主角，其它只做衬托。** 用户要“一块水体”，主角就是水；岛、树、山、相机系统只做到能衬托水为止。场景本身出的问题（地形 NaN、相机穿地、远山网格）只修到不挡主机位看水，不排进主线。
- **扩大范围就是目标变更**，按第 4 节报告用户，不能自己加。
- **第二需求（检验方法能不能迁移）等主作品过关后再做**：主作品的 TARGET 主要特征已达到、用户回读没有反对、适用的陪审没有未关闭的否决。由一个**新的、没参与制作的 AI** 只读 Skill 去做；作者和各陪审（F、A 及其它目标／美术陪审）都不兼任出题或制作。八步骤里的异需整合和再调用证据仍然必须有，只是排在主作品之后。

`INTENT.md` 本身也是首次结果，和其它产物一样要按 [首次结果独立核验](comparison-and-regression.md#independent-first-result) 由另一个真实 AI 对照原话核过才采用。核验不阻塞：发出核验请求后，作者照常继续取参照、做第一张粗画面；核验发现漏掉或改写了原话，就当场改 INTENT/TARGET。但它核的是“有没有漏掉或改写原话”；“理解得对不对”最终只有用户能确认，见下一节。`TARGET.md` 从 `INTENT.md` 展开，两者冲突时以 `INTENT.md` 和用户原话为准。

<a id="intent-readback"></a>
## 2. 意图回读：第一张粗画面出来时，最晚 30 分钟

给用户发一条一屏以内的白话消息：

> 我理解你要的是：【一句话】。参照是【3 张图】，我会重点做出【3–5 个特征】。这是第一版粗画面【图】，差距最大的是【3 条】。如果方向不对请直接说。

- **发完不等回复，继续做。** 用户纠正时立即改 `INTENT.md` 和 `TARGET.md`，并在下一条消息说改了什么。
- 到 30 分钟还没有粗画面，也按时发：附已取到的参照，写明粗画面什么时候出、哪些点名参照还没取到。不为等粗画面或凑齐参照推迟。
- 第 1 节第 6 条的未知项、取不到的点名参照，都放进这条消息一起问，不单独打断。
- 这是唯一能防住“共同误读”的环节，任何 AI 陪审的票数都不能代替它；它也不代替 AI 之间的独立核验。
- 这条消息由主交流 AI 用白话写，不改动陪审的用户可见格式。它是进度汇报，不是方案评估：同时用陪审 Skill 时以【📍 进度】开头，不套【🧭开始评估方案】。

<a id="forward-progress"></a>
## 3. 什么算“前进了一版”

每个新版本至少做到下面一项，否则不能称为前进了一版：

- **新增**或明显加强 `TARGET.md` 里的至少一个特征（例：出现成型的岸线泡沫带）；
- 修掉**主机位或用户会看到的视角**里一处明显缺陷。

只在诊断视角、边界机位里出现的问题进待办清单，等主线特征齐了再处理。**连续两版主机位对比图没有可见变化，就停掉当前技术线**，回到 `TARGET.md` 里差距最大的那一条。如果差距最大的那一条在当前做法里推不动，按[选路线](route-selection.md#route-change)换做法，不在原路线上继续打磨。这和“最小场景最多一波”一起用：技术问题可以修，但修完必须在主机位上看得出来。

**每波收尾跑 `scripts/wavelog.py end N --main 主机位.png --ref R1.png`**：它拿主机位和上一波比，判断有没有可见变化、算不算前进；连续两波没变化时退出码为 4，照输出的“下一步”回到差距最大的那条特征。它只做机械比对，好不好看仍要亲眼看。

本页只定义作者怎么判断前进；陪审怎么打分按陪审 Skill，不在这里改。

<a id="drift-check"></a>
## 4. 漂移检测：每波开头 1 分钟

每波开头跑 `scripts/wavelog.py start N --push T1,T3`，写明本波推进哪几条特征，它会顺带查下面第 1–3 件事，退出码 4 就是发现了漂移；第 4 件它查不了，要自己看。

每波开头查一次；波中准备拿一个新找到的工程、教程或资源做主体之前，也先查一次。把当前 `TARGET.md`、计划和 `INTENT.md` 对照，查四件事：

1. **参照集合变了吗？** 少了或换了用户给的参照。
2. **有特征被删掉或弱化了吗？** 例：评审建议“岸边允许大段没有白线”，等于删掉卡通泡沫。
3. **范围扩大了吗？** 例：新加了第二个场景、第二条溪流。
4. **主体还是核心名词说的那种风格吗？** 拿一个别的风格的现成工程当主体，哪怕它更漂亮、文档更全、更快能跑，也等于换了题。这类来源只能借来解决某个子问题，见[选路线](route-selection.md)第 2 节。

任何一项为“是”，都标成**目标变更**，写进下一条给用户的消息，说清改了什么、为什么。用户确认前继续按原目标做。目标变更只能由用户批准，作者、统筹和任何陪审都不能批准。
