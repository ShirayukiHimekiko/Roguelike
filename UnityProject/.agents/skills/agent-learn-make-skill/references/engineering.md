# 工程学习：把细节放回作用链

## 目的、权威与取舍

先按[受控学习](learning-control.md)建立完整目标／规模／品质、基线与动作预算；本页承担工程选法。学成熟作者怎样做完整系统，不只学算法公式、API或当前自制实现的下一个局部。

领域学习先建立理念、方法家族、完整生产链及关键子系统的联系；代表案例选不同工艺、适用条件与取舍，不把眼前报错当唯一阅读目录。再从用户结果、作者合同、生产入口、消费者与失败路径深入源码：生产者 → 配置/序列化 → 装配/导入 → 原生绑定 → 有效求值 → 消费结果；标明状态所有者、生命周期和版本。一个字段、文件或命令成功不能替代后续消费。

### 还原作者的完整系统选择

对有助于当前目标的成熟工程，取得下面实际存在且会改变选择的关系；无此机制可有据排除，缺资料保未知，不能用名词清单让AI猜架构：

| 方法关系 | 必须从原件学到、用于本项目的决定 |
| --- | --- |
| 工作分解与数据表示 | 作者按什么任务／空间／命令／群组／个体分工；实体／组件／字段怎样组织，谁拥有和更新。为什么用该粒度，哪里需要独立身份，哪些量可以共享或压缩。 |
| 平台、规模与最坏量 | 实际硬件／后端、对象数、密度、候选／邻居分布和最坏扩展；总内存、带宽、计算和帧预算怎样随规模变化。平均数、访问下限与完整负载分开。 |
| 调度、串行与搬运 | 哪些量每帧／分频／按事件更新；依赖链、串行段、同步、CPU/GPU边界、上传／读回和驻留，成本转给哪个阶段／消费者。并行入口存在不等所有关键工作并行。 |
| 组合与行为 | 导航、拥堵／避让、战斗、命令／Reset、渲染／动画怎样共用数据与时间；终端交接、身份／生命周期、安全和失败恢复怎样保持。局部原理相加不自动成立完整系统。 |
| 取舍与失败史 | 作者为何采用／放弃某表示和更新策略，哪些输入／密度／平台会失效，调整前后原件及效果；解释和人类动机缺记录时不补造。 |

把这些关系接为当前完整系统选择：用户保证／差距→有据工艺与数据表示→共同状态／时间／资源和关键成本→可消费子结果及接口→联合消费者／恢复。高难任务优先核最可能推翻整链的耦合及规模，把首次作者操作落到该差距，而非串联独立探针。计算下限、忠实小复现或有限实验可建立选路依据，足证即组合真实代表结果；不预要同规模成品，不从单访问／kernel推整个范式上限，不承诺任意任务必成。

### 整体反证须回父级假设

按[父级决定](workflow-learning.md#next-author-work)选择下一任务，本节提供工程特有的判断关系：原功能／连续表现、控制／服务周期、规模代价及状态寿命共同决定完整作者结果。sort、单kernel或精度命题只支持其实际范围；能力／表示／组合不足不必先找通用BUG，合法技术收益仍保。

例如交接若给“百万实体积分／访问探针、完整战争严重慢、CPU事务向GPU转译”，只能分别支持探针、当前实现和转译事实。应调查完整负载的表示／密度最坏量／调度搬运及组合方法，做能改变路线判断的首动作；不能据此断言ECS已到上限或GPU必然可达。亲读的专业资料须进入选择／实践或有据拒绝，不能只挂参考名单。

### 用户保证与可替换实现分开

明确三类：用户可观察的功能／人数／行为／性能／安全／交互／恢复保证；当前实现选择；临时诊断合同。逐位CPU oracle、software double、某后端或全步拒绝可以承担具名保真诊断，未经必要性论证不自动成为永久产品约束。先说明诊断保护什么，替换表示／算法／后端后如何用合适误差、行为与消费者证据保该保证；不默认删除诊断，也不护旧实现而阻止有据替换。

优化保原真实工作量、行为与恢复，不能删导航／战斗、冻单位、减人数或弱化期望求绿。同条件测完整负载，拆阶段测量只归因相应命题；不同版本／环境的两次帧时不自动构成唯一因果提速，更不能线性外推未测规模。

保留能解释设计与支持复用的因果关系和必要细节：为什么用原生作者数据而不另建状态库，为什么在适配层转换坐标，为什么限制候选对预算而不偷偷采样。不要以“最小解释”为由省掉素材结构、完整保存配置、模块组织和架构前提。把架构不变量、项目惯例、历史技术债与未知分开；依赖当前坏行为的测试也可能需要纠正。

## 参数不是名字和值的清单

系统学习时深入所学方法的关键参数和相互作用，包括尚未引发当前故障、但会决定其它合法用法的细节。以下问题用于理解，不要求每项机械填表；明确紧急／专项任务才按该局部问题缩读：

| 内容 | 要查的实际问题 |
|---|---|
| 定义与消费者 | 谁提供、谁读取？别名经过哪次映射？未接线默认值是否实际有效？ |
| 数值语义 | 类型、单位、坐标/时间域、正负方向、归一化范围、精度与阈值。 |
| 三种值 | 声明默认值、用户/作者设置值、经过驱动/钳制/插值后的有效值。 |
| 作者呈现 | 已有/所需参数面板优先中文标签与说明，对应原程序键、类型、单位及有效值；显示名称变更不改机器合同，核界面值确实接原求值位置。 |
| 相互依赖 | 缩放、密度、时间映射、光照/颜色空间、采样率、纹理通道、导出选项如何共同起效？ |
| 边界与成本 | 退化输入、零尺度、非均匀缩放、超预算时怎样失败；选择值是工程约束还是艺术起点？ |
| 可证预测 | 改哪个值将改变什么、保持什么？通过哪一结果区分解释？ |

拿不准一个参数到底控制什么，用同目录的 `scripts/paramap.py`：`def` 先写下以为的含义，`obs` 记每次设的值、读回值和结果，`fit` 找出没作用、方向相反、阈值或饱和、选项分不开、保存值≠生效值，`pick` 只在量过的范围里内插。

参数/层级/场景同时改变时，追它们共同作用到哪里：空间/密度/阶段映射是否仍一致、覆盖优先级或预算是否冲突、单项正常的设置组合后为何失效。按实际触发选能区分耦合的组合和正常对照，不穷举所有值；结果用于修参数选择与适用条件，而非只增边界警告。

例如表达式允许 1.25，而 shape-key 的 `slider_max=1`，实际变形应读求值后的值；`from_mix` 可能让新 key 继承当前混合，再 `+=delta` 就不再是绝对 Basis+delta。应学会原生 API 的状态前提，而不是记住某件衣服的修补数值。

## 接线与隐藏供给

同时读代码、真实 Scene/配置/材料/数据和消费者。核入口参数是否真正传入、哪个对象/骨/节点拥有被读属性、事件何时触发、状态谁归还；同名对象不保证同一身份。源副本、导出物、安装包和进程各有版本，不能借旧检查跨版本授通过。

遇到材质等图结构，核实际 link、socket identifier、激活分支、贴图通道和颜色空间。linked socket 的 default 往往不参与求值；LUT 的 R/G 可能编码相邻空间切片，并非可随意替换的“噪声颜色”。全局 setter 与实例属性的所有权/恢复也应进入迁移决定。

时间同样有接线：业务命中时钟、表现局部时钟、归一化寿命和 shader 相位可能不同。先求映射；`phase=0.5` 不自动代表 0.5 秒或半段寿命。先核完整原 Scene 的阶段接力，再决定能否缩时。

## 空间与变换

发生空间操作时明确每个量的空间、单位、原点/pivot、轴向/手性、向量种类及矩阵乘法约定，再追实际转换位置。不要仅凭变量叫 `world`、UI 显示 Transform 或导出轴开关推定结果正确。

系统学习覆盖所学方法实际依赖的空间关系，包括当前尚未出错、但会决定其它用法的细节；明确专项才围绕该问题缩读。按真实对象选择适用数学，不展开无关领域：

- 点、方向和法线的转换不同；非均匀缩放下法线的处理不能照搬位置变换。
- 局部顶点位移、对象变换、父子装配和引擎坐标适配分别由谁承担？几何用于局部噪声/膨胀/明暗时，改顶点“贴地”会同时改变这些输入。
- 欧拉顺序、四元数/骨骼 rest/pose、相对/绝对形态、单位缩放与导出前后是否保持同一语义？读取实际求值链，不以 rest 数值替动作结果。
- 屏幕像素、UV、对象米制、世界和接触面的法线需明确对应。面积阈值随线性尺度平方变化；固定像素描边不等于固定毫米挤出。

采用可复算的小对照：非零平移/旋转，非均匀或镜像缩放，源/回导对应点和法线，修改后重建并由真实消费者读取。阈值来自所学合同与精度，不为过关放宽。它们可支持空间技巧；制作能力还要换任务意图、形态组织或消费入口，完成相应新结果，不能用同一个实例的位置稳定替代。

## 从真实失败中学什么

工程推演须能选择当前工序和控制，而不止解释既有代码。项目特定的比例/单位/材料/状态要求先映射到作者源；工具/API或作用关系未知先查真实版本与一手依据，再做有区分力校准。其命题足证就回目标制作，不能用更小误差、更多exact或入口修通持续代整体设计进展。

用户的 BlenderPro 案例区分两种问题：局部衣领/遮罩保持测试不能建立完整二次元角色的比例、脸、发和整体设计；而 `from_mix`、rest 轴与 owner 接线是值得保留的具体技术知识。二者各归相应责任层，不以一项替另一项。

用户的 MyTA 特效案例中，缩短阶段前漏读Scene的时间关系，后续才确认尺寸余速、色温、烟龄/裂孔相位与LUT空间编码的共同作用。应保留这些细节，并继续学它们如何服务不同事件的形、节奏和层次；只复算碰撞寿命、保父层变换，不能完成“学习做特效”。艺术调参要由制作意图和作用链共同指导。

迁移验收须同时有合法正常例和失败/边界例。数值算法可加平移、旋转、反向绕序、尺度等关系测试；资源管线可核保存/重开/源改重建；新增功能应调用现有能力而非复制第二份算法。记录仍未覆盖的并发、平台、精度和视觉范围。

已有失败证明某条AI自主设计路线尚不能驾驭目标时，后续不能凭熟悉API或读过索引重启同样的自信。先亲读专业原件、实际素材、配置与装配，定位自己没有掌握的设计和工艺，再通过忠实复现与有依据的变体建立能力。此结论限制未经证实的质量宣称，不免除继续深入学习和受控实践的责任。
