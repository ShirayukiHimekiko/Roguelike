# 把学到的内容设计成可用 Skill

在新建 Skill、把学习成果封装为 Skill、整理制作调用入口/作者呈现，或重整现有 Skill 的知识结构时读本页。目标是让后来接手的 Agent 能据此选方法、做出结果、识别失败，而不是只会复述资料。

按[完整流程与解释迭代](workflow-learning.md)把实际节点/分支、参数/供给/状态和失败恢复连到因果、预测与证据，再将有效知识组织成下面的形式；自主执行和适用协作沿主文约定。

学习及修订本身遵循[受控学习](learning-control.md)的步骤和行为预算；进入沉淀前已有对应实践／回归。目标Skill写该专业的可执行工序、输入输出、选择和恢复，不把整套学习管控复制给所有领域。具体步骤／参数在专业错误易发处细化，不能只给“选合适方法”让下一AI重新猜。

源工程与生产型能力另按[生产供给到自主执行](source-to-automation.md)把真实工具/模型/供应商、资源与试错/调整历史转成可用配置、具体操作及恢复方法；目标是在必要供给、工艺控制及品质依据成立后由Agent连续完成新需求，而不是只会解释或把每步退给用户。是否需要脚本由实际自动执行缺口决定，文字方法与现有工具也可承担完整路径。

## 先决定这个 Skill 承担什么

用真实委托说明使用者给什么、要得到什么、在哪个宿主/工具执行，并接回[可扩展学习基准](scope-and-selection.md)。触发描述按已证能力限域，原学习目标与品质缺口继续保未闭；不能靠缩短描述或改名让缺口消失。检查已有Skill：同能力补充原位维护；有独立触发、消费者和使用方法的新能力才另建，避免两个入口各维护同一知识。

`description` 写能力和触发情境，必要时给一个容易混淆的边界。不要只写“专业助手”“高质量完成任务”，也不要把所有相关领域都吸引进来。把例子、历史失败和具体项目条件保在适用范围，不能直接升级成所有任务的规范。

名称用小写字母、数字和单连字符，少于64字符，目录与前言 `name` 一致。入口至少是实际可读的 `SKILL.md`，带 YAML `name` 和非空 `description`；需要版本时沿现有 `metadata` 记录。已有宿主约定、发现范围和调用策略以实查为准。可读的 Skill 与机械能力合同是两种产物，JSON 报告、索引或合同不能替代正文。

## 选择知识的表达方式

按它在新任务中改变什么决定组织；同一 Skill 可以组合以下方式，不要求每份内容都填同一套表。

| 知识类型 | 后继 Agent 需要据此做什么 | 要留下的内容 |
|---|---|---|
| 理念/机制 | 解释、预测并选择方法 | 要解决的问题、作用链、成立前提与代价、改变条件的预测、反例及替代解释。事实、作者说明与自己的推断分开。 |
| 条件化选法 | 从真实需求差异选择工艺、供给与作者操作 | 可观察的适用/失效信号、有来源的取舍理由、实际工序/控制及耦合、怎样调整或改用什么；把已证关系写在方法入口，不只列方法名或保存任务历史。 |
| 流程 | 从输入走到可检查的产物 | 开始条件与必要材料、分支判据、每步真实入口与动作、可观察结果、失败后修哪里及从哪步继续。只在顺序确有依赖时固定步骤。 |
| 技巧 | 在流程的某个位置作正确调整 | 采用线索、作用机制、适用/不适用条件、具体操作、必要参数/单位/素材/耦合、预期效果与成本、失败征兆和退路。 |
| 作者操作与批量执行 | 按已明确工艺控制原生源、装配/变体/导入导出并减少重复 | 复用真实工具，需要时写临时脚本；给项目差异到控制/输入输出的映射、保持项、前提、错误和恢复。先实做目标对象再扩大，脚本可承担制作，不凭数学/循环包办设计。 |

“检查输入→执行→验证”没有说明怎么判断和处理，尚不是可复用流程。“注意单位”“优化效果”没有说明哪一步改哪个关系，尚不是技巧。知识不必全部程序化；能指导真实制作的具体文字本身就可以承担方法型能力。

专业经验正文让后继直接获得可用的认识：当前意图／感知或使用关系为什么值得保，真实控制通过什么机制影响结果，改变素材／参数／结构／时间／规模后通常怎样响应、可能连带损失什么，什么条件下改用别的办法。具体工序、有效单位／范围／耦合、必要原件和观察／成本依据随方法保留；单次值带当时条件，有限感知经验保其可信范围，不包装为普遍配方。用实际解释、图例／曲线或可编辑源把这些内容连起来，而不交一张等后继再填的why表。

相关解释更新时，修实际分支／操作及其依赖。按[选法与任务供给](workflow-learning.md)给有差异的新需求，核后继能否从持久Skill找到相应关系、作条件化预测、定位源操作并识别失败／继续；只能靠原聊天或另附答案完成，就补经验内容／入口或真实供给。独立再用应取得完整已沉淀知识及必要解释／证据，不为盲性删掉经验，也不额外喂新题的正确选法。正常、反例与新条件按实际影响核，不把一次技巧或文件齐全当整套专业能力。

### 制作类 Skill 的正文顺序：先写目标效果怎么构成

**结论：** 学的是“做出某种效果”的能力时（例：二次元水、卡通角色描边），正文按下面三层写；踩过的坑、修过的 bug 放附录，不占正文主体。

1. **目标效果由哪几层构成。** 例：二次元水 = 分层色阶 + 岸线泡沫带 + 硬边高光 + 流向。每层写它在画面上长什么样，对应 `TARGET.md` 的哪几条特征和哪张参照。
2. **每层的做法和参数。** 实际改哪个源、用什么技法、关键参数和有效范围、和其它层怎么互相影响、常见失败长什么样。
3. **怎么和参照对照判断。** 用什么机位、并排图怎么拼、看哪里、什么算达到 / 接近 / 未达；动态效果看原速录像。

附录：技术坑和修法（例：深度拷贝时机、NaN、相机穿地），每条写触发条件、症状、修法。它们帮后继少踩坑，但不能代替上面三层。

**检验：** 另一个 AI 只读这份 Skill，能不能做出**更像目标**的结果，而不只是**更少 bug** 的结果。正文主体只剩技术坑和技术约定时，说明沉淀的是排过的错，不是做法，回到上面三层补。

把[工业工艺和项目注入](production-learning.md)转成后继能执行的步骤：关键差距→适用工序/真实控制→项目特定供给/操作→可回改源→实际效果/反证。通用工艺与项目适配分离，后继改需求时能重新选择；不将私有常数、当前Demo或全部项目要求硬化为全领域规则。生图和临时脚本按[实际工序分工](ai-assisted-production.md)接入，不能只列工具名或模板字段。

### 从概括转成可执行内容

例如从本仓库的实际 `learnpack.py` 学到“来源漂移要谨慎”，应继续表达：

- **为何**：合同指纹绑定的是解释所依据的源版本，当前源变动后原解释不必仍成立。
- **如何做**：在明确的 `--source-root` 下执行 `validate`，依据 `source-drift` 定位实际文件；比较内容，追到受影响规则和消费者；修解释/适配并做受影响的原坏例与正常对照，再有据更新指纹。
- **分支与恢复**：材料根指错时先纠正根，不能对错误副本重签；真实语义变化时不能仅刷新 hash；只改注释也应核实际差异，而非笼统断定所有能力失效。
- **何时够用**：当前来源及受影响结论有据，可继续对应调用；这不认证其它领域或视觉效果。

这是依实际工具说明的例子，不要求所有 Skill 都有指纹、合同或这套命令。对目标领域，用其真实入口、参数、素材和失败征兆替换概括；数字须连成立条件保存，不能照抄案例常数。

## 作者呈现与制作调用

面向作者/使用者的场景与测试用例显示名、参数标签/分组、帮助/示例和诊断说明，默认鼓励中文；已有明确目标语言、固定专名/引文和给定业务内容按要求保留。旧模板用了英文不自动成为明确语言要求。新增类、方法、字段等程序标识采用非中文常规编程命名；现有公共API、协议/序列化键、稳定资源标识与工具参数按原合同保留，显示层用中文映射，必要时并列原名和单位。按实际触及范围处理，不为此另造参数UI或全仓翻译。

制作API优先减少真实调用者所需的步骤与概念，用最少必要、语义一致的入口和明确参数/结果贯通常用制作；默认值可省正常重复设置，高级必要控制与真实失败仍可定位。统一不要求把所有操作塞进一个函数；必要专用入口按真实职责保留，保旧薄兼容入口须先按[错误追因与选择处置](workflow-learning.md)明确其意向、依据、行为、代价与退出条件，不能用兼容掩盖本质缺陷。配置字典、已知类型分派按明确字段合同正常使用，不能为凑单入口抹类型/字段含义、吞错或隐藏人工串联，也不强加静态框架。

已有或明确要求多类制作时，优先复用实际共同的输入校验、资源/输出归属、批量编排和导出等职责，领域差异由相应类型/适配承担；不复制另一套同责任底座，也不把不同生命周期/业务权威强合。先核真实共同点再抽取，不为假想类型搭万能Manager或多层空包装。对适合统一的多类，用实际调用及产物核主路径、共同准备复用和旧调用正常；只有单类需求时不为示范复用另造第二类。

## 让入口够用，细节找得到

入口负责选择，参考正文承担通用方法和条件化领域技巧；必要工具承担重复作者劳动，案例说明依据/适用边界，历史保存失败与撤回。通用机制与项目定制分清，原话/操作全日志不持续堆入默认方法正文；确为重建必要的入口/供给仍随调用保留。反馈形成的新思路改到现行读取位置，不每次失败新建一份同类文档。

`SKILL.md` 保触发、目标、必要约束、方法/模式选择及第一项真实动作。长的条件分支或领域细节放 `references/`，在入口写明何时读哪页；不要让后来的人先扫全库。需要边查边做的具体步骤、数字和失败处理不能因“入口简短”被删掉。

`scripts/` 只放实际能减少重复或错误的操作，`assets/` 只放制作要消费的素材/模板。不要生成空目录、无用包装器或一套必须维护的占位文档。必要外部材料给取得/定位方式、版本与使用前提；不要硬编码本机绝对路径当通用默认值。被链接的方法必须有可读正文，所需素材必须存在或明确仍缺。

宿主支持 `agents/openai.yaml` 且确需 UI 元数据时才使用；保现有 `policy`、`dependencies` 与用户选择。可用时按当地 `skill-creator` 完成结构设计/检查；没有它仍按本页实际写出可消费 Skill，不虚构依赖或停止。

## 实际写盘和交给后继

1. 按[自动定位与持续推进](task-continuity.md)从上下文自主确认实际目标根和已有写入授权，查既有 Skill 及本地改动；有据可定的目录/名称不例行停问。新目录用最终名称，现有 Skill 走[维护流程](skill-maintenance.md)，不重复初始化。
2. 根据已经理解及实践的内容写实际 `SKILL.md`、必要参考/工具/素材，再读回；删完模板占位，核入口与每个分支能接上真实工作。保未知及试验范围，不把尚未尝试的方法写成成熟能力。
3. 按实际产物读回并检查入口、前言、正文和必要供给。有用且可用时使用 `skill-creator` 的 `quick_validate.py`、本包 `python scripts/skill_files.py inspect SKILL_DIR` 或已有等效检查；机械工具不是开始/继续学习的条件。它们不认证知识、行为或宿主发现。
4. 用不同输入/条件的真实任务检验方法选择、产物、失败恢复和正常对照，据新事实修订/回归；适用评审或独立使用者凭委托、Skill和原材料反馈，有据意见接回实际修订。非代码方法同样看真实输出或反馈，不靠字符串测试认证；缺必要消费者或效果证据保对应未闭，不以单Agent自主替代。
5. 据实际结果修责任位置：知识不足补机制/条件；分支错误改判据；缺依赖补真实供给；操作易错补具体步骤或确有必要的工具。不能只增加“务必认真”或把失败输入永久排除来逃避所声明的能力。
6. 交付实际路径、调用名、依赖、支持范围与观察证据。普通已授权 Skill 创建可沿宿主实际约定放入发现目录；项目源、隔离样例和显式路径调用不自动等于已安装或自动发现。仅在实际观察过对应宿主发现/调用后这样声明。输出根不是安装授权，发布与外部写入仍取用户范围。

深入学习的证据需要合同检查时，再生成 `contract.json` 和学习结果，沿主文工具执行。一个方法型 Skill 可以只有完整的 `SKILL.md`；流程/技巧清晰和新任务可用性，比文件数量更重要。
