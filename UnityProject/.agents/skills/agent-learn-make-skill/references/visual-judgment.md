# 看图方法：选参照、比风格、给方向

**结论：** 判断“像不像目标风格”不能靠看一眼下结论。按下面的顺序做：先选对参照，再并排、眯眼看大关系，然后量颜色、看边缘和形状，最后才下结论。每一步都要留下能指出来的证据。作者在学习时用它拆参照、自查每一版；美术陪审用它评审。

**为什么要这样做：** 实际案例里，AI 很擅长找缺陷（噪斑、错位、穿帮），却判断不了风格。它把“没毛病”当成“好看”，被岛、鸟居这类场景内容吸走注意力，对“整体偏灰”“高光是一团而不是条带”这类风格差距不敏感。结果修了 7 版 bug，主画面始终是一块写实湖。

## 1. 先核参照选得对不对

<a id="ref-tiers"></a>
**参照分三档，逐张判成“主基准 / 局部参照（学什么）/ 补充参照 / 剔除（哪条陷阱）”。** 门槛是为了挡住会把目标带偏的图，不是为了少选：能学到某项特征的实机图被一律拒掉，目标会越收越窄。

| 档 | 用来做什么 | 要满足什么 |
|---|---|---|
| 主基准 | 定 `TARGET.md` 特征；每版判“更近/更远”时对照它 | 下表 6 条全过 |
| 局部参照 | 只学某一项：一块浅滩的透底、一段岸线泡沫、水和环境的整体色块组织等 | 是点名作品（或“如”列出的同类作品）的实机画面，要学的东西清楚可见；水面占比不限，可以裁切。写明裁哪块、学什么、避开什么（人物、HUD、文字、技能特效） |
| 补充参照 | 旁证，帮助理解变化范围 | 画面可信地像目标作品的实机，但出处核不了。标“出处未核”；不定特征，不作主基准，也不能顶替任何点名作品的实机参照 |

“实机”靠这两样之一认定：画面里看得出该作品的 HUD、角色或玩法；或者核过的来源页、官方视频。两样都没有，画面再像也只能算补充参照。

主基准的 6 条：

| 检查 | 合格 | 常见错误 |
|---|---|---|
| 来源 | 用户点名作品的**实机画面**或官方实机视频截帧（电影、动画用原片截帧） | 同人图、宣传渲染图、加了滤镜的截图、别的游戏 |
| 主体 | 要学的东西（如水）占画面 40% 以上，而且清楚（只约束主基准） | 人物近景、大半是草地或码头、水只是背景 |
| 干扰 | UI、字幕、水印可以框掉，不压住要学的区域 | 小地图或血条正好压在水面上 |
| 覆盖 | 整组参照覆盖不同的光照、视角、距离（近岸／远景／俯视） | 9 张都是同一个机位、同一种天气 |
| 特征可见 | 能在图上指出你要学的特征（泡沫带、高光形状、色阶） | 图很好看，但看不出要学的东西 |
| 记录 | 每张写一句“学它的什么” | 只存了图，不知道为什么选它 |

整组参照里，每个点名作品至少要有 1 张亲看过的实机图（主基准或局部参照）才能开工；补充参照不算数。电影、动画这类非游戏作品，用原片帧代替实机图。这条卡的是 TARGET 定稿和正式制作；还没凑齐时，照样可以在隔离目录先用已有参照出粗版，缺的边做边补。

<a id="ref-traps"></a>
**任何一档都不收的图：**

- **标题不等于身份。** 搜索标题、文件名、查询词和许可证都不能证明图来自哪部作品，必须亲看画面。真实照片或写实渲染配着游戏名（摄影式的密集细节、真实地名或摄影水印），直接剔除。
- **别人的候选作品和待评结果**（包括和待评图字节相同的）不是参照，只能当反例。
- **同一张图只算一张。** 字节相同或几乎一样的，不能当成多张佐证。
- **HUD、技能特效、战斗光环不是水的特征。** 能裁掉的可以当局部参照；压在要学的区域上又裁不掉的，剔除。

判完就登记：选入的用 `refgrab.py pick 图… --subject 作品名 --why "档＋一句看到了什么" --out refs/selected`，剔除的同样用 `pick --reject` 登记并写明是哪条陷阱；它生成 `SELECTED.md`，编号带出处和 sha256，`TARGET.md` 的参照表直接引用这些编号。

## 2. 先描述，后判断

对每张图（参照和当前版都要），先写 5 行纯描述，**不用“好、差、高级、不错”这类评价词**：

1. 主色：画面里面积最大的 3 种颜色，偏什么色相、饱和度高还是低。
2. 明暗：最亮和最暗的区域各在哪里，明暗分成几块大区域。
3. 最亮的东西是什么形状：条带、星点、一团光晕，还是线。
4. 边缘：泡沫、高光、倒影的边缘是硬还是软。
5. 细节分布：哪里细节密集，哪里大面积安静。

描述写完再比较。描述写不出来，就说明还没看清，回去裁切局部再看。

## 3. 并排、同条件

- 用 `scripts/refgrab.py compare` 或 `look` 把参照和当前版拼成一张图：尺寸相同，构图尽量接近。
- 只比较同类画面：近岸比近岸，远景比远景。不要拿当前版的俯视图去比参照的平视图。
- **忽略场景内容，只看要学的东西。** 岛的形状、建筑、人物都不算水的风格。

## 4. 眯眼看大关系（最重要）

把两张图都缩到宽 64 像素左右，或者模糊到看不清细节（`refgrab.py look` 会直接输出这一列），再比较：

- 明暗块的分布像不像；
- 主色像不像；
- 画面的“节奏”像不像：哪里亮、哪里安静。

**缩小后已经不像，细节修得再好也不会像。** 这时下一步必须改大关系（水色分层、明暗分布、主色），不能去修小问题。

## 5. 量颜色

**先量目标和每个候选差多少，再比候选之间。** 只量两个候选之间，得出的“两者差不多”回答不了离目标有多远。

1. 在目标参照（主基准）和每个候选或当前版的**同类区域**取色，例如清水区、近岸、远处各框一块，避开 UI、倒影里的天空和云影。场景不同就找同类区域，不必坐标相同。用 `refgrab.py crops 目标 候选甲 候选乙 --labels "目标|甲|乙" --regions "清水=…;近岸=…" --out cmp/crops.png` 一次裁出并量好：**目标放第一张**，它报的就是每张和目标的差；构图不同时用 `|` 给每张图各写一组框。不用自己写裁切脚本。
2. 逐个写出“目标 vs 候选”的差距，再写候选之间的差别。例：清水区饱和度，目标约 60%，候选甲约 25%，候选乙约 20%。
3. 比较三件事：色相跨度、饱和度、明度能分出几阶。

要把参照颜色写进 TARGET 当可检验目标，用同目录的 `numspec.py`：`extract` 从主基准取各区域目标色，`steps` 沿近→远一条线数色阶，`check` 拿当前版逐区域判达到／接近／未达（输出可直接给 `wavelog end --status`）。

数值只作旁证：能支持或推翻眼睛看到的差距（如“整体偏灰”），但不能换算成相似度，也不能单独决定排序。区域的深度、光照、视角不同，要在结论里写明。
- 风格化（二次元）水的常见特征：色阶分明（能数出 3 阶以上），饱和度高，暗部不发灰发脏。当前版测出来“饱和度明显低于参照”“只有 2 阶”，就是具体差距。

## 6. 看边缘和形状语言

风格差距经常不在颜色，而在形状：

- 高光：参照是横向断续的硬边条带或星点，当前版是一团模糊光晕。这是差距。
- 泡沫：参照是成型的白色带（内缘硬、外缘碎），当前版是一圈细碎白点。这是差距。
- 倒影：参照被波纹横向切断，当前版是完整的镜面复制。这是差距。

每条都要能在图上指出位置。

## 7. 下结论的格式

1. **离用户的判断句：更近 / 没变 / 更远**，依据是哪一步的哪个证据（例如“缩小后远水仍是灰块，参照是深蓝”）。
2. **差距最大的 3 条**，每条写“参照是什么样、当前是什么样、怎么看出来的”。
3. **下一步要新增的特征**，至少 1 条，写具体技法或参数，以及预计画面会怎么变。

## 8. 自我校准（每次评审前做一次，1 分钟）

把一张合格参照和一张明显不像目标的图放在一起，比如写实照片、上一版或别的风格，按第 2、4 步说出它们的差别。说不出明确差别，说明这次的看法不可靠：改用裁切局部和量颜色，在结论里写明“视觉判断不确定，依据以测量为主”。

## 常见看错

- 把“没有毛病”当成“像目标”。技术正确只是底线。
- 被场景内容带偏，例如“鸟居倒影很清楚，所以好”。
- 只看最好看的那一处，忘了整幅画面。
- 对整体偏灰、偏暗不敏感。这类问题用取色来对冲。
- 只比候选之间、没量离目标多远，得出“两者差不多”就停了。
- 用自己的审美替代用户点名的风格。判断标准永远是参照和用户的判断句。
