# 一句话启动、自动定位和持续推进

启动学习、决定工作区/目标 Skill，或下一次继续已有任务时读本页。自然一句话加现有上下文足以开始；路径、材料位置、目标名和验法可由 Agent 实际调查补齐。可选请求 schema 的 `output_root` 等字段由 Agent 据调查填写，不要求用户先填。只有查后仍不可判定且会改变目标、权限或正确性的关键未知才问，同时继续不依赖答案的准备。

共同顺序／额度从[受控学习](learning-control.md)消费；到限且目标未成先按[阶段预算决定](learning-control.md#stage-budget-decision)实接多AI的重分配/方案重评或具体续额请求，不把阶段余额0当父任务停止。恢复要携原结果／因果未知的预算已用、失败、在途和延长状态，换窗口／Agent／任务名不重置。只重开被新输入／反证影响的步骤，有据复用已成立部分；不以“自主”略过关键证据。

## 找到合适的位置，不另造一套权威

先读当前任务、项目治理入口、既有学习/维护记录及相关 Skill。按当前项目和已知相关目录有限检索（有 `rg` 时优先使用）；跟随真实来源/调用关系扩大范围，不扫无关全盘，也不只按目录名、时间戳或旧“通过”选对象。

区分四种位置，它们可相邻但职责不同：

| 位置 | 选择与使用 |
|---|---|
| 原材料根 | 原作、源码、配置、案例及版本的实际来源。先只读，实验在学习工作区；任务另有产品修复授权时才按其写域修源。 |
| 学习工作区 | 复用与本目标/材料相符的持久工作区及未完接点；没有时沿项目约定创建。独立学习没有项目约定时，在授权且用户可写的工作根建立有意义的学习目录；不把安装/缓存目录当实验根，不让临时目录成为唯一学习成果。 |
| 目标 Skill 作者源 | 用户明确位置优先；否则读现有候选的触发、正文、资源、作者归属与实际调用。同能力的相符 Skill 原位维护，有独立能力才命名新建。已有作者仓库就改作者源，不能只改发行 ZIP、缓存或消费副本。 |
| 宿主消费位置 | 与作者源分别核。没有指定位置、项目约定或现有作者源的新可发现 Skill，按实际宿主约定落位；Codex 通常用实际 `$CODEX_HOME/skills`，未设置时 `~/.codex/skills`。尊重隔离测试/用户指定根。创建 Skill 的授权不等于覆盖另一份安装、改全局配置或发布远端的授权。 |

用户点名Skill时，亲核其 `name`、正文能力、作者源和实际接点；发现目录没有就沿相关作者仓库找，不用名字相似的另一个Skill代替。先看目录是否存在、可写及谁正在修改，保用户未提交内容、元数据和资源，不重复初始化。能据项目约定和授权决定的普通落位自行决定，不例行停问；多个候选用能力、来源和任务接点判别，真有无法查清的权威冲突则保原件和待决项，不擅自覆盖。

目标名尚未给出时，按能力取简短、可区分的名称，遵从[设计](skill-design.md)的命名/发现约定；不是每次学习都另建一个 Skill。安装副本若是用户明确指定的维护对象，照其范围处理，但不据此推定作者仓库或其它副本也已同步。

## 边学习边落到同一个目标

确定当前有效目标和实际目标路径后，沿[完整流程学习](workflow-learning.md)研究、解释、实践和修订。已得到支持的部分及时按[设计](skill-design.md)写入真正的 `SKILL.md` 及必要参考/工具；已有目标沿[维护](skill-maintenance.md)有界更新。保候选/试用和未知边界，不能为尽快写文件就把未经实践的知识认证为成熟能力。

源工程/生产流程沿[供给到自主执行](source-to-automation.md)取得工具链、模型/供应商、资源和失败/调整历史；接清当前工艺/控制为何适配项目独特要求、下一目标内作者动作及观察，再自主执行。配置/入口齐全不代这些前提；未知主动查证，不把决定退用户，也不凭“方向已定”直接信任AI未证设计。

学习笔记和实验为目标供给证据，目标 Skill 保存后继能实际选择和使用的现行流程、推理与技巧。每次有信息的发现都核：它改变哪项解释、分支、参数/技巧或失败恢复？当前方法是否已修到实际读取的位置？哪些旧正常/原坏例/新条件需要回归？只追加日志、报告、索引或示例，而目标仍是旧方法，不算持续沉淀。

工作区保存原始实验与历史，交给后继的 Skill 要有可读入口及必要供给；不能只留下本机临时路径、越根依赖或空链接，便称为自含可调用包。确需项目原件的 Skill 声明材料根和依赖，按实际项目上下文验消费，不冒自含安装。

## 恢复主线与失效队列

同一身份明确经历上下文缩减、知道必要上下文不足、收到继续指令或发现摘要与原件冲突时，先读原任务/治理入口已给定的同一当前定位，再决定依赖动作；不从mtime、Tail或最近文件猜当前，也不因压缩新建身份/角色。原有效授权与已证事实、F/A职责/完整原意见/gain事件/否决闭权和原预算继续按对象/条件生效，不全盘清零。

把当前定位同真实后到用户修订、源/消费版本及原operation/run/request终态对照：确认当前目标/范围/可做禁做、唯一writer、资格维持/撤回与原未闭、已证/未证、失败/已用/在途及下一具名作者结果/消费者。短段与原件定位须足以支持首动作，不强固定字段表或全历史复制。摘要只作导航，旧“已够/仅剩X/准停”不覆盖新作用域或真实终态；原PRE计划不能把已执行未达标写成未运行，已完成不重放，unknown/pending先查原作业。

首次新解释仍按[独立核验](comparison-and-regression.md#independent-first-result)待证；摘要不足不自动否定同条件旧证。沿[完整选法](workflow-learning.md#next-author-work)区分接线/实现与能力依据；当前只改Skill的委托不接管原产品，真实制作委托仍接原专业任务。缺关键原件/控制只限依赖它的动作，合法读取/保护和其它就绪工作继续。核后实际执行第一合法结果，在原接点保存发生/未发生、消费者与剩余接回，不只复述恢复规则。

已知压缩事件、本人上下文缺口与其它AI是否收到分别取证。宿主确实暴露contextCompaction时，保真实thread/item/source和started/completed阶段；started不冒完成，completed不认证任务事实/权限。给定历史rollout的compacted元数据仅证该owner/时点，不推当前自身或peer实时知情，也不与已废弃的thread/compacted通知混同。无事件仍保unknown，按当前源恢复；不为探测部署API宿主/服务、造广播或每轮扫大日志。元数据检查不向模型/输出展开消息、加密或隐藏推理内容，并如实说明容器解析/语义检视边界。

<a id="continue-or-stop"></a>
## 答复、继续与实际停止

完整有效目标仍欠结果／品质且有可行授权动作，就按[父级决定](workflow-learning.md#next-author-work)接下一项；有效旧证复用，失效方法自主停改，局部回滚保原件。目标真实达成则交付，不为持续强造工作；阶段产物和adopted不独自关闭父目标。

**阶段答复本身不是停止委托。** 用户要状态、先给方案、能力边界或阶段有据结论时，及时给已证／报告级／未审范围、当前决定和下一实际动作；不为这次答复另开准停轮。按实际行为与受托结果判断，不按commentary/final等通道名判断。不得因答复搁置已授权且就绪的必要工作；确待外部依赖就如实交接，未部署执行／唤醒不声称仍在后台工作。答复不代产品采用、完整完成或发布许可。

**真实停止与完整完成须核原委托。** 拟实际停止必要制作核验／推进，先核全部有效目标、现行Skill及供给、首件／新需消费、回归和否决；执行仍可行授权动作，缺方法先求具体推进建议。目标已兑现，或相称查证后确阻断且独立就绪动作已落实，才申请相应停止；交范围、证据／未闭、主要继续路径与替代、权限／资源、在途终态和恢复，不把举证推给陪审或要求全球穷举。

适用陪审或用户要求陪审时，真实申请并取得本次实际停止范围的明确许可；适用双职责就分别取得同对象／版本／范围的允许或“停X继续Y”。未答、ACK、内容通过、负分和completed不代许可，子scope不抹必要未闭。被打回落实指引后按新结果核原委托，不补一局部就重申；已有同版审查合并停止语义，不另造长报告／仪式轮，也不为普通无陪审学习增双审。

**擅自停止受托推进，或适用陪审时未申请即实际停止，仍P0阻断、打回。** 保原停止／后果，先恢复已授权下一动作再核原坏例和正常；预算限一种方法不授权放弃目标，保未完成声明不能免责。真实采用／发布按各自品质和权限另核。

用户明确暂停／撤销／等待立即执行，不等票。必要权限／供给／宿主缺口只限其依赖；宿主硬中断能保存就保存，下次接原未闭，不补造事前许可或后台执行。

## 用文件接回，不重新开始

持久化复用原归属记录与已有保存机制：自然决定/实物、真实用户修订或权限变化、关键未闭变化，以及不明终态写入前的必要意图，更新足以安全接续的当前事实/原件定位并读回；不逐工具复制长摘要或建第二状态库。独有材料、旧预算/失败/在途及撤回理由保留，稳定历史按需下钻。

收到继续/增量后按[同身份接续](#same-identity-compaction)先核现源，再接原目标Skill的第一合法结果。已知事件或状态实质改变影响其它职责时，沿原消息通道一次真实交给对应原职责，区分已发/实收/本人承接；没有事件或投递证据就保unknown。无需新schema、固定表或强制新角色。发布/推送/安装分别按真实授权，不由持续沉淀自动扩权。
