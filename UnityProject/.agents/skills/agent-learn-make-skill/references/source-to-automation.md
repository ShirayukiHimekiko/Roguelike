# 生产供给、入口绑定与真实终态

学习源工程、生产流程，或将方法封装成配置后可自主运行的 Skill 时读本页。既取成功最终件，也主动寻找它依赖什么、怎样生成、经历过哪些验证/失败与调整；这些事实要改变可调用方法，不只成为清单。调查、实践、写入目标和回归可以交错，沿[持续推进](task-continuity.md)执行。

## 沿真实生产链主动取得供给

从项目入口/治理、构建与运行脚本、依赖/锁定文件、导出导入配置和实际日志追到最终消费，再从结果反查漏掉的供给。必要时取得获准相关仓库/发行资料、维护方文档、原作者材料和可达旧版本，不能因当前目录未见便宣称不存在。核实际使用的对象和生效值，不按文件名、工具广告或自己的常用组合猜测。

| 对象 | 要取得并核实的内容 |
|---|---|
| 工具与环境 | 软件/CLI/API、插件/扩展/自定义脚本、运行时和关键依赖的真实版本、调用入口/参数/配置、平台/硬件/格式要求、可达性及必要许可。安装过或出现在依赖表，不等于此流程实际使用或现在可调用。 |
| 工具链 | 每段由谁执行、读写哪些原件/中间格式、单位/坐标/色彩/精度等变换、保存/导出/导入/构建/绑定/运行/检查怎样连接，缓存/状态/人工过桥在哪；保原生可编辑文件和重建路线，不能只学最终导出件。 |
| 模型与供应商 | 所学工程实际使用的模型/服务，而非本次学习Agent身份。按存在项追基模、微调/附加模型、版本/修订或权重来源、量化/后端、关键推理/生成参数、提示/模板、随机性和实际输入输出；供应商、兼容代理与本地宿主分清，保模型ID、服务入口的配置引用及真实调用依据。闭源未公开细节保未知；配置声明不冒实际请求。无模型的流程如实不适用，不为字段完整强接服务。 |
| 资源与素材 | 原出处/作者、取得位置、版本/身份、许可或已知使用前提，原件→加工/生成→组装→当前消费的路线；生成资源连工具/模型配置与必要输入。替材会影响质量时保原供给与重新验证条件，不能静默换成占位物。 |
| 验证与试错历史 | 测试/CI/构建/运行日志、实验/评审/工单、版本/提交/diff、失败和中间产物、旧配置/分支、编辑层/工程文件、手动调参/修形/返修的前后原件及反馈；追它们怎样影响现在的方法和验法。 |

取材尽量覆盖与目标有因果关系的可访问历史，而不是固定抽几份成功报告。先用已有索引/日志定位，再实际打开关键原件；记录已查范围、找回的材料以及未保存、不可达或权限不足的具体缺口。不能把主动查找退为要求用户先整理全套资料，也不为“尽可能多”无界扫描无关账户/目录或复制整盘。

凭证只留环境变量名、secret/配置引用、所需权限和取得/检查方式，不将密钥、令牌、账户私料或无关日志写入 Skill/归档。原件可保在授权材料根，Skill 留必要知识、身份和可达定位；大体积历史不必全部塞入安装载荷。引用依赖要能按声明根复读，不把本机临时路径冒通用配置。

## 把失败与人为调整学成可选择的方法

对有信息的沿革，接清当时目标/版本、输入与配置、完整结果和失败征兆、谁据什么观察改了哪一层、前后具体差异、复验与尚未知。保旧失败原件和撤回理由；历史错误不因真实发生过而变成正确规范，当前成功也不能抹掉旧边界。

区分真实人类说明、工具记录、Agent操作和自己的推断：commit作者/时间戳不独自证明手工过程或动机；只有最终图像不能还原具体调参。缺人工操作记录时保未知，可做自己的受控实验，但要标为事后实验，不能补写作者经历或把Agent修订冒充人类调整。

将有据调整译成后继可以执行的条件和动作：**什么征兆出现时，在流程哪一处，改哪些参数/曲线/结构/素材或模型设置，为什么，怎样判断够用，失败从哪恢复。** 保数值/单位/耦合和前后条件，避免把一次手调值升为万能默认。对编辑器里的裁切、修形、分层、接线或跨工具过桥，尽可能找到可重放的原生操作/API/CLI/已有自动化；没有这些能力时不要用“人工精修”四字藏掉必要步骤。

据新事实实际修目标 Skill 的现行解释、分支与操作，按[流程与推理回归](workflow-learning.md)核原坏例、旧正常和新条件；工具/模型/素材或人工调整链改变时，查受影响消费者。只保存失败截图或追加警告，不算学到了失败恢复。

## 原入口、当前run与实际终态

恢复先以确切对象/版本、成员/源ID、当前操作或run定位后到真实终态，再看旧计划。已满足目标不制造新effect；held/撤销先限制相应操作；pending/unknown/lost reply先查原作业/检查点，不重放。消息、源或检查点变化时只重判受影响资格，保同scope撤回与其它scope正常，不拿全局状态覆盖不同对象。原Library/Runner/Session/消费者已有权威时复用其入口与typed结果，不复制第二状态机/渲染器或以sidecar替代真实消费。

方法修改后沿后继真实公共入口重开/选择/制作/消费；显式路径可用、宿主发现、常驻服务和自治运行分别取实际证据。原生返回、阶段receipt、目标输出和独立Verify分开；Verify若只是回显expected或自填passed，仍须从受控实际对象/状态与effect历史独立观察业务目标，不把stub绿灯升级成业务已成；“旧计划要做”不能压“当前目标已满足”，0effect也应交完整类型结果。此节是存在这些机制时的生产合同，不要求所有艺术/文本作品新建run平台。

## 先核控制能力和项目适配，再连续执行

先按[受控学习](learning-control.md)确定步骤、已用／在途预算和[风险／回归](comparison-and-regression.md)。区分三类工作及证据：**作者原样复现**核原输入／配置／工序／完整结果；**项目组合适配**核各方法衔接处的控制、数据／时间、关键代价及原用户保证；**自主新研究**明确未知、竞争解释和有限判别。成熟部件可组合，不能只列多个方法名就认为整条链成熟；自制CPU实现能作为语义／诊断原件，不自动成为GPU生产架构依据。

完整结果反证时按[工程父级假设](engineering.md)区分实现／接入缺项与路线能力依据不足，让规模、密度／最坏量、调度／搬运、驻留和真实消费者决定下一主动作。有限研究可以建立答案，足以决定即回父级选择；不先要求未来同规模成品已存在。旧实现／保真诊断可有据保留或替换，不能自动覆盖真实用户保证。

配置/入口可达不是工艺成立。将本项目的必要差距接到原生作者控制：能改哪些形态、材质、组织、行为或交付属性，哪些仍不能直接控制？按[项目注入](production-learning.md)把独特需求落到源/供给/参数/操作与反馈。控制不足就调查成熟工具或更充分的表示；不能因旧脚本易调、旧数据易保而退回不能承担目标的路线。

关键工艺、API/版本、控制或供给未知，调用碰壁或结果推翻解释时，主动查项目原件、工具实际能力及一手方案；检索结果须改变选择/操作。对最小工具缺口修对应入口，确认后立即回目标作者动作，不靠入口发现、修码或反复诊断冒工序已实践。失败原请求的输入、代码与当前修订版分清，修了脚本不等旧调用已重跑成功。

生图和临时脚本按[AI辅助制作](ai-assisted-production.md)接入真实工序。它们可以做实质供给与作者操作，不止解释/检查，也不凭生成或批量规模取得设计正确性。

配置和初步方案可由 Agent 从现有项目/目标主动恢复、检查和拟定，不要求用户填新表或逐项批准。真正缺少决定性偏好、必要权限或费用范围时才最小澄清，已授权且可判断的正常选择直接做。把以下条件接到目标 Skill 的真实入口：

- **可用配置**：实际工具/版本、模型/供应商/素材、材料/输出根、凭证引用和授权范围；实际调用/读回核依赖与控制能力。缺依赖主动查合法可达供给/替代工艺，并核其对原品质/编辑/消费的影响，不凭“有据替代”四字许可占位或简化交付。
- **初步方案**：成熟工艺为何适配当前差距，项目独特需求怎样改变工序/控制/供给，首项作者动作与事前预测、可编辑结果、反证和恢复。足证即执行，不等用户逐步决策；关键依据未知先定向查证，不由“目标足够”跳到未经证明的AI设计。方案不扩新权限。
- **自主执行**：沿已核工艺自行制作/生成、导入/重建、观察、返修/回归和保存。对作者优先少量语义统一的制作入口，把真实共同准备接到可复用底座，保各领域控制/输出归属与可定位失败；不让调用者手工重复串联共享准备，也不复制原工具权威。复用原CLI/API/编辑器自动化，需要时写临时脚本执行明确的原生作者操作或批量输出；不只限机械检查，也不建无用永久框架。受控探索按要减少的未知组织可比候选，生产扩量前在目标内核代表作者动作是否改变必要差距与达到相应品质。
- **失败恢复**：分别核wrapper返回、原生exit／timeout、阶段receipt、目标输出和输入保护；无ERROR标记不等编译／消费成功，日志疑点也不独证唯一根因。显式UTF8读写并读回字段。未知终态先核原作业，不盲重放；保存更新先保原raw、stage读回再提交，提交后读回异常可能已写入，不能称旧状态不变。必要时复用原生单文件安全保存，不冒多文件事务或恢复已丢历史。按真实差异修输入／工艺／供给，保失败和原费用；不越授权或降品质。
- **交付验法**：核当前新产物、保存/重开/下一消费者及受影响旧能力。视觉/声音/动态结果仍用相应实际观察和必要反馈，不能用命令退出0或文件存在代质量；Agent应承担能自行完成的判断，不把所有质量检查都外包给人。

配置和初步方向成立后，在共同步骤／预算和风险条件内实际执行，不为常规参数／正常修复等用户逐次推动。反证、到限和准备扩量须走对应核回，不能以配置已齐免除。适用陪审正常用有据意见，缺陪审不伪造核回；不把本次开发治理或特殊工具写成所有目标Skill门槛。

对不能执行的节点查可用入口/成熟等效工艺并核控制与损失；确不可得就保具体动作/判断/供给、影响及接回条件，推进其它就绪部分。不能退回易自动但不能承担目标的控制族，也不能把必要人工步骤藏入配置后宣称全自动。恢复有据旧动作不回退原品质，未知终态先查原作业，不重放付费或不可逆操作。

## 用真实新任务核交接

让目标 Skill 在已配置、已有初步方向的条件下，完成一个有相应变化的新需求；观察真实调用、产物、失败识别/恢复和新旧回归，不能只检查配置文件或再次复述历史。记录需要过哪些人工输入、是否逐步催动、哪些决策已自动完成及哪一段仍未实现；配置后自治、显式路径使用、宿主发现和真实服务调用分别据实声明。

没有模型服务、专用编辑器或外部供给的实例，只证明它实际具备的自动路径，不认证其它供应商/领域。未来真实项目中遇到新供给、漂移或反例，按[维护](skill-maintenance.md)接回同一目标 Skill 和当前知识；不靠复用一张旧“全自动”标签继续失效路线。
