# 识别：复刻／参考／视角／单位三问／交付类型／应有而缺失

<a id="scope"></a>
## 这一页解决什么

同一句话在不同严格度下要求完全不同。「复刻」和「参考」都可能被说成「做个一样的」：前者要求逐项可核的对应，后者只要求可辨的取向。混为一谈的后果是两头都错——要么把借鉴当成必须逐像素还原而永远做不完，要么把复刻当成随意发挥而交付失败。

「视角」同理：玩家实际看到的、作者在编辑器里看到的、诊断时放大慢放的，是三种不同证据，互相不能冒充，但报告里常常只写「我看了」。

「单位三问」是元素模型的完整性骨架：从哪里来、在干什么、到哪里去；成立还要放回本项目世界、意图、表现和整体预算。

**本页集中定义识别概念、适用条件与查找入口。** 产品严重度、裁定与证据责任沿各节指向的结果正文；识别不替代相应实查，也不另增产品底线、权限或审批。

<a id="replication"></a>
## 1. 复刻 / 参考 / 借鉴：先定严格度

看到「还原」「复现」「照这个做」「一模一样」「像这个感觉」「借鉴一下」这类话时，**先判档位，再谈做法**：

| 档位 | 识别信号 | 本次义务 | 允许的偏离 |
| --- | --- | --- | --- |
| **复刻** | 还原、复现、一比一、照这个做、要一模一样 | 对象身份、比例、布局、时序、参数逐项有对应依据，差异要能说出原因 | 仅技术不可行、授权不足或用户另行取舍处，逐条列明并由用户裁决 |
| **参考** | 参考这个、像这个感觉、按这个方向 | 取向可辨：风格、结构、手感的方向一致 | 具体尺寸、参数、实现可自定 |
| **借鉴** | 借鉴、灵感来自、别做得像某个具体作品 | 仅要求不与目标冲突、不侵犯授权 | 大体自由 |

**识别不出时按「参考」处理，并明说这是推定**，不要把推定写成用户已选复刻。用户后到改口按原话调整，保旧记录不重写。

**复刻档的常见误判**：拿「部件齐全」「文件名正确」「资源已导入」当还原完成——身份与绑定仍须按[参照对象身份](constraints/12-resources.md#reference-identity)实核。反方向也要防：用户只说参考，却被要求逐项复刻，同样是错。

<a id="perspective"></a>
## 2. 视角：先说清是谁的眼睛

| 视角 | 谁在看 | 能证明 | 不能证明 |
| --- | --- | --- | --- |
| **玩家视角** | 目标设备、目标尺寸、正常速度下的真实玩家 | 可读性、遮挡、节奏、手感、反馈是否可辨 | 底层数值、权威状态是否正确 |
| **作者视角** | 编辑器、Scene、资产预览、Inspector | 结构、绑定、参数、引用 | 玩家实际看到的结果 |
| **诊断视角** | 放大、慢放、多机位、骨线、速度图、逐帧 | 定位与解释原因 | 不能当体验证据，也不证明正常速度手感 |
| **参照视角** | 原图、原视频、目标作品的机位与画幅 | 对照与还原的依据 | 不等于本项目视角，不能直接套用 |

**报告视觉或体验结论时必须写明用的是哪一档。** 用作者或诊断视角得到的结论，不能签玩家体验通过；这正是「编辑器里看着没问题」却能交付坏结果的原因。玩家视角要求在目标尺寸与正常速度下亲看，沿[玩家视角的动效对照](constraints/04-visual.md#player-motion)与[实际视觉验收](review-standard.md#visual-review)。

**机位一致性**：做复刻或对照时，参照视角与本项目视角要对齐画幅、焦距、高度和朝向；机位不同导致的差异不能算作还原失败，也不能反过来拿来当还原通过。

<a id="unit-state"></a>
## 3. 元素模型：以三问调查现状与应有缺口

实质任务默认起步与持续维护由[默认模型义务](dialogue-coordinator.md#model-autonomy)主动承担，不等用户点名。每次当前判别从有效目标、世界规则和下一消费者反推应有对象、关系、能力与转换，再同作者源和实际观察对照。模型既容纳已有，也容纳应有但待证、尚未找到、确证缺失或被反证的关系；不只复述作者已列元素。疑似缺失实际按[应有而缺失](#absence)核应有依据、真实承载／生成／装配及等价供给，区分合法不需要与仅未找到。

**三问是调查骨架，模型建立不等于结论成立。** 下列三问均须触及；未知如实接未查范围和下一查证，不为齐答编事实，也不等所有命题已证才建模／调查。共用世界／机制依据可复用，身份、状态、位置、意图不同的实例仍须分清；未用素材库不强造全量模型，代表一件不能签全部元素合格。

1. **从哪里来**——由谁生成或取得，所处世界及允许例外有什么原件，归属、权威、初始身份／状态是什么；表现或设定如何说明其来历。
2. **在干什么**——当前作用、行为、目标、朝向和与他者的空间／业务关系；该行为如何符合当前世界规则、主体目标与已知信息，外观／动作／反馈传达的含义是否与之相符。
3. **到哪里去**——意图中的下一结果和真实转换、退出、回收／归还是什么，由谁承担，失败／取消／重入如何接回，其后果怎样继续影响世界与其它元素。

**逐命题核可信依据，再决定怎样使用。** 对影响当前判断的存在／身份、目的／意图、实际作用、后继、表现和预算，分别接可定位原件、对象／版本／条件及支持范围，分清直接事实、设计／推断、具体未知与证据冲突。设定能证明应有或设计意图，不自动证明实现／运行已兑现；有证存在不担保作用／去向，局部证据不抬升整元素或整体预算。说明当前哪些足以采用、薄弱／未查在哪里及什么反证或观察能改变判断；任务／修改目标的解释也须核证，首次印象或后到关键词均无额外证据权重；置信依据不能被整项统一高低、百分比或描述的自信代替，亦不新增固定等级／全元素字段表。共用证据只在实际支持范围复用。

元素及其属性／关系／命题随目标内原件动态增补、拆合或撤回，三问不是封闭schema，也不新增交付／权限。视觉因果任务还须分清所见元素与实际载体，接“有效作者控制及条件→局部作用→完整构图／空间／时间与成本→混杂／失效→新条件预测和后继”；共享载体不强拆独立模块。关闭／中性化、粗调／细调按本题原话和真实源安排，不强所有元素开关或全域固定N。看见变化、识别因果、设计有价值及迁移／P0关闭分别核；有关对照须保连带变化，不能由复合干预推唯一原因。已有有限经验／对照复用，必要未知接实际作者任务，字段齐或数量不代模型完整。

**数量也是独立命题。** 涉及条目集合、重复表示、样例、可见窗口或容量／上限时，主动核实际集合来源与成员、单位及身份去重／过滤口径；按当前判断区分现有总量、样例／所选量、可见量、容量与资源数，不把不同口径的同一数字互证。固定、示例、可变或未知分别给本版依据与适用条件：有据的双角色比较位、唯一已携或有限集合可保，不默认任意N；静图有限只证该快照，不能代替数量选择、全集覆盖及变化后继的设计责任。数量不足／冗余按原目标和消费者查，不凭作者列了几个就定完成。

**关键命题的表达。** 实际呈现或接续时，用“命题／应有结果 → 依据与支持范围 → 成立条件 → 反向失效边界 → 代价／资源 → 后继／验证”压缩表达，可用短段、合并列及共用依据回指。无关项不凑空栏，影响判断的条件、失效和资源不能省。按实际依赖说明条件／资源状态变化的影响，触及失效条件才撤对应策略／能力，保仍足余量与独立能力继续成立；代价接实际承担与后继。创作设定、推断和待验证动作分清，不以列齐字段代成立，亦不强制全元素六栏。

**成立条件一起核。** 三问与有效世界规则、外观—行为、意图及整体预算的对应命题及依赖有据，才能在已核范围称元素合格；描述／问答／字段齐、版本或三者赞同均不代成立。规则以本项目有效设定及修订为准，实际实现与应有规则冲突分开；奇幻、伪装、反派、合法跳切等不能套现实物理或道德判断。主体意图按角色目标、当前知识、关系、控制输入和约束解释，未知不编心理；无自主主体按设计目的、功能与触发核，不强加意愿。视觉命题按[视角](#perspective)与[视觉验收](review-standard.md#visual-review)亲看对应对象／版本及必要状态／完整过程；图上观察、语义身份与运行推断分证，同源图／稿不当独立互证。完整当前静图可在已看范围作有据判断；它只支持所见快照，不能签未看动态、隐藏全集或任意N，也不免数量设计责任。缺观察只限其依赖，不编故障。

**预算核组合。** 按本项目真实约束和观察核规模、并发、持续寿命、共享依赖及耦合后的合计成本与可用余量，保单位、时间窗口和已用／在途；各元素分别过线不保证整体可承受。未知成本保具体缺口，不编通过或故障，也不凭更轻预算删除原功能／身份／意图。

**所有元素模型持续论证，并可被推翻。** 对所有目标内模型及既有／新增命题，在自然成果、关键决定、新原件、条件变化、弱前提或恢复处，主动核来源、结构、行为／意图、后继、表现及组合预算等适用依据与成立／失效条件，并找能区分当前解释的合法反例／观察，不等现成反证。创作设定／推断依有效设定与明示前提论证，未证不冒成立／实现；稳定旧证可复用，不强找错误、逐工具重填或启动后台永动。用户纠正按相应原件／对象版本核；图示标注须亲看当版图并核用意，不凭颜色推修改授权。冲突须改当版命题、brief及作者动作，实际接法沿[默认义务](dialogue-coordinator.md#model-autonomy)。实际反证接同一活记录的“原判断及版本／条件 → 反证 → 撤回／保留范围 → 依赖消费者及责任端 → 第一查证／修源动作与结果”；只撤真实依赖，保独立已证及条件仍同的事实，不能只改描述、计数或置信标签。按因果追责任源，不强制同一追查链，也不把候选总量当同时可见量。沿[共同裁定](review-standard.md#decision-order)限实际依赖动作，建模、必要调查、授权修源和独立工作继续。模型误认与产品违约分开；违背原目标就修作者源，不改称装饰或改世界规则使之合法。原否决由原职责核回，真实用户修订沿原主线接续。

模型沿[一处活理解](project-workspace.md#workspace)承载当前命题／观察、原件与支持范围、反证及未闭，不另建平行模型库。实际参与职责共享同一定位和变化仍各自亲核，不把共识当事实；对话本人建模质疑沿[默认模型义务](dialogue-coordinator.md#model-autonomy)，真实过程／声明按[现有呈现入口](message-style.md#user-facing)，不新增世界模拟、固定全表或第二状态平台。

来源、当前、去向分别取证，调查骨架不代完成。业务位置／状态／关系沿[F-P0-03](p0-progress.md#method-f-p0-03)，生成／清理／隔离沿[A-P0-01](p0-architecture.md#method-a-p0-01)按实际严重度裁定；本模型不自授运行、改设定或发布权。

## 4. 交付类型：谁是这个产物的下一消费者

**先核本次有效委托要让谁完成什么，再核当前中间产物交给谁。** 中间接收者与受托消费者不同时，沿真实采用关系说明它服务哪项本次必要结果、怎样接回该结果；不能仅凭中间产物可继续交接就认可整条排序。用户确实只委托方案或研究时，按该范围核其依据与可实施性。

| 下一消费者 | 成立的含义 | 验收动作 |
| --- | --- | --- |
| 玩家 | 他实际能做想做的事 | 走目标游戏中的玩家路径，看真实结果 |
| 非游戏使用者（工具／API／工作流） | 他能完成当前实际任务 | 走真实使用路径，按[可用性方法](constraints/11-methods.md#early-value-check)核收益与负担，不借玩家路径代验 |
| 决策者 | 依据、取舍与可行性可判 | 核依据与可实施性，不要求成品 |
| **制作者**（下一个做内容的人） | 他能用它生产、替换、扩展内容 | 按约定扩展入口完成一次代表性生产任务 |
| 调用者 | 输入给出预期输出，必要使用目标成立 | 用真实输入实际调用；调用正确不代普通默认用法或减负成立 |

**"框架"可以作为成品或方案交付。** 制作能力是否必要，按用户目标、有效约定与实际下一消费者确认；用户要求可继续生产内容时，不以作者是否宣称"可接手"为前提。配置层、扩展点和制作工具只是调查线索，不能单凭作者实现反推额外交付义务。

**常见的滑移**：交付里同时有"跑起来的东西"和"别人能接手的结构"，但只有前者被验——因为前者有现成证据，后者要另做一次生产任务才证明。这不等于验不了，是那一步没被安排。

**按有效委托确定本轮验收阶段。** 纯方案核必要能力、扩展接口、取舍与可实施依据；实际交付供制作者使用的产物时，验收不是数文件，而是**按约定扩展入口完成代表性生产任务，无需侵入无关共享核心；产物按合同保存、重新加载，并被真实消费者采用。** 约定的规则或绘图代码扩展是合法入口。缺实际任务不能签生产能力已交付；作者自行改称方案不能缩减用户委托。

**结构与行为一起核，不能互相替代。** 必要结构齐全不证明生产任务走得通；生产任务走得通也不证明结构职责、引用和生命周期正确。两者分别取证、分别裁定。

框架类与其它类的结论**分开给**：模拟规则、配置消费、构建与胜败可以真实通过；生产结构未交付仍记未完成，不能因为前者通过而合签后者。

<a id="absence"></a>
## 5. 应有而缺失：检查"该有的东西在不在"

"从应有对象反查"在[当前要求与证据范围](review-standard.md#decision-order)里已经是既有义务，本节不新增这条义务，只把**查法**集中说清，并为它补一个可判的缺口形式。这里的应有对象也包括当前结果必需的关系、能力和状态转换，按有效要求确定，不限定为某种文件／类／Prefab。

**"我查过的都正常"不等于"该有的都在"。** 两者是不同的命题，不能互相替换；同理，"已有模块全部查过"不推出"所需生产结构齐全"。这条不成立不是因为没人写过，而是因为两句话读起来太像——所以缺什么要能被单独指出，不能靠"都查过了"覆盖。

**做法：从要求反推应有对象，再逐个证明它存在。**

1. 从当前有效要求列出**这个产物必须包含的对象**（不是作者做了哪些，而是要求的下一消费者需要哪些）。
2. 对每个应有对象，定位**实际约定的承载处、生成/装配入口与消费者引用**；不预设文件名、目录或某种Prefab形态。
3. **逐个核供给及等价实现是否存在并履行合同**。存在，按已有正文核质量；已证必要供给不存在，写明缺什么、谁需要、哪个后继做不成；仅查询未命中则保具体未知。
4. **缺口证据是"按真实合同应存在的供给确实没有"**，不是"我没找到"。给实际查询范围、生成/装配及替代供给的核查结果与版本；单一空目录、零caller或关键词未命中均不够。

**合法缺失的对照**：不是所有项目都该有同一种结构。用户只要一次性演示、明确不要扩展、或项目形态本身不需要该对象时，缺失是设计选择，不算缺口。判断依据是**用户要求与下一消费者**，不是"别的项目都有"。作者文档写下"本次不做"不自动等于用户已接受。

**缺失与错误分开裁定**：对象存在但做错，走各角色已有的 P0 方法；对象整个不存在，先按本节证明缺口并说明它挡住了哪个后继，再按[当前要求与证据范围](review-standard.md#decision-order)处理，不因"它不存在所以没有可查的错"而判正常。

<a id="symptom-trace"></a>
## 6. 症状 → 静态追查（不是猜，是走链）

玩家或作者报来一句现象（"僵尸突然在屏幕中间冒出来"）时，**先分路，再逐条静态追查**；分路本身不是结论。

**三件事必须分别完成：**

1. **分路**：列出可能共存的原因（合法设计 / 生成或坐标错 / 相机与视口 / 反馈缺失），按命题分别查证；一条已确证，不因另一条未排除而撤回。
2. **实际走链**：对每一路给出可执行的静态检查点——谁生成、从哪生成、身份是什么、池的取得与重绑定顺序、相机与安全区、谁清理与归还。**"我看过了"不是走链**；要能指出具体文件/配置/调用点与预期。
3. **给解除条件**：分别说明已证结论与缺证命题，后者保"疑似 + 已排除项"、补证责任及支持/推翻信号；完整静态链可确证对应违约，连续体验另取正常速度过程。

**合法变化先行**：按[先定现象与合法变化](causal-diagnosis.md#method)，瞬移、跳切、钻地生成、固定刷怪点都可能合法。先把合法对照列出来，再判是否真违约；否则会把设计判成 bug。

**工具入口**：`jury_candidates.py plan --symptom <id>` 把症状映射到受影响工作块、U 卡、产品结果与静态追查链；它只准备材料，不认证检查已做，也不声明发现缺陷。可用 `--symptom` 多次组合。

**不得做的事**：拿静图/单帧签权威坐标与生成合法性；用"动态待验证"代替静态已能查的部分；把分路清单当成排查已完成。

## 7. 何时读本页

任务出现下列任一情形时读取：用户提到还原／复刻／照做／参考某个具体来源；需要判断画面或体验用什么视角下的证据；审查单位、对象或世界状态；**委托是框架／模板／脚手架／基座，或要判断"这东西做完了吗、别人能接着用吗"**——此时读[交付类型](#delivery-type)；**准备说"已完整""结构齐全""框架完成"**——此时读[应有而缺失](#absence)，先列应有对象再逐个证其存在；**用户或作者报来一句可观察的异常现象**（凭空出现、穿模、卡住、闪烁、掉帧、存档丢失等）——此时读[症状 → 静态追查](#symptom-trace)，按 `jury_candidates.py plan --symptom <id>` 取材料。其余情况按任务命中正常读取，不因本页存在而增加必读负担。
