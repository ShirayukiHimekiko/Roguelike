# 双角色协作：共同提交、独立检查与意见交流

本页处理两个真实角色之间的反证交流与接续，保留现有路径和锚点。派发与角色职责沿[核心入口](../SKILL.md)，不增加第三裁定或共享源writer。

<a id="complex-trigger"></a>
## 何时消费

已安排双角色独立审查，或有跨职责发现、互相矛盾结论、建议副作用需要核对时，按本页交流；读取文件不代实际派发。

普通查询、控制或同字节转交本身不另造制作任务；执行中两位空闲按[自主审核](coordination.md#wave-review)自行查既有材料，不要求工作端逐小改重新提交。普通增量接续原身份。新独立观察的身份条件按[输入独立性](coordination.md#independent-input)，保原意见和未闭。专项全量核查只按本次委托，不递归spawn或变成常驻第三角色。

<a id="collision-role"></a>
## 两条职责与反例

两个角色先从完整原需及现场独立确定必要结果、目标内路线与停法，再对同一任务及产物版本亲查，各自按[检查选择](candidate-mechanism.md#selection)和[结果主责](review-standard.md#decision-order)承担必要覆盖与裁定。同一对象可以有不同问题，不按文件隔离角色。工作端在同一来源接续实物、新证据和未闭，影响双方的材料同步两方，不另造两套提交或填假证据。

各保自己的证据和判断，不由一个Agent模拟两角色，不平均分或由统筹另裁。建议/必修与关闭依据按共同裁定；审查委托不授未授权的产品写入或外部联络权。

<a id="collision-loop"></a>
## 独立形成判断后交换意见

统筹按[独立首轮输入](coordination.md#independent-input)交同版原件和双方当前窗口真实可达地址，跨窗按[机制继承](coordination.md#activation)新建读旧材料，不试连历史身份；核双方初判已回传后再开放作者解释与实质交流；已证失败、必要否决、原始补证及紧急事实按该合同立即共享，不等待初判齐活。

1. **转交可核问题。** 给同版对象/原件位置、实际触发与待核断言，指出需要同伴核哪处生产来源或行为；观察和推断分开，不传隐藏推理或预期通过分数。必要失败同时报工作端，不等同伴同意。
2. **回应反证。** 对齐版本、对象及条件，亲核决定判断的原件后回传维持、补充、修订或撤回，并保仍未闭的必要问题；ACK或同伴通过不代自己的依据。无新影响不复做已有适用调查。
3. **区分分歧。** 不同必要后果可同时成立，按[共同裁定](review-standard.md#decision-order)分别保结论和关闭权；同因同后果共用事实，不重复计分。真正相斥的命题用相同对象/输入及能区分两者的查证判断，不折中降标；仅真实用户目标/取舍歧义请用户决定。
4. **实际接续。** 新改稿或反证同窗口只送受影响原角色；跨窗口沿[同职责后继](coordination.md#activation)交正式接替角色给新来源裁定，保原命题/反例，不冒原人已关闭，另一方保仍适用意见。对当前阶段允许发送的内容，运行角色用send_message投递；空闲/completed角色需要重新查证时用followup_task触发回合。其他宿主按实际能力区分投递与触发；消息可达、prepare或排队不证明已开始/完成复验。

直连确不可用时由统筹忠实转交并注明未直连，不停止独立检查或无关工作。已形成双方初判的适用交流不重复；本段尚有必要调查或出现新的相关对象／证据时，按原职责接续；不周期轮询或以回传／保存触发重复调查；completed不等后台监听，暂停／撤销优先。

本入口的必要发现按共同裁定复验关闭，作者或同伴不能自行抹掉原否决；实质意见与处置沿[原件保存](coordination.md#opinion-records)，统筹接回双方来源及分歧，不新增第三裁定。

<a id="advancement-guidance"></a>
## 推进指引：具体执行方向与细节

陪审提出缺陷、返工或改序意见时，连同裁定给可执行的接续；工作端推进困难、下一动作不明或拟因局部障碍收段时，也主动请求这份指引，并交具体卡点、已试结果及仍可执行范围。实际受影响职责从原需和当前实物独立给下一具名结果、首个动作与必要依赖；需要双职责时再交流建议，保真实来源及与路线指令／缺陷裁定／履约义务的区别。意见须让原工作端知道改哪个对象／位置、依据什么、先做什么以及怎样核回；有已证修法就给对应改动或接法，原因／供给未明就给可区分的查证或取得任务。影响采用的收益、代价及止损信号据实际问题补充，不为简单修复凑全套材料。按可用次序接回，当前有效方向与独立就绪工作继续。

涉及首次纳入或继续采用整条产物路线时，按[当前主线的路线准入](source-authority.md#current-mainline)核达标依据、决定性前提及当前取舍；决定性可达前提未证时只交有界查证，不先记为正式产物任务。扩展按同一主线由工作AI／F／A三方明确认可同版范围及取舍后纳入；实际交工作端，不另等用户逐条确认。提出方真实发送具体建议，实际受影响职责本人给相关路线／修法及接入／验法的判断；需双职责时实际交流。运行角色用send_message，空闲且需回应时实际唤起。工作端下一条实质答复同名给本人依据/处置/落实接回，在原计划／工作单／当前入口维护来源、已纳入项、承担和下一动作，并在既有授权内实施／核回；不只互谈、留档、ACK或挂“未获采用”。具体事实反证或受阻交原职责有据修订／查证，仅限依赖动作，不能借权限边界新增逐项采纳审批。

预期收益不是已得整数、实际效果或成品通过；当前负分不自动否定具体建议的正向预期。实际或合理可能的跨职责后果交受影响职责本人核，真实分歧／关键未知不伪装认可；缺陷、必要履约、超级P0和紧急事实沿原合同直接送工作端。建议不得替换原目标、代关否决、抢writer或扩运行／发布权限；提出与采纳不使虚构事实变真，拟新增供给仍核主线的三方共识、可靠取得依据或有界查证条件，不因陪审提出就自动必做。

<a id="suggestion-writeback"></a>
## 保存与关闭

意见原文按[保存合同](coordination.md#opinion-records)落现有记录并读回。依据有效要求和证据，分清已证必要缺陷、影响当前放行的必要待查与可选建议，不能由作者改名决定必要性。工作端接回制作／采用意见前，按[共同裁定](review-standard.md#decision-order)合取当前允许动作、同一完整目标的必要差距及路线前提。“继续制作／保生产基线／无新门”是实质继续许可，不能用“艺术未过／仅静态／制作中”把否决只留给下游。局部核回只关对应命题，保留失败证据不等于保为获准生产基线；有冲突不能摘“继续／可交付／无需继续”句执行，先暂缓所涉继续制作／采用／扩散／交付／停修，将原争点交原职责核旧许可当前效力、具名修源／判别范围及第一动作／解除信号。授权内有据因果修源、完整修法中的局部子步及无依赖工作可连续推进；不因同一源、程序化或未完成本身禁修，也不逐补丁预批。下一相关动作前回应争点，按本阶段授权落实查证或修正，明确承担位置、下一动作与验证信号，或给可定位反证；具体受阻时保影响、责任和续办条件。仅ACK、留档、记“采纳/暂缓/拒绝”或承诺以后优化，不算执行、复验或关闭。有据分期保后续责任，不免当前必要前提；目标外可选建议或等效方法可有据不采，但保全部有效履约结果。

作者可对事实、适用范围或严重度提出具体反证；原职责须亲核决定性材料并明确维持、补充、修订或撤回。作者不能用自己的反驳、重命名、降级或另一角色认可消除独立否决。必要争议按[P0共同合同](p0-review.md#review-contract)及实际依赖约束后继，保合法诊断、修源、受控复验与真正独立的工作；目标外普通建议不升为新审批，直接原需／既有合同不免除，AI扩展依主线三方认可，不借履约名称自动纳入。

关闭须保原命题/坏例、当前版本、实际改变与对应核证；同窗口由原角色复核，跨窗口沿[机制继承](coordination.md#activation)由合法同职责后继裁定。事实证伪/修复关闭与真实用户撤回或改变要求分别记因，不能将范围变化冒成旧缺陷修好。保历史与必要未闭；结构检查、作者自查、承诺、分数、保存或转发报告不代独立结果。未完必要项继续落实责任和下一查证/复验。
