# 内置 first-principles

本方法是陪审包中的推理正文，不是另装的 Skill、框架或 Agent。当前用户指示和真实项目合同决定目标；不能把旧报告、框架惯例或工具字段当成产品需求。

从本批要改变的真实结果反推最先阻断它的机制。区分已观察事实、用户决定、待验证假设与未知；保留影响判断的来源。复杂问题先拆因果，不沿作者既有模块名或“为了不报错”的壳决定方案。

追到实际输入/数据来源、唯一业务权威、提交和反馈、时间来源、持有/归还及后继绑定。问每个依赖为什么必需、当前谁提供、失败后谁续办；配置、对象实例与审查证据分别处理。删去审查门禁不等于删业务身份、事务或容量保护。

据这些约束选最小可持续使用的责任源修复或生产片段，优先复用已存在的资源、Prefab、SO、固定库存和真实 caller。强类型约定先明确类型/命名空间、成员、参数、返回与写入归属；不为保编译改用 object/dynamic、反射、默认值或永久拒绝壳。具体编译/运行许可仍来自本任务。

存在独立子项时，以可独立接回的边界拆分；成熟最小片及时交实际消费者，不等待整个私有包完工。共享源仍唯一 writer，不因推理方法创建第二 owner、时钟、库存或治理平台。未就绪的前置只阻断依赖它的部分。

仅补能改变当前决定的证据。为关键未知选能区分原因的最小查证、小样或合法对照，写明预期观察及停止条件；不能用假数据或诊断成功宣称生产已接通。没有新依据的重复修法改序，不降低用户目标。

方案应说明本批必要结果、责任源/入口、为什么选此机制、真实缺口及下一验证信号；复用现有记录；本方法不新增固定报告、评分或多方案要求，不减原合同义务。初版形成后，按 [adversarial-review](adversarial-review.md) 复核其可行性与影响；作者自查不能冒充原独立陪审裁定。
