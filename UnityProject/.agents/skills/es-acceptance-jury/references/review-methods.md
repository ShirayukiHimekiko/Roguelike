# 最容易揭出问题的审查方法

<a id="scope"></a>
## 共同方法边界

先执行[具体查找任务](review-perspectives.md#exploration-first)：明确对象/触发、怀疑违约、搜索入口和确认/排除结果并主动搜索。未发现后按[机制与前提](#method-match)定位具体查法。阻断、高风险或高要求先沿[知识检索](reading-guide.md#knowledge-use)找适用的手法与反例切入。下表只导航，执行步骤和判据取对应正文；记录复用现有目标评审。
缺动态工具或运行授权时仍须先按[可用证据边界](#available-evidence)分析已可读取的源码、资产、文本和截图；仅剩余动态问题按[恢复路径](evidence-recovery.md)补证，不能把计划写成已执行，也不能以缺证代替调查。

| 当前敏感点 | 选择的方法 | 要揭出的盲点 | 可先执行的静态／截图分析 |
| --- | --- | --- | --- |
| 点击、选择、模态、禁用、数据刷新 | [差分对照](constraints/11-methods.md#result-difference) | 看似操作成功，实际没有变化或错误路径也通过 | 选应产生不同结果的合法输入，沿分支、提交和反馈复算预期；有前后截图时比较实际可见变化 |
| 取消、重开、异步请求、窗口复用 | [中断交错](constraints/06-lifecycle.md#interleaving) | 旧操作在新状态建立后仍然写入 | 沿真实回调追A取消→B建立→A迟到，比较校验、写入和清理顺序，并核合法当前请求 |
| 状态正常但录屏异常、采集与报告冲突 | [证据链定位](constraints/09-evidence.md#capture-chain) | 把采集错误判成产品错误，或把日志成功当画面成功 | 核截图/日志的对象、版本、时刻与采集入口，沿状态到显示绑定区分产品链与采集链 |
| 动效改变内容位置、透明度、遮幅、滚动区域 | [中间态内容保护](constraints/11-methods.md#intermediate-content) | 开始和结束正常，过程中遮字或不可读 | 看已有中间帧中的真实字形、遮罩和透明度；沿关键帧/插值/裁切推导最可能损坏内容的状态 |
| 3D动作、骨骼/根旋转、方向、位移与接触 | [3D动作专项](constraints/13-motion-3d.md#spatial-checks) | 终点正确却中途错向、扭转、双重位移或滑动，数字掩盖实际动作失败 | 查父子坐标、根与骨骼写者、位移合成；从截图查可见支撑、接触和姿态，分别限定世界状态与画面结论 |
| 连续动效、“有感觉”“符合原版”“反馈清楚”等体验目标 | [同触发效果对照](constraints/04-visual.md#continuous-motion) | 有代码和动画却未产生目标需要的可见作用，往返或循环中断裂 | 对同触发的可用帧、曲线、持续时间及驱动检查阶段和反馈关系；未见连续播放不签正常速度观感 |
| 层叠、透明覆盖、模态、焦点隔离或关闭恢复 | [遮挡与输入三链](constraints/06-lifecycle.md#occlusion-input) | 看起来被挡住，射线或导航仍操作底层 | 截图查实际遮挡，源码/Prefab查射线、焦点和交互开关，沿关闭/取消查恢复与底层输入路径 |
| 窗口/页面交付、尺寸适配、长文案、代表状态 | [UI 完整性](constraints/03-ui.md#03-11) | 控件可达/单卡正常掩盖整页任务错位、无效排布/步骤或必要路径缺失 | 打开整幅截图先对回用户任务、核心内容/主动作与辅助信息取舍，再查主次/上下文及必要内容、布局/长文案/真实操作路径；滚达或无遮挡不代任务效率 |
| 方向差异/高返工入口；易用、减负、复用或继续生产目标；普通默认新增前置／抽象 | [早期价值与可用性](constraints/11-methods.md#early-value-check) | 技术联系成立掩盖普通推荐成本、使用断点或成本转移 | 从真实owner／caller核新增前置的必要保证与总负担，沿当前角色任务查使用／扩展／恢复；未执行步骤分开，纯方案不冒效果 |
| 构图/字体/材质/交互/节奏的设计改进 | [设计诊断](constraints/04-visual.md#diagnosis) | 只给审美形容词，无法指导下一版或误删风格识别点 | 从截图定位承载区域、对比层级、素材比例与注意力，再追样式/材质/布局关系，给具体修改及保留依据 |
| 认可视觉参照、方案转控件/宿主、视觉改善声明或双端共同盲点 | [独立对照与目标保持](constraints/04-visual.md) | 作者选材塑形判断、只比前版或流程完成掩盖目标差距 | 将可打开的参考与产物在对应状态/尺度下比较，核资源身份与绑定；缺参考仍分析产物本身的目标符合性 |

<a id="method-match"></a>
## 按机制与前提精确匹配

自主搜索未发现问题后，先从必要结果和当前生产链提出具体待验证命题，再对照方法正文的适用机制与前提：实际输入/触发、对象身份与状态、写读/提交/清理顺序、时空关系及可取得的结果来源。方法适用前提与失败成立条件分开，未证实有缺陷不妨碍匹配；核查才决定坏例是否成立或合法保护是否有效。关键前提未知先分析现有材料确认，不假定成立或直接跳过。类型名、领域词或表中一行相似不够；确无该机制时换适用查法，不为套方法新增异步、事务、动画或业务状态。

匹配要落到本项目的具体对象/绑定、实际合法输入或事件顺序、准备推翻的假设、独立观察位置、失败信号与合法对照，并说明方法中哪段可执行。先用能回答该问题的源码、资产、文本或截图执行，动态只补它们无法回答的部分；只说“匹配UI完整性/中断交错”不算已匹配或已查。方法中多个分支按当前成立条件取对应分支，不把整页标题当成步骤。

例如，“有异步”不直接匹配中断交错：先核存在真实异步结果、取消/重建或复用，以及结果可能在状态变化后到达，再沿本项目A取消→B建立→A迟到检查身份校验是否在写入/清理前可靠拦住旧结果，并核B正常完成。旧结果被正确拦住是正常对照，不因没发现旧写入就拒绝匹配；完全同步且不存在该事件顺序才不套这条查法。“是UI”不直接匹配裁切检查：须有必要可读内容及真实裁切/遮罩或尺寸关系，才对照当前长文案、父遮罩、布局约束和截图中的实际字形；允许裁切的装饰不冒必要内容失败。

方法校准只证明这类样例能检出，不保证任意产品都能自动识别。已知坏例与合法对照均需保留
具体观察，不能只检查 Skill 是否出现相应关键词。新类型需要补方法时，优先引用现有领域
测试/评审入口，确认缺口后才补最小观察能力；不把陪审扩成业务实现或通用自动化平台。

<a id="available-evidence"></a>
## 可用证据的分析边界

围绕必要结果先分析已有源码、配置、资产及对应版本/条件的原始观察，给已成立范围与具体未知；验证选择、环境复用/隔离、生成退役及回看沿[唯一决策正文](verification-scope.md#relevance)，不因新角色或追查更深自动新建/重跑。

- 源码、Scene/Prefab、配置及文本：沿真实输入、绑定、状态写读、分支、时间/坐标与消费者核预期。完整静态链可确证错误；名称或关键词只作线索。静态正常在已查机制/条件内有效，支持前提已成立的下一动作，不冒运行/体验通过；剩余补证按[证据与动作](causal-diagnosis.md#causal-blocking)选择，不因追得深逐层另跑。
- 截图及已有帧：实际打开完整画面，必要时放大，查可见内容、裁切、遮挡、比例、层级、姿态和空间关系；同对象前后帧可支持实际覆盖的变化分析。版本或运行状态不明不妨碍分析本图可见事实，但须保绑定限制；单帧不签权威状态、真实交互或连续时序。可疑行为从画面提出假设后追源码，不直接伪称原因已证。
- 在原记录说明已查材料／分析、成立结论与剩余未知；两角色共享适用原件、各自判断；现有证据不能回答必要命题时补对应观察，不重复仍有效的实验。缺视频／Player／测量不等于无材料；确无可访问材料时先按授权查找，保具体缺口，不编观察或只贴缺证标签。
