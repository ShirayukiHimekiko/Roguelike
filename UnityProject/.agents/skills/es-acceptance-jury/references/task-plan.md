# 任务依据与计划

本页适用于通用中大方案、Unity制作及本包维护；领域合同只对命中对象适用。供工作AI和陪审消费同一任务依据，不建立第二套需求权威或状态服务。权限沿[来源与权限](source-authority.md)，裁定沿[原目标覆盖](review-standard.md#goal-coverage)。

<a id="consume"></a>
## 先消费已有依据

按[当前主线](source-authority.md#current-mainline)接全部有效原话、修订、上次承诺及实际结果；作者清单不定义完成。工作端由[角色卡](worker-execution.md#worker-duty)接项目原记录；选下一成果用[优先队列](must-read-work-priority.md#core-loop-progress)。命中下节才评估方案，已有同版认可是否仍有效取[开工依据](#start-readiness)。


<a id="plan-evaluation"></a>
## 方案评估

中大型任务，或关键路线／供给未明、涉及共享合同／数据／关键体验／不可逆后果时，在定案与依赖制作前进入planning-start实际事件，前台核事实并从[呈现入口](message-style.md#user-facing)展示。普通查询不造制作任务，成熟局部返修复用仍有效认可。

从完整有效原需反推消费者要完成的结果、必要品质及保持项；AI扩展按[三方采用](source-authority.md#ai-extension)采用。复杂任务按可消费结果分解，接清原作者源／责任、前后输入输出、共享状态／时间／资源和完整消费；分别判断设计依据、有效控制、供给与观察。先选能解除主要差距的完整结果，再定操作，不从现脚本可调项倒定题。规模／负载／等待影响选路时核真实条件；首版覆盖本阶段必需操作，未接的必要维度进入真实后继、负责人及接回信号，不能长期只列“父未闭”。成熟基线复用；未知只做能改变父决定的判别，结果足证即接主体。高难度由这条联合链及反证后的改法承担，不承诺任意任务必成，也不以难做废弃要求。

首次及敲定方案，作者交基础结果/本次范围/下一消费者，以及必要细节或进阶增强/必做可选后置及影响的事实；对话AI按[用户呈现](message-style.md#user-facing)向用户说明，后台不拟用户稿。

真实F/A先按[独立输入](coordination.md#independent-input)从原话与实物核必要结果、路线价值及共同盲区，再讨论作者方案。在原计划直接分清F要实际取得的消费者结果、A要查的决定性前提／代价以及所需能力；同原件可复用，不要求两个完整同构调查。没有角色能核的必要结果仍未完，由原任务取得专业供给，不能靠缩scope或两局部票完成。

把作者默认底层也作为待证路线，按[统一判据](must-read-work-priority.md#continue-or-change)核来源真实、局部可做与父路线品质依据。制作供给按[主动探查](evidence-recovery.md#joint-source-search)实查具名机会、成熟工艺／资源及耦合，分核设计依据、编辑控制和组合消费者；A核能力／代价，F核操作／后继。缺侧补源或判别，足证整合，独立准备并行；不以手边唯一方案、数量或全球穷举自证。用户广域深学、充分素材、批产与精选按[充分度P0](review-standard.md#quality-blocking)核计划投入／实际动作，必要供给、批次及精筛接具名作者动作，不只列未完；数量保全而不代未证共同前提。随后按下节开工。

<a id="start-readiness"></a>
## 开工依据：两位认可前置与同版思路，再开始制作

正式制作前，把必要结果／品质、源与写域、方法／供给、验法、失败回点和首动作接原计划。先分清谁能真实取得哪项必要证据：作者制作，F核操作与后继，A核关键前提／控制／代价；角色标签不提供专业能力，无人接的结果仍未核。真实F/A各自实查分工，分别明确认可同一当前方案、首版思路和全部适用前置，给缺口就只限相关依赖。对话AI核两责覆盖及共同遗漏，展示并实交作者；不要求人人重复整套取证。

采用前逐份核实际意见支持的对象、版本、条件和结果：技术通过、包可用、专业品质及完整交付各有所据；旧包意见与新包局部通过不能合成最终整体认可。可靠共用事实复用，不拿票数／同波次／open0代覆盖，也不固定增第三审。

专业供给区分取得／原样消费、设计依据、实际编辑控制与目标组合效果。必要关系须由有来源作者操作承担；缺方法／表示／控制就按[下一投入](must-read-work-priority.md#continue-or-change)补对应侧。操作有据只缺当前组合观察，直接进入相称首件和消费者，不预要未来成品。准备可先读源、搜成熟方法或在原权限独立域作最小判别，保输入、不同预测、停止和不采用边界；正式业务／资产制作再守本段认可，不把制作改名探索。

**探路首件不等方案评估。** 视觉/体验类任务里，作者在 F/A 评估方案的同时，可以在隔离目录做一张完整的粗画面或粗原型（不并入正式源、不作交付），和方案、`TARGET.md`（用户点名参照 + 可检验特征 + 候选技法）一起交给 F/A。F/A 对“方案 + 粗画面”一起给意见；没有任何画面的方案评估最多一轮。这样第一轮评审就能看到真实差距，而不是只评文字。

**路线准入与执行。** 三方认可仍须有依据支持整条产物路线达到目标必要结果与品质：核可消费供给、适用工艺、真实依赖及可靠取得路径。理论可达、局部加分或旧承诺不保证品质；决定性前提未证先做有界判别，不铺依赖生产。同版认可仅在目标、对象、范围及条件仍适用时复用；范围／取舍发生实质变化重核受影响决定。认可路线内不新增交付、职责或验收范围的实现细化自主执行，不逐参数／工具会签；既有Skill义务按原来源落实，AI新推导不能借其名称绕过三方。共识不扩用户目标、唯一写域、付费／发布等操作权限，不另加用户逐项确认；实际交接沿[推进指引](candidate-collision.md#advancement-guidance)。

认可只在对象、目标、版本、依赖和条件仍适用时复用；普通调参、编译与返修不逐补丁重批。新修订、反证或关键供给／路线变化只核受影响决定。决定性质量前提未证不派依赖扩量；足证按已核路线整合首版并交[自主段](coordination.md#autonomous-intervention)核回。

用户指定先学习／理解时，保指定范围及深度；转制作前接清已证机制、适用条件、关键未知、允许第一动作及采用依据。解释应支持当前参数／接线／时序与代价的选择，必要时用可区分反例／正常例；局部试用只证对应范围，不循环要求全部未来参数或成品预存。F核顺序与消费者，A核作用链／耦合及证据，足证即接制作。

<a id="ui-first"></a>
## UI首版的领域依据

成套UI先明确各必要页面的用途、操作和反馈，再形成各页整页构图、元素供给与状态。参考须亲看完整画面及按钮／面板轮廓、边缘装饰、材质、图标和真实字形局部，将借用特征接到本页素材／作者源、标题／正文／数字／按钮的字体选型与真实文案试排；不能只借分区与配色。新作与整体整改用实际UI母图／部件或既有合格UI资产校准代表整页及关键状态，再扩展同套；背景、人物、武器和几条线不代控件设计。用户要求生成UI时实际生成UI母图／部件并看原图，其它已要求生图对象仍按原需实际生成，保提示词、输入／输出和消费；可生成无字UI部件，文字独立可编辑，不一律排除面板／边框／按钮。不新生图仍须取得合适且许可可用的UI素材与字体；原创矢量／代码作者源按实际形体、材质、排版与状态质量判断，不以媒介名称或合法简洁例外免除本任务必要品质。局部修复复用仍有效方案与资产，只核受影响关系；一致不等于重复布局，代表页通过不扩成全套通过。具体核回沿[视觉验收](review-standard.md#visual-review)。现有功能逻辑不锁死视觉布局；数据、页面、步骤和特效数量不定义设计完成。新增业务模式无目标依据，或首样未证目标相关可见收益时，仅许可查证该未知，不许可依赖它铺开生产；真实委托的规划／编辑工具仍按其任务与必要控制核，不把此视觉判据套全部技术任务。

<a id="task-tracking"></a>
## 原记录里的实际进度与风险

沿原计划/工作单/活接点记录已做、在做、待做、具名下一结果/责任与实际阻断；“已开始”须有真实动作，排队/ACK不算。状态对回当前对象/版本、可读证据和当前观察，running/mtime/工具数或百分比不代进展/完成。局部结果不关闭父目标，下一必要制作/核验不写成未来条件已闭；原失败/暂停/未知/原职责关闭保真，新反证只重开受影响判断。

风险逐项保来源、已证或未知、实际影响及受限依赖动作、下一处理/责任端与接回信号；已证失败不改成缺测，未知不冒产品故障，零风险不凑预警。严重反证/P0/用户控制/关键在途在安全边界及时实发前台和受影响职责，不等定时探查；正常状态由前台主动看原件，后台在自然关键成果/交接前把已做/在做/待做/下一动作/阻断一并对照实际终态更新，避免只添done却遗留旧active，不周期/逐工具密集上报。

只维护已有归属记录，不建第二权威/进度平台。需脚本探查时可用原JSON或同一原记录内的小jury-state块，字段/只读边界取[探查入口](message-style.md#user-facing)；无结构时前台读原件/定点索取，不自动判完成/无风险。事实维护和预警不授新操作权，真实许可/必要否决仍取原来源和适用合同。结束取[完整核回](review-completion.md#completion-coverage)。

<a id="repair-batches"></a>
## 按原因安排修复与定向复验

共同原因集中修，按[优先队列](must-read-work-priority.md#core-loop-progress)交真实消费者；低收益、停止与改法直达[统一判据](must-read-work-priority.md#continue-or-change)。变化影响的复验按[相关性](verification-scope.md#relevance)决定，不经其它导航往返。

## 默认中小计划，按需展开

已有依据不足时，直接维护覆盖必要目标、依赖、验收信号和下一步的中小完整计划；不为详略默认询问或等待。用户需要时随时展开同一计划，已有选择沿用，不因恢复、压缩或换窗口另抄计划。

用户明确要求先问或等答时保留等待；仅要求先制定计划时完成计划后按已有实施授权推进，不自动等批准。一般目标细节或范围内设计模糊按[默认需求决策](project-understanding.md#intent-default-progress)主动厘清、展示并推进；真正缺操作权限、明确等待或有效独立否决只约束对应动作，事实缺口作有界查证，其余工作继续。默认采用依据任务策略，沉默和经过时间不创造授权。

**什么时候问用户。** 问之前先自查：路径、文件、状态、日志这类自己能读到的不问。
- **必须问**：决定成败、又只有用户能给或能定的。例如用户点名的参照换了渠道仍拿不到；价格、名称、ID 等业务事实；需授权的远端写入、付费或发布；会改变用户目标的设计取舍。
- **不该问**：不影响结果的措辞或配置含义；已经选好默认、只是想让用户点头的（直接按默认做，在进度消息里说明“可随时改”）；同一个没变的问题换个说法再问；让用户在窗口之间替你传话（先用原生消息或文件回执，都不通才请用户转达，一次写清要转的原话和回执位置）。
- **怎么问**：同一时段的问题合成一条，按影响排序，给推荐选项和不回答时的默认；发出后继续做不依赖答案的部分。

用户拒绝文件时保留对话依据；收到修订后的下一条实质回复须更新同一计划的原记录／对话依据，并保留已执行事实与修订来源，不重写历史。

<a id="template"></a>
## 中小完整计划模板

采用现有可维护记录；缺少时使用以下短模板。每项只写当前事实，少量阶段即可，不能预填完成或验收通过：

```text
来源与版本：当前用户主线及真实修订定位；当前计划及产物版本
目标与边界：全部必要目标；范围、禁止项
验收：各目标的可观察信号、所需证据类型
阶段与要求：本批阶段/质量目标及来源；优先顺序与依赖；批次范围；负责人
进展：同一任务条目的真实状态、依据或必要未闭；主线下一实质动作及责任；有暂缓项时写对应动作/恢复线索
修订与结果：真实变更及理由；实际结果/证据链接
```

不为陪审另抄一份需求或另建状态服务；阶段页与现有目标记录互相引用，状态语义沿[轻量任务追踪](#task-tracking)。计划只能说明待做与已做事实，不能替代实际结果或独立验收。

<a id="placement"></a>
## 安全放置

先消费目标项目的现行放置和保留规则，复用已有任务记录，确认具体绝对路径后读写；临时计划标记 `temporary-task`。正式需求规格、正式交接和领域证据仍走其既有归属。按当前项目明确采用的规则执行，不从其它项目推广义务。

仅在没有放置要求和标准时，使用 `<projectRoot>/Library/AIPlans/<task-id>/TASK_PLAN.md`。绑定已确认项目根，检查实际路径及重定向，写后同路径读回；不依赖默认 cwd，不去用户主目录创建镜像。Library 是可再生临时存储，不能成为正式证据的唯一归档。[项目理解活工作区](project-workspace.md#workspace)属于项目持久记录，不采用本临时缺省位置或temporary-task轮换清理，退役按真实授权和正式保留合同。

<a id="cleanup"></a>
## 数量触发检查，逐件清理

清理授权须在当前真实用户及任务范围成立，已有授权不重问；本次用户许可不随 Skill 分发到其他用户或项目。规则不启动后台清理器，也不承诺离线常驻清理。

本节只管理临时计划；构建、录像与历史证据按项目原所有者的保留、迁移及到期清理规则处理；缺少规则时，由责任端按[生成与退役责任](evidence-lifecycle.md#retirement)在原任务依据补明，不套本节计划数量阈值，也不因曾被陪审引用就永久保留。仍承担当前验收、未闭合问题或恢复责任的材料先保护；责任退役后的删除保留原结论和处置记录，明确原件不可复核。陪审审查依据与损失，不接管文件清理。

仅将本机制拥有、已完成或明确放弃、无未闭合项、无引用保留义务且有真实可重建来源的临时计划列为合格候选。活跃、暂停、状态未知、人工或外部文件，以及唯一的原话、修订、失败证据均保留。所有权标记和日期本身不能证明可删；无可靠所有权、引用或来源证据时跳过并报告。

默认合格闭合计划超过20份时，保留最近20份，再对更旧的逐件复核后有界清理；按真实闭合时间排序，时间未知者跳过。项目规则更严格时从其规定。数量只触发检查，不是删除理由，不为凑配额删除。

优先使用项目已有清理工具并尊重其能力边界；仅提供候选的清理预演不能称已执行删除。没有执行工具时，由宿主按已核定的绝对文件逐件操作，临执行前重新检查路径、状态、引用和保留责任；发生变化或未知即跳过对应项。不得递归清空 Library 或项目的 AI 资料目录，也不得删除含未知文件的整个任务目录。记录实际处理项和保留原因；修订本规则不等于已清理旧计划。
