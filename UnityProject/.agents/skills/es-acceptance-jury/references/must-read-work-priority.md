# 工作优先队列：选批、制作与累计纠偏

<a id="core-loop-progress"></a>
## 选批、共同前提与承诺兑现

初期按[方案评估](task-plan.md#plan-evaluation)核有效需求及待评／三方已认可扩展与当前有据支持的路线；此后按各自适用P0、全部必要品质及真实后继核回组织制作。早期已见风险立即处理，详查按实际依赖接续。任务前消费项目活记录及原件，用户暂停／撤销、权限、扩大损失止损优先；必要品质及漏查沿[共同裁定](review-standard.md#decision-order)限制依赖，不停真正无关的就绪工作。

<a id="partial-result-continuation"></a>
## 局部结果后的实际接续

编译、小修、检查、候选、文档或单一消费者结果只证相应命题，不收父委托。在自然成果、答复、恢复、等待审批或依赖、角色completed等推进边界，从当前原接点核完整目标的必要未闭、本结果已证／未证及具体受限动作；按[继续／改法](#continue-or-change)选择下一具名作者结果和消费者。局部准停只结束获准对象／版本／范围，父任务有合法必要工作就继续；旧票、分数、ACK、completed、文件／hash或服务状态不代接续。

下一主投入从全部必要结果择序，比较直接兑现关键差距、解除真实前置及其它就绪工作的剩余成本与风险，不因容易验证、局部置信或沉没投入偏袒原法。必要前置沿真实消费说明缺它会使哪项结果失败，并核所需品质／精度／可靠性和恢复；达到消费者所需程度即接入，额外通用化、封装或整理不占主线。安全、数据、兼容、性能及维护保障可复杂且暂不可见；真实委托的工具、编辑器、文档、诊断或研究可自成结果，不强转玩家体验。

下一工作取完整有效目标内已授权、必要或有据有价值的结果；AI新增范围仍守原采用，不因可做扩需或无限优化。实查可直接制作、可补必要方法／源码／素材／原创内容供给及真正受阻路径；“没有现成候选／已验证生产合同”不证明无事可做，也不预准未证路线生产。可补供给先搜源、学习或作有区别判别，足证按原开工合同接制作；就绪就实际继续到消费者。确仅剩受阻项才保具名障碍、责任与接回并申请[停止](review-completion.md#stop-request)，不把局部限制推为external-only父停。用户暂停／撤销／明确等待、真预算与权限按实际范围执行；未知作业先核原ID不重放。承诺未兑现或前置挤占就绪交付当轮改序，接回暂缓项，不填忙；原告警、否决和未闭保持。

玩家功能先追合法入口／条件→规则提交→反馈→后继，再集中编译、保存与相称运行；Editor直调／注入不代玩家链。工具／资源／静态委托核自身生产、采用及退出／归还。共同原因集中修，成熟成果及时交消费者；实际体验沿[玩法](real-play.md#play-chain)，分组沿[任务分组](task-groups.md)，波内制作与自主审查沿[协作](coordination.md#wave-review)。有效旧证复用，不逐工具重排或重审。

修责任源并核原反例、合法正常；不以样例硬编码、测试专用逻辑、假数据、隐藏失败或删弱有效断言求绿。规格／错误测试确需改动保修订及行为依据，夹具不冒生产。临时止损／迁移保用途、替换条件及后继；完成沿[结束覆盖](review-completion.md#completion-coverage)。

<a id="continue-or-change"></a>
## 由原结果选择下一投入

本节统一制作、诊断、搜源和审核，不另设台账或审批。先对回完整必要结果及实际作者源，分清当前局部命题、它对主要差距的作用、父路线承担剩余品质的依据；真实技术收益保范围，负分／整体未过／单项有信息不自行决定下一主任务。

1. **依据足够，做对应作者结果。** 有据工艺／控制能承担必要差距，或成熟完整基线只有已定位局部缺陷，就整合、校准或修原责任源，核正常消费者。操作有据只缺本次组合观察时直接接代表首件，不预要未来成品，也不因小收益／负分强制重构。
2. **关键判断未分清，做能改变选择的判别。** 回实际入口、设计操作／表示／供给、完整对象与前后状态，找最能推翻路线的关系；前段／控制变化时核它影响的准备、切换与后继，不把旧后段／局部证据跨条件相加。选真实输入、竞争解释和可区分观察；必要局修只恢复该查证，答案足够立即回父决定，不串行续小题。
3. **关键依据失效，撤回相应主生产并补能力。** 已反证设计／表示／供给或完整品质时，停止依赖它的续修／扩量，下一主任务实际取得缺失工艺／有效控制／合格供给，或比较有区别路线、修责任源／重构后核完整代表结果。无需先找到通用BUG；也不从一实现失败推出整个范式不可能。有不同真实能力的新供给可有限验证，不能凭新标签／新预算复活旧假设。

每次决定先把已见完整失败对到本次要改变的设计／表示／供给／接线及作者操作，接具名源、完整结果、首动作、消费者和解除信号；原职责核首次真实派发和后继是否据此改变。局部“有信息”、有限scope或未签整体不是依赖同一失效前提继续扩量的理由；能区分父决定的研究和不依赖该前提的小修继续。主要差距未减少时，优先取得能有意改变它的成熟作者方法、控制或合格供给，而非再命名旧技术。确缺供给实查替代并[索取](ai-tooling.md#supply-request)，新材料按实际差异补证；不以查重要求发明新工艺或完全同款教程。

继续者给从现在达标的可核因果；存在可达有效替代时比较剩余代价、耦合／回归风险与供给，不偏袒沉没投入、不穷举。父目标／因果未知的已用和在途持续继承，路线资格先于续预算；不得以AI自设额度降品质、删行为、冻对象或缩规模，真实用户限额／暂停／费用及外发权限优先。原失败由原职责或合法后继核回，真正独立就绪工作继续；难以接续按[推进指引](candidate-collision.md#advancement-guidance)求具名动作。

<a id="foundation-first"></a>
## 游戏制作：先基础循环，再扩大内容与细节

按三方草案和现有工程，先核决定首个可用结果的资源、工具及关键技术/视觉依据，复用或搭建这段循环所需的最小底架和责任接点；明显UI遮挡/不可读/不可操作、流程断点及关键供给缺失放进同一优先批次，不能先铺完整通用框架才看入口。资源按[制作前依据](evidence-recovery.md#production-readiness)及[主动探查](evidence-recovery.md#joint-source-search)落实到可用样件、适配与真实消费者，不以链接或下载成功代接入；拟开工首版所依赖的前置须全部成立并获两位认可，未来产物不要求预先制成，边界统一取[开工依据](task-plan.md#start-readiness)。独立准备按依赖并行，已有底架与成立循环直接复用，不回炉重造。

首个基本循环须让真实入口、必要操作、规则后果、反馈、下一操作/重试及必要退出或恢复在同一适用对象上成立；依本游戏必要流程验证，不强塞战斗、存档等不存在机制。按钮能点、Scene打开、编译通过、代理数据或截图好看都不代真实循环。对应循环及本阶段决定路线／交付水准的必要品质均有适用依据后，再扩量并处理其余细节；不采用“功能循环通了，关键工艺／表现／组合品质留后补”的扩量解释。后续必要品质保目标、责任、接回和验收，不要求未来全部品质预存，不把循环小样冒完整通过。

基础循环先执行[因果阻断与依赖修补](causal-diagnosis.md#causal-blocking)：最小可见结果不能代替其供给、权威状态和生命周期成立，不以强接入口形成演示循环。已证P0、数据保护、扩大损失或影响关键方向的反例不推迟；决定可行性、风格/动作路线的样件和本阶段必需品质应提前，提交画面仍按完整有效目标审查。只委托局部UI、素材、方案或工具时按该结果推进，不强制回跑游戏全流程；必要细节本身就是当前任务时直接处理。未要求的远期框架不抢实际入口/循环，普通偏好不借“基础”升为必修。

<a id="route-leadership"></a>
## 路线、事实反证与实际后继

按[职责边界](source-authority.md#delegated-direction)，作者负责具体路线与生产，对话AI保完整目标和取舍，F/A按实查结果／前提核采用；审查者建议不自带路线指令权。原需／已适用合同的必要履约和有证缺陷须落实，不由作者降成偏好。

改变采用、继续或改序时，给原件、受影响命题和下一作者动作／解除信号；作者落实或交具体不可执行条件、代价及等效替代，审查者据事实核回。自己提出的路线也须接受另一职责或作者反证，不能凭原票续签。正常段不逐补丁预批，真实关键变化只重核受影响决定。

否决限制依赖被否决前提／结果的继续制作、采用、扩散和交付；责任源修正、必要判别及无关就绪工作继续。原发现职责核修后结果；其判断若被决定性同件反证须重核或撤回，不能以独立关闭权压事实。冲突先核对象／条件和区分证据，不平均分、不强制阵营或再加裁决人。

具体争议在原risk接closureOwner及recovery：争的是哪条命题／受限动作、哪种观察能区分、证据由谁取得/第一动作、回哪位原审或已记录合法同责后继重核。按challenge→evidence-needed→真实证据→review-needed→本人retain/revise/withdraw接回，不把“原审应该改判”当恢复已实现。jury_session review-step只返回拟接回facts，不写源/认证真人；重核从该责任本人当前意见的reviews取得并绑定实际证据。维持保原限制，修订给剩余限制并只释放旧减新的动作，二者不冒风险已关；撤回只解除该命题的限制。released不等可执行restored，仍须扣同一动作的其它已声明current风险、未知／反证命题或未答考虑，并列stillHeld来源。原风险未闭且上次已裁，后到新证据用recheck给实际本地请求原件和changeReason，保旧裁定history、原责和限制再进取证／重核；不重放在途或原来源。同路径新版本按已存请求字节指纹区分，缺旧快照不猜版本；新文件名／理由字段不证事实变化，原责仍核实际差异。closed结果走新来源风险，不洗新wave。作者不能自关真否决、讨票换人或引入第三永久裁判；不同意仍给区分查证/承担，不无限会签或全局停机。

原计划／[活记录](project-workspace.md#maintenance)保路线、依据、被拒方法、未执行项及解除条件，撤回保历史。工作端主动承接；陪审在[自主段](coordination.md#autonomous-intervention)接回／采用边界核第一实际动作与消费者结果，局部票、负分／未测或completed不解除推进责任。原writer／权限／关闭权保持。
