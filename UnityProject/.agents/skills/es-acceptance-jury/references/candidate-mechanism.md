# 检查选择：执行义务、产品对象、工作块与定向调查

<a id="selection"></a>
## 选择与问题严重度分开

每次实质审查／受影响复验，从本段已分工的必要结果／决定性失败命题处理本角色义务；进度按[p0-progress](p0-progress.md#review-contract)，架构按[p0-architecture](p0-architecture.md#review-contract)，各自确定适用底线和对象/关系，按[自主搜索后精确匹配](review-perspectives.md#exploration-first)先带问题线索搜索同类问题，未发现后匹配自己的具体方法查询比对，给有据裁定并核原未闭。共同证据及动作限制沿[p0-review](p0-review.md#review-contract)，不合成同一清单或默认重复全查。UI遮挡、存档失效、单位异常、跳变确证仍按P0；F0/A0是执行义务。静态/方案/Skill维护按真实对象核适用性，不新增游戏、存档或Player义务；缺材料不能冒不适用或跳过已有证据。

按原任务、真实变化、依赖和声明识别全部命中工作块，检查对应候选；具体症状、旧失败、敏感顺序、同伴反证及自主发现启动定向调查。执行义务/产品对象/按块/定向是检查来源，不是严重度。块或定向发现四类确证错误同样判P0，四类不是封闭白名单，必要品质差距按共同超级P0、必要漏查按审查阻断，其它发现依有效要求与真实影响判断，不冒用户逐条采用AI建议。

调查可交叉并共用证据，不逐ID造报告。后到来源揭示新依赖时补相关块和受影响旧结论；合法对照推翻假设而无新影响时不重开无关块。无变化可有据复用，原否决仅由适用独立复验或有效用户修订关闭。

候选不是低优先级问题：按损失可逆性、扩大速度、证据及下一操作排查，具毁档/错写因果线索可先于已知P0进行权限内具体止损和有限查证，不必先改名升级或假报已发生。暂停/撤销优先；止损只限可能扩大损失的动作，保现场/玩家数据，不冻结无关工作。给可区分原因的下一观察与停止/改序信号，不凭猜测永久占队头。进度按本批业务主责及实际链展开；架构/系统/生态审查按[全项目基线与追踪](p0-architecture.md#project-tracking)深查整个项目，首次不能以无症状/无diff免查，后续据追踪接续受影响模块和未闭。无需每批重复已查且仍适用的全量，也不以此缩减首次项目覆盖。

<a id="candidate-contract"></a>
## 调查合同

从有效要求列本项应有参与者/对象、必要状态与消费者，反查真实入口/caller、提交/写显示及后继；新增或改变的参与者须追受影响的进入、阶段转换和退出中的实际owner/写入，首绑与终态清空不代中间身份交接。作者已实现清单不能反推覆盖。应有资源须到实际选择/读取/输出，零caller先证必要性与合法入口，不自动P0。按有效底线→当前对象/消费者→合法触发→真实状态/副作用链→决定证据→正常对照→最小修正/损失→原命题复验与后继查证。自然说清，不逐ID填表；适用结果读references中的权威method正文，原F05失败/续办只在真实机制存在时展开。真实源码/资产形成必然违反链可静态确证；关键词、字段名、未用Prefab、假stub、返回true或目录数量不够。动态只补具体未知，具体证据与裁定沿[共同规则](review-standard.md#decision-order)。

必要失败修复，必要未知补证，范围外改善作建议。一次调查可支持多命题但各自覆盖须成立；不因测试名强增token、单Store、容量、回滚、预算或新业务机制。未注册命题可手工检查，工具计划不认证检查完成、来源、权限或产品行为。

<a id="shared-role-duty"></a>
## 两角色共用的执行条款

按必要结果和当前能取得的专业证据分主责，不按文件或首发现者分工；同一真实原件可共用，两人各自承担实际结论／反证，不靠重复全查或强制不同意见证明独立。无人能核的必要结果仍未完，由原任务取得供给，不能转交作者独自宣称专业通过。回传只展开本人新判断、决定证据／差异和必要条件，共用背景一次；原角色、原整数、原主事件及不同否决／未闭各自保真。

以下条款对进度／功能与架构／技术生态／可玩性**同时生效**，角色卡不再各自复述，只写本角色差异。

**追因。** 症状定位、局部补偿或反复返工时，读取并执行[共同追因方法](causal-diagnosis.md#method)，按[触发与行动](causal-diagnosis.md#intent-action)当轮实际查证；证据充分时按责任层修复/复验并收束扩查。

**方法调用。** [8+2工作区](game-workspaces.md#approach)承担游戏与工程判断、查证和方案；原ID保唯一方法及意见定位，按任务调用，不把工程任务全改写成玩家问题。先从当前项目痛点定位决定结果的配置/绑定/调用或素材，再调用具体方法；缺能力主动调查合项目的成熟方案，不以ID盘点或建议搜源代执行，不逐ID造报告；需求修订、证据真实性及协作接回按其实际使用跨块生效。缺材料先分析可用部分，不假报不适用。

**定向调查。** 按症状、旧失败、敏感顺序及自己的领域理解，选[领域定位](constraint-index.md)或具名新问题，借[U操作卡](unity-candidates.md)和原正文实际查证；U卡供上述检查复用，目录不封闭，不在等注册号才查。按原机制和合法对照限制建议，不把单Store、容量、回滚、token及预算惯例推广全域。

**交流。** 先亲查共同材料，再按[交流正文](candidate-collision.md#collision-loop)交换跨职责事实、反证及建议副作用，明确维持/补充/修订；可共同查同一对象，自己保证据，不借另一方通过抵否决，不互相清否决。保原候选身份及各自的必修/补证/建议、最小修正与复验信号；共用一份记录，普通ACK不新审，不为编号另造报告。

**P0 导航骨架。** 两张角色卡都按同一骨架指向自己的权威正文：候选与完整方法以本角色 P0 权威正文为准；先履行该正文的审查义务与阻断，再按本批适用对象实际查询和裁定；工作卡不另持 P0 规则正文。工具与长任务按[AI工具方法](ai-tooling.md#scope)核本角色的实际动作、执行域与结果。角色卡只写本角色差异，不复制本骨架。

<a id="blocks"></a>
## 面向游戏结果的 8+2 工作区

[游戏流程](game-workspaces.md#flow)与[可玩性](game-workspaces.md#playability)是贯穿八块的+2。八块兼顾游戏设计与工程生产，按[任务判断与方案](game-workspaces.md#approach)分别核游戏品质和资源/工具/架构等工程交付；工程必要性不要求先有玩家故障，工程通过不代游戏优质。

| 块键 | 工作区与命中依据 |
| --- | --- |
| goal | [G1项目目标、方案与推进](game-workspaces.md#goal)：游戏/工程交付、取舍、前置、分工及下一消费者 |
| rules | [G2玩法规则与世界实现](game-workspaces.md#rules)：规则/数值、单位建筑、状态/行为与组合关系 |
| interaction | [G3操作、界面与关卡内容](game-workspaces.md#interaction)：输入/反馈、信息、路线、内容顺序及学习节奏 |
| art | [G4美术与音画制作](game-workspaces.md#art)：资产、动画、镜头、特效、声音的具体表达与制作 |
| resources | [G5资源与内容生产](game-workspaces.md#resources)：命名/路径、目标环境、依赖、加载释放、品质与主动找源 |
| tools | [G6工具与制作流程](game-workspaces.md#tools)：AI侧MCP/CLI、审批权限与执行恢复；Unity工具缺能力调查、实际采用及生产结果 |
| architecture | [G7架构与系统集成](game-workspaces.md#architecture)：Prefab/UI/Scene、项目约定、强类型、低损耗及责任源修复 |
| delivery | [G8运行与交付](game-workspaces.md#delivery)：平台/构建/加载、负载、持续使用、同版交付及适用体验 |

按任务及实际依赖选全部命中区，块外新问题直接调查；不每轮全跑、不逐块凑意见。原32项保为唯一核查方法，按需多区引用并真实读取；需求修订、意见接回和工具真实性由共用检查承接，证据真实性随任何块使用证据而生效，不只在G8查。

<a id="routes"></a>
## 对象与操作

通过[U1–U9](unity-candidates.md#routing)按需进入当前领域正文。领域现存叶号仅作定位，不定义产品严重度；目录外有据问题直接调查，不因未改文件漏依赖。

<a id="selection-tools"></a>
## 当前工具

`scripts/candidate-routing.json` schema3唯一登记原检查身份与方法，八块引用检查，流程与可玩性两个贯穿区随首轮读取并作用于每个命中块；可用--block flow|playability进一步展开本角色方法；多块命中保activatedBy并去重方法，不抹独立后果。plan输出obligation/product-check/shared-check/work-block，默认读取P0审查义务与阻断及本角色权威结果摘要；--product <当前适用结果ID>将相应权威method加入readSelectors，prepare首轮消费同一权威合同并给方法导航。产品对象另给severityIfConfirmed=P0，未调查不输出已发生P0；声明选择、材料齐全不证明全部适用结果已识别或已实查。inspect/prepare核材料绑定和正文，不认证语义、真实身份或宿主执行。旧叶号`--legacy`/`--include-legacy`明确返回retired-interface并指向包外历史；未登记的新问题仍手工调查，不把旧接口撤销变成禁止查问题。
