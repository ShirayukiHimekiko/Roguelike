# 穿透诊断：从现象追到决定结果的机制

<a id="method"></a>
## 两角色共用的穿透诊断

用于症状定位、方案取舍及局部补偿，按[续修依据](#intent-action)触发，不等反复失败；用户当前提到的组件/做法是线索，局部改善不等于该层就是主因。“项目地基不足”同样只是待检验解释。进度沿必要业务结果追链，架构沿供给与执行机制追链，各自保证据与关闭权；具体例子见[用户的动画与IK问题](../knowledge/cases/animation-ik-premises.md#user-example)。

**先定现象与合法变化。** 对齐当前目标、触发/输入、对象与可观察差距，分别保已观察事实、允许的取舍和未知；比较什么状态/对象会发生、什么不会。低频物理步进、瞬移、跳切、风格化动作或既定性能取舍可能合法，不能先把不连续都判成底层错误。先分析可用代码、配置、资产和实际画面，原因尚未成立时仍给已能成立的判断，不只列待查清单。

**沿结果逆查，找到关系的失配。** 从最终结果回到真实消费者、最后一次写入/覆盖、变换或适配、调度及输入/数据来源；按当前机制核相关身份、状态、时间/阶段、坐标/单位、资源绑定与供给条件，不机械全扫这些名词。对照每个必要边界应收到什么、实际收到什么、谁负责产生/转换及何时采用，找能解释现象的最早失配；上游合法而下游误用时，不把上游改成另一种权威来迁就它。多处同节奏/同条件异常提示共因，仍须追到共用关系；单个正常样例不证明整条链正常。

**按疑点选择查证入口。** Git、真实底层能力、工具采用、知识库及原始需求/实现难度都是穿透诊断的常用入口，按能改变当前解释或下一动作的具体问题选用，不每次全跑，也不按命中数量证明深入：

| 入口 | 具体追什么及如何接回 |
| --- | --- |
| Git演变 | 先核实际分支、工作区差异和目标版本；沿相关提交/历史文件追谁改了哪个前提、旧路线为何撤回、哪些未改消费者仍受影响，再对照当前调用。提交说明/作者名不单独证明原因或用户授权；不为追历史改写他方工作区。 |
| 真实底层能力 | 核当前版本/API/模块、数据/资源与实际生产者能否供给所需结果，沿类型、装配、时序和caller查真实边界；按[现成接法](project-understanding.md#existing-path)区分缺能力、未接上与误用，不从框架名或功能表猜已支持。 |
| 工具采用 | 核工具是否被当前对象实际启用、配置、绑定和消费，检查真实产物及下一消费者；沿[工具结果核验](ai-tooling.md#results)区分存在/登记/调用/采用，不停在推荐库名或工具列表。 |
| 知识库 | 按[知识检索合同](reading-guide.md#knowledge-use)的触发与接续检索适用原理、实践和反例，只读命中段，将条件映射到当前对象；没有匹配就转真实项目/外部依据，不默认全库预读或拿案例作当前结论。 |
| 原始需求与当前实现难度 | 核[真实用户主线](source-authority.md#current-mainline)、后到修订和当前差距，再按[项目投入边界](project-understanding.md#stage-fit)查具体依赖、成本与限制，区别缺事实、缺接点、确缺能力和需用户取舍；不拿难度降低目标或把AI自产配套当必要需求。 |

**把查证接回推进链。** 沿“原始目标→当前必要前提→已采用的供给/工具/知识→本批改法→下一消费者与可验证成果”找断点。缺一段就指出具体对象、缺什么、哪个实际模块/执行者接续及完成信号；在已有任务记录接回已证、已排除、未闭和下一实质动作，不以“再查Git/先补地基”替代推进，也不另建账本或后台平台。

**让不同解释产生不同预期。** 按已有证据保留仍可能的解释，不强制凑三种：

| 可能的责任层 | 能区分解释的观察 | 相应改法方向 |
| --- | --- | --- |
| 局部内容、曲线、配置或算法 | 同一供给/适配链下只有该对象失败，失配出现在其局部输入或运算；正常对象作对照 | 修该资产/参数/算法，保共用链与必要反馈 |
| 接入或适配 | 源与消费者各自成立，接合后的空间/单位/时序/格式/绑定不匹配；隔离正常、接入失败只是线索，须查具体接点 | 在真实边界补转换、装配或执行协调，保双方合法合同 |
| 共用供给或底层能力 | 目标所必需的状态、表现样本、身份、时序或能力没有生产者、输出已错或被另一写者覆盖；能解释相关消费者的失败 | 修供给/责任源或补确缺能力，再接当前消费者；不只在末端加平滑/重试/刷新 |

**选择能推翻当前解释的最小查证。** 写清哪条观察会支持或推翻它，再用当前对象的边界值、同输入/状态对照、代表对象替换、隔离接入或必要阶段取样验证；只做当前授权允许的真实/隔离操作，不为试因改生产权威、删用户数据或关闭保护。完整静态链已能确证时直接定位，实际体验/动态品质只对剩余未知补证。关掉IK/某层后现象消失、加阻尼后幅度降低，都可能只是屏蔽消费者或掩盖输入问题，不能单独证明主因；需与保必要结果的正常对照核回。

**据结果改责任层和制作顺序。** 命中[触发规则](#intent-action)先查证，停止无依据的同层微调；局部因果已证且修法覆盖剩余差距时直接局部修并复验，不先重构或证明全部底层正确。必要适配/能力优先核[现成接法](project-understanding.md#capability-fit)，按真实依赖决定复用、扩展或必要迁移，不把“最小”缩成永远只能改一个文件，也不以“查本质”为名扩成无关系统重建。

给实际对象/位置、因果关系及决定性依据、要修的责任源或适配点、保留行为与下一验证信号；推翻了什么、哪些仍未知随现有记录保留。原因未明时给能改变下一决定的具体取样/查询及不同结果下的动作，不只说“检查地基/加适配”。诊断必须接到下节的阻断范围与修补顺序；局部症状改善、原因修正、实际采用与最终体验分别关闭，权限仍取原任务。

<a id="causal-blocking"></a>
### 从实际问题到动作边界与依赖修补

底层指真实生产链中最早的决定性失配，不按抽象层数命名。两职责沿上节逆查责任源，再由源接消费者；若原因在UI、字体、素材或局部算法，就直接修，不附加无关重构。

用户暂停、禁止和权限独立生效；已证必要品质／产品故障及必要漏查沿[共同裁定](review-standard.md#decision-order)限制实际依赖的普通制作、采用、扩散、交付、通过与完成。保对象／版本、差距或缺查、受限动作和解除信号，缺证不冒已证故障；原职责或合法后继据证关闭，工作端／另一票不得代关。审查未过不授产品停机、禁入、恒拒或放弃必要优化；真实安全保护保留。

授权内止损、修源、隔离查证及为具体缺证所需的受控集成继续；受控集成保自身身份、数据、资源和安全边界，可停止，不先要求它要取得的答案通过，也不能改名为正式铺量。真实不依赖坏前提且自身就绪的工作继续。真实合同与可靠供给路径已证、能力尚待实现时可按[接线边界](constraints/01-architecture.md#strong-wiring)制作；已证错误合同不能用此例外铺下游。

完整静态输入／绑定／调用／决定逻辑已足时，可关闭对应源码命题并接前提成立的制作。追查深度不增加独立运行层数；剩余动态优先结合真实消费者观察，一份适用证据可覆盖多层。仅在有效委托／合同要求，或现成路径不能安全回答必要未知、须隔离共享风险时单独运行。源码通过不代动态坏例、保存／平台／负载及品质，不能用强接、默认值、吞错、恒拒、重试或删内容遮失败。

下一增量按[继续／改法依据](must-read-work-priority.md#continue-or-change)接回真实消费者；跨职责事实当轮转交，各自亲核，不互等／代关，不以报告或局部加分替依赖修复。

<a id="intent-action"></a>
### 触发、查证与收束

原验收信号未兑现，且继续局部修法的因果、供给或接点无可复查依据，或支撑继续该修法的关键前提／因果预测被推翻，就当轮按[继续／改法依据](must-read-work-priority.md#continue-or-change)停止无据原法并查证，不等累计失败或绝无希望。有据数值收敛的估计误差和信息性实验负分支按该正文保留；局部改善、换参数／波名不续期，累计失衡警告另按[选批正文](must-read-work-priority.md#core-loop-progress)，不替本轮判据。

工作端与两职责按上节方法实际核最早未证边界，用源码、配置、Git、资源或真实观察区分局部、接入和供给解释，回传查了什么、支持／推翻什么、决定位置及下一动作。局部因果和正常对照足以覆盖差距就局修，足证即收束；必要运行仅补静态不能回答的具体未知，不按层数另造样件。

受阻保真实尝试／错误、具名缺项和续办条件，用已有材料完成能成立的分析；其它必要命题、原失败与最终结果仍接回，不以收束冒整体完成或扩操作权限。
