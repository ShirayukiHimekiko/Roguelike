# 单一交互入口与后台制作接续

适用于本Skill派发、承接、恢复及用户明确的多窗口分工。优先落实当前用户要求，延续已实际采用且仍有效的工作方式；已有明确迁移则沿新方式。只修过期、已失效或与当前有效方式冲突的启动部分；不复活过期/已失效的启动脚本、provider或配置，以及已撤回/已失效的旧限制或权限。仍有效的配置、暂停、只读和权限不因年代改变，按当前对象/范围继续生效。

## 1. 对话AI守用户入口，工作AI后台制作

对话AI按[本人角色卡](dialogue-coordinator.md#dialogue-duty)亲核目标、产物和关键决定，承担采用/解释/纠偏；后台原生作者制作/F-A独核，产品唯一writer。用户默认一个持续入口，保明确直连作者/多窗口范围；聊天/查询不造角色。

按[身份与安全接续](coordination.md#activation)给原需/版本、写域、原件/未闭/在途和接回信号。恢复不能收下身份、ACK或重述计划就停止：核当前原活后实际完成第一项合法业务动作，并沿自然成果继续必要工作。缺前置只限依赖动作；真正已完或无可替代阻断据实交付/说明，不捏造忙碌。正式源仍须安全交域，原暂停/预算/闭权保留。

## 2. 四职责按当前宿主真实接续

布局、改名和旧页签处置由当前已受托且有权限的恢复/窗口控制职责承担；不是每个backend角色都开窗或操作UI。实际任务页签必须按职责/依赖放在可辨识分组或窗口，每组最多六个；超出则拆为有名称子组。名称准确反映当前职责，职责变动同步改名；ID/历史编号/“恢复成功”不单独代职责。组数/总量按当前任务，不固定四组十二个，也不为每Agent建tab。

原为用户直接交互PowerShell且要求仍有效，就续其交互入口；其它终端/宿主/原生后台按实际既有方式接续，不强迁PowerShell。只补真实缺失实例，已有效实例继续使用；不按旧快照重开全部历史窗口，不把排队/进程存在/启动回执冒业务接通。

## 3. 写域先分清，独立工作连续推进

明确各角色目标、写域、产物和接回点；产品单写，意见/对话分域。冲突只限相关动作，不加全局锁、人为前置或逐补丁许可；缺输入限依赖，就绪工作继续，用户暂停/撤销及原权限优先。

先核当前UI页签↔本次旧实例↔有效替代实例及实际在途/持有。对已确认失效、额度不足或内存失败退出业务的旧页签，接回必要上下文/控制/独有材料/原意见和未闭，保历史可查；已无在途/持有就处理该旧页签，不等整个项目完成。仍有写入、作业或资源持有，先按原operation核终态并安全归还，再关闭对应旧页签；只限制其安全处置，不全局等待。

历史失败、旧PID或单次超时不证明当前实例坏，不误关已恢复正常的新实例或外来/共享进程，不自动重试耗尽额度。未知先查原作业和实际目标，不盲关/盲重放。实例退出不等停止原委托，原唯一writer/职责/否决闭权由已合法接通实例继续，不能以关tab转移权限。

## 4. 复用证据，只补影响决定的差额

同对象/版本/条件证据直接复用，作者/陪审/恢复端共原件各自判断；恢复优先源码和现成终态，只补身份/归属、未知在途及第一合法动作的必要缺口。变化、实际失败或具体未证条件影响决定，才按[验证选择](verification-scope.md#selection)补相关检查；ACK/格式/回执无语义和条件变化不重跑。少测不删除原坏例/必要未闭，也不免本人亲读或使旧证跨条件成立。

仅维护本Skill不授当前桌面、页签或进程操作权；静态案例/旧布局记录不冒今天已分组/改名/关闭。实际操作仍先观察真目标、按实际授权和工具结果合同核回，不额外逐窗口索批。

## 5. 用户明确授权的每小时统筹巡查

用户明确采用每小时巡查时，timer每小时仅唤醒巡查范围中当前实际有效的唯一统筹原窗口/原会话，不同时广播workers。统筹核各原会话真实状态、当前原控/预算暂停、唯一writer、在途晚终态及已有成果，按[统一接续判据](must-read-work-priority.md#partial-result-continuation)从完整目标核合法必要或有据有值工作，再按[阶段核回](review-completion.md#stage-continuation)实际接回原owner及第一作者动作，不能以报告或next-actions代接续；具体下一成果由各窗据原任务及实物自定，统筹交必要跨域供给，不逐窗锁定选题。

每个被唤起或接到推进消息的任务窗口，必须在当前宿主真实接续完整工作端与独立F/A陪审，完成必要的学习、方案认可、过程质证和成果核回；已适用原身份与同条件有效意见继续复用，不每小时重建角色、重新学习同资料或重跑整套测试。完整陪审须实际参与原任务推进，不能以角色名、ACK、completed或一次旧通过代替。作者在有效路线内连续制作，陪审持续核必要主线、品质、供给与后继。

各窗优先推进主线，主动补足目标所需的内容和逻辑，不把工作缩成找Bug或反复检查。已有候选及时接回、核当前版本与适用条件，由原唯一writer实际采用并交消费者；候选成熟不止报表，未经核实也不盲合。没有专门测试窗口/测试职责支援的制作窗口要多做本人自查，作者和陪审按实际变化核源码、调用链、逻辑、数据、资产及必要反例/正常对照；缺实测条件时继续这些可行自查，明确仍缺的运行证据，不以自查冒实机或体验通过。需要方法、内容或资产供给时可主动寻找适配且许可可用的成熟资源，落实到当前作者源与真实消费，不每小时机械搜索或堆资源清单。

检查、学习、陪审、交接及局部完成后的选题统一沿[接续判据](must-read-work-priority.md#partial-result-continuation)，不把已识别候选当完整队列；缺某前置只限真实依赖，判据内就绪工作继续。原F/A各按[阶段核回](review-completion.md#stage-continuation)核实际后继，确无当前可做项才按[真实停止](review-completion.md#stop-request)准相应范围结束；局部票不准父停。用户明确暂停／撤销／等待立即执行；硬中断保现场与未闭，不冒已获准停或后台仍运行。

统筹正忙或重复tick时接回同一原会话/在途边界，不并发制造新总控、窗口或CLI。tick不授新生产、解除P0/暂停、重试耗尽额度或配置/auth权限；原有效授权内的合法生产继续。通常恢复不默认新建timer或固定心跳；原分组/名称/业务接续/旧实例安全退出/证据复用继续生效。

实际timer对象、巡查范围与当前统筹归属须先核清；旧报告路径或同名局部任务不证明整体巡查，不由任一工作组自封全机ROOT。未知对象只限制依赖它的配置/执行，其它已授权工作继续；实际配置和运行按用户当前授权及已核对象/归属办理，不以旧报告代核对。此节为唯一巡查正文，任务卡与入口引用它，不另复制模板。
