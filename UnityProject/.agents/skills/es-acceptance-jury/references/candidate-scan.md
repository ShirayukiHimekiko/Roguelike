# 检查候选的实际调查

本页候选是检查命题，与[交付候选](../SKILL.md#terms)区别。选择沿[统一机制](candidate-mechanism.md#selection)：执行义务、本角色适用主责结果、全部命中工作块与定向调查；产品严重度独立沿共同判据。U卡供操作复用，旧号定位原正文，目录外有据命题可直接进入。只查任务要求及受影响合法结果。

<a id="hit-to-action"></a>
## 从症状定位到检查动作

候选不是已知缺陷或通过。先按[问题线索](review-perspectives.md#exploration-first)主动搜索同类问题，未发现后按[机制与前提](review-methods.md#method-match)匹配本角色具体查法；工作块和旧号只导航相关正文及成立条件，不凭标签判匹配。说清真实对象、合法输入/事件、待验证命题及正常对照，不为强制候选虚构风险或因未登记拒查。基础义务和必要结果仍履行，无变化转交不假造新检查，父导航不代具体步骤。

匹配后实际读当前源、参数/资产、caller与消费者，并分析已有画面、文本和原始观测；按[可用证据边界](review-methods.md#available-evidence)给已成立结论，仅对仍需连续行为、真实负载或交互的具体未知补观察。缺部分证据不能跳过现有分析，纯代码扫描也不能冒视觉或玩法已经通过；关键词/计数/正则结构不代语义调查。

自然保`候选/启动依据 → 适用范围 → 已查对象/对照 → 观察及边界 → 必修/补证/建议/未发现与下一动作`，层身份不随严重发现更名。用原记录承接，调查可支撑多候选，不逐ID造表/JSON/报告；目录或计划如实记准备检查。缺口只限对应结论，不停无关工作，不假报不适用/已通过。

<a id="scan-depth"></a>
## 深度与范围

检查本批真正受影响的责任链和最可能推翻结论的合法情形，追副作用先后、提交/反馈、取消/归还及后继，而不只验证函数返回成功。共同原因集中查修；碰撞提出的替代也须核自身损失/等待和可维护性。建议与必修分开，必修必须关联用户必要结果、已批准规则或真实新增损失。

一般源码任务沿受影响调用/状态/资源查，不遍历全库；当前受托视觉/可玩复验按[实际视觉验收](review-standard.md#visual-review)完整检查本次画面/状态全部有效目标与必要过程，不能按差异缩图；必要品质差距与必要漏查按超级P0当轮阻断。**用户要求本次Skill维护全包检查时**，库存/引用/入口覆盖实际包全部文件，语义调查覆盖本次改动、相关旧条款及实际调用方，并说明未验范围。独立检查可由两个内部角色按职责承接；用户另行明确指定新扫描角色时按该要求执行并保真实身份。未变范围有据继承，文件盘点、结构通过与语义判断分别报告，数量不冒逐行证明或所有未来输入已验。

<a id="scan-outcome"></a>
## 反馈、停止与实际闭合

重大事实立即传递，保真实角色：仅扫描/建议角色用“扫描结果/建议”，不给陪审增益或套独立裁定/复验标记。普通扫描/碰撞建议由作者有据采纳、暂缓、反证或拒绝并写明理由，不需等裁定批准；只有已经形成的独立裁定、否决、必修及对应完成声明，由实际裁定者独立复核接受或关闭；跨窗口按[机制继承](coordination.md#activation)交正式同职责后继给新来源裁定，保旧原件，不冒原人已关闭，不能作者自关。独立陪审实质意见按[无损消息合同](coordination.md#message-delivery)逐项主对话可见，扫描原文也保记录读回。编号给短名及实际适用理由，不只贴号。未发现只限实际对象/版本/条件，不证明风险不存在。

修复波后实际复验原反例、正常对照和受影响消费者，再沿原记录关闭；建议写回不等采用，源码存在不等接回。普通转述/控制或无新委托/事实时，不为同材料启动扫描循环；用户当前委托同画面复验属于真实观察任务，即使同字节也按[实际视觉验收](review-standard.md#visual-review)重新整幅亲看，不能只转旧结论。仍有新问题继续下一实质波；已满足当前目标且无新增风险则结束本次审查，保未完成但不属本波的责任。碰撞过程见[独立候选碰撞](candidate-collision.md)。
