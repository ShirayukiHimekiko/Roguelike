# 陪审协作与消息

<a id="no-simulation"></a>
## 角色不可模拟（本包最高优先级禁令）

只有真实陪审创建、受派及回传的意见才能带角色／分／事件；工作端不得模拟、代写、预设双通过。转述核真实创建、发送与收到原文，文件可读不认证这些事实。实测来由见[原案例](../knowledge/cases/role-simulation.md#observation)，当前字段与验据时点取[消息合同](#message-delivery)／[原增益](#wave-gain)。

## 独立身份与启动

活任务持续的是已适用的独立职责、事实核证和原件责任；阶段completed、一次通过、摘要或换窗不解除F/A持续交互及原否决关闭责任。前波意图优先／首次AI新结果待证等当前有效用户修订，进入下一任务、首动作、原生派发和恢复；同条件已证事实／原授权继续复用。未触发完整F/A的普通任务，由一名真实独立AI核该委托的全部必要命题，不能缩成片面局部，也不能替代已适用的F/A；真实完成准停、用户暂停／撤销按原合同改变对应职责。

同一当前宿主核真实身份、职责／模型、状态和收发，沿原人followup；新修订、必要未核关系、自然成果或反证需该责处理就真实唤起并给首任务，不以completed省略。用户暂停／撤销先实发受影响职责并撤下一依赖动作，核实际接收、当前在途安全边界与原生终态；ACK／入队不代停止完成，传播间跨界产物保真，不猜收信后故意违令。后到隔离学习／独立工作许可按对象生效，旧停止不变全球永久禁令。作者按有效路线连续制作，F核真实消费者／后继，A核决定性前提／供给／代价，独立首判后实际交流；介入时机只取[自主段](#wave-review)，通常不默认固定心跳／无信息轮询；用户明确授权的每小时统筹巡查按[窗口合同](window-interaction.md)只唤醒当前有效唯一统筹原会话，再由其据真实状态按需接原任务，不向workers定时群发。root是宿主位置而非产品writer；旧地址、running或prepare声明均不认证实际角色／实收。视觉任务启用 🟪T 后 A 仍在：同一波有技术品质或正确性问题时，T 和 A 各自出意见，见[分工](target-art-review.md#role-split)。

**接管／恢复：压缩后、上下文不够、摘要对不上、换窗口、跨宿主接替，都按下面五步。** 目的是尽快接上原工作继续做，不是先做一轮全面审计。

1. **找现场，只补缺的。** 读同一份活记录，确认：用户最新原话和修订；当前对象、源和消费版本；范围、权限和唯一 writer；各职责的原意见、原分、否决及由谁关闭；资格和还没闭的事项；在途操作的真实终态。同条件已证的事实直接复用，不重读全部历史，不重建身份和角色，不清原预算。旧摘要不能让已完成的动作重放，状态不明的不能当成功；某项限制只卡依赖它的动作，不扩成全局停工。核完立即做第一项合法动作（见第 5 步），不等第 2–4 步全部做完。
2. **压缩的事实分开查。** 只在需要判断或说明压缩事实时做，不阻塞第 1、3、5 步。压缩有没有发生、有没有完成、发生在谁身上和什么时候，以及对方有没有真的收到，各自取证：宿主暴露了 contextCompaction 就按 started/completed 记；历史 rollout 里的 recordType=compacted 只证明它的来源；什么都没暴露就记 unknown，不从 running/completed、日志大小或 turn_aborted 去猜。文档说有某种能力，不证明当前宿主已订阅或会自动广播。状态实质变化影响既有职责时，在原接点存下来源，真实交付一次，并按影响接回。不为此新开 API 宿主或服务、每轮扫日志、输出消息、加密内容或隐藏推理 payload；元数据只按实际解析到的范围下结论。
3. **能续原会话就续。** 先延续用户当前要求和已采用的有效做法。同一顶层任务，宿主确实支持、没有重复的有效实例、在途和写域安全，就恢复原会话，不因恢复另起顶层或换配置。**全局配置（`AGENTS.md`、`config.toml`、模型设定）变更只影响之后新启动的角色**，不据此换掉或打断正在工作的作者和陪审；只有用户明确要求或服务端确实拒绝当前模型才换，见 [换人和图片](target-art-review.md#role-swap)。禁止 resume 的只有跨宿主原生子Agent的私有 thread／句柄，不能扩成禁止正常的顶层会话恢复；同机或 daemon 也不等于同一窗口。
4. **跨宿主接替：新建实际原生的同职责后继，交一份完整交接。** 交接包括：用户原话和修订；对象和版本；本职完整原意见和依据；原分、主事件、否决及由谁关闭；已证、未证和先验暴露；暂停、预算、失败、在途和独有材料；唯一 writer；下一步具名动作。旧 ID 只当历史。接收者亲读后回一句“继承了哪些要求、哪些还没闭、第一步做什么”，先做读取、核对和回传这类不写产品的动作；要写正式产品，先按第 5 步让旧实例把具体写域明确交回，不以先写产品作为移交前提。排队、文件可读或自称“已接手”都不算收到，来源、送达和理解各要真实回件。
5. **接上就干活，再退旧实例。** 不能停在收到身份、回 ACK 或重述计划：核完现场就做第一项合法业务动作，沿自然成果继续。给用户的接管消息说清接到了哪里、还缺什么、现在开始做什么；恢复请求已发、已恢复、联系不上分开说。后继真正接通并承接原命题后，才据原坏例、正常和当前原件裁定，保留旧来源、时点和原分事件，别的职责或作者不能代关。后继就绪、旧实例在途按原操作核到终态、独有材料保全、具体写域明确交回后，旧实例才移交或退出；已接回、无在途也不持有的已确认失效旧页签按[窗口合同](window-interaction.md)及时关闭并保留历史，不等项目整体结束。不凭旧失败或旧 PID 误关有效新实例或共享进程；不明的不重放、不盲关，不借恢复扩权。容量或能力缺口按[模型正文](model-choice.md#availability-recovery)只卡真实依赖，独立就绪的工作继续；没部署常驻只说明运行能力，不免除当前宿主的必要接续。

<a id="wave-review"></a>
## 真实波次与双空闲自主审核

波次取能独立判断的成果或实质决策：交谁什么结果、改变何种行为／消费者、依据及下一步。按真实委托或必要依赖划分，不按时长、文件、参数、工具或角色数；失败／零收益保原目标、失败与原分，不事后缩波。

<a id="both-idle"></a>
### 两位空闲时自主查证，工作端连续制作

按[持续接续](#activation)在当前host实际唤起有必要任务的空闲／completed职责，交原需、本段结果／写域、原件及旧未闭，不先喂作者疑点；空闲或“还能查”本身不触发重复审核。运行状态不解除活任务责任，也不成为后台监听／无信息轮询。

工作端在有效路线与许可内连续制作；陪审独立选对象／时机，按下节介入。未知仅限真实依赖，继续／改法取[统一判据](must-read-work-priority.md#continue-or-change)。


<a id="autonomous-intervention"></a>
### 定向后的自主制作与随机介入

在[同版开工](task-plan.md#start-readiness)范围内：
- **开段并行。** 对话AI把原需、可读原件、写域和接回信号实交后台工作AI及适用陪审；作者连续实施，陪审自主查供给／正常对照／后继，不等两位同时空闲。
- **过程随机介入。** 陪审自主择时看首批动作和中间实物；阶段反证、关键成本或业务／表现缺口出现时，按[统一判据](must-read-work-priority.md#continue-or-change)独立重判当前主投入及作者默认底层，不等作者只送下一微改。必要风险、品质差距、漏查及受限对象／下一结果当轮实发。工作端在首个安全工具边界同名实答，落实或交事实反证。
- **收段核回。** 作者一次交真实实物／差异／未闭及下一动作，必要结束申请合入此交接；空闲职责真实唤起。F核消费者结果，A核决定性前提／代价，对话AI整合完整原目标和共同漏项，不再逐人重复全scope取证／签述；必要反证在依赖采用前落实，原职责据证关闭。

同目标、消费者与安全边界内的小改仍为波内制作，不逐文件重开方案／评分；普通成果按实际受影响职责单审或错峰，必要双审先各自初判再交流。正式产品唯一writer。

共享合同／保存格式／所有权／寿命／时空渲染变化或显著批量采用、迁移、删除替换、发布，在依赖扩散前核受影响旧消费者及退出；已证必要差距沿[共同裁定](review-standard.md#decision-order)限制依赖。有效旧证复用，不机械全项目重审。结果实际交[推进指引](candidate-collision.md#advancement-guidance)。


<a id="opinion-records"></a>
## 完整意见保存与追加

实质意见当轮完整保存并读回，保来源、对象／版本、判断、原分／事件、否决／条件及未闭。优先原记录追加；需替换current时先保原raw，再stage读回并单文件提交，独占历史同byte可复用、异byte拒覆盖。可复用`scripts/jury_io.py --current … --candidate … --history …`，实际writer及根须先绑定；这是单writer单文件，不是多文件事务。提交后异常先核实际current／snapshot，不盲重试或称旧值未变。处理／纠正另段，原错／裁定不覆盖；追加后hash变化不冒旧原件未变，已丢字节保真实缺口。

需要投影／采用的本人当前意见，在本人原记录用具名根部jury-opinion块或本人JSON原件承载，保taskId/waveId/id、真实role/actor、原分/事件、对象／范围／结论、必要未闭／条件／损失及[两项本人依据](source-authority.md#grounded-consideration)。来源自写，作者不替审者/root生成判断。原文件历史追加不使同一块失效；新意见由本人给新id/实际定位，不能按文件最新时间猜当前。提取、原源完整性与实际前台消费沿[呈现合同](message-style.md#user-facing)，不在这里另建意见库。

同文转交、ACK或没有判断变化的互读控制不另造长稿／意见文件；新实质判断仍按[消息合同](#message-delivery)保存与展示，不漏受保护字段或代关否决。回看及环境失效状态接[原任务入口](#bounded-inspection)，不建新台账。保存失败／禁止时保可恢复来源与缺口，不冒已保存，继续独立授权工作。

<a id="independent-input"></a>
## 独立首轮输入与后续对照

**本人及其它AI首次形成的需求解释、方案、判断和产物，一律不可信。未经另一真实AI实际独立核验，不得作为事实／方案采用，也不得作为任何依赖制作、扩量、放行、交付或完成的依据。** 作者、F/A、对话AI／root、旧模型与工具派生的新命题同样适用；撤回“低支持”概念，不保留可先用的解释。用户真实授权和同条件已证原件不清零，新推断不继承其已证地位；不设数学概率，不改原评分。

实际交给另一真实AI：先从同版有效原话和原件独立判断，主动查最可能推翻首判的合法条件，并以决定性原件、正向证据及适用正常对照实际核证；不先定错、辱人或凑反对。回件明确命题、实际查证、支持／反证／未知及成立条件。仅未发现反例、低置信标签、“同意／通过”、签名、身份、两票、hash或准备器ready均不能解除未经核验的禁止采用；必须有实际正向核证。审者自己的新推断同样不可信，接受原件／其它实际职责质疑，不凭审者身份自证，不递归增设第三审。

接回者只能按另一真实AI已经实际核验的对象、条件和范围确认采用，证据未覆盖的部分仍不得采用；反证则修正或阻断相应依赖，不能只换置信标签。正确首判经核验可保留；必要差距／漏查和必要未核结果沿原合同限制依赖并给原负整数，评分不替代事实核证。读源、调查、隔离验证仅用于核验候选，不是产品先用、依赖制作或借探索包装放行；真正不依赖该未证命题、已有证据及授权的工作继续，不扩大成全局停工。已有适用F/A按[持续接续](#activation)实交；普通委托由一名真实独立AI核全部首次必要命题，不缩局部、不替适用F/A或同人自演。确缺独立能力仍不得自审放行，保具名核证与接回条件；同条件已核证据与有据返修可复用，不重做首轮。

首轮给实际参与者同一份有效用户原话／修订、范围／禁止项、验收依据，送审对象／版本／入口、客观已做未做、原源码／资产／图像／日志及证据限制；续作接上次承诺、实际观察、原未闭及停止／改序信号。有效旧材料引用原定位，不反复抄历史。

实际交付沿[首作业任务包](juror-prompt.md#task-packet)接到当前角色的业务成果、方法和第一动作；scope／角色／材料目录只是调度，不能代这个任务。原生直派与工具准备各按真实所走路径取证，不从可读默认分支推某次host已调用。

作者的结论、预期疑点、原因推断、推荐修法、评分与期望结果，在各自从原需和实物形成有据初判后再提供；原产物内作者声明当待核主张，不能冒用户要求。双职责可错峰，单职责不等未派角色。已知故障、历史否决、数据风险和紧急事实始终即时带来源共享，不为盲性隐藏。

同一真实原件及已核绑定可共用，独立性不要求另造观察；另一职责仍亲核本人要作的决定、必要反例和未接的核心结果，不只复核作者预定的通过scope。对象／入口／绑定或条件变化、旧证失效／冲突时，只重核受影响事实，不重复同伴全套测量。首判足以改变下一投入即发，互读只加实际变化，未改判断按控制消息处理。保首轮输入／初判／交流定位及真实暴露，不以fork none或自称忘记造盲性；新未知确需未接触观察才新建身份，普通增量／已知缺陷复验接原人。

## 反馈、暂停与接续

自主审查取[介入正文](#autonomous-intervention)，身份与交接取[接续](#activation)。用户暂停／撤制作或转追责覆盖原制作时，先把原话、受限对象／动作真实送到受影响职责并撤旧依赖派发，再长读材料／分析；不继续派原制作／扩量。核实际收件及工具在途／终态和跨界产物，不以排队／发送时戳冒已收到／已停。在安全边界收束，不承诺瞬停；保原未闭与writer，追责／只读权限不冒产品或其它Skill写权。真正不依赖被否决前提且仍获授权的独立查证／责任源修正按实际继续，不据此全局停工。

<a id="wave-gain"></a>
## 原增益与范围

**首稿与转述分时点。** 真实创建并收到本任务的陪审自行生成、回传自己的首次实质意见，原整数及主事件随该首稿给出，无需先回传一份意见或先发ACK。统筹转述他人意见时，须已核该源真实创建标识、真实发送及已经收到的原文；缺哪项就补核，只暂缓未证来源的角色转述，不替角色写分，不冒缺失职责已核证。原件可读不认证上述事实；伪造角色的实测范围见[案例](../knowledge/cases/role-simulation.md#observation)。增益仍是原角色对本波的评价，工作源不能代造。

每个新实质波次、每个实际参与角色都必须给出-100至+100的具体整数，并随该波首次实质结果提供事实；禁止“待核/未知/未给/待评分”等占位、留空或推迟到后续波次。按[真实波次](#wave-review)的原目标与实际变化评收益／损失：产品结果、诊断和必要前置分开，计入已证返工与使用／维护成本，不按文件、工具调用、测试或角色数量评分；重复确认和升版不再计已得收益，不累加平均，不用分值抵否决或制造完成。只评价实际参与角色；同波后续每条实质输出仍保本人原分、原主事件及当前本人结论／复核范围，不重评或虚增成果；长会话、恢复和无新风险不豁免。纯控制、索材和忠实同文转发不另立波；含实质判断时，新波给本人新分，同波携本人原分。

评分时，本波必要结果或所宣称收益确实无法核实，必须给-100至-1的负整数，说明无法核实的对象、已做查证、缺口及影响；缺证本身就是负分依据，不能用0、正分或已证局部收益遮掉必要缺口，也不能改小受托范围规避。负分幅度由原角色按缺口重要性与已有损失说明，不伪造实测。0仅用于已核实无净增益也无净损失；正分只用于已核实的净收益。无法核实仍按证据不足或未运行报告事实，负分不把工具缺失冒成已证产品故障。

未兑现的预期产品收益不计正分。当前委托本就只要求诊断或必要技术前置，且该范围已核实，可据实评分；前置正分须核真实必要依赖、已取得/采用证据、具名下一消费者及兑现信号，不能冒作玩家结果。若必要核实仍缺失，按上一段给负分。累计承诺不兑现先改方法。

**主线计量。** 每个波次开头由作者写明本波推进的是 `TARGET.md`（或原需）里哪一条差距。增益按这条主差距的实际变化来评：对照并排图，特征从“未达”到“接近/达到”就是可核实的收益。与当前主差距无关的修复（包括容易证明的小 bug）不计入本波正增益，只进待办清单；修小问题不能替代主线推进。必要结果没核实仍给负分，这条不变。

**分数和主机位挂钩（视觉／风格任务）。** 主机位是 `TARGET.md` 里定好的那组固定机位（没定就用用户第一眼会看的那个画面）。这一波主机位的 [参照｜当前｜上一版] 并排图看不出可见变化，任何角色（T、F、A）都不能给正分，技术修复做得再多也一样；可以给 0（已核实无净得失）或负分。范围仍是 −100 到 +100，未核实仍给负分，缺分仍记 −1。

**分数必须配白话说明。** 原整数旁边写清三件事：看到了什么（文件、位置、现象）；和目标差在哪（违背 `TARGET.md` 哪条特征或原需哪一项）；下一步改什么（具体技法/参数及预期变化）。只给数字、或只写术语化结论的，对话 AI 向原角色要求同波补正；补正前不把该意见当作可执行的改进方向。

原角色独立评分，统筹不替其评价成果或损失。实际收到的新实质意见遗漏整数或给占位时，统筹当轮依缺分规则记-1，并在该来源块明确“原来源未提供合法数值；此分依缺分规则记录，非原角色评价”，保原件及全部必要意见，向原角色要求同波补正；补正保前值、真实来源与依据，不拖到下一波。这个例外只登记已发生的缺分，不签成果通过，不抵已知损失或否决，不为尚未收到意见的角色造分。工具不裁分，不新增评分器或自动统计。历史原值及缺字段只按历史范围转述，不回填，也不充当本波评分。本机制修改权限按[评分机制保护](skill-improvement.md#scoring-protection)。

<a id="jury-event"></a>
## 唯一主事件

保每个来源原主事件、具体事实与下一动作。必要体验失败/纠偏未执行仍影响交付时，不能由局部源码关闭改称持续推进。无事件不凑类别，作者不猜造；旧意见保原主次与历史格式。

<a id="breakthrough"></a>
## 下一结果

低收益和下一动作直达[继续／改法](must-read-work-priority.md#continue-or-change)，不再回跳task-plan。


<a id="message-delivery"></a>
## 后台事实、真实送达与前台呈现

工作AI/F/A只交事实，不编排用户Emoji、阶段标题或拟用户稿。实质意见保真实角色/状态、对象版本、原整数及范围、原主事件、本人判断和全部必要否决/未闭/条件/损失/证据限制/关闭责任及下一动作；两项本人依据取[source-authority](source-authority.md#grounded-consideration)。可用简洁文字或原记录的结构事实，控制/索材/忠实同文不凑波次；评分/缺分和无法核实负分仍取[原增益](#wave-gain)。

对话AI主动读原件和实际动向，逐源核真实创建、发送及已收原文，另给本人处置；后台不替陪审答或关否决，前台不代制作。严重失败/暂停/用户控制/实际阻断及时送达，不等另一方或下次探查；普通状态沿自然成果和主动读取，不增加周期/逐工具密集报告。完整意见[保存读回](#opinion-records)，文件/工具输出/入队不代送达。

用户视图只由对话AI按[呈现入口](message-style.md#user-facing)组织有意义职责／判断／变化及原分、原主事件和必要意见；后台原身份／原主事件／原分／历史完整保，不把分配名当用户解释，最终正文自足。转述前用`jury_session.py check-roles`核真实原件存在，或复用同集合/原字节的relay-message receiptCheck；无Emoji角色事实同样须预检，缺源仅暂缓该源转述。原件预检不要求用户正文粘贴后台身份或整段日志，也不认证身份、逐源覆盖、语义或实际送达。

路线/限制/纠偏涉及下一投入沿[路线正文](must-read-work-priority.md#route-leadership)，给受限对象/解除信号；纠正保原错误事实和处置，前台取`correction`事件呈现。遗漏当轮补记且保首次原件，不倒写历史。

<a id="phase-display"></a>
## 实际阶段事件

阶段是实际动作/决定，不是排版或通过。后台在原任务记录保当前事件、已做/在做/待做、下一结果/责任与实际阻断，按[进度风险](task-plan.md#task-tracking)接回。规划/项目理解/收尾的触发仍取各自正文，不因探查脚本调用自动成立；未发生阶段不记完成，未来步骤标计划。

对话AI从原记录和当前实际动作核事件，沿[呈现入口](message-style.md#user-facing)显式请求相应用户视图；标签/Emoji映射集中在jury_session，不让后台重复标题/拟稿。普通控制或无变化不凑阶段/报告，不加全组等待、固定频率或第二进度平台。
