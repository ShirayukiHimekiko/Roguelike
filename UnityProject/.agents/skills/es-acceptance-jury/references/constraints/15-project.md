# 内置候选｜15项目理解

当项目类型/阶段/目标/接法/责任有变化或理解可能决定路线时，按下表症状命中具体叶项。每项读唯一正文，并按[专项扫描](../candidate-scan.md)提出可达风险、实际核原件和调用者。完整目录不是必读清单。

| 编号与短名 | 精准触发 | 要核的风险与实际对象／唯一正文 |
|---|---|---|
| 15/01 项目事实适配 | 类型/用途、宿主、交付需求、风险或惯例改变，或推荐依赖未核项目事实 | 从任务/当前产物/真实consumer核事实与允许试错域，不凭标签推标准，读[项目事实](../project-understanding.md#project-fit) |
| 15/02 投入与风险边界 | 进度/交付目的/消费者或危险点影响推荐、优先投入和后置配套 | 核置信度、可逆性、既有合同、代价/责任/重触发，不以Demo豁免危险或成熟标签全禁扩展，读[行动边界](../project-understanding.md#stage-fit) |
| 15/03 已有接法调查 | “没专用类型”推出必须新增公共能力 | 有限搜索遗漏通用接法；查真实入口/消费者和已有组合，读[已有接法](../project-understanding.md#existing-path) |
| 15/04 必要性与语义变化 | 修改/普查命中含义、状态、身份/资源来源、生命周期或持久/共享consumer期待；旧default/映射/绑定变也命中 | 比较原接法与必要新语义，追定义/生产/读写/旧数据与后继；自产配套不升用户必要，不猜生产事实，读[必要性与证据链](../project-understanding.md#necessity-before-dependency) |
| 15/05 旧机制与坏架构区分 | 旧版整体否定、整包搬回或无据重造 | 丢成熟机制/资源或重引错误选型；核有效事实与生产caller，读[已有接法](../project-understanding.md#existing-path) |
| 15/06 画像更新与自我反证 | 后到目标、实际入口/consumer或普查新事实否定旧推荐前提 | 更新相关画像/风险与后置触发，核旧判断/兼容责任；不固化旧bug或同条件全库重验，读[策略复核](../project-understanding.md#strategy-recheck) |
| 15/07 需求定案与默认推进 | 复杂/模糊需求反复等用户确认，或未定边界就开工 | 核两角色真实参与、具体意图/目标/严格边界、AI默认来源、真实文件与Notepad调用及下一动作；默认采用不冒产品通过、不超授权，读[默认定案](../project-understanding.md#intent-default-progress) |

来源/写入仍按07，收益/证据按09，候选不是权限或发现。实际用于裁定才展示注册号与短名，不因启动读过项目说明刷号。
