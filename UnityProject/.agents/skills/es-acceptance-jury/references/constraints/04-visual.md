<a id="continuous-motion"></a>
## 04/07 连续体验

**触发与假设：** 存在连续动效，或目标涉及原版体验、表现力与反馈强弱时，质疑“加入 Tween/Shader 是否真的
产生了任务需要的效果”。

涉及玩家观感、摆幅/快慢或多实例表现时，先消费[玩家视角的动效对照](#player-motion)，区分要修的责任层与可支持的观察范围。

需要录屏/抓帧、密采或连续观察入口时，按[采集与动效分析](../capture-motion.md#scope)核真实目标、时间戳、局部加密与安装/接入缺口；已有观察仍适用则复用，不新增每轮录屏义务。

**最短操作：**
1. 有认可的参照或明确体验目标时以它裁定达标，前版另用于判断变化和回归，沿[目标与变化](#target-and-change)。
   固定控件、内容、比例和触发；原作对照先核实游戏/页面/状态，不同游戏只能说明借鉴。
   没有外部参照时仍按既定目标判断本地反馈是否清楚；时序对齐到同一触发，不通过变速拉伸把差异抹掉。
2. 观察进入、停留、动作反馈和返回，指出具体变化如何引导信息顺序、区分 hover/选中/确认、
   保持可读或干扰操作；正常速度结论须有相应观察。未知原作内部 Shader 不妨碍比较实际外观。
3. 有疑问时用隔离副本或现有开关移除一个效果作单变量对照，检查它带来的实际收益与代价；
   保留素材/状态一致，不把改文案、放大主体等其它差异算成该效果的收益。
4. 连续效果用真实可观察媒体的正常速度播放或实际交互，按对象实际具有的阶段完整走一次进入→
   停留→操作反馈→退出→再进入；不为单纯循环补造选择功能。有常驻循环则看完整周期和首尾接缝，
   有允许打断则在风险时刻取消/反向并观察衔接，禁止打断的窗口则验证输入确实按约定处理。
   区分 hover、选择、确认各自的状态与可见反馈，检查关键内容出现顺序、等待时间、注意力争抢及
   操作是否及时可理解。密帧/慢放只补中间态，不能替代正常速度的节奏与手感判断。

**失败信号：** 所要求的两种反馈实际无法辨认；动效使必要信息更难读；宣称显著增强却没有可
指出的目标相关变化；只提交曲线、时长和 Shader 开关而未观察效果。审美判断需说明具体画面
和理由，不能由像素变化量、测试分数或参数数量推出“玩家惊艳”。
循环跳变、往返突停、打断后不连贯、关键内容晚于可操作时刻或装饰抢走任务焦点，均需绑定具体
时刻及目标影响判断；没有明显 bug 也要检查节奏、可读性、反馈区别与效果收益是否达到本次目标。

**校准：** 坏例是控制了错误材质实例/未生效目标，程序参数变化但实际画面没有对应变化；
合法对照是刻意克制的反馈，不因幅度小就判质量差。无原作参考仍可比较本地反馈是否清楚，
但不能解除原版一致性。无连续观察能力时先给可支持的画面/可测时序结论与具体缺口。
既定设计中的有意跳切、允许且不损害目标的输入窗口也可合法；沿原合同/基线说明，不能看到失败后
临时发明例外。风格参考不是唯一审美答案，特效数量不计质量分；否决须指出实际观察如何损害目标。

**复验解除：** 当前版本按同一触发和实际速度重看完整往返及受影响循环/打断，比较原失败时刻与
合法对照，确认节奏、信息时序和反馈区分改善；未取得连续观察则只解除已证实的静态问题。

<a id="design-basis"></a>
## 04/02 设计关系

1. 复用项目已认可的小样、实际参考和原始目标，指出本版最值得保留的识别点与主要体验。将“高级、爽、克制、有冲击”等词落实为本对象可观察的关系：谁先被看见、读到什么、哪个输入引出何种响应、何处形成峰值与停顿。没有明确方向时提出带依据的假设，不冒称用户已选择。
2. 对照同用途、相近信息量、尺寸和状态；先看本阶段已有且适用的完整画面/操作证据，再放大问题部位；文字方案先审描述与关系，不索要尚未制作的操作链。标清题材/平台/输入/交付阶段差异，不用孤立精修特写否决完整界面，也不把参考的字体、装饰或品牌样式整套搬来。
3. 按问题查[已整理来源](../../knowledge/sources/design-sources.md)，把“来源明确说的”“本项目如何借用”“尚待验证”分开。已有可靠依据可复用，不每轮全量搜索；遇到未支持的判断或争议再回源，参考不足沿既有[主动补源](../evidence-recovery.md#joint-source-search)。只读文字不能说看过链接内录像。外部资料只提供适用依据，不自动要求项目全面采用；已明确采用XAG等标准时，按其适用条件核相应义务，不能以主观未观察到干扰跳过承诺。来源的品牌取向、参数和技术功能不升级为跨项目标准。

<a id="diagnosis"></a>
## 04/03 可制作指导

选择与目标相关的行，给真实位置/时刻；不要把表变成每轮全量打分或统一风格配方。

| 设计关系 | 怎样揭出问题 | 给作者的具体调整方向与保留边界 |
| --- | --- | --- |
| 构图、层级与密度 | 在目标尺寸看整页：主内容/主操作是否被大面积高亮、重复边框或装饰夺走；相关信息是否被距离/分组拆散；留白是否帮助组织。缩略/灰度只辅助定位，不能代替实尺寸判断。 | 指明竞争的两个区域，先调相对面积、对比、间距、对齐或前后层次，再看主次关系。保留有目的的偏心、重叠、密集和共享布局；不以居中、整齐或留白多自动判优。 |
| 文字、图标与语义 | 看实际字号、行宽、字重、背景和长短内容；标题/数值/说明是否同权重；换字形后是否拥挤、标点断行或图标含义不清。 | 在原风格内调整文字角色、行长、字重/间距和承载区域，核对真实字体消费者；装饰字形可留作识别点，正文另解决阅读。不得通过删必要信息、换掉指定字体或全缩小来掩盖布局失败。 |
| 色彩、材质、光与 Shader | 在真实内容上看明暗边界、材质尺度、光源方向和高亮峰值；扫光/噪声是否只像白层覆字，材质是否与邻区脱节，透明叠加是否改变内容颜色。 | 指向承载表面及遮罩：边缘/纹理/高光/背景各自承担什么，先调局部对比、范围、方向和强弱。可用表面细节、受控流光或状态高光强化质感；不靠全局变亮、加饱和度或特效数量证明高级。保留任务允许的非写实材质；Shader 实现和性能交原制作能力验证。 |
| 指针、焦点、选择与反馈 | 按实际输入覆盖移入→移动/聚焦→按下→提交/拒绝→移出/失焦；看悬停是否误像已选，是否在真实结果前误报成功，目标是否因形变移动到不可点。 | 分清预览、收到输入和结果的强弱及持续时间；即时按下反馈＋稍后异步结果可以成立。指出轮廓/表面/位移/内容中的哪一项表达当前状态，移出回到正确基态，选中按真实数据保持。高品质不等于大缩放；触屏不硬加悬停，控制器焦点不冒充指针。真实状态/隔离验证复用原方法。 |
| 入退场、转场与常驻节奏 | 在正常速度看注意力如何转移、反馈何时到达、内容何时可读；对照快进快出、打断与重入，常驻循环是否抢过操作峰值、反复遮字或出现接缝。 | 指明主体/分区/陪衬的先后与重叠，调整路径、重心、缓动、错峰和停顿；输入确认及时，高潮留给有意义的事件，常驻强度与目标相称：作为核心主视觉时可以突出，阅读/操作阶段不遮盖必要信息。原项目实测时序是起点，无依据数值标为待调；不统一整页淡入、全员弹簧或把线性/安静效果一律否决。完整播放和中间态沿[连续动效](#continuous-motion)。 |
| 整体风格与表现力 | 同页/相邻状态一起看形状语言、描边、纹理密度、色光及运动性格；是否每块局部漂亮却无法形成整体，或修复后丢了本来有价值的识别点。 | 保留主导语言，指出哪个局部冲突及可调整的从属关系。若正确但平淡，围绕目标的一个关键时刻加强层次、材质差异或节奏对比，做可辨别的小样；不能把消除错误当作高表现力通过，也不能为了安全把强风格磨平。 |

<a id="actionable-guidance"></a>
### 让下一版可制作、可比较

每项设计意见串起 **定位与观察 → 对目标的影响 → 优先修改哪个关系 → 保留什么 → 怎样复看**，必要时补建议代价；用自然句，不强制五列表。避免只有“加强层次、优化质感、参考大作”。建议具体到承载区域、状态、相对强弱和时序角色；尚无依据的数值是待调起点，不能包装为权威参数。基于原目标与成本/收益判断局部修正或更大方向变化的价值；不要求证明局部修补绝不可能，也不迫使作者采用陪审方案。

作者负责小样和取舍，陪审独立看差异：在可比内容/触发/观察条件下，目标是否更清楚或更有表现力，保留项是否受损；原失败、潜在损失及未测分别回到原目标记录。设计建议和保留理由也按[信息保真](../coordination.md#message-delivery)转述，不能压成“已优化”。仅方案阶段可交有据方案；没有实际画面/连续观察时不签收观感，测试数量不能证明“玩家爽”。

有认可参考、方案转控件/目标宿主或视觉改善声明时，先执行[独立对照与目标保持](04-visual.md)，
再用上表诊断实际差距；返工未带来目标相关收益时按其[制作分流](#outcome-and-repair)查责任源。

<a id="comparison-inputs"></a>
## 04/06 完整可比产物

复用本任务的原话、认可参考及真实修订，保留可回看的版本、适用页面/状态，以及决定质量的可见关系。
例如主操作与装饰的注意力顺序、正文与次要信息的可读层级、主体占比、材质层次、状态区别和动效节奏；
只选当前目标实际依赖的关系，不要求用户先写完整设计规格，也不把作者推定写成已获认可。
允许的近似、变化维度及仍须保留的效果随用户真实修订继承，沿[近似边界](10-delivery.md#bounded-approximation)。

送审时让陪审能访问**原目标/参考与本次当前完整画面、状态及所需过程**，整幅复验沿[目标与前版](#target-and-change)；局部裁片不代完整画面。用同一包中的独立段落或路径放作者修改说明、原因假设和测试结果。
缺陷、权限限制及已有否决即时共享；不为独立性隐瞒它们，也不强制分两次派发。
整体结论须有本阶段适用的整页/完整构图或操作链；局部特写只能支持其范围。保留真实数据、状态、
视口、缩放/像素密度、字体与采集版本的已知条件，不把不同内容、裁切或放大带来的变化归功于修改。
条件不完全一致时先说明仍可比较的关系及缺口，不一概拒绝全部观察。

<a id="independent-observation"></a>
## 04/04 独立观察

- 陪审先按[目标与前版](#target-and-change)对本次完整画面全目标亲看，再作必要局部观察并核作者解释：哪里符合、哪里最可能推翻当前完成声明、
  依据是哪处画面/状态。按风险自行选择作者未强调或最容易暴露共同假设的区域、输入或内容；没有新疑点
  不为凑反对意见扩大检查。可直接观察的原产物优先；需要作者采集时由陪审指定目标状态和上下文，亲自看回传结果。
- 首轮及接触披露须实际消费[独立输入合同](../coordination.md#independent-input)；分清亲看、作者解释与待证假设，同伴同意不代独立证据，已知严重失败／历史否决即时保，不自称恢复盲性或默认另开角色。
- 核对作者提出的修复是否真正作用于目标：查看真实字体/资源/状态的消费者，或在授权范围使用一个
  可区分的内容、状态或开关对照。选择能推翻具体假设的最小动作，不以多看截图、换模型或重复提问保证独立性。
  观察链与制作端共享了哪些假设要如实说明；拿不到所需完整产物时，指出具体缺证和下一采集动作，
  不让漂亮裁切、作者评分或提交次数补成整体通过。

<a id="target-and-change"></a>
## 04/05 目标与前版

涉及上述视觉目标的实质裁定，同时回答：**当前产物是否达到本次有效目标；相对前版改动带来了什么收益或损失。**
没有适用前版时只判目标，不虚构历史。两项判断写入已有意见/分项目标即可，不要求额外固定格式、分项分数或两份报告。

目标参照取有效原需及已采用的HTML、设计图、真实样件或体验要求；前版只用于核变化和回归，局部通过或陪审共同修法不将前版升为目标。制作媒介／工具变化不改变受托对象及正向品质，排除被否定特征不定义成功；原需或已采纳建议确定的参考部分及效果关系，须持续约束设计选择、生产与完整效果判断；相关造型、材质、排版、动势和信息关系按该范围核。指出当前关键差距及下一版可观察的解决信号，保有效改善；“更好”“无明显bug”“意见全关”不足关闭原目标。

方案→控件→整页→目标宿主的交接继续携带同一目标参照与未闭合差距。认可 HTML 的截图只证明 HTML；
目标宿主的字体、资源、遮罩/层次及交互须在其实际产物中成立。跨宿主验收沿用户要求的效果关系与精度，
不默认逐像素相同，也不以“宿主不同”免除已要求的观感。设计改动按真实用户修订或[授权建议采纳](../source-authority.md#current-mainline)更新参照并保留来源，原质量目标不随自选参考缩小，
不把旧标准永久冻结；合法原型阶段可独立通过，但不升级为最终成品通过。

本次整幅／状态亲看、同图复看、源码事实复用与控制转述边界，须实际消费[视觉验收](../review-standard.md#visual-review)；版本差异另用于原因及收益／损失，不以旧局部观察代当前全目标判断。
“局部改善”可与“整体返工”同时成立；将该判断按[交付与停修裁定](../review-standard.md#decision-order)接到实际下一动作，不由本地修复、工程安全或参数生效推出本阶段参考达标。

<a id="player-motion"></a>
## 连续体验补充：玩家视角（04/07）

**先看玩家会看到什么。** 在目标尺寸、背景、镜头与正常速度下观察完整行为，有群体用途再看所需密度；放大、慢放、骨线和速度图用于解释问题。围绕本次目标指出重心/方向、可见幅度、快慢分配、部件先后、释放反馈与终态的具体作用。小而可读的反馈可以合格；幅度更大、参数更多或循环更平滑不自动更好。采集掉帧可能改变节奏，先区分采集问题与实际播放器问题，不据失真采集判原动作。

**空间、时间、群体分别判。** 往返动作先核可见支点、中心和真正两侧极点，再看接近极点、换向、中段通过的时间分配；骨骼速度归零可能停在视觉中间，全身同时停住也可能丢失跟随。群体随机相位或不同速率不能修复单体的匀速感；单体成立也不证明密集场景没有齐拍、遮挡或注意力干扰。可独立评价的动作先查单体，协同或相互接触的动作用最小交互组。不要把双端慢拍、对称幅度和随机速率套给所有动作，恒定旋转、机械节拍或设计要求的同步可以成立。

**独立核参照与标记。** 先在真实原图/姿态中自行选有语义对应的根部、接触点、领口或头主体，再核对作者数值；展示原点、挂点和可见支点不能混用。共用作者的错误常量再独立运行脚本，仍不能构成独立坐标依据。核资源在实际播放中的组合、速率和挂接，区分实机画面、原资产求值和社区重建。跨比例比较固定一种有理由的尺度、地面和镜头，说明比例残差及选点不确定性；站高相同不能顺带证明头宽比例相同，逐帧缩镜头不能证明摆幅修好。姿态对照须绑定同一语义动作事件或明确源相位映射；相同百分比只称“周期进度对齐”，非线性重定时后不保证同姿。实际秒用于节奏，适配曲线不冒称原时序。

**让判断改变下一步制作。** “匀速”先查周期内快慢，“左摆不足”先查标点、中心和幅度；陪审指出可见差距和能区分原因的观察，由作者选择修法。先用代表极点/经过姿态与正常播放验证关键假设，再扩大制作；已经观察到的问题不能仅因无翻面、插值连续或事件次数正确而关闭。连续几次局部指标改善而目标仍失败时，应改比较依据或制作假设，不能仅重复“整体未验收”。

**证据边界不洗掉失败。** 按[连续观察](#continuous-motion)分别记录亲看、运行测量、作者材料与用户实际播放反馈。用户指出的动态失败是已有观察，AI无连续视觉输入只限制自己的观察声明，不把该失败降成笼统缺证，也不把用户结论冒充亲看。继续可行的修复和有区分力的局部复验，指出当前版本哪项仍需正常播放确认；生成影片、RAF采样或反复静帧检查均不补成亲自连续观看。

## 04/09.01 有效视觉返修

工作AI把可见差距落实到制作责任源与本次可检验假设，陪审检验输出。以目标宿主的一块代表区域或一页先验证
最不确定的布局、字体、素材、材质/遮罩或交互能力，再扩大复用；代表样件通过不签收未查页面。
陪审给具体差距、保留关系和复看信号，作者选择实现方法；陪审方案也可被实际结果推翻。

若本次声称视觉改善，需指出当前版本在可比条件下出现了什么目标相关的变化，以及原差距是否关闭。
提醒送达、意见转述、测试通过及机器 `passed` 各只证明其技术范围；功能修复可按功能目标通过，
不强求每次代码修改都产生视觉变化，也不把它计作尚未发生的视觉提升。
相同画面被换了更肯定的解释，或只把旧截图重新编号，不构成视觉修复。

持续返工时区分卡点：明显差距仍被签收，改观察/比较方法；能指出差距但做不出来，查制作假设及宿主能力；
参考或采集不可靠，先修证据链。沿[寻找突破](../coordination.md#breakthrough)选择有新依据的小样路径、预期观察与停止信号，
不以再加提醒或再跑无关测试代替改变方法。没有可行路径时保留目标、具体缺口与恢复条件，不擅自降标或签收。

## 04/09.02 方法校准

新增或修订这类方法时，优先用已获授权且来源明确的实际失败；没有可用案例可使用注明来源的隔离可见样例。
让执行陪审实际观察参考与产物，并检验其能否识别“局部改善但未达到目标”“流程齐全但可见失败”，同时接受
用户确已允许且满足保留要求的合法差异。预期问题与答案留给评估者，不能把作者标注复述算作独立检出；
执行者已有相关上下文时披露污染，不宣称盲测。既有否决和真实安全事实不为试验隐藏。

只报告实际检出/漏检、误拒、具体观察和制作结果；提示里写着缺陷、关键词匹配或字段齐全都不能证明视觉能力。
隔离静帧检验不证明动态体验、真实项目修复、跨宿主适配或普遍收益。方法判断正确与制作端达到标准分别取证，
后者仍未完成时如实保留，不能因方法校准通过宣布视觉风险已消除。
