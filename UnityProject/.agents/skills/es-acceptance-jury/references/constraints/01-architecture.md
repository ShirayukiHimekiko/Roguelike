<a id="local-commit"></a>
## 01/05 局部提交

普通库存、选择或生产领取应在原有效对象上局部提交并更新相关表现；接口不足修原责任源。不能为少量状态变化 Capture、序列化比较、恢复全世界或重绑整场景。真正载入/恢复仍沿当前项目允许的生命周期，不为删除错误架构破坏合法恢复或玩家数据。

<a id="finite-supply"></a>
## 01/06 成熟供给

核真实 provider、saved 数组、有限且独占的存储、body/view、取得及归还 caller。资源在盘、Prepared/Bound 或 Accepted 不证明资源已可消费或更大范围 Ready；例如 Prepare 可合法完成却没有 ready actor。readonly 依赖若仅在构造取得，稍后资源到位也不自动证明现有 Retry 能补入，须核真实供给及继续路径。

<a id="strong-wiring"></a>
## 01/07 接线规则

**Unity职责落点检查。** 本批给共享控制器、伤害数据、公共接口新增具体武器/单位类型、专属字段或策略分支时，必须查该层为何拥有此状态，以及内容变化会迫使哪些共享模块跟着改。读类型引用/asmdef、实际字段赋值、事件生产与消费；测试返回正确也不能略过这一步。

状态归属、任务执行者、输入输出合同按[核心用词](../../SKILL.md#terms)区分。查字段生成/赋值、读取、重置/释放及有效期，再核参数/返回、可空条件和副作用的调用约定；函数所在文件、字段名owner或协作writer身份不单独决定模块职责。合同变化须同批核直接调用方及绑定，签名没变也不能略过。

坏例：通用EnemyController识别某RocketSupport、公共DamageFingerprint持有其掉落次数/handled状态。合法对照：通用伤害快照、池对象生命代次，或已批准扩展接口把死亡事实交由具体武器owner处理；跨模块引用本身不自动错误。改名、藏helper或移动到另一个公共文件不改变职责归属。

无该层职责依据则返工落点：专属规则归其实际owner，共享层只供必要通用事实和合法扩展；保延迟死亡、回池、防重复、原未受影响玩法。复验同时检查静态依赖/状态所有者与原坏例正常对照，不以功能绿、局部收益或临时方案抵销架构失败。具体操作见[Unity候选卡](../unity-candidates.md)。

强类型交付核具体类型/命名空间、接口/成员、程序集及参数/返回，沿生产caller保真实失败续办/清理；不用object/dynamic、反射、默认值、永真或永久拒绝壳补业务。仅新能力未到位、真实owner已确认合同及其前提有依据、且没有依赖性P0阻断时，消费端可按该合同写隔离调用，供给端同步补实现；准确记未到位类型/成员/程序集、交付人及下一闭合批次，不猜签名或接受任意编译错。已有共用供给/职责/身份/序列化合同错误或必要前提未查明时，先按[因果阻断与依赖修补](../causal-diagnosis.md#causal-blocking)处理，不用“同步补实现”给普通下游铺量或正式采用放行。依赖到位且对应阻断解除后及时验证受影响组合；未编译本身不判类型错误或认证安装/运行/点击，未到位的必要依赖及已知必要失败不获该范围正式通过。未知规则/容量/资源槽查原依据，不另造关卡/库存/owner。

必需关系在原装配/取得处落实，约定非空的玩法路径直接调用；缺失即合同错误，不用层层判空、`?.`、静默return、默认值或空实现吞掉。可选关系、预期拒绝及退出按原合同；Unity对象的`?.`不识别销毁态。错误暴露仍保06的寿命复核/归还及项目预算，不以仅开发构建的断言认证正式路径。

跨模块关系变化时核受影响供给方、调用方和契约归属，分清数据、命令、回调方向及原转换/适配责任。游戏中沿本批玩家动作追原规则/状态提交及视听/UI反馈，核拒绝/取消后的合法操作与归还；不以层数或接口数代玩法接通。静态引用/程序集依赖与运行调用分别追；合法回调不单独证明引用成环，实际静态环仍须按项目约束核其影响，不默认每层接口、新适配层或全项目映射。

采用延后队列时，区分请求受理与业务完成，核所需发送时事实、消费时资格及结果返回／续办；不凭入队成功宣称后续业务完成，寿命责任沿06/05。

涉及Unity Scene/Prefab时核获准实例、保存引用/监听或已有合法caller；按钮和Editor返回true不代接通，空targetGraphic不独断不可点击。

<a id="takeback"></a>
## 01/08 唯一接回

交叉源码按真实current before、唯一writer、依赖顺序和三方窄差异接回，旧快照/candidate不整件覆盖后继，原GUID/meta和机制保。三方动作及主工作AI/HOST采用容量沿[集成接回](../task-groups.md#integration)，不因未分组免除。文件存在、排队、消费、融合、main采用、资产保存及运行分记。后继到位核实际源/caller，让已消除的旧缺定义/调用制作任务退出；旧失败及未闭合意见保留，退任务不代产品裁定，无新影响不重审已闭同字节项。

封存不创造删除、搬移、抢锁或操作他方数据库的权限。生成清单无名可能是生成失败，不证明旧资产已无用途；清理先核原所有权、引用、原件和恢复条件，权限及保留沿现有[来源](../source-authority.md)和[项目记录](../task-plan.md#cleanup)。工具/磁盘失败不扩写域。

反例位置、合法触发/复验信号用[独立代码判断](../review-standard.md#code-review)，区分已观察损坏、源码失败、条件风险和缺供给；建议损失、更正及分析/产品验收用[目标覆盖](../review-standard.md#goal-coverage)，历史/项目参数用[规则维护](../rule-maintenance.md)。低收益按[闭环推进](../must-read-work-priority.md#core-loop-progress)及[寻找突破](../coordination.md#breakthrough)改序，不把无新依据分支转辅助空转。

<a id="execution-context"></a>
## 01/09 执行域分离

跨宿主建议、接线或新增/移用工具类时，按实际caller、程序集/API与执行宿主归域，不凭目录或“Tool”名称豁免。

| 消费者 | 适用责任 |
| --- | --- |
| 游戏运行时 | 沿当前业务/生命周期与[项目预算](02-performance.md#project-budget)；JSON/内容身份只按[运行边界](../must-read-continuity.md#runtime-evidence-boundary)。 |
| Editor作者工具 | 核编辑器程序集/API和获准保存对象；保存结果与运行行为分记，不能把UnityEditor依赖带入玩家路径。 |
| 工作AI进度/留档 | 审查证据仅离线，沿[关键增量](../must-read-continuity.md#incremental-records)；不变成游戏协议、业务准入或存档。 |
| 工具类/共享helper | 不是豁免域：由运行时调用就承担运行时约束；Editor或离线工具分别沿其写域/权限，不能借名称混入跨域依赖。 |

共享代码追各实际消费者；Editor或离线工具的允许操作不自动授权运行时，同样不把游戏预算无依据地强加离线工具。
