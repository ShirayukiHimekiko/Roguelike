# 参考与验证恢复路径

视觉制作依赖尚待建立或改变，或命中缺参考/验证手段时，必须读对应章节。本文件指导双方主动核实制作依据、补来源缺口与提出可执行补证，工作AI负责主要搜集和制作，陪审独立核实与批评。它不要求每次都跑全套，
不接管原始设计、业务实现或采集工具，不新增网络、宿主、Unity 或发布权限。

## 先把问题对应到原目标

选择当前未完成的必要目标，先按[可用证据边界](review-methods.md#available-evidence)分析已有源码、资产、文本和截图，给已成立事实及剩余具体未知；没有视频或Player不能跳过这些材料。再区分观察到的不合格、尚未观察、工具失败：
不能把工具故障判成成品质量差，也不能因没有发现缺陷就判断已合格。
在现有任务记录里说明“目标 → 影响结论 → 下一动作/责任 → 解除条件”；几句话或现有分项行即可。
不为普通问答另造质量档案。回源、重试和采样沿[同一验证选择、复用与回看正文](verification-scope.md#relevance)，已有依据足够即裁该问题；缺口不自动触发新项目或重复采集，必要动态结果仍补对应观察。

<a id="production-readiness"></a>
## 依赖性制作前：参考、素材与材质依据

工作AI在建立或改变视觉方案、资源选型、材质/渲染路径，或把方案转成目标宿主实现前，先核实
本批所依赖的制作依据；不等做出失败画面、陪审提醒或用户催促。即使只做一个对象，只要会把
未定的资源、材质或效果假设固化进实现，也适用。只检查当前决策依赖的项，复用现有任务记录
及仍适用的观察；统一按[开工依据](task-plan.md#start-readiness)取得两位认可，不新增另一套资产清单、开工报告或逐次审批。

命中[开始评估方案](task-plan.md#plan-evaluation)条件时先完成该阶段，按[阶段事件](coordination.md#phase-display)保真实动作，前台集中呈现；最早方案/小样送审沿[实际送审材料](coordination.md#worker-message-prefix)交当前已查依据和必要未知，不要求所有小对象另开完整评估。不能等成品做完才补依据或准备提醒。

| 依据 | 足以支持下一步的内容 |
| --- | --- |
| 目标与参考 | 指定原作/已认可 HTML、设计图或样件应有可打开的对应对象/状态，实际观察并指出当前要保留的可见关系；已有观察可有据复用。仅有链接、缩略图、风格词或作者转述不足以支持其未展示的细节。原创任务可先形成可检查的视觉假设、草图或探索小样，不凭空追加指定原作，也不将推定写成用户已认可。 |
| 可消费素材与制作路径 | 核实本批关键材料真实存在、内容及使用条件适用、能被目标消费者读取；缺素材时明确获取、加工或原创制作路径及待解缺口。参考图不等于可用资产，分件表不等于完整动画，文件可打开不等于能接入。已有资产、矢量、程序化和原创路线均可用，不强制购买或联网换图。 |
| 材质与呈现配置 | 把目标效果对应到实际对象/表面、渲染器或控件及所用材质/Shader、纹理或样式路径。按依赖核对管线与平台兼容、纹理导入/色彩与缩放、透明混合、遮罩及排序/深度、光照/阴影/后处理和必要性能约束；纯平面任务不硬套 3D 清单。只写 Shader 名、“高级材质”或套用默认值不算方案；默认方案已有证据符合目标时可复用。 |

未知参数不要求纸上猜定。工作AI先独立选择有依据的制作假设，以能解开关键未知的最小样件
确认：用实际计划采用的材料与相关目标条件，先核关键工艺能否支撑目标品质，检查最可能推翻路线的画面/状态；不能只测能打开/运行，或先做粗正式版再找方法。可复用仍适用的
宿主样件，不能拿另一个宿主的漂亮预览代替兼容和效果依据。涉及目标效果的未知尚未验证，
即使配置表写全，也只能支持方案或探索；先解决它，再把该路径固化或扩大到依赖它的制作。
不要求先验证与本批决策无关的未来细节，也不以某个小样证明全部场景、平台或最终品质。

发现必要缺口就按[主动探查](#joint-source-search)当轮推进：查现有材料/来源、核实制作方法，
形成下一样件及解除条件。允许继续的探索、代理或接线工作须说明正在验证什么、范围和停止
信号、如何替换或撤回；不能用“先做可逆初版”铺开依赖未知项的成品实现。缺口只暂缓依赖它的
选型定稿、效果承诺和实现，规则原型、无关代码及已具依据的制作继续；无运行权限时可完成
方案/离线准备，保留目标宿主未验，不自行启动。已明确只是布局或生命周期缺陷且相关依据
仍适用时直接修复，不强制重搜、重做材质样件或等待全项目素材齐备。

陪审收到方案或小样就独立核实这些依据，不能只核对作者有没有填记录；从原目标及可达材料
判断是否漏掉关键依赖。首次有据发现不足，当轮主动探查，沿同一缺口追踪加工/拆图、适用的
动作制作、接入和真实效果复验。按同一[开工依据](task-plan.md#start-readiness)核准准备与查证范围，沿既有成果送审，不另增签字轮；方案、加工样件和
宿主效果各按证据范围裁定。关键素材、消费者、渲染路径或目标状态变化时，只重查受影响依据；
陪审已列为必修/缺证的项由相应实际证据及原陪审复核解除，不能靠填完配置或下载完成关闭。

<a id="joint-source-search"></a>
## 资源与制作方法的主动增效探查

调查效果缺陷时，比较源件、导入/压缩加工、材质绑定与目标输出，分清供给与处理损失；来源充分而配置错就直接修配置。涉及找原作时先定[复刻/参考档位](recognition.md#replication)：复刻要找的是同一来源的同版本同状态，参考只需可辨取向——档位不明时按参考处理并说明这是推定，避免为了“找不到原图”卡住可继续的制作。方案、首版、实质反馈、核心品质停滞或拟采用／结束时，工作AI与陪审从完整目标主动识别能改善效果、控制、效率或复用的具名机会，不等报错或用户点名。网络查源、实质质证、生成／编辑、生产素材及[成熟工具／依赖](project-understanding.md#capability-fit)按本次作用调查与推荐；代码可做或尚非不可替代不代供给选法充分，也不把所有潜在改进变成新增交付。
必要对照或供给缺失、低保真占位、制作依据不足、整体问题持续而局修无效，用户已要求取材却遗漏，或作者无据称不可得时，同样当轮核查。
在原任务接点给具体作用位置、决定性原件／反证、收益与总负担、负责端和下一作者成果；实际开展有界关键探查并真实交接。相关且在既有授权内可行的选择由工作端取得或试作，陪审核精选加工、目标消费与损失；不足按原裁定限制对应采用、扩量或停修，不只留“可以优化”。未采用有目标或事实依据，关键未知先查证；已有充分正常证据可复用，不为凑工具调用重做。

需要找源或制作方法时，双方消费[分层探查](resource-discovery.md)：按本项目 → 已知项目 →
匹配网络站点 → 网络执行；层内范围、升级/停止条件和跨来源边界以该页为唯一正文。
适用材料复用，不每轮重新联网。已认可的几何/程序化风格、只验规则的原型，
不因外观简单强制换素材；已定位的布局、输入或生命周期缺陷直接修责任源。原因未明时用
定向查证区分资源、制作与接入问题，不预设换图能解决。合法原型也不能冒充最终成品通过。

素材缺失、对照难找、工具不足或真实外部限额到达都不意味着需求降级；不能把高质量成品悄悄改成
低质占位，把指定原版改成相似原创。先处理影响当前必要目标的来源缺口，再作依赖该来源的
定稿；不依赖它的制作可继续。双方均须主动推进，不默认让用户承担找图或补测试的必经步骤。

- 工作AI负责主要检索、加工/定制和接入；陪审独立检索或打开决定方案的关键原始材料，
  核查遗漏及相反证据，形成相关独立观察，不只重复作者摘要或凑网址数。已有观察复用时
  标明来源与范围。工具受限时记录真实错误、可行替代及取证责任，不把未搜索写成搜索无果。
  共享实际线索和已查范围，避免双方重复全库或整段视频；工作AI不等陪审提醒才处理已知缺口。
- 陪审找到或推荐资源不等于该资源合格；仍独立核对适用性和最终效果，不接管初版制作，
  不因采纳自己的建议而降低验收。搜索、下载、使用素材和外部操作分别遵守当前授权。
- 高质量以目标适用为准：可核对来源/版本，图像或片段完整清晰，内容与状态相符，风格及
  分辨率适于交付。用于制作的素材还核对使用条件、可获取性及加工损耗；官方身份、下载成功
  或大尺寸本身都不证明适合本任务。参考可支持外观事实，不自动支持原作内部实现猜测。

1. **执行分层探查。** 按[查找顺序](resource-discovery.md#search-order)核实当前消费入口、
   复用相关完整教学，再围绕可回答的问题补源，例如“详情页哪些版块先动、何时可操作”。
   高保真对照先核对同游戏/版本/界面的真实材料，再按目标允许的范围考虑同类设计。
2. **标清借鉴范围。** 同类游戏可以支持载体/反馈方案，静图可以支持构图与终态；它们不解除
   指定原作的时序一致性。没有精确参考时沿[制作前依据](#production-readiness)限定探索/代理范围，把依据、推演和待核对部分分别写清，
   不悄悄将“原版体验”改为“原创小样”。只有影响原目标的重大取舍才向用户补问。
3. **将来源推进到消费样件。** 分清参考图、可消费资产与制作教程；取得足以选择方法的依据
   即收束搜源，由工作AI选择复用、改造或原创路径，制作能检验当前缺口及相关对象关系的样件。
   按材料与目标核查裁切/透明边界、尺度/锚点/层次、动作时序与触发依据、目标宿主绑定；
   部件表不等于逐帧动画，重新编排不冒称原作时序，每帧独立居中可能产生锚点抖动。
   保留可复现的加工与接入结果，合法的程序化生成或运行时装配同样可用，不强制特定资产格式。
   陪审沿同一缺口追踪加工、动作、接入及受影响旧功能，在真实消费者中对照目标复验；静图
   不证明正常速度动作，漂亮原图或独立合成图不关闭宿主内缺陷。纯研究批次可交研究结果，
   但保留产品未完成项、下一样件及回验责任，不要求在当轮越权完成运行制作。

搜索及供给失败按[搜源收束与交接](resource-discovery.md#selection-and-handoff)和[继续／改法依据](must-read-work-priority.md#continue-or-change)处理：有新依据再查、足以制作即接消费者、真缺件实际索取并接回障碍，不反复空搜或以自定预算弃必要目标。可逆代理只支持明确结构／接线阶段，保待替换对象、合格条件与后继，不自动转最终素材或取得成品验收。真实范围／阶段调整按用户采用处理；缺供给仅限对应依赖，目标与其它授权工作保留。

每次新观察说明具体来源、观察者、实际区间/帧号、方式、音频是否观察、看到的事实、未知项及
对制作的影响。下载、转码、元数据读取、生成联系表均只是处理；实际看过图像才能报告该图观察。
连续播放命令成功不等于观察者看到连续画面。下游继承已有观察与完整制作指引，避免重复研究。

<a id="test-capabilities"></a>
## 缺测试手段时怎么定位

仅对已有材料不能回答的必要未知，按[验证选择](verification-scope.md#relevance)核当前宿主真实工具、原项目入口及可安全接回的环境；复用不适用才取最小必要隔离，不将缺工具默认转成新项目。必要能力确缺时当轮主动提出[具体安装或接入建议](ai-tooling.md#installation)，不只报缺工具；抓帧、录屏与时序定位按[采集与连续动效分析](capture-motion.md#scope)选实际查法。按下面的缺口分别处理：

| 缺口 | 最小检查与可行路径 | 本次可证明什么 |
| --- | --- | --- |
| 目标绑定 | 核对项目/进程/窗口/场景身份、前台与暂停状态；检查工具是否支持这个项目根 | 找对被测对象；不能据工具存在称已操作 |
| 采集或刷新 | 用一个确实会变化的小动作，同时观察运行状态与渲染/窗口输出；先维持原运行条件 | 定位输入、更新、渲染、呈现或采集的嫌疑链，尚不能仅凭一项推断根因 |
| 采样不足 | 按实际动作时长选连续覆盖或有时间戳的密采，保留原素材；必要时缩小区域 | 可检查中间态与先后；静止段允许重复，压缩噪声/鼠标变化不等于目标在运动 |
| 输入未验证 | 使用真实设备/系统输入及独立结果；程序化事件另记 | 各自输入路径是否生效，不能把调用回执当交互结果 |
| 无连续观察能力 | 用亲看原尺寸帧与实际时标先分析可见缺陷/已覆盖时序；有可用连续观察者则交具体原片段，宿主输入确缺时主动给接入建议 | 帧序列不冒正常速度观感/听感；另一个同能力Agent或仅装播放器不补模型感知 |
| 来源或工具均不可用 | 查获准替代并主动给具体安装/接入方案，列实际失败、必要能力、准确来源和验证动作；不以自定预算免查 | 保该项未完成与续办条件，继续其它工作；既有授权覆盖时直接处理，不默认要求用户逐项手工补证 |

例如一次短 UI 探针可以覆盖稳定基线、进入、返回及停止，持续约3–5秒；时长和采样密度应依目标
选择，不把这组数值定成所有项目标准。真实输入时间、实际运行状态和画面时间需能对应，记录
采样开销。已有工具无同步观察入口时，明确这个具体能力缺口，不能宣称命令已经完成归因。
强制重绘、变更 timeScale、手动推进 Tween 或增加后台运行可以用于单变量诊断，但要与原条件
分开保存，不能拿修饰后的运行条件掩盖实际输入或帧节奏问题。

## 陪审怎样把观察变成有用意见

对已提供的方案提出“触发/时刻 → 具体画面或状态 → 对用户目标的影响 → 修正要求 → 复验信号”。
例如用户要求清楚的选择反馈：指出悬停与确认在实际哪个状态难以区分，要求下一版观察两者在
连续操作时仍能辨认；不凭空指定某个毫秒数或统一特效，也不把个人偏好冒充原作规范。

体验任务按实际目标检查注意力、反馈差异、可读中间态、输入可用时机、打断/返回和常驻影响；
纯静态任务不强求视频，只有数值逻辑任务也不凭空加美术验收。可见缺陷应具体指出，证据缺口
给出补证步骤；“更高级”“再惊艳一点”“自行补视频”不是足够的制作反馈。

## 什么时候结束本轮

按[继续／改法依据](must-read-work-priority.md#continue-or-change)结束已足证命题、停止无信息原法或接回真实障碍；按[原目标覆盖](review-standard.md#goal-coverage)分别保局部通过、缺证、原失败与独立关闭权。不能把停一种方法写成必要目标已完成。

## 使用项目已有能力（按需接入）

- 质量失败与缺证：沿[原目标覆盖](review-standard.md#goal-coverage)及项目已有质量流程。
- 真实媒体采集、连续观察、独立输入与结果检查：核对当前宿主的实际观察能力，按当前权限复用。
- UI 动效制作：沿当前任务实际安装的制作工具与案例/观察说明，不把某项目副本当唯一版本。

不重复建设采集或质量系统。工具源码存在、示例成功及结构校验都不证明当前成品通过。
