# 执行错误的工作流整改

出现执行错误、漏做／错做或复盘时读本节；正常审查不预先展开全部整改细节，已经触发的整改不能因分段而免除。

<a id="workflow-correction"></a>
## 执行错误以工作流承担主要整改责任

**纠正与反面教材须记录并直显。** 工作AI与陪审遇到任何真实纠正、错误结论／思路／承诺／实现或反面教材，当轮在原任务／角色记录保原话或行为、对象／版本及来源、反证原因和影响、实际处置／核回及必要未闭，不覆盖首次错误。作者/F/A只保纠正事实并真实接回；对话AI在下一条实质用户正文从correction事件呈现原错/为何纠正/当前处置，标签由脚本给；仅文件、链接、工具输出或“已更正”不算展示。漏报须标“事后补登”补齐，不倒写首次正确；已完整展示的同一事实可引用原定位，有新纠正或处置变化再直显，不逐消息重播。真实新增规格／偏好不自动冒旧错，假设反面教材标明假设；无新事项不凑错误或空栏。落盘与用户可见分别核，不以记录齐、标签或通过替代责任源整改和实际核回。

先定位导致错误结果的实际失效：读取／刷新、制作承接、判断／批准、派发、采用、核验或退出；分清后到规格、旧义务漏查、原依据失效和偏好变化。证据指向规则缺失、入口未触发、验收对象缩窄或错误批准时，再修相应模板、条款、派发或审查消费；项目出错本身不证明Skill是根因。既有规则存在也不证明引导已生效，须核它是否实际影响了动作和裁定。陪审复核自己的认可或漏拦截，保当时行为及依据。用户明确仅追责Skill时，以工作端／陪审的当时行为和依据调查其引导、约束与审查消费，修正已证问题，不另立个人／模型责任主体；其它任务按实际失效处理，不倒写历史。

纠错意见按[推进指引](candidate-collision.md#advancement-guidance)交给原工作端：已证原因给可执行的首个修正，原因未明给能区分它的下一查证；指出受影响决定及核回信号，不能只要求认错、重读或“继续优化”。工作端据此在原承担处修正并接回结果，由原职责按原反例、合法正常对照和下一消费者核回。规则已改、实际动作已做和完整品质已达分别取证；仅相关缺证限制对应决定，其它授权工作继续。
