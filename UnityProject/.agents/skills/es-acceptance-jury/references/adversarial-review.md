# 内置 adversarial-review

用反例检验已有方案或完成声明。不创建Agent或扩大权限；作者自查不冒独立裁定，制作与修复仍由工作AI承担。

1. **明确待推翻命题。** 写清“哪个实际对象，在什么合法输入/条件下，必须产生什么结果”，指出当前结论依赖的关键前提及其源码、绑定或观察位置。方案查所需类型、接口和资源是否真实可供；复杂因果未清时沿[first-principles](first-principles.md)查责任源。
2. **构造可达反例。** 找会使关键前提不成立的合法输入或事件顺序，按当前合同算出应有结果，并保留其他必要前提相同的正常对照。例：确有取消/复用和迟到回调时，查“A取消→B建立→A迟到”是否在身份校验前写入或清理B；不存在该机制就换查法。
3. **查证反例结果。** 沿真实入口追到决定结果的判断、写入及消费者，比较实际状态和反馈与预期；返回true或作者日志不代独立结果。先读可用源码、资产、文本或原尺寸截图，静态因果链可确证错误，截图可确证本图可见问题；仅对剩余具体未知执行对应验证。测试替身的身份、时钟和事件顺序须核真实生产者，不向生产对象注入故障。
4. **复验修正及损失。** 用原反例和正常对照检查修正，比较改前/后同输入的实际结果及相关副作用。优化查同负载下成本是否被搬到初始化、加载或保存；修复查是否靠删必要内容/反馈或永久拒绝避开错误。只处理影响原要求的损失，不为个人偏好扩大必修。

发现直接给对象/位置、合法触发、决定性证据、目标影响与复验信号；未查或工具失败注明具体未知，不冒产品故障，也不把已证失败改成缺测。通过须有原命题的实际正常依据及覆盖条件，未查或证据不足不签通过。旧依据仍适用时复用，新反证或相关变化才重开受影响命题。

Unity性能按当前项目预算与实际负载判断，序列化边界沿[运行合同](must-read-continuity.md#runtime-evidence-boundary)；本次提交画面的观察范围按[视觉验收](review-standard.md#visual-review)。结论进入现有记录，实质独立意见沿[保存与转达](coordination.md#opinion-records)处理。
