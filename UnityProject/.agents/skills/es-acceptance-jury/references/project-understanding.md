# Unity项目理解、推荐与风险边界

<a id="project-fit"></a>
## 任务前项目理解与生态P0约束

实质制作、审查或推荐前，先读当前任务原话和项目AGENTS，沿实际源码／资产／装配核本项目目标、宿主、成熟度与已有价值、制作／使用者及成功结果，定位生产／作者入口、状态／数据／资源权威与来源版本、职责／读写／生命周期，以及直接和受影响的旧消费者。按实际惯例及适用普查危险点核关系，不凭目录、文件名、作者摘要或“已理解”自报放行；同工程的可逆试验和成熟共享底座分别界定，但都须保真实合同。

项目内容还须按[元素模型与三问](recognition.md#unit-state)解释所处世界、意图、表现、行为后继与组合预算，沿原活记录共享可复读修订／观察和未闭；工程接线正确不代世界含义成立。

**四类生态禁项按P0核。** 当前用户明确禁止以下真实生态缺陷，不能按实现／分层偏好、局部能跑、原型或可回滚降级，也不另等毁档或主功能失败：

- **胶水代码**：用拼接／转接壳、默认值／吞错、反射或重复状态等绕过实际职责、真实供给或既有合同，把尚未成立的关系硬拼成能跑片段。
- **多入口影响**：新旧入口／写入路径分叉，绕过统一权威、规则或生命周期，或本次入口变化的旧消费者影响未核。
- **来源杂乱**：生产／作者源及版本、导入与当前消费权威不明或冲突，复制成第二权威而没有真实归属与承接。
- **硬接线**：把具体策略、实例、路径或标识绑进无职责依据的层，旁路项目现有装配、配置或扩展合同。

沿真实owner／生产赋值→入口／绑定→读写消费者→退出／恢复核证；已证违约直接产品P0，关键关系必要漏查按审查P0，不伪造已证故障。真实类型调用、原装配处绑定、多输入同权威或明确格式边界的适配，须以当前职责合同和实际消费链证明；不按关键词一刀切，也不靠“adapter／强类型／合法适配／作者认可”标签免责。必要生态检查由对应职责亲查、据证关闭；A漏查不能由F功能通过、作者自评或绿色测试代关。

项目架构／系统／生态审查按[全项目基线与追踪](p0-architecture.md#project-tracking)实际覆盖生产模块、装配及依赖，不限当前diff。初期路线判断核会改变选路／品质可达或当前安全的必要关系；普通制作／采用前核清该动作全部实际依赖，整体项目通过前完成全基线，不能把后续详审统一前移或借阶段化遗忘覆盖。局部制作／查询取真范围，不自动授修复或运行权。

区分事实、用户明确取舍、AI设计假设和必要未知；有效规范、实际承诺或真实消费者依赖的约定才是合同。偶然稳定实现/旧bug不作正确规范，但旧档/外部caller的兼容与迁移责任仍保。有据默认设计直接推进；影响方向、持久语义或风险的未知先查原源；按实际缺口加深项目与依赖理解，必要时联网查权威资料，并按[真实索取](ai-tooling.md#supply-request)提出精确问题，不以AI自定的小预算缩减必要调查。恢复先复用仍有效理解；目标／人群、权限、供给／接口、阶段或普查改变前提时，只更新受影响依据和下一动作，保来源／修订定位，不另建画像表、数据库或逐项审批。明确不可改／无权改的核心不排入制作，先在已授权扩展口、外围适配、配置／内容或成熟替代中选路；不能暗改、复制成第二权威或旁路其必要合同。技术不可用与权限禁止分别处理，未知先定向核责任和合同；无可行路径时只保具体依赖受阻，独立工作继续。

**据项目理解限定下一动作。** 先从项目治理入口定位并实际读[活维护工作区](project-workspace.md#workspace)，在同一记录与既有任务依据中给出本段下一必要结果、实际承担／改动位置与选路依据、必须保留和不可改部分及其来源、拟执行动作与受影响消费者；工作端给原件依据，F独立核业务入口／提交／反馈／保存后继及旧行为，A独立追真实权威／来源／绑定和受影响未改模块，不由作者填卡或另一职责代核。必要关系未查、原件与自报冲突或做／不做边界无据，按[P0审查阻断](p0-review.md#review-contract)限制依赖它的方案定案、普通开工／修改、采用、扩散、交付及完成，不能只留给推荐／通过阶段或先制作后补背景；目录／AGENTS已读、字段齐、测试绿及prepare.ready均不认证理解。查源、必要提问、权限内止损、受控判别和真正无依赖的已就绪工作继续，不等完整画像才报已有据P0；阶段／交付取舍读[行动边界](#stage-fit)，语义／依赖变化或普查命中读[必要性与证据链](#necessity-before-dependency)。

<a id="intent-default-progress"></a>
## 明确结果，然后制作

会影响实现方向的歧义，先从用户原话与项目约定说明要解决的问题、交付物、改动对象、必须保留的行为/数据和可观察成功信号；分清新增/替换/删除/纠错。玩家任务才描述玩家过程，工具、架构、资源和性能各核对应结果。有据设计默认直接推进，事实未知有限查证；只有无法据现有信息决定且会改变用户目标的设计歧义才请用户决定；必要原件／素材／事实另按[真实索取](ai-tooling.md#supply-request)提出，不把问材料误作要求用户提供内部设计或重批已定方案。

实质制作须满足[开工依据](task-plan.md#start-readiness)：两位真实陪审核准同版思路及全部适用前置，再由工作端承接；“默认推进”或“小修”不自行豁免。命中复杂[方案评估](task-plan.md#plan-evaluation)时展开该阶段，已有有效认可可按原条件复用。游戏选批沿[基础循环优先](must-read-work-priority.md#foundation-first)，不让用户逐文件批准。

确需方案文件时UTF8保存读回，按现有展示约定打开后继续已授权工作，不等普通ACK、用户阅读或关闭；小修沿既有记录，用户明确等待则遵守。方案委托只交方案，不自动改工程/运行Player/恢复旧制作；选定方案不等产品通过。

<a id="stage-fit"></a>
## 从项目事实决定投入与风险边界

1. 对有效交付需求确定本批用户是谁、要验证/使用什么、哪些既有结果必须保。探索、体验演示、完整产品和长期维护可以同项目共存，不用阶段标签降低目标或自动追加全系统义务。
2. 新系统或系统改造先核必要性，比较复用、扩展、修源/迁移与新建；沿实际影响链评估功能体验、职责依赖、目标环境、数据/旧消费者、寿命与失败恢复、运行及维护代价。未知明确假设，以授权内可逆小样查证，不凭低置信猜造事实/身份/共享合同，不强造无关配套。
3. 体验方向待探索或用户明确只要有限演示时，优先完整可见表现、自然流畅交互、核心路径与决定性假设；未要求且不影响本次必要结果/受影响既有合同的通用化、完整扩展面和远期系统配套可以后置。在既有记录保限制/代价、接回责任、重新触发条件及解除信号，不只写“以后再补”。不得用假状态/截图冒真实消费，不能放开已取得资源/玩家数据、生命周期、已要求保存/P0或必要品质。
4. 激进开发期可在当前授权与有效合同内改旧系统/核心，成熟期也不禁止有据且已授权的修源；明确禁改／无权改不能以“发现错误”自行撤销。涉及含义、标识、状态、持久或共享合同，先核需求、扩展惯例、旧数据/caller及迁移责任；普查发现的旧隐含关系同样适用。阶段标签不授越权/旁路，维护需要也不冻结错误实现；真实用户修订按来源与范围接回。
5. 建议说明动作依据、已知可做项、待查关系/最小验证与失败信号、后置代价/接回、须保数据行为及停止/改序条件；不强填类型表或预算比例。

优先投入改变工作/观察重点，不改宿主Token/费用、授权或问题严重度。用户明确要Demo可按有限结果验收，作者不能自行以Demo缩掉已要求的完整可玩、视觉、保存或预算；后到真实用户修订按新范围接回，旧否决保历史。交付目的或实际消费者升级为完整可玩/生产维护时，重新核后置配套及同候选必要入口→选择/动作→规则后果→反馈→后继/退出，不继承早期演示通过为整体完成，也不每批重跑全游戏。

### 按实际委托匹配证据

| 委托结果 | 本次检查 | 不能据此声称 |
| --- | --- | --- |
| 设计/架构分析 | 需求关系、状态归属、依赖、输入输出约定及具体接入位置 | 实现已采用、运行或体验达标 |
| 源码/静态合同修改 | 实际语句/引用、供给和直接调用方、必要绑定；按要求编译 | 未观察的Player行为或性能 |
| 资源/Editor工具 | 指定产物、导入/保存、使用入口及需要的消费结果 | 未委托或未验的整局玩法 |
| 功能/原型 | 委托的机制、入口与结果；需要交互/画面时实际观察 | 未覆盖的完整游戏或商业发行 |
| 性能/兼容 | 指定平台、配置、负载及预算下的有效观察或测量 | 未测平台、负载或长期表现 |

完整静态因果可确证错误，不以Player为全部筛查前置；源码关闭不代必要动态/体验/保存后继。维护重构按所改对象验收，不一律追加玩家入口；已委托完整可玩也不能缩成静态小修。

<a id="existing-path"></a>
## 现有Unity生态与成果

查框架/API、Unity版本/平台、Packages、Scene/Prefab、资源与业务owner的实际接法；缺专名不证明无通用能力。功能目标不授权绕过必需入口、职责、状态提交与寿命合同。按已核[可改边界](#project-fit)、当前目标和影响在授权内修源、扩展或替换，保旧数据/caller及迁移恢复；不为单功能擅改公共核心、藏helper或另写状态旁路。已确认关键合同违约沿[真实P0准入](review-standard.md#decision-order)裁定，不按核心文件名禁改；保素材/引用，不搬旧场景、固化旧bug或盲删数据。

<a id="capability-fit"></a>
## 制作选型与能力调查采用

制作选型、实质反馈，或出现工具/API/Shader缺口、重复手工、通用能力硬重写时，工作AI与相关陪审先核项目实际包、版本、样例、约定和已有组合；从完整目标查成熟工具／模板／库能否改善本次效果、控制、效率或复用，不以代码能做自证充分，再围绕实际作用查权威来源及符合Unity惯例的接法。优先官方/维护方文档、源码与对应版本样例，结合实际维护状况和项目接法判断；热门和权威是优先线索，不能替代适用性，也不把固定品牌当白名单。

明确要替代哪段工作，在决策依赖范围核Unity与API/后端、渲染管线、依赖和许可、数据/线程/生命周期及接入成本；既有设计是起点，有据兼容扩展可直接做，不能把“尊重设计”变成禁止新能力。System.Text.Json、HybridCLR、DOTween和Shader等[已读来源](../knowledge/sources/unity-production-capabilities.md#capabilities)可供找切入，按实际需求调查其它成熟方案同样有效；不能用.NET端示例证明Unity/IL2CPP已适用。

选择能满足需求且总成本合适的复用、适配或最小自研，说明决定性依据而非强制多方案打分。已有授权与项目依赖约定覆盖时，工作AI直接完成必要依赖配置、强类型接点、生产者/消费者接线和相称验证；不止停在建议/链接，不为新增依赖一律另请批准。确有不匹配则保具体原因并改路，不要求先证明全网都不可用才自研。

用当前代表输入/对象验证所需行为、失败/释放及受影响正常路径，按委托补当前目标环境证据；不安装本任务之外的库，不让一个样例代全部兼容。沿现有记录接回“缺口→采用依据/实际入口→结果/未证范围”，不新增选型报告门禁。

<a id="necessity-before-dependency"></a>
## 从修改和普查触发必要性与语义证据链

新系统/改造先读[行动边界](#stage-fit)及[系统合同](#existing-path)，分清功能、AI方案与用户授权；仅真实共用缺陷/必要结果展开配套，自产依赖非必修。集中修源不逐文件审批；用户有效修订可改项目约定，AI不能自行撤禁令或扩权。

命中依据是当前变化与适用普查中的实际关系：对象/动作含义、可表达状态/类别、身份/归属/资源来源、生命周期，或持久/外部/共享消费者期待是否改变。没有新增类型但默认值、映射、绑定、配置语义变化也命中；新增名字/关键字仅是线索，不设具体内容案例白名单或全库类型门禁。

沿有效任务/领域→原权威定义及生产/作者入口→真实读取/使用/保存和后继消费者→新合法状态及旧数据/旧caller→实际配套/失败恢复核证。选能推翻推荐的敏感反例与合法正常对照，不拿编译、资源存在、字段同名或计划绿代语义。没有原caller的新必要能力可由有效任务、真实领域约定与可实施接点支持，不能因尚未实现就一律拒新；没有依据却有跨合同后果时，先查具名缺口或复用现路径，不编内容只为编过。

有据必要扩展按当前授权实施，未定设计在授权试验域明确假设并验证，不能偷写成成熟生产事实。静态完整链可直接裁定，动态按具体未知补；推荐、风险、合法行为与解除依据进既有任务记录，不另造画像平台、固定迁移系统或逐类型批准。

<a id="strategy-recheck"></a>
## 允许推翻旧判断

后到真实目标/事实或普查发现改变画像时，核受影响推荐前提及本次未改的字段/caller；陪审提过的路线无豁免。有效反证可纠正旧通过并保原事实/撤回理由，不固守错误，也不每批全工程重验。项目理解、材料可读、实施采用和实际体验分别报告，仍适用旧事实不说本版重测。
