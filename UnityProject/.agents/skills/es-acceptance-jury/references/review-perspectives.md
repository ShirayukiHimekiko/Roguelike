# 评审对象、视角与覆盖分工

## 先带问题线索自主搜索，再精确匹配方法

评审对象说明本轮交付是什么：方案检查依据、方向与可实施性；成品检查实际结果；
过程复盘检查事实、决策顺序与因果解释。可同时涉及多种对象，但分别标明结论范围。
过程报告成立不代表被复盘产品通过，方案通过不代表成品已达标。

AI先指出本次要查的具体错误并立即搜索：`实际对象及触发/状态 → 怀疑违反的要求 → 首个可定位的搜索入口 → 确认或排除的结果`。入口用真实成员、资源/绑定、文本段落或图中位置。入口不明时，从现有材料定位该结果的写者、绑定或承载位置，再搜索同机制实现和相关问题案例；遇阻断、高风险或高要求须执行[知识检索](reading-guide.md#knowledge-use)，必要时按具体缺口查外部资料。

例：查旧回调写回，搜索该对象的回调写入及取消/复用入口，核旧身份校验是否早于写入/清理；查标题裁切，搜索该标题的父遮罩与布局绑定，查看原尺寸截图中必要字形是否被截断。两例只说明查法，按本批实际对象选问题。

自主搜索发现有依据的问题，立即指出对象、位置/时刻、目标影响及因果，必要精查和止损不等匹配完成。自主搜索未发现问题时，对本次适用但仍未证实的结果或必要关系，按[机制与前提的精确匹配](review-methods.md#method-match)进入方法中的具体查法并执行；不是按视角标签选一个方法名。搜索未命中、方法不适用和核查未发现分别说明依据，不能都写成“没有问题”；未命中仍须继续匹配，必要结果仍须有据裁定。规则方法不机械全跑；架构/系统/生态对目标项目的全局覆盖必须沿[全项目基线与追踪](p0-architecture.md#project-tracking)完成，不能用规则库按需读取免除。

缺运行、连续播放或部分材料时，先按[可用证据的分析边界](review-methods.md#available-evidence)实查当前源码、资产、文本和截图，再补无法回答的具体问题；不能只写缺证而跳过已有材料。静态可追机制，截图可查本图可见关系，两者可以形成确定发现或有依据的风险线索；推断、已证事实及仍未知部分分别说明。

下面的视角只供自主搜索后的方法导航；实际匹配以具体问题命题、生产机制及方法成立前提为准，可以组合、补充，也可以有据排除：

| 视角 | 要回答的问题 | 方法入口 |
| --- | --- | --- |
| 工程正确性 | 状态、生命周期、依赖和失败恢复是否支持目标；测试前提是否真实 | [独立代码判断](review-standard.md#code-review)，按实际风险接[敏感机制](review-methods.md)及项目原有测试 |
| 参照还原 | 参照适用吗；对象身份、资源含义、绑定与输出一致吗 | [参照与身份](reference-fidelity.md) |
| 体验表现 | 信息、操作、节奏和视听是否兑现体验目标 | [视听观察](audiovisual-regression.md#audiovisual)、[连续动效](constraints/04-visual.md#continuous-motion)、[UI完整性](constraints/03-ui.md#03-11) |
| 3D运动表现与空间合理性 | 完整阶段、姿态旋转、意图与各方向、位移/接触和控制恢复是否一致 | [3D动作专项](constraints/13-motion-3d.md#scope)，仅实际包含该对象时消费 |
| 内容设计 | 内容逻辑、角色动机、选择后果及表达是否成立 | [内容审查](review-standard.md#content-review)及使用项目的内容方法 |

这些是可重叠的检查视角，不是固定枚举、五选一、五个Agent或全部必跑清单。
仅增加视角不会提高权限或产生额外必填字段；没有声音、剧情或原作还原目标时，不要求新增。

## 独立提问，再核对覆盖

工作AI按有效用户目标、当前阶段和实际下一消费者整理必要结果、架构约束及品质参照；双职责审查时，两位陪审各按主责从同版原始材料反推必要结果，独立提出并执行[具体查找任务](#exploration-first)，形成初判后再对照作者与同伴材料，不从作者已做清单反推验收范围。
独立性来自问题依据，不靠隐藏资料：已知严重缺陷、安全事实、历史否决立即共享；
不能要求陪审先忘记它们，也不能仅让陪审复查作者已经列出的缺陷。

视觉参考、跨宿主制作或视觉改善命中时，按[独立观察](constraints/04-visual.md#independent-observation)由陪审选择
最可能推翻完成声明的原产物位置/状态，实际观察与作者解释分别核对；来源相同的两方同意不算独立佐证。

在现有目标记录中对应：
`目标来源/阶段 → 消费者要完成的任务 → 必要对象/状态/关系及品质依据 → 实查位置与观察/版本 → 结论/未闭及下一步`。
证据指向可复读的真实位置：源码路径与成员、资产与装配/引用处、文稿段落，或原图/录像的画面区域与时刻；说明预期、实际观察及支持范围。不存在的对象按[缺失查证](recognition.md#absence)核应出现处、生成/装配与等价供给；待查位置、空字段、工具已准备或“已读”不冒实际证据。不强制新表、固定平台或每项hash。
先覆盖影响身份、整体结果和核心体验的条件，再按风险展开细节；原有工程测试仍保留。
截图、测试或缺陷条数不能代替对象与目标覆盖；代表样本用于早期找共同原因，
不能自动推广为未查对象的最终通过。没有固定样本数或要求每轮全量重看。

双职责各自形成初判后，先各自从有效原目标重建必要消费者任务及剩余结果，再对照作者／同伴的机制表和已报缺陷，专查**哪些必要任务两人都没有取证**，并质疑共同成功解释：原证据证明了消费者结果，还是仅代理指标／局部能力／技术步骤？同一解释两票不增加正向品质依据；把未查结果或错误前提接回具体查证及受影响许可，不强制新问题数量。实际成果、制作／接手链及必要品质不能被一个技术余项遮住；声称“整体仅差X”前，逐项核除X外其它必要消费者结果已兑现。空白具名接回责任、下一动作及解除信号；两票、局部全绿或已报问题全关不补表外覆盖，避免重复检查挤占遗漏项。
高风险点可刻意交叉验证，不以“去重”为由取消独立确认。使用已有通过/返工/缺证/未运行
状态：违反已成立目标的已知失败回到责任源修复；观察不全先分析可用材料，仅对剩余具体未知补证；工具前提有误则先修前提。
合法变体不因偏离个人期待判失败。按[职责与审查权](source-authority.md#delegated-direction)，作者负责方案和生产，两陪审分别从完整原需核各自决定证据／共同盲区；对话AI持完整目标和未接责任，不让两局部票合成未证整体。AI扩展仍按三方价值／充分度／审美采用，不因审查者推荐自动必做。作者落实批次，陪审以事实反证核采用并查本人建议的真实损失，
不接管制作；按[批次与定向复验](task-plan.md#repair-batches)消费。
