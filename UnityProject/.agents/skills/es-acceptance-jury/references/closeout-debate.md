# 超大任务收尾辩论

<a id="workflow"></a>
## 收尾辩论

### 触发与目标范围

用户明确要求“收尾／辩论”时组织；否则在实际影响路线／采用／交付的关键争点、共同成功前提未证或两职责给出冲突许可时进行实质质证。普通制作／视觉提交仍须实际验收与完整目标核回，但不再仅因要结束就另开固定阵营问答；同版已实查且无未决关键争点时直接在[一次结果交接](review-completion.md#completion-coverage)给本人裁定。已知必要失败不因少开辩论消失。

范围取当前完整有效用户委托及真实修订，不由作者现有产物或可测scope缩减。视觉／交互／品质必须看当前真实对象及必要过程，方案不冒成品，技术检查不代实际消费者。缺能力的关键结果须补供给或保持未完，不能用两票或诚实边界把委托的核心结果永久移到任务外。

### 围绕真实相反假设，不固定F正A反

F主查消费者结果，A主查决定性共同前提／代价；任何一方、作者或对话AI都可提出可核反证。先说要改变哪项许可／路线、实际原件支持什么、哪个合法观察能区分解释；观点相同可以有据维持，共享原件正常，不强制两套资料或互相反对。审查者自己提出的方案也须受另一职责及作者质证，自己赞成不证价值。

被质疑者据同一对象／版本／条件实答，承认、补必要证据或给可定位反证，并说明原许可维持／受限／撤回；决定性反证成立就改变作者实际下一动作和消费者核回，不能只修报告/打标签。谁提出不影响事实效力；原发现职责核修正，也必须重核自己被反证的票，合法同责后继沿原机制接，不新增第三裁决。

一次实际可区分的查证足以决定就落实结果，无新依据不追问。未分清的必要争点具名接责任源／下一动作，限制实际依赖而非全局停机。事实质证／作者修正／当前裁定合在同一原记录保存，不默认F-A-F-A轮数、长对称稿或全历史复述；原分事件／必要未闭／两项依据保真实来源。

### 质量不足时找资源与替代方案

有据发现现有产物、素材、工具或路线无法支撑有效品质要求时，A须指出具体差距，并提出能改变结果的搜源、补参考、换工具或替代制作方案，说明要补什么、为什么可能改善及怎样验收；不能只批“质量差”或泛泛要求“上网找找”。可直接质询：“这份质量不足以收尾。继续在当前材料上打补丁的依据在哪里？本机现成资源、网络成熟方案和其它制作方法核过哪些？给出可用候选及效果对照。”未查来源只作待核线索，不预言一定有合格替代。

资源与参考沿[分层探查](resource-discovery.md#search-order)查当前项目、本机已知相关项目／共享库及匹配网络来源，工具与实现沿[能力调查与采用](project-understanding.md#capability-fit)查已有Skill、成熟工具、教程和替代路线；按当前缺口选择，复用有效查证，不强制每次全查或联网。工作AI在已有授权内实际查找和验证，F逐项回应A：查了什么、为何采用／拒绝、还缺什么、下一动作；A亲看决定性材料和当前目标的消费结果，找到链接、文件或候选不代质量达标，工作AI／其他角色不得据此代关；原职责或合法同职责后继核证实际消费结果达标后，依现行合同决定关闭原否决。确需用户供给时沿[真实索取](ai-tooling.md#supply-request)发出问题并接回，偏好取舍或新增操作授权分别核；能自行查证的先做，其余授权工作继续。路线确需改变时接下方重新定案，不把找资源变成降标收尾。

### 原始输入与工作AI经历回溯

沿[独立输入](coordination.md#independent-input)给两方同版有效原话、实际产物、原始证据和已知必要失败；双方有据初判形成后再对照作者解释与同伴观点，已读仍适用可接续，不每波重做盲审。工作AI主动交原始事实，已知严重缺陷即时共享，不能为盲性隐藏。

任一陪审可要求工作AI恢复与收尾有关的真实经历：收到过什么要求、做过何种尝试、失败或改序、哪些承诺没有兑现、实际写入和验证发生在哪一版。工作AI提供可核事件摘要和原话、文件差异、产物、工具输出定位，区分本人亲历、交接资料和当前推定。回忆是查证线索，须核原件；口述与记录冲突就追查，不回填历史或编造“当时其实想过”。缺原件保具体未知，只约束依赖它的结论。原工作端不可达时据真实交接恢复，不冒本人亲历或跨窗连历史身份，不索取隐藏推理、全聊天重读或另建记忆平台。

### 实际交流与后继行动

实际主张的提出者给完整对象／范围及正面依据，另一职责独立核最危险失败或共同盲区；任何人可提出反例，被质疑者据原件实答，作者落实责任源修正，受影响职责对新实物核回。沿[真实反证交流](candidate-collision.md#collision-loop)实际发送和触发已空闲角色，在线、ACK或排队不代实质回应。这里不是固定F-A-F-A后宣布终判的脚本。

辩论按[继续／改法依据](must-read-work-priority.md#continue-or-change)处理当前必要争点：有区分力证据就核、前提被推翻就改法，足证即收束，无新依据不机械追问。必要未答或确缺供给保具体障碍与接回条件；双方对一个反例一致只改对应判断，未修问题／整体缺口不因辩论结束而关闭，不设固定轮数或以“无上限”拖延真实结果。

整体裁定、交付及结束前，按[完整目标与一次交接](review-completion.md#completion-coverage)由对话AI整合原需，F/A各以本人已分工的决定性实查支持当前裁定，必要消费者结果和未接责任均须有去向；必要品质差距和必要漏查保超级P0阻断，再沿[独立覆盖核对](review-perspectives.md#coverage-reconciliation)查双方共同遗漏；局部通过不关闭其它必要后果，检查／哈希不能代整体兑现。原失败、修订、取舍和未闭保原来源，最终用户可见结论自足。

### 本质偏离时追查并重新定案

本质不合有效原需时，立即撤回受影响的完成主张，按[因果阻断与依赖修补](causal-diagnosis.md#causal-blocking)追最早决定性责任源，区分误读需求、错误前提、供给缺失、路线不适配或局部实现错。工作AI必须实际开展能改变决定的查证；不能只尾注“未满足”后停止整个已授权任务。

若原路线已不能兑现必要结果，把已证差距、真实供给和验证信号接回[重新定案](task-plan.md#plan-evaluation)，取得原双职责对同版受影响方案的明确通过、展示并实际承接，再继续授权制作和消费者复验。局部修补即可且路线仍成立时定向修源，不把每次不满变成全方案重做。真实后到用户修订可改变目标，保来源和原因，不能冒旧缺陷修好。合法诊断、修源、受控复验及真正不依赖坏前提的工作继续；不借收尾辩论新增付费、发布、删除或其它外部权限。

### 收尾事实与用户事件

后台按实际收尾动作/质询/答辩/修正/裁定交事实，不编排用户阶段标题。对话AI核这些原件和当前动作，按[呈现入口](message-style.md#user-facing)请求closeout系列事件；实际动作才支持阶段，不因event字段形成批准。原角色/整数/主事件及必要意见保持，未发生动作不列空栏，普通进度不造收尾。

### 收尾结论与继续条件

两方各自明确给对象、版本、需求范围、证据和未闭；工作AI忠实汇总，不按胜负、平均分或多数作第三裁定。

| 有据状态 | 可用结论标识及实际动作 |
| --- | --- |
| 当前有效委托全部必要结果有据，必要失败／缺查及独立否决已由原职责核回 | accepted：允许当前范围收尾保两方同版结论、交付与使用边界 |
| 真实委托或有据认可的阶段已达标，但更大父目标仍有必要余项 | stage-delivery：阶段交付/父任务未完指明剩余结果、负责端和下一动作；当前原授权内可推进的必要工作继续，不以自称阶段终止整体任务 |
| 原路线仍成立，但有必要失败、未回应问题或缺证 | repair-needed：暂缓/修复补证落实责任源、动作与解除信号，修后原角色核证 |
| 有效原目标被本质误读，或现路线无法兑现必要结果 | closeout-reject：拒绝/追查重定案按上一节查证、重新定案、实际继续及复验，不把判失败当任务已完成 |
| 真实外部障碍或当前所需独立核验无法取得 | evidence-blocked：缺必要核证/保障碍给来源、受限动作与恢复条件；无关授权工作继续，不改名通过 |
| 用户真实补充或改变委托，未指示暂停／撤销 | user-revision：用户修订/重核范围更新有效目标、受影响依据及本轮收尾范围，按仍有效授权继续；不自动暂停、不新增继续确认，不把范围修订冒作旧缺陷修复 |
| 用户明确暂停或撤销 | user-paused：用户暂停/撤销优先安全接回真实指令、现场与未闭；无需等辩论同意，不回写为完成 |

真实角色接续沿[身份](coordination.md#activation)执行。无所需独立核证不得冒双通过，既有否决不消；本机制不增加常驻角色、后台唤醒或宿主自动识别服务。阶段交付、停止一种方法、用户停止和整体完成分别记因，不扩纯方案或局部委托的验收范围。
