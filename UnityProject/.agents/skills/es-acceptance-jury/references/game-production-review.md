# 游戏制作审查｜候选入口

<a id="scope"></a>
## 共同适用边界

仅在游戏方案、真实玩法、业务接线、准备/保存/退出、性能整改或相应修复/完成声明实质变化时读。先按[项目理解](project-understanding.md)核阶段、交付与现成能力，再按[8+2工作区](game-workspaces.md#approach)分别判断工程生产和游戏结果，给具体方案；纯工程交付可按真实产物、合同和消费者完成，涉及游戏使用或品质声明时按[真实玩法](real-play.md)核当前局面与整体体验，技术接通不代品质成立。用户原话、已批准设计、真实配置与生产caller是依据；不另建运行时检查器、世界/库存/时钟或通用业务框架。按实际对象追影响链，不把方法目录变全量必跑表，架构/系统/生态普查仍保全项目覆盖。

本页定义游戏制作检查的适用范围；具体检查按命中的现行专项正文执行。

涉及跨宿主建议或工具移用时，按[01/09执行域分离](constraints/01-architecture.md#execution-context)区分运行时、Editor、工作AI留档与实际工具消费者，不互借权限或预算。

选批先按[核心闭环推进](must-read-work-priority.md#core-loop-progress)核必要结果与真实消费者；状态正常或局部接线成功不证明玩法选择、规则后果和连续体验成立。接回、整体损失和完成声明按[共同裁定](review-standard.md#decision-order)检查。
