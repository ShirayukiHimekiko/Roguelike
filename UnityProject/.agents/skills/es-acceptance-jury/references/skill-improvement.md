## 当前版本与2.2系列历史冻结

当前版本 **2.9.11**。详见[版本履历](../knowledge/history/jury-releases.md)。

**升版规则。** 已完成、通过适用验证且有实质变化的一波Skill维护交付，自动递增末位补丁号（小版本，如2.4.3→2.4.4），不因尚未推送沿用旧号；未交付候选、同波返工、重复验证、回执及重复打包不另计版本。中版本（如2.4.x→2.5.0）只在用户明确要求时递增，AI不得自行升级。

历史冻结、授权原话及旧版本说明保在[维护沿革原件](../knowledge/history/jury-releases.md#maintenance-policy-history)，不作默认执行合同。



## 维护方式

后台事实与用户呈现分工沿[消息合同](coordination.md#message-delivery)，本人两项依据和原评分/事件/必要意见仍保；用户Emoji/阶段标签集中在脚本并仅由前台呈现；不恢复旧固定检查栏、占位与强制计数；实际角色、原总体评分及其来源、原唯一主事件和必要意见/条件继续保真。历史原件保当时真实排版，不倒写。

已授权维护不逐文件重复索权；正式写入前仍须完成[适用方案评估与同版交接](task-plan.md#plan-evaluation)。写入时同步替换受影响链上的冲突、歧义及模糊旧文，并核实际消费者；隔离候选和必要查证可先做，不能用授权或候选替代正式落实。

<a id="text-changes"></a>
后台提供每波真实原文差异，由对话AI向用户展示真实文本变化：标明文件位置及实际新增、删除、替换的原文，用修改前后对照或实际diff呈现；摘要、字数统计、链接和“已修改”不能代替正文。差异取自本波写前版本与落盘读回，未改内容不算本波修改，并行来源另标，历史变化不混入本波。

**每波同时报净增。** 与同一份 diff 一起给一行实际数字：本波 `references/`+`SKILL.md` 的正文字节净增或净减、新增义务条数、删除或合并的旧表述位置。净增为正时说明为什么必须有新增而不能改写既有正文；说不出就说明应当改写而不是追加。这不是配额或字数上限，不因篇幅自动否决有据的必要扩充，也不新增审批；它只让“纯增补”在同一波可被看见——`SKILL.md` 与 `references/` 顶层正文的否定式表述在本次结构重整前为 449 处、约 344KB，缺乏这一行时只能靠事后清点才发现。历史各波不回填。

<a id="format-protection"></a>
### 用户呈现格式保护

没有真实、有效且明确覆盖该格式变更的用户授权，AI无权改写、简化、删除、合并或以“修复/优化”名义修改当前用户规定的呈现格式。一般维护/节约/去冗余授权、作者偏好、陪审认可、统筹转述、hash/工具通过不代该授权；尤其不得擅改角色标识、加粗标题/标签、增益与事件的结构/顺序或合并实际来源。

原样执行有效规则、补正偏离及必要引用同步直接完成，不需用户重复确认。真实明确用户可按新范围变更格式，保旧记录；本条不是永久冻结或所有维护逐文件审批。无覆盖授权的格式“修复”不实施，继续其它已授权独立工作。当前用户已明确修订评分机制，按下节和[数值增益](coordination.md#wave-gain)直接执行，并清理相关冲突；本次用户已取消的检查/追踪正文格式与强制统计按当前消息合同撤销；未取消的角色骨干、原总体评分、主事件及历史原件继续保留，不扩产品权限。

<a id="scoring-protection"></a>
### 用户评分机制保护

按用户当前明确要求，每个新实质波次必须有具体整数评分，禁止待核、未知、未给、留空或延后；确实无法核实必须给负分，不能以0或正分替代。原角色独立评价，原意见缺分当轮记-1且明确为规则记分、非原角色评价；范围、依据、补正和历史边界以[数值增益](coordination.md#wave-gain)为唯一正文。

未经真实用户明确授权覆盖具体改动，AI不得改变数值必填、无法核实给负分、缺分处理、评分来源或适用波次；一般维护、优化、精简、去冗余、作者偏好、陪审认可或测试通过均不构成授权。不能借改提示、展示、脚本或范围绕开它。原样落实、修复违反本机制的实现及必要引用同步直接执行；当前用户已授权的具体修订不重复确认，后到明确用户修订按其范围执行。


只在修改本Skill时读，游戏制作不默认加载。真实用户当前范围内的改写、合并、迁移、错误修复及必要引用同步直接执行；后到明确目标/策略修订优先，不逐文件索权。规则维护授权不自动授Unity产品写入、发布或存档删除权。

保用户暂停/撤销、独立角色与指定模型、完整实质意见及未闭、当前游戏质量标准、真实业务身份/取得归还和合法数据。用户明确变更这些机制时按真实修订处理；普通精简不能偷偷降级。格式与记录不证明语义审查。

改法围绕真实故障：原目的→新承担位置或有据撤销→实际消费者→坏例/合法对照。尤其查入口瘦身后旧下游是否重新要求全读或产生第三层；执行规则、工作方法归references唯一正文；领域知识、行业依据与项目经验归knowledge，保知识依据、适用条件和未证范围，单方建议或本包推导不写成行业共识，不以知识文件另设执行合同。知识正文先给能改变判断的结论、适用/反例和来源，删重复免责声明、规则复述、空泛背景及同义罗列；证据位置、失败与撤回范围保留。检索触发与执行唯一沿[知识检索](reading-guide.md#knowledge-use)，不把必须检索改成泛泛建议。改Unity定位时删除无关默认路由，必要领域方法/锚点保当前路径，已撤旧工具合同由包外原版归档保全，不能用“兼容”让旧默认复活。

写后实际读回，核入口、角色卡、候选调查和测试替身语义；大波做有界独立全包核查，普通小修不复制全系统审查。源码/链接/hash/测试结构分开报告，未实测不宣称模型检出率、玩法质量或节省Token。恢复保原包和原意见，不恢复撤销策略为当前默认。

知识新增/迁移时同步所属分区索引和准确正文锚点；总入口只登记实际独立领域，不随叶条目增长平铺。领域只有一个有效落点时直达正文，多项内容再用短分区索引；分区只保问题线索、正文定位和用途，不复制知识。保旧有效定位与来源范围，不把分区/兄弟条目全部设为默认或必读续边；沿实际reader核旧项可达、单路下钻及无匹配换路，接续与再检索唯一沿[知识检索](reading-guide.md#knowledge-use)，不另建缓存/重播平台。

通用知识新增、保留或淘汰前，固定实际项目任务和行为判据，用目标模型/强度的全新独立原生Agent（fork_turns="none"）核对。首轮按正常开发读取必要原件，不给疑点标签、作者答案或同伴结论；包括“项目最近多处现象”、用户刚提出/部分认可方案或局部正常反例引出的错误路线，同时保合法取舍。直接提示疑点或关键诊断线索后会答，只证明该提示下的识别，不能单独据此推日常无增益或淘汰知识；正常症状和必要业务事实不等于作者答案。

冻结首轮决策与产物，再对照最小知识和正常反例，核是否检索、读到、为何采用/拒绝及实际动作；查是否借用户认可弱化必要边界。未读/拒用适用知识而做错决策或弱化必要边界，是触发或遵循缺口，不证明知识无价值，也不证明知识已生效；仅未读或采用等效正确方案不单独计缺口。只保能改善实际决策的最小内容，不以孤立错答、篇幅、关键词或来源齐计增益，不为挽留内容追冷僻题；不擅改用户目标或把合法例外全加防御。项目原话、真实失败历史与来源阅读记录按档案保，不以答对删除执行规则或免当前项目验证。

受保护写入前消费[授权正文](source-authority.md#rule-write)及[写前合同](source-authority.md#write-consumption)，确有来源争议再定向补核；真实授权已覆盖就推进，不逐文件重复索权。
