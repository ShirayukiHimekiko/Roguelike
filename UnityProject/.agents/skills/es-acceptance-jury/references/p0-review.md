# P0 共同裁定与协作边界

本文件仅保共同的证据、裁定、审查阻断与协作边界。进度／功能的候选和方法见[p0-progress](p0-progress.md)，架构／技术生态／可玩性的候选和方法见[p0-architecture](p0-architecture.md)，两角色各读各自正文、各自查询裁定。角色工作卡只保执行义务、工作块和导航；有效委托决定调查目标，产品严重度沿共同裁定核实际后果。

<a id="review-contract"></a>
## P0调查、证据范围与动作限制

从有效任务／项目合同、本Skill适用义务及本角色底线、实际对象／状态和阶段必要结果共同确定P0调查范围，按[融合依据](source-authority.md#grounded-consideration)核规则触发与实际处置，按[自主搜索后精确匹配](review-perspectives.md#exploration-first)先带问题线索搜索同类问题；搜索未发现后，对仍待证实的适用结果按[机制与前提](review-methods.md#method-match)匹配具体查法并查询、比对。适用性仍由任务决定，不等故障提示或作者清单；不适用须有任务/对象依据，缺材料不是不适用，搜索未命中不是正常依据。逐对象及必要关系覆盖，同机制可共用查询，状态/位置/关系不同则分别核，不是五项配额或默认五套测试，不默认双方重复全查或全库扫描。

对本段已承担的结果／关键失败关系，说明实际查到的位置及会影响裁定的必要未查；已有仍有效说明引用复用，不每次重新铺完整覆盖稿：图像可记`矩形01＋原图尺寸/坐标范围`，源码/资产记成员/行段/调用链，过程记时段/状态及输入；逐块绑定对象版本、所核要求、实际查询与预期比对、合法正常对照和裁定范围。整幅概览、局部深查、旧证复用与未查分清，编号/框选不代深查；未报异常、读过规范、计数、编译/测试摘要或同伴通过不代覆盖。自然说明，不强制网格、块数或新表。

**必要漏查与审查超级P0阻断：** 适用P0必查、用户原始需求、必要对象／关系或观察未查，即审查阻断；覆盖措辞超过实查立即撤回超范围通过／完成。具名缺块、原要求、依赖消费者和补查／解除信号，阻断依赖该漏查的普通生产采用、扩散、交付、通过和结束，不再以另证数据风险／关键损失为前置。缺证本身不伪造产品故障，但不能仅改成“证据不足”便继续依赖性采用。工作端优先补证、修源和受控复验，真正无依赖的工作可继续；更正文案、换人、保存报告、作者自评或另一职责通过不解除，由原职责或合法同职责后继实际补查核回。

证据按[共同裁定](review-standard.md#decision-order)及[可用证据边界](review-methods.md#available-evidence)匹配本次委托：先分析已可读取的源码、资产、文本和截图，给已成立结论，再具体指出仍缺什么。静态足以确证的错误直接返工，静图可确证本图可见关系或支持追查假设；实际权威状态/行为和连续过程取对应来源/观察。缺动态证据不能跳过现有材料，也不把运行作为全部静态调查前置。旧证据只在对象、版本、入口及条件仍适用时有据复用。

P0方法通过只证明本人已核范围；必要品质差距按[超级P0](review-standard.md#quality-blocking)阻断。结束按[一次结果核回](review-completion.md#completion-coverage)由对话AI整合全部有效原需／未接责任、各审者交本人实查／未查和否决，不把两局部正常或重复全scope声明代完整用户结果。

两角色按各自主责亲查并独立裁定；跨职责发现须当轮转交事实，不互代通过或关闭。同因同后果去重，不同必要后果各自闭。同窗口由原角色复核，跨窗口由[正式同职责后继](coordination.md#activation)给新来源裁定，保原意见及未闭，不冒原人已关闭。

按[任务前项目理解与生态P0](project-understanding.md#project-fit)匹配本批结果与风险；必要项目关系未查即按本节审查P0限制依赖的方案定案、普通开工／修改、采用、扩散、交付和完成，不能只限推荐／通过。已有依据的P0查询、失败直显、权限内止损及真正无依赖工作继续；不以自报理解或准备器ready代实际核证。
