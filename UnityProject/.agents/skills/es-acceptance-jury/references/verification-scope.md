# 验证相关性与必检选择

<a id="relevance"></a>
## 先说明显性、隐含影响，再选检查

工作端与实际陪审在确定检查／复验范围、采用当前结果前，先对回有效委托、适用P0和原未闭；在原任务记录及本人依据/处置/落实中说明：改了哪个输入／责任源或合同，经哪些实际关系可能传到哪些消费者／必要结果，因此本轮查什么、沿用什么证据、凭何排除什么。已有仍有效声明可复用，只补变化；不新增每工具必填表、评分或批准轮。

相关性沿真实生产与消费追：调用／装配与间接引用，共享数据／资源／配置，生成或导入产物，空间与时序、生命周期、平台／构建及旧消费者。已有关系或可核共享前提支持影响可能，就必须纳入检查，不等已经出现失败；有影响可能的必检不能以“微小改动”、文件后缀、模块名称不同或当前局部正常免除。必要交付验收、原坏例／独立否决和变化的观察前提，即使相关文件未改仍须核回。

关键关联未知先做能判别的静态追查或最小观察；合理可能尚未排除，就保具名未闭并限制实际依赖动作，不能把“没有查到／未运行”写成不相关。排除须给已核的隔离边界、供给／读写／配置关系和旧证据仍成立的条件；搜索零命中或改动少不单独证明隔离。抽象地说“任何东西都可能相关”也不自动要求全系统重跑：追当前目标的可核关系及共享前提，依据足够决定该范围即停，无关就绪工作继续。

检查范围不重写交付范围：本次完整提交画面仍按全目标亲看；有据无影响的未提交对象可复用；原必要结果、品质和原职责关闭不因选批、拆ref或小改而丢失。需要选择具体验证方式时实际消费下节。

<a id="selection"></a>
## 按待判命题选择证据和执行

先核派发／回件是否考到原目标的必要判断、操作和完整结果，漏考修原题，不用技术小题关专业能力。首轮接清当前已知的正式入口、运行／导入条件、观察口径和退出；相关条件集中核，可独立的运行／静态工作并行，新反例再定向补。旧证按对象、版本、入口、依赖及观察条件复用；原坏／正常、静态／运行／体验各证其命题。只有实际改动、失败或具体未证条件会改变当前决定时才补受影响检查；同对象/版本/条件的原件跨职责复用，本人亲读不等重复采集/执行。文字实际改变AI决定仍按读取/派发/执行及消费者核必要语义；无语义/条件变化的ACK、格式或回执不触发重跑，不因后缀/AST相同免必要核验，也不每次全跑。软件未覆盖的政策判断另核。

投入、停止原法和改路统一沿[继续／改法依据](must-read-work-priority.md#continue-or-change)，不以自设限额免必要核验，不以必要未知尚存继续无信息试错。真实限制保来源、受限动作和续办条件，无关就绪工作继续。

两角色共用原始产物但各自判断；每份媒体／运行结果优先一处原件多处引用，不机械复制整包或反复嵌入base64。工具只返回所需数据，避免倾倒PowerShell／.NET对象图，必要嵌套内容仍保全。复用不免[本次完整亲看](review-standard.md#visual-review)、[完整意见及逐源展示](coordination.md#message-delivery)；亲看不等于重采。

生成／隔离环境前读[环境复用](evidence-lifecycle.md#environment)，任务[恢复](evidence-lifecycle.md#recovery)或[退出处置](evidence-lifecycle.md#retirement)时实际读相应正文；缓存仅在[真实空闲旁支](evidence-lifecycle.md#idle-cache)处理，不成为无关主线的新前置。

<a id="examples"></a>
## 分析相关性的两侧条件示例

这些是条件案例，不是按模块名建立互不影响白名单，也不证明某个当前Unity项目有故障：

| 改动 | 可能相关，必须查的链 | 有据独立时可排除的范围 |
| --- | --- | --- |
| 角色动画 | 动画事件／骨骼或位置、边界被UI跟随／业务反馈读取时，查对应UI状态与显示。 | 只变独立角色姿态，已核无UI绑定／事件／共享状态或空间前提变化，可沿用无关UI证据。 |
| 编辑器工具 | 导出或序列化运行数据、导入资源、配置／生成代码被运行时读取时，查相关负载和行为；工具自己的响应性能也按任务核。 | 只变独立编辑器说明／布局，已核不改运行供给或执行关系时，不强跑无关Player性能。 |
| 渲染 | 相机／空间变换、可见或拾取来源、几何／遮罩等被命中链共用时，查对应命中；渲染自身必要效果和负载照查。 | 独立外观改动且已核命中来源、相机／几何／空间等前提未变，可沿用无关命中证据。 |

真正项目必须用实际绑定／源码／资产关系判，不把这里的示例条件自动预填成事实；出现反证重开受影响结论。
