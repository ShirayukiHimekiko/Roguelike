# 抓帧、录屏与连续动效分析

<a id="scope"></a>
## 选择本次需要的观察能力

按本次画面/动效目标与现有证据选[采集](#capture)、[取帧](#frames)或[分析](#analysis)，不默认运行游戏、录全桌面或处理整段长片。先复用项目/MCP/浏览器/录制工具；能力确缺时同轮提出[具体安装或接入建议](ai-tooling.md#installation)，已有授权与可行分析继续，不等用户再问。

分清三层：能录制、能解码取帧、观察者能接收正常速度连续画面/声音。FFmpeg、录像文件、播放命令或联系表不为模型增加视频/听觉输入；最后一层缺失时，明确需要能回传对应连续输入的宿主/工具，而非反复装播放器或换同能力Agent。先完成可支持的画面与时序分析，原动态失败保未闭。

<a id="capture"></a>
## 采集到正确对象与实际时间

固定实际项目/构建/Scene、进程与窗口句柄或明确区域、视口/缩放和触发。先用可识别变化核输入→状态→原生渲染→采集链；独立窗口句柄或区域须实际对应目标，工具成功不自证绑定正确。录到错误窗口、被遮挡/最小化、后台暂停或采集掉帧时先修采集条件，不能把它判成产品冻结。

围绕原失败取稳定基线、真实触发、动作全过程和后继；存在循环或打断才覆盖接缝、取消/反向与再进入。时长和采样频率由最快必要变化决定，不统一规定几秒/几fps；短暂挡字或一帧跳变须能落入实际覆盖。保原录制条件，强制重绘、变速、单步推进与后台常驻只作另存的诊断对照。

源视频/原尺寸帧与输入时刻、实际时间戳和已知采集条件保可追溯；分开采样频率、编码帧率、实际帧时间和真实运行帧率。需要声音时使用已授权、确有声音轨的录制链并核实际可听输出；静音录屏不签音效或音画同步，也不默认录麦克风/系统其它窗口。

<a id="frames"></a>
## 按真实时间戳定位关键区间

先看完整画面和可观察的正常速度片段，再按触发、进入、极点/接触、换向、中间态、退出与循环接缝定位。用视频实际PTS或带时标的原生采集帧，明确时间原点、缺口和重复；变帧率不按帧号除名义fps猜时刻，不插值/补帧后冒原采样。

先在相关短区间保全部实际帧，或按已知变化选有依据的粗采；发现异常、采样无法排除短暂问题或时序不符时，对该邻域按原帧加密。联系表每格带时间/帧定位，缩略图只导航，必要细节打开原尺寸帧；ROI用于同坐标部位分析，原整幅保留，不逐帧居中、缩镜头或裁掉相邻对象掩盖跳变。

相邻帧差、重复帧段、对象/支点轨迹与时间间隔帮助找候选，不自动裁定冻结、流畅、观感或P0。静止等待/设计停顿可以合法，鼠标/压缩噪声不证明主体在动；小区域一帧遮字也可能只有很小全图差，不能只看变化量最大的帧。均帧/连续插值不关闭已观察跳变。

<a id="analysis"></a>
## 从连续表现追到可修原因

在实际尺寸和正常速度核目标相关的先后、快慢、幅度、重心/方向、跟随、接触、可读中间态、反馈与输入时机、注意力及循环/打断衔接。慢放和密帧用于定位具体时刻，再回正常速度核其实际影响；合法切镜/传送、机械匀速、同步群体或克制反馈按本游戏设计判断，不统一改缓动或随机相位。

同一触发下将参考、前版和当前版按语义事件与实际秒比较，视口/尺度一致；周期百分比不自动代表相同姿态，不用变速对齐抹掉节奏差。先确定画面实际显示的问题，再沿状态、时间/坐标、动画/变换写者、材质/遮罩/排序和相机追原因，用单变量对照区分产品与采集影响；不能只凭截图猜具体根因。

意见落到“原件/时刻→具体对象与可见差距→玩家影响→责任源/下一查验→同条件复看信号”，同时保正常行为、整体风格和必要内容。按已有[玩家视角方法](constraints/04-visual.md#player-motion)给实际改法，不以帧数/曲线/工具安装或无异常计数代品质。无连续输入时仍给亲看帧中的确定缺陷与已覆盖时序结论，明确其余手感/声音未证；用户原动态失败不降成未知。

<a id="helper"></a>
## 按需使用现成采集与取帧脚本

`scripts/jury_media.py`复用本机FFmpeg（PATH、显式`--ffmpeg`或已安装imageio_ffmpeg内嵌版本）及Pillow。`doctor`只核依赖并给缺失能力的安装来源，不自动安装；ffprobe是额外诊断入口，不因PATH缺命令就忽略已安装的可用FFmpeg。

```text
python -X utf8 -B scripts/jury_media.py doctor
python -X utf8 -B scripts/jury_media.py --timeout 900 sample input.mp4 --start 1.2 --end 2.4 --every 0 --output review-slow
python -X utf8 -B scripts/jury_media.py sample input.mp4 --start 1.2 --end 2.4 --every 0 --reuse --output review-r1
python -X utf8 -B scripts/jury_media.py capture --region "100,100,800,600" --seconds 3 --fps 60 --output capture-r1 --dry-run
```

例中源文件、区域/窗口、区间和频率须按真实任务替换；dry-run仅列命令，不录屏。版本/设备查询默认每条30秒，前缀检查及取帧各600秒，录制主体为请求时长加30秒；全局`--timeout`置于子命令前，以有限正数秒覆盖每条外部命令，不是整个操作的总期限。Windows启动器先将本次命令归属匿名作业，再执行目标；前端先退仍等本次后代完成，超时回收该调用链，避免等后代管道失限。归属失败在目标启动前明确拒绝，不静默无界回退，也不按名称清理其它实例。长前缀或慢机器可显式增大；启动与回收有有限开销，不承诺硬实时零误差。超时明确失败，doctor返回退出码2，保诊断、日志和已有部分产物，不发布成功清单。工具期限不替代必要审查或品质要求。获准录制时可选真实`--hwnd`或物理像素`--region`，不默认全桌面；该Windows采集入口无音频。已知目标/前台/遮挡和需要的音轨由实际采集方核，脚本不冒已绑定或已听。

`sample`不改源文件，CLI须显式给`--every`：0保所选区间全部解码帧，正值按任务所需间隔只选实际帧；Python API保留默认全帧能力，`--roi`只影响变化量分析；输出原尺寸PNG、PTS清单、带时标联系表、原始变化信号及`review.html`。先查到所选末点的解码前缀，遇变尺寸/格式重初始化或时间倒退明确拒绝，不静默缩帧或重置时标；保原视频和日志，改用能保该变化的解码/采集路径。时标以首个解码视频帧归零，不冒墙钟/真实输入时刻；原视频仍是完整播放依据。HTML只是原视频与联系表入口，生成成功不等于观察者已播放或浏览器支持该编码。首次生成使用新目录；同源、同参、同工具的完整成功产物用`--reuse`校验后只读接续，不再解码或另建目录/报告。源全SHA、参数、helper/FFmpeg/Pillow及精确产物集合与hash须相符，旧记录缺依据、缺失/改动/链接产物或参数变化均拒复用，不覆盖修补旧证据或自动另建rN。源视频允许正常路径读回并绑定真实文件；输出入口及产物拒链接/逃逸。成功清单最后发布，提取时源发生可见变化不发布可复用成功。capture继续真实新录制，复用取帧产物不代本次完整目标亲看或当前现场取证。失败保日志和部分产物，任务结束按[生成与退役责任](evidence-lifecycle.md#retirement)处理已无责任的临时输出，不把每次调用留成永久副本。

实现查证用[FFmpeg设备说明](https://ffmpeg.org/ffmpeg-devices.html#gdigrab)、[select/showinfo过滤器](https://ffmpeg.org/ffmpeg-filters.html)与[官方获取入口](https://ffmpeg.org/download.html)，具体设备/参数仍核当前二进制。脚本只供采集与辅助分析，不自动给通过、故障或体验评分，也不为记录成功授运行/安装权限。
