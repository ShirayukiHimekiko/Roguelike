# 承接专项：运行边界、记录与恢复

首次完整消费 SKILL.md 的核心职责和底线，本页仅在运行边界、记录或恢复动作命中时读对应章节与必要依赖；不再要求三份旧 must-read 无条件全文加载。已读且仍适用正文复用，丢失或变化只补相关部分；旧文件名/锚点保留，用户/项目明确要求指定全文时照实消费。暂停、撤销、紧急止损立即执行，不等阅读；复用不冒称重新读取，当前目标和未闭合状态仍须核对。

<a id="runtime-evidence-boundary"></a>
## 离线证据边界与游戏 JSON/schema 时机

审查JSON、证据版本、包清单和hash仅离线定位本波实物，不能自动植入Unity游戏协议或业务准入。游戏已有真实业务身份、版本/格式与合法校验另按项目合同判断，不因清审查字段删其职责。

Unity游戏的JSON、存档、序列化和schema是否采用、在何时运行，取当前批准设计与实际性能/数据合同。本Skill不统一禁止自动存档、后台保存或运行时JSON，也不默认添加这些机制。若项目明确禁止持续存档/某格式/特定阶段操作，按其范围执行；用户后到修订替代相关旧禁令，旧MINIX或其他项目要求不得推广当前游戏。

检查实际调用频率、读写一致性、异步线程/Unity对象使用、提交与失败恢复、加载/首帧及代表运行负载成本；有必要存档责任时保合法旧档、备份与续办。仅移到初始化/预热/后台不能自动证明预算通过。项目有明确禁令且实际违背时判失败；性能按当前预算与有效测量判断，缺必要测量保性能未验，不把单一Profiler工具作为通过门。

<a id="incremental-records"></a>
## 记录降温：只落关键增量

默认复用既有任务记录和可恢复原件。只把改变下一必要动作或验收结论的关键进度、用户标准/授权/暂停变化、实质意见、必要证据变化和交付/恢复条件增量落盘；普通 ACK、收件、重复提醒、无变化检查及同字节转交留在真实会话，不另写报告、JSON、清单或 generation。受保留管理的完整实质意见须一次完整保存并读回，后续只追加处理与复验增量，旧否决和未闭合依据不得覆盖或删除，详见[意见落盘](coordination.md#opinion-records)。

不为每轮、每条消息或每次工具调用重序列化、重散列全包、复制全量表或刷新版本。只有实际字节变化、当前身份漂移疑点或必要交付完整性核对时，才按受影响范围补证；引用已有版本/哈希不等于新观察，无需为了落盘强制生成 JSON 或新哈希。已有裁定的适用性仍由真实变化判断，不能靠不刷新掩盖漂移。全量扫描/全量代际写入的现有工具不冒称增量存储，默认沿既有记录追加；明确机器未核对的范围，不伪造工具成功或旧通过。性能与空间收益未实际测量时只报告规则收敛，不认证节省量。

- 从当前用户原话及已确认修订恢复目标、标准等级、禁止项和授权范围；局部改善、上一轮通过或测试变绿都不降低原验收标准。依据不足只暂停依赖它的工作，已有授权内能推进的步骤继续，不把“一句话完成”变成反复让用户调度。
- 复用当前任务记录，确认真实产物/版本、原职责、最新完整意见与未闭；相关用户更新送回原链。未明确暂停/撤销且实质工作恢复时，沿[主动回接](coordination.md#interruption-recovery)及[窗口边界](coordination.md#activation)接续：同窗口核并联系当前可达原身份，跨窗口按本次所需职责新建后继、承接材料。中断或completed不解除原职责与未闭，换人不冒已通过；记录失联先找回实际依据，旧裁定仅限原对象。
- 实质工作首条说明必须按[消息展示](coordination.md#message-delivery)呈现陪审真实状态和下一动作；恢复请求已发、恢复成功、不可达分别说明，不能只在工具日志或最终文件里体现。一句话即可凭已有事实答复的小任务按[启用例外](coordination.md#activation)直接完成；一句话提出的制作、基线变更、未闭合问题或送验仍须同步原链。
- 本轮选定一个有可观察结果的推进批次，保留原目标尚缺什么、下一动作和结束信号。交接带上可达的原意见、标准、当前结果和下一送验点，接手工作继续接入陪审；不要另建平行状态库或每轮抄全表。
- 实质送审消息沿[工作端发送合同](coordination.md#worker-message-prefix)，陪审意见与对外转达沿[现行展示合同](coordination.md#message-delivery)。分别核对“实际发送格式”“完整意见已落盘读回”“责任问题已修复复验”，任何一项都不能替另外两项作证。普通收件/控制消息不制造新审查和新报告。
