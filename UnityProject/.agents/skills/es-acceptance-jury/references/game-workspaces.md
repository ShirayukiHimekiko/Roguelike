# 高质量游戏与工程生产的 8+2 工作区

<a id="approach"></a>
## 从任务判断走到真实方案

八块同时覆盖游戏设计与工程生产，游戏流程及可玩性／可用性是贯穿八块的+2，按实际消费者分支。游戏最终品质以实际玩家体验判断，代码能跑不能证明游戏做对；资源、工具、架构还须独立判断制作、接入、维护和项目推进是否成立，不必先出现玩家故障才查工程问题。按项目类型、阶段、交付需求和生产惯例确定本批结果，不把用户举例或目录当检查边界。

每个命中区先沿[融合依据](source-authority.md#grounded-consideration)核任务／项目合同和本Skill适用要求，再定位当前委托及其实际依赖中的差距与具体痛点，完成“看出什么→为什么→怎么改→怎么验证”：从原话／项目合同、适用规则、实际产物/过程、失败和生产依赖确定差距，指出对象及玩家或制作/接入/维护后果，不能仅把标题改成疑问句；涉及症状定位、局部补偿或反复返工时，按[从现象追到机制](causal-diagnosis.md#method)区分局部、适配与供给前提，用能区分原因的查询、对照或小样核假设，给推荐改法、实际采用位置、必要代价和预期改善。检查须验证必要要求或改变诊断、选型和下一制作动作，不按块/ID凑问题；低价值之名不能免除必要P0与项目基线。泛称“优化体验”“调整架构”“完善工具”不算方案；原因未明给能决定改法的下一查验，已有充分依据可直接给方案，不强制多套比较或样件。

进度／功能核目标兑现、业务结果、工程交付与下一消费者；架构／技术生态／可玩性核职责与依赖、资源和工具生产链、可维护性及游戏品质。两者均须有领域洞察并提出可实施改法。工程证据可以独立证明相应工程结论；游戏体验结论仍须相应画面、过程、声音或真实玩家反馈，二者不互相冒领。缺资源、缺工具或同类手工/补丁反复出现时，主动查项目现成能力及权威、成熟、Unity惯例常用方案，按[能力调查与采用](project-understanding.md#capability-fit)落到实际接点，不等用户给库名，也不默认硬重写。阻断、高风险或高要求必须按[知识检索](reading-guide.md#knowledge-use)找适用原理、实践或反例，落实到当前方案和验证。

八块按命中读取；两个贯穿区按当前对象核游戏流程、可玩性或使用者可用性，不把读到游戏方法当作非游戏API的玩家验收义务。纯工程交付按工程证据完成，说明相关游戏影响和未证范围，不强迫每个工程问题先转成玩家缺陷；涉及游戏使用或可玩完成声明时，按受影响流程和体验核证，工程通过不关闭原游戏未闭。检查身份唯一登记、多区引用；共同查询、证据与协作完整执行[P0共同合同](p0-review.md#review-contract)。

<a id="goal"></a>
## G1｜项目目标、方案与推进

**找痛点。** 从当前要求、实际产物、未闭与下一消费者找“本批做完什么就能继续”，分清规则未定、资源不足、工具缺能力、接入断点和品质差距；不把任务数、检查量或无画面变化当进度。

**查原因。** F核上次承诺、真实采用与当前失败，A核依赖是否必要、现有项目能力能否直接组合。把阻断假设追到具体文件/资源/入口和应有输出，以现有证据或能区分原因的试验判断；只卡相关链，可并行的制作继续。方案从具体玩家情境或工程使用情境推演，不用常见功能拼装代设计。

**给改法。** 推荐当前最能解除关键缺口的一片成果，写清改动源、采用者、必要代价与下一验证；成熟能力可直接采用，前置反复不兑现就改序或换方法。保用户目标、原数据和有效意见，不另立阶段审批或管理系统。

<a id="rules"></a>
## G2｜玩法规则、单位与世界实现

**找痛点。** 从玩家此刻能力/资源、必要选择与全体应有对象出发，查规则兑现、单位建筑位置/目标/行为及组合是否支撑玩法；算式对或数量对不代合理。

**查原因。** F按有效规则算预期，对照同版配置/SO、Prefab覆盖、初始化赋值与权威结果，区分规则本身失衡、错误数据、错误实例和实现错误；同机制群体共查原因，各对象位置/状态和关系仍按实际条件核；**每个单位/对象按[单位三问](recognition.md#unit-state)分别答“从哪里来、在干什么、到哪里去”，缺一问即该对象未查完**，三问齐备也不代证据。A追实际写者、时钟、生命周期、坐标/层级与驱动，查重复推进、错绑或串扰。业务距离/阻挡/路径合法性归F，可见空间与命中归A。

**给改法。** 在真实规则/数据/生成或驱动源修正；选择被挤掉时调整实际代价与收益关系，状态错则修赋值/转换，不靠冻结、重复补写或删必要内容遮错。用原异常关系及合法转换/重试/后继对照，具体难度与组合体验由+2验证。

<a id="interaction"></a>
## G3｜操作、界面与关卡内容

**找痛点。** 亲看完整画面并按实际目标走必要操作，定位玩家看不懂、点不到、操作不符意图、反馈误导，或关卡学习断层、无效往返与节奏断裂发生在哪一步。命中UI整页／窗口时须沿[任务追加入口](reading-guide.md#task-additions)直读[03/11](constraints/03-ui.md#03-11)及用途四卡；只查输入／关卡机制不默认整UI。

**查原因。** F从意图→实际输入→权威结果→显示逐点比对，再沿路线核每段已知、会用和拥有的条件与挑战/回报。A查真实UI Prefab/Scene实例、RectTransform/Canvas、事件/焦点/遮挡、相机/空间和数据绑定，区分内容表达、布局、命中与状态错误；不能只查无报错或按钮响应。**结论标明[视角档位](recognition.md#perspective)：编辑器里可点不等于玩家视角可用。**按本游戏查，不强造战斗、波次或检查点。

**给改法。** 落到具体控件层级/绑定、交互映射、信息主次、区段布置或出现顺序，优先修制作源而非到运行时逐帧补位置和监听。同任务/原问题路线及正常路线比较理解、决策与后果；保必要信息及批准的探索/高难，无实际过程只签已有材料范围。

<a id="art"></a>
## G4｜美术、动画、镜头与音画制作

**找痛点。** 在目标尺寸、背景与正常速度下看/听完整产物，指出风格混杂、辨认困难、动作接触/镜头不自然、视听层次抢占等具体时刻和玩家影响，不能只判“有素材、有动效”。视觉／交互方案、参照或提交命中[任务追加入口](reading-guide.md#task-additions)的设计／视觉验收正文；UI页再直读[03/11](constraints/03-ui.md#03-11)及用途四卡，不把图/动画任务一律变整UI。

**查原因。** F核演出身份、含义及规则时点；A对照适用参考，分离原素材品质、加工/导入压缩、材质Shader/光照、排序镜头与时空驱动的作用，用同条件对照或实际驱动证据排除疑因。**先判[复刻/参考档位](recognition.md#replication)**：复刻要机位、比例、时序逐项对应，参考只要取向可辨；档位判错时后面的对照全是错方向。批准的像素、低模、机械动作和切镜按设计判断，不把保真度高当质量的唯一方向。

**给改法。** 在决定性来源改造型/比例、构图色光、姿态曲线、接触、镜头或声部主次；源不足主动按[资源探查](evidence-recovery.md#joint-source-search)找更合适材料/制作方法，现成Shader/工具不足按能力调查处理。保必要表达与内容密度，在原条件复看；找源、制作与整体体验分别有据完成。

<a id="resources"></a>
## G5｜资源与内容生产

**查可达与依赖。** 从项目AGENTS、目录/命名惯例及实际loader查文件名、相对根/地址键、分隔符/大小写/扩展名的真实API语义，追meta/GUID、配置、Prefab/Variant、材质纹理/骨架和打包依赖。核本项目实际需要的Editor、目标构建、开发/发布、本地/远端环境；Editor可读或当前目录有文件不代目标可达，不统一强套大小写规则或检查无关平台。

**查加载与释放。** F核正确内容和下一消费者，A沿真实加载入口→依赖取得/句柄→实例与共享持有者→切换/取消/失败→释放/卸载→后继再用，查重复加载、漏释放、过早释放和卸载后仍被用。按项目实际API、所有权及引用关系比对，不把Destroy实例、Release调用或引用计数变零直接当全部内存已回收；没有的池/异步/远端机制不新增。

**查品质并给改法。** 在目标使用条件比较源件、导入/加工、材质绑定和最终输出，判断低质来自源不足还是处理损失。低保真/占位不能支撑当前目标时，工作AI主动按[分层探查](resource-discovery.md#search-order)找更好且适用的来源、加工或原创路径，陪审独立核关键候选；已批准像素/低模风格不强换高模。方案落到资源、路径/依赖、加载持有/归还或制作源，保其他共享消费者、原身份和数据；以原失败环境、合法共用和后继复用验证。纯素材按委托产物及必要消费结果完成，其已要求品质不等进游戏才验。

<a id="tools"></a>
## G6｜工具与制作流程

**AI侧工具。** MCP/Apps、CLI、浏览器/文件操作、Skills/插件、审批权限、长任务及原生协作也命中本区；按[AI工具方法](ai-tooling.md#scope)选实际动作对应正文，核能力、调用、结果与恢复。AI离线工具按其宿主和任务验，不强套Unity/Player条件；Unity生产工具继续沿下文调查与采用。

**先找能力缺口。** 针对反复手工、重复代码、导入/编辑/调试低效或现有工具做不到的具体结果，主动查项目Packages/插件/API、已有用法和统一设计，再按[能力调查与采用](project-understanding.md#capability-fit)找权威、成熟、Unity惯例常用方案。用户指出的System.Text.Json、HybridCLR、DOTween和Shader是方向，不是每项目必装清单；不能等用户逐项点库，也不能只会验证已有工具。

**核适用并采用。** F用代表性真实输入核所需输出/消费者和原有数据，A查准确能力与版本、Unity/API/目标后端、渲染管线、程序集、依赖/许可、初始化和退出清理；只核当前选型所依赖的条件。按项目接法复用或做有职责的薄适配，在当前授权内完成接线与必要验证，不止列库名/链接或交待批推荐。已有方案不适用时给具体不匹配依据，可最小自研，不为“必须复用”穷尽所有库。

**验生产效果。** 比工具前后的同任务结果、保存重开/重复执行及适用失败恢复，保原数据、引用和编辑能力；Tween查目标寿命/取消、JSON查真实类型与数据来回、Shader查当前对象/管线效果，热更查真实构建与加载链，按实际需求取证。工具范围可独立完成，单样例或Editor绿不冒目标Player/全部流程/游戏品质已过。

<a id="architecture"></a>
## G7｜架构与系统集成

**从Unity实物找痛点。** 先读项目设计、命名和装配约定，查真实Prefab/Variant、Scene、UI层级/事件、SO配置的保存引用、覆盖、初始化与销毁，定位依赖缺失、职责错位、重复状态或接入难点；不只在C#类图里谈分层。项目级架构/系统/生态审查沿[全项目基线](p0-architecture.md#project-tracking)覆盖全项目，局部改动追实际影响链。

**查合同和损耗。** F核业务语义、失败与后继保留；A按[强类型与接线](constraints/01-architecture.md#strong-wiring)核具体类型/程序集、参数/返回、必需/可选关系、读写/归还者及实际消费者。比较序列化/拷贝、重复查找/重绑、运行成本、迁移和Prefab/Scene作者编辑损失；低损耗按项目目标判断，不强造0B或抽象层指标。

**修源并核生态P0。** 先按[项目理解与生态P0](project-understanding.md#project-fit)核真实权威、入口、来源、绑定及可做／禁做，不能以胶水旁路现有合同。 能在原Prefab/Scene绑定、配置、接口或状态owner解决，就修该源并接齐受影响调用方，不用反复Find、业务反射、object/dynamic、静默判空、全世界Capture/Restore或多份补写兜底掩盖缺合同。保有真实格式/平台/第三方边界职责的适配和成熟库内部实现，不为强类型口号删合法动态/序列化。给复用/局部扩展/必要迁移的具体理由，保GUID、数据、生命周期和玩法，以原坏绑定/顺序及正常装配/后继验证；工程结论不代游戏品质。

<a id="delivery"></a>
## G8｜实际运行、性能与交付

**找痛点。** 从目标设备、真实内容和当前交付追启动/加载慢、操作延迟、持续卡顿、内存累积或构建差异，绑定同版产物、实际配置和问题时段；不以菜单均帧或一次空场签全部。

**查原因。** F核目标内容/规则、旧失败和交付版本，A对照有效CPU/GPU/内存及加载/释放证据，区分采集扰动、热路径、重复生产/加载、容量和依赖问题。按需要比较冷/热启动、切换和持续使用，不机械追加全平台；选择能区分疑因的真实采样或源码链，缺样本不写零或捏造故障。

**给改法。** 在真实热点、资源寿命、装配或构建配置源修正；同等必要内容/画质/输入比较收益与损失，查成本是否搬到加载、保存或后继。按项目实际目标，不统一发明帧率/0B。工程构建按委托范围完成，涉及游戏使用仍验对应过程与品质；编译、构建、运行和交付分别保证据，打包不授发布权。

<a id="flow"></a>
## +1｜游戏流程、场景视角与当下世界状态

本节仅对游戏流程命中；工具／API的日常工作流按下方可用性分支，不强造玩家、场景或Player前置。

**判断。** 场景与视角转换是否符合游戏推进；当前证据中的局面能否由玩家通过真实条件到达；此时此刻全部应有单位、建筑、UI的位置、状态及关系是否正确。

**双角色与查法。** F从真实入口和推进条件恢复到达当前局面的依据，对照阶段、对象及状态；A比较转换前后完整画面、视角、空间关系和操作上下文，追场景/镜头/显示的实际采用。连续证据可复用，不强制从零重玩；调试摆场或加载成功不能代玩家可达，代表单位正常不能代全局正常。暂停、退出、保存继续仅在项目存在时查其恢复局面。

**方案。** 精确指出错误转换、生成/保留/清理条件、相机或UI状态源，在原责任源修正；从问题前一合法状态推进到问题局面，并核全部受影响对象和正常转换。不能把游戏流程缩成按钮路径或Scene调用顺序。

<a id="playability"></a>
## +2｜可玩性与可用性

**先分消费者。** 游戏可玩性按下述玩家过程判断；工具、API及制作／维护流程的可用性，按[11/07](constraints/11-methods.md#early-value-check)核当前任务、新前置收益及总负担。F核任务与反馈兑现，A核抽象、接入和维护代价；同人兼任不把成本搬家当消失。工程正确、游戏好玩和使用者减负分别取证，不互签。

<!-- jury-read-continue: references/constraints/11-methods.md#early-value-check -->

**游戏判断。** 按游戏类型和目标玩家，判断挑战与应对是否可理解、公平且可调，学习、变化和张弛是否适合；整体风格是否一致，操作、动作与镜头是否流畅无意外跳变，机制能否彼此促进，特效与音效是否清楚、有层次并达到表现要求。还要查当前游戏特有的体验矛盾，不把这些维度当封闭清单。

**双角色与查法。** F将玩家可用能力、已获信息、威胁、应对机会和失败代价放进同段过程比对，查结果是否来自可理解的选择与执行，定位学习断层、难度失控、违背设计的单一最优解、无效等待或机制互抵；A以完整画面、正常速度过程和实际声音判断风格、连贯、视听品质及组合体验，再追驱动原因。单项反馈正确、均帧达标或素材精修不代整体好玩；静图可判风格与构图，不能签手感和声音，未有真实玩家反馈不冒称玩家已验证。**可玩性结论只能出在玩家视角**：作者视角的编辑器试玩与诊断视角的慢放补帧都不签手感与节奏，见[视角档位](recognition.md#perspective)。

**方案。** 从最影响当前体验的原因入手，具体调整挑战/应对关系、内容编排、节奏、控制响应或视听表达；说明预期玩家变化和可能损失。用同等必要内容、正常速度及相应难度情境比较，必要时找目标玩家验证；不得删除已要求或承担必要玩法价值的机制/效果来规避原问题，允许有据删冗余并核实际损失。
